Memory & sessions

Two different stores: curated facts you keep on purpose, and episodic transcripts you pull when you need provenance. Neither is auto-injected into prompts by the daemon.

Pull, don’t inject. Success and staleness of recollect are surfaced for judgment — they are never silent score terms or auto-deletions. Capture wins over any live mid-flight view if they ever disagree.

Curated memory

Remember/recall only work for corpora with memory_scope = "global" or "project" in kb.toml (or ones created by the Claude kb-memory plugin + /kb-setup). A normal artifact corpus alone is not enough.

# minimal memory corpus (then restart the daemon)
# [kb.memory]
# path = "/home/you/kb-memory"
# memory_scope = "global"

kb remember "We pin arrow and lance to the same version" \
  --title "Arrow/lance pin" --salience 0.9 --tags "invariant,build"

kb recall "arrow lance version"
kb recall "arrow lance version" --explain
kb forget <id>

Verify with kb recall "test" / kb status. Empty or error results usually mean no memory-scoped mount is loaded.

Recall fans out across in-scope memory corpora and ranks by a fixed formula: rank-position × salience × decay. Supersede is a tombstone applied at recall time (history stays inspectable). Forget hard-deletes the memory artifact file. Pin holds a memory above the decay floor. Promote (SPA) copies a memory into a chosen regular non-memory kb and strips memory metas (salience/decay/pin/supersedes) — it is not a project→global flip inside the memory corpora, and there is no kb promote CLI verb.

For a human gate instead of immediate write: kb propose → kb proposals list|approve|reject. Approving uses the same write path as kb remember.

Episodic sessions

# Why is this file the way it is? (path → sessions + decisions + commits)
kb why path/to/file.rs

# Have we done something like this before? (semantic over session digests)
kb recollect "federated search fan-out"
# sessions similar to another session's digest (session id, not a file path):
kb recollect --similar-to <session_id>

kb sessions list
kb sessions show <session_id>
kb sessions read <session_id>
kb sessions by-commit <sha>
  • kb why — reconstructs past sessions that touched a path, with prompts, decisions, and commits (confidence labeled).
  • kb recollect — semantic search over session digests; surfaces recency, errors, commits so you can decide whether to trust a hit.
  • Canonical session id — recovered from the transcript’s own sessionId (ground truth), not a truncated filename.

The indexed surface is a deterministic digest, not the raw JSONL. Full transcript text is evidence you pull on demand; default search stays clean.

Capture and hooks

Claude Code (and sibling harness adapters) capture at Stop (and related hooks). One long session may produce many capture rows; list/show tooling scopes reads to the newest capture so counts do not double.

Setup for Claude Code: marketplace + kb-memory plugin + /kb-setup. Other agents: shell out to the same kb verbs; put the protocol in AGENTS.md / instructions.

kb sessions capture …     # explicit capture when needed
kb import claude-history  # bulk import historical transcripts

Verify capture: after a session Stop hook, kb sessions list should show a row. Empty list usually means the daemon is down, the plugin/hooks are missing, or the harness adapter is not installed. kb why / kb recollect need at least one digest-indexed capture. Captures are pull-only — the daemon never auto-injects them into prompts.

Reading progress for agents

Before revising a long doc, check what a human actually read:

kb reading <artifact-id> --json

Progress is cumulative (max-merge), seeded on open, no SSE noise. It also feeds derived read-state on reading lists.
