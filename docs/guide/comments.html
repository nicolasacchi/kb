Comments

Human and agent leave margin notes on rendered artifacts. The daemon owns the review files; the CLI is the only safe mutation path for agents.

On this page

In the UI

Open an artifact, turn on annotate (comments dock / inspect sheet). Click a block: a text selection becomes a Selection anchor, a heading a Chapter, an element with an id a Section. Threads live in daemon-owned .review/<id>.json (kb-comments/1) — never edit those files by hand; the SPA listens over SSE for live updates.

Anchors and staleness

On every reindex the daemon re-resolves open anchors. If a target moved too far, it marks the comment stale (badge + stale-anchors dashboard). The resolver is detection-only — it never silently rewrites the frozen anchor. When you intentionally move a section, re-point with ground truth:

kb comments reanchor <comment_id> --path <artifact> --anchor section:<new-id>

Stable heading ids in source HTML are what keep Section anchors healthy across regenerations. Avoid UUID or timestamp ids.

Agent loop

Typical agent turn:

kb find <path-or-name> --json
kb comments list --path <artifact> --json
# edit the source file on disk (watcher reindexes)
kb comments reply <comment_id> --path <artifact> --body "What changed."
# resolve one comment (kb + artifact id + comment id as positionals):
kb comments resolve <kb> <artifact_id> <comment_id>
# or resolve every open comment on an artifact:
kb comments resolve --path <artifact> --all

Triage rule

  • Clear, small fix (typo, phrasing) → edit + reply + resolve.
  • Ambiguous or large → reply with a question or options; leave open.
  • Unsure → reply rather than silently resolving.

Realtime loop from a terminal: kb comments watch. Export a full thread with kb comments export; bake comments into a portable HTML copy with --embed and read them back with import.

Batch apply

When one review turn produces many mutations, send them atomically:

kb comments apply --path <artifact> --ops-json '[
  {"op":"add_reply","comment_id":"c_aaa","author":"claude","body":"fixed in §2"},
  {"op":"set_anchor","comment_id":"c_bbb","anchor":{"kind":"section","id":"overview"}},
  {"op":"resolve","comment_id":"c_ccc"}
]'

All ops land or none do; one SSE update. A batch cannot reply to a comment it also creates (ids are server-minted).

Identity (attribution, not authorization)

kb can record who acted — edge identity (e.g. Authelia Remote-User over a trusted hop), per-user API token, or the configured loopback operator — and keys read-state and comment authorship per user.

What it does not do: passwords, roles, read-only tokens, or ACLs. Every admitted identity is a full co-operator. The one hygiene exception: editing or deleting a comment body is owner-only (403 otherwise). Resolve, reply, attach, and reanchor stay open to all collaborators.

author: you|claude is the human↔agent role split; the user field is the identity string.
