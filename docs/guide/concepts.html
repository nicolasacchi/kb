Five nouns

NounWhat it isWhere it livesPrimary verb
artifact One HTML or Markdown deliverable — the atom kb indexes and serves A source folder (a corpus) kb search / kb get
note A Markdown artifact with [[wikilinks]] and GFM checklists Inside a kb (kb-category: note) kb notes
list An ordered, section-aware reading list; read-state is derived Per-kb kb-list/1 document kb list
memory A curated, agent-explicit fact, recalled deterministically A memory corpus (global or project) kb remember / kb recall
session An episodic agent transcript, digest-indexed, pull-only Sessions store beside each kb kb why / kb recollect
Memory ≠ session. Memory is what you chose to keep (curated). A session is what happened (episodic). kb recall answers “what do we know?”; kb why / kb recollect answer “what did we do, and can we trust it?”

Daemon and kb

A daemon is one running process (default http://127.0.0.1:4000). You can run several side-by-side on different ports. Each daemon mounts one or more kbs — a kb is simply a named folder of artifacts declared in ~/.config/kb/kb.toml (or added with kb add).

One process can federate search, recall, sessions, lists, and notes across every mounted kb. That is multi-kb on one daemon — not a multi-daemon proxy. Fleet tooling (kb fleet status, SPA Settings) watches many daemons; it does not merge their corpora into one search.

How indexing works

You do not run a separate “index” job for day-to-day work. The daemon watches source folders and keeps the index current.

source folders │ file watcher (~400ms debounce) ▼ parser → title · headings · tags · category · prompt · link edges │ per-kb back-pressured ingest ▼ indexer → storage → lance (vectors + body) + sqlite (metadata) │ ▲ └── embedder sidecar (out-of-process) ──┘ │ axum server ◄─┘ REST /api/* · SSE events · SPA · artifact subdomains
  • Content-hash gated — unchanged bytes are not re-parsed or re-embedded.
  • Quarantine — unparseable files surface at the quarantine API rather than vanishing.
  • Force paths — kb reindex rewalks; kb reset --kb NAME wipes index state (comments in .review/ kept unless --all).

Artifact ids are a stable 12-hex digest of the source-relative path. Rename changes the id; content edits do not. Prefer the relocate engine (kb mv / move API) over raw filesystem moves when you care about comments and history.

TUI retired (v0.24). The old five-tab terminal dashboard is gone. Fleet monitoring is SPA Settings + kb fleet status + kb events --follow. It is not coming back as a product surface.

What kb refuses (recorded decisions)

These are scope boundaries, not missing features:

  • No in-daemon LLM — ranking and digests stay deterministic; LLM steps live in agent skills/commands.
  • No CRDT / multiplayer editor — comments and .review files are the collaboration surface.
  • Identity is attribution, not authorization — kb can name who acted (edge identity / token / loopback operator) but does not do passwords, roles, or ACLs. Every admitted identity is a co-operator.
  • Corpus mount is the ACL — what the daemon mounts is what it serves. Cross-trust sharing is kb share or a dedicated public daemon.
  • Mobile is a reader + capture slot, not an editor.
  • No MCP server yet — the CLI is the protocol until a harness cannot shell out.
