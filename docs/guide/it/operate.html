Operare

Share ed export

kb share pubblica un file o una cartella su un host statico (Cloudflare Pages + Access di default, oppure GitHub Pages con --public), oppure scrive un bundle offline autocontenuto.

kb share path/to/doc.html --gate email:example.com
kb share path/to/folder --public
kb share --list "Q3 design pass" --local ./bundle.zip
kb share path/to/doc.html --page ./out.html     # single scrubbed page
kb share list
kb share revoke <name>
L’export rimuove sempre <template id="kb-prompt"> — il contratto di generazione privato non esce con l’artefatto. --no-scrub è un opt-out esplicito e rumoroso. --with-comments pubblica lo stato di review altrimenti privato; usarlo deliberatamente.

kb download invia in stream il sorgente grezzo o uno zip di cartella/kb per uso locale, senza deploy.

Monitoraggio della flotta

La TUI è ritirata. Usare:

kb fleet status              # health sweep over ~/.config/kb/daemons.toml
kb events --follow           # live SSE tail (Last-Event-ID resume)
kb status
kb metrics
kb pause / kb resume / kb reindex

Nella SPA, Settings offre le pagine Overview / Pipeline / Traffic / Errors / Live per gli stessi segnali. Le liste multi-daemon vivono in daemons.toml (CLI) e nelle impostazioni del browser (SPA).

Token e identità

kb token generate
kb token rotate
kb token show
kb token issue alice           # per-user registry token (username positional)
kb token revoke alice          # drop that user's registry line(s)
kb whoami
kb users

Il loopback bypassa i controlli bearer. Fuori dal loopback serve Authorization: Bearer … (o l’header configurato). L’identità si risolve una sola volta per richiesta, a fini di attribuzione; non è un sistema di permessi — vedi Commenti → identità.

Salute e ciclo di vita dell’indice

kb daemon doctor
kb backup <kb>
kb restore …
kb reindex --kb NAME
kb reset --kb NAME
kb compact --kb NAME
kb exclude …                 # per-file exclusions
kb config show | validate | edit

Dove vivono i file

  • Configurazione — ~/.config/kb/kb.toml, token bearer in ~/.config/kb/token, lista flotta in ~/.config/kb/daemons.toml
  • Stato — sqlite per-kb, vettori lance e .review/ sotto la directory di state XDG (tipicamente ~/.local/state/kb/<kb>/)
  • Modelli — pesi di embedding nella cache XDG (…/kb/models/)
  • Override di path — KB_HOME, oppure KB_STATE_DIR / KB_CONFIG_DIR / KB_CACHE_DIR
  • Pulizia per mismatch di dimensione — fermare il daemon, rimuovere $STATE/<kb>/lance/, riavviare

Checklist di produzione

  • Tenere il daemon su 127.0.0.1; mettere davanti Traefik/Caddy/nginx con TLS
  • Token bearer presente; non avviare mai un bind pubblico con KB_ALLOW_NO_AUTH a meno che il proxy da solo sia il gate
  • Impostare artifact_host_suffix (certificato wildcard per *.artifacts.…) e parent_origin all’origine della SPA
  • trusted_proxies solo quando il proxy raggiunge il daemon fuori dal loopback (es. bridge Docker)
  • Lo scrub outbound opzionale per-kb rimuove kb-prompt e le redazioni sulle richieste di artefatto non-loopback; kb share rimuove sempre il prompt in export
  • Fare backup regolari dello state (sqlite + lance + .review)

Cose da sapere per scrivere artefatti

Gli artefatti che si indicizzano e commentano bene condividono un contratto breve (scaffold con kb new --template … --title …):

  • Un <title> reale e leggibile da umani, allineato all’unico <h1> — campo primario di ricerca e titolo della card in galleria.
  • Gerarchia pulita di <h2>/<h3> con id kebab stabili (niente UUID o timestamp) così gli anchor di commento sulle sezioni sopravvivono alla rigenerazione.
  • <meta name="kb-tags"> e <meta name="kb-category"> per le facet.
  • Contratto di esecuzione dentro <template id="kb-prompt">, con tetto a 8 KB — indicizzato in locale, rimosso su share/export pubblici.
  • Sicuro per la sandbox: niente <base href>, niente target="_top", niente scorciatoie su window.parent (la SPA padre è cross-origin).
