Liste e note

Le liste di lettura ordinano il lavoro. Le note ospitano checklist e wikilink. Entrambe usano i meccanismi ordinari del corpus — nessun database parallelo per l’organizzazione “soft”.

Liste di lettura

Una lista è una sequenza nominata e ordinata di artefatti interi o di §sezioni di essi. Lo stato di lettura è derivato (override → permanenza sulla sezione → completamento dello scroll) — non un “flag letto” memorizzato a parte che finisce per divergere dalla realtà.

kb list create "Q3 design pass" --kb research
kb list add <list> <artifact>
kb list add <list> <artifact> --section overview
kb list show <list>
kb list update <list> <entry> --read     # entry = le_… id or 1-based index
kb list move <list> <entry> --to 1       # 1-based position (or --before/--after)
kb list prune <list>                    # dry-run: list tombstones, exit
kb list prune <list> --yes              # apply: drop them
kb list export <list> -o reading.md     # kb-list/1 Markdown or JSON
kb list import reading.md --into <list>

Le voci tombstoned (segnaposto di elementi eliminati) puntano ad artefatti eliminati o che non si risolvono più nell’indice. prune rimuove quelle righe dalla lista; non cancella i file sorgente.

Per condividere o esportare offline un’intera lista come bundle autonomo (voci ordinate + TOC generato) si usa kb share --list … --local out.zip — vedi Operare → share.

Note e checklist

Una nota è un artefatto Markdown con kb-category: note. È ricercabile e commentabile come ogni altro artefatto, ma esclusa dalla griglia della galleria e dall’atlante, così gli appunti personali non affogano la libreria.

kb notes new --folder projects/kb --title "Open threads"
kb notes append <note> --item "Wire the guide into docs/README"
kb notes check <note> --item 0
kb notes list --kb research
kb notes show <note>

Le task item GFM si attivano/disattivano in ordine di documento. Helper di stato: done, archive, rm --yes.

Wikilink e backlink

Nelle note, [[target|alias]] è tessuto connettivo, non una nuova tabella. I link si risolvono localmente al corpus (id → path source-rel → titolo esatto → basename univoco) e usano il grafo di edge esistente (kind=link), così compaiono nei conteggi di backlink, nelle linee di collegamento dell’atlante e nel pannello Links del reader.

kb notes links <note>      # outlinks + backlinks
kb backlinks <artifact>    # who points here

I target ambigui vengono esclusi dal grafo anziché indovinati. L’HTML servito mantiene [[…]] letterale; la SPA renderizza i link risolti a partire dalla mappa del server.
