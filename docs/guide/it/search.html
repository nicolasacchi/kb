Ricerca

La ricerca ibrida keyword-plus-vector è il default. Un verbo CLI, un’API, gli stessi modi nella command palette del web.

Tre modi

ModoCosa faServe un modello?
hybridBM25 + vettore fusi con Reciprocal Rank Fusion (k=60). Default.Sì
keywordMatch lessicale puro BM25 — termini esatti, path, token di codice.No
semanticSimilarità vettoriale pura — il significato conta più della formulazione.Sì

Se si richiede hybrid o semantic senza un modello di embedding, il daemon risponde con un problem+json 400. Un reranker opzionale può raffinare i risultati hybrid quando è configurato sul daemon.

In dubbio, restare su hybrid. Solo keyword perde le parafrasi; solo semantic perde gli identificatori esatti. Hybrid è il default quotidiano per un motivo.

CLI e API

kb search "borrow checker" --kb canon
kb search "borrow checker" --kb canon --mode keyword
kb search "borrow checker" --kb canon --mode semantic
kb search "borrow checker" --kb canon --json
kb search "borrow checker" --offline          # keyword-only, no daemon

# HTTP (loopback needs no token)
curl -s 'http://127.0.0.1:4000/api/search?q=borrow&kb=canon&mode=hybrid'

kb find <path-or-name> risolve l’id a 12 hex e i path quando si sa già all’incirca quale file. kb get / kb cat recuperano metadati o HTML una volta che si ha un id; kb read apre il permalink SPA (o il file locale) nel browser, non scarica il contenuto su stdout.

Ambito e filtri

  • Per-kb — passare --kb NAME sulla CLI, oppure kb= sull’API. La CLI non ha flag --scope: omettere --kb auto-seleziona solo se il daemon ha esattamente un corpus; altrimenti la chiamata fallisce.
  • Federata (API / SPA) — la ricerca cross-kb usa scope=all (la ricerca senza scope della SPA). L’ambito di default è un solo kb. Il fan-out multi-kb avviene su un singolo daemon, non su un proxy multi-daemon.
  • Categoria — --category / ?category= filtra su kb-category. I transcript delle sessioni sono esclusi dalla ricerca di default di proposito (regola R0); passare --category memory-session oppure usare gli strumenti per le sessioni.
  • Filtri della galleria — tag, cartella, finestra mtime, stato di lettura, insiemi espliciti di id — vivono sulla lista docs e sui deep-link dal reader; vedi Reader web.

Embedding e modelli

Gli embedding girano nel sidecar fuori-processo kb-embedder (ONNX Runtime, collegato staticamente). Il daemon non linka mai ORT in sé.

Ordine di risoluzione del modello all’avvio (vince il più alto):

  1. embedding_model per-kb in kb.toml
  2. [defaults].embedding_model a livello daemon
  3. Default del registry bge-small-en-v1.5
kb model list
kb model set bge-large-en-v1.5 --kb research
kb model set bge-small-en-v1.5 --kb research --in-place   # same-dim swap
I cambi di dimensione falliscono in chiusura (fail closed). Al boot si confronta la dim lance su disco con il modello. In caso di mismatch di dim: fermare il daemon, rimuovere <state>/<kb>/lance/, riavviare così l’indexer ricostruisce. Gli swap a stessa dim possono usare --in-place.

Se il subprocess embedder muore, un probe di liveness lo respawna; se non può, la ricerca semantic degrada a solo keyword e segnala lo stato degradato nella SPA e in kb metrics.

Misurare la qualità

kb bench trasforma il retrieval in numeri: scaffold delle query, scoperta degli id rilevanti, poi report di Recall@k, MRR, nDCG e latenza a caldo per modo. Usarlo quando si cambiano modelli, chunking o reranker — non come gara da classifica.

kb bench init
kb bench discover
kb bench run
