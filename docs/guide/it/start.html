Installazione e primo avvio

Due binari, una cartella di file, un daemon in loopback — ricercabile in meno di un minuto dopo la prima build.

Installazione

Scegliere un canale. Tutti installano due binari affiancati: kb (CLI + daemon) e kb-embedder (sidecar di embedding). Tenerli nella stessa directory così il daemon trova il fratello.

# one-liner (Linux / WSL2)
curl -fsSL https://raw.githubusercontent.com/nicolasacchi/kb/main/scripts/install.sh | sh

# Docker (both binaries + SPA + baked model)
docker pull ghcr.io/nicolasacchi/kb
# minimal run — mount config, state, and a corpus the container can see:
docker run -d --name kb -p 4000:4000 \
  -v "$PWD/config:/var/lib/kb/config:ro" \
  -v "$PWD/state:/var/lib/kb/state" \
  -v "$PWD/corpus:/corpus:ro" \
  ghcr.io/nicolasacchi/kb
# Paths inside kb.toml must match container mounts; non-loopback clients need a token.

Da sorgente

Servono rustc (fissato da rust-toolchain.toml), protoc e, opzionalmente, node 22+ per il bundle web. Compilare i due package in invocazioni cargo separate così ONNX Runtime resta isolato all’embedder:

git clone https://github.com/nicolasacchi/kb && cd kb
cargo build --release -p kb-cli        # → target/release/kb
cargo build --release -p kb-embedder   # → target/release/kb-embedder
install target/release/kb target/release/kb-embedder ~/.local/bin/

# web reader bundle (gitignored; daemon serves web/dist)
# just ci-spa   # or: cd web && npm ci && npm run build
Soglia glibc dei prebuilt. I binari curl richiedono glibc ≥ 2.39 (Debian 13+, Ubuntu 24.04+, Fedora 40+). Su glibc più vecchie o Alpine/musl, usare l’immagine Docker o compilare da sorgente. install.sh rileva una libc incompatibile e lo comunica invece di fallire in silenzio.

Primo avvio in 60 secondi

kb daemon                         # binds 127.0.0.1:4000 — no token on loopback
kb add ~/notes --kb notes         # register a folder as a corpus
kb search "the thing I wrote" --kb notes
kb status                         # health
curl -s http://127.0.0.1:4000/healthz

Lasciare il daemon in primo piano (o avviarlo sotto systemd / Docker in seguito). Aprire un secondo terminale per i verbi della CLI. Le modifiche sotto la cartella registrata vengono reindicizzate automaticamente dopo un breve debounce.

In loopback non serve un token. CLI locale, curl e browser funzionano subito su 127.0.0.1. L’auth interviene solo quando il socket è raggiungibile dall’esterno.

Embedding opzionali (consigliati)

Senza un modello, la ricerca keyword (BM25) resta pienamente operativa. Le modalità hybrid e semantic richiedono un embedder. Aggiungere un modello quando si registra il corpus (al primo avvio scarica ~130 MB una sola volta nella cache):

kb add ~/notes --kb notes --embedding-model bge-small-en-v1.5
# or later:
kb model set bge-small-en-v1.5 --kb notes

Il modello di default del registry è bge-small-en-v1.5 (384-dim). Modelli più grandi possono migliorare il recall sull’inglese tecnico; un mismatch di dimensioni all’avvio fallisce in modo esplicito invece di corrompere l’indice — vedi Ricerca → modelli.

Aprire l’interfaccia web

Aprire http://127.0.0.1:4000/. Si ottengono galleria, ricerca, reader sandboxato, atlante, liste, sessioni e commenti. Se si è compilato da sorgente senza just ci-spa, API e CLI restano utilizzabili; manca solo lo shell della SPA.

Oltre il loopback

Il bind di default è sicuro. Non appena si espone un indirizzo raggiungibile (0.0.0.0 o un IP di LAN), fare tutte e tre le cose:

  1. Generare un token bearer — il daemon rifiuta un bind pubblico senza token (override solo con KB_ALLOW_NO_AUTH=1 quando il gate è un proxy a monte): 
    kb token generate     # ~/.config/kb/token, mode 0600
kb token path
    Riavviare il daemon dopo generate/rotate.
  2. Mettere TLS davanti — Traefik, Caddy o nginx terminano TLS e impostano X-Forwarded-For. Non esporre HTTP in chiaro su Internet pubblico.
  3. Impostare i campi di produzione [server] in ~/.config/kb/kb.toml: 
    [server]
addr                 = "127.0.0.1:4000"            # keep daemon on loopback
artifact_host_suffix = ".artifacts.example.com"
parent_origin        = "https://kb.example.com"
# trusted_proxies    = ["172.17.0.1"]              # only if proxy is off-loopback
Schema sicuro: tenere il daemon su 127.0.0.1 e lasciare che il reverse proxy possieda l’indirizzo pubblico. Un bind pubblico senza token è a cielo aperto — ecco perché il daemon rifiuta di avviarsi così.

Lo scrubbing outbound opzionale per-kb ([kb.NAME.outbound] strip_kb_prompt = true più pattern di redazione) rimuove il template privato del prompt e applica redazioni regex sulle richieste di artefatto in non-loopback (es. quando un proxy imposta X-Forwarded-For). Lo sviluppo in loopback resta intatto. kb share strippa sempre il prompt in export, indipendentemente da questa impostazione — vedi Operare → share.

Collegare Claude Code (opzionale)

# in Claude Code
/plugin marketplace add nicolasacchi/kb
# install kb-memory, then:
/kb-setup

Gli hook di capture e recall invocano kb da shell; nulla esegue un LLM dentro il daemon. Altri harness (Codex, OpenCode, …) guidano la stessa CLI via shell e file di istruzioni — vedi la pagina agente per memoria e sessioni.
