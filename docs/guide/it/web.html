Route

URLVista
/Galleria — griglia / lista / atlante / cronologia (+ canvas opzionale, shell map-home)
/a/<kb>/<path>Dettaglio — un artefatto in un iframe sandbox (permalink stabile)
/sessionsElenco/dettaglio delle sessioni catturate (?focus= ne apre una); CLI: why / recollect
/replay/<kb>/<sid>Replay di sessione
/anchorsAncore fissate; ?filter=stale per i commenti con ancore rotte (/stale-anchors reindirizza qui)
/settingsTema, preferenze, elenco daemon, pagine di stato in stile flotta

Lo stato della galleria (kb, filtri, ordinamento, vista) vive nell’URL — ogni vista è condividibile e resiste al reload. Si apre la command palette con ⌘K / Ctrl-K per le modalità di ricerca e la navigazione.

Galleria

  • Griglia / lista — card virtualizzate con titolo, tag, età e chip di progresso di lettura.
  • Filtri — tag, albero delle cartelle, capability, intervallo di date, categoria, stato di lettura.
  • Ordinamento — recenti, indicizzati, titolo, parole, data di creazione.
  • Ricerca — ibrida / keyword / semantic dalla palette (stesse modalità della CLI).

I metadati cliccabili su un artefatto aperto (tag, categoria, cartella, mtime) deep-linkano di nuovo a una galleria filtrata — un unico costruttore di URL, così i chip restano coerenti.

Atlante

Una mappa 2-D di un kb: ogni artefatto è un punto, colorato per cluster, così il lavoro correlato sta vicino al lavoro correlato. Il layout è deterministico (stessi input e seed → stesse coordinate). Si ricalcola quando il corpus si è spostato molto:

kb atlas recompute --kb NAME
kb atlas recluster --kb NAME --k 8    # retune clusters without full layout

Lo shell opzionale map-home (?shell=map oppure Impostazioni → preferenza home) fa dell’atlante la superficie di navigazione principale su desktop — esperimento opt-in, non il default.

Reader di dettaglio

Ogni artefatto si carica dalla propria origin (<id>.artifacts.<suffix>) dentro un iframe sandbox. L’isolamento same-origin è ciò che rende sicuro incorporare HTML arbitrario prodotto da LLM.

DNS locale degli artefatti. Default: suffisso .artifacts.localhost, parent http://127.0.0.1:4000/. Se l’iframe del reader è vuoto, verificare che *.artifacts.localhost risolva su loopback: 
getent hosts s01.artifacts.localhost
Molte build Chromium risolvono *.localhost senza DNS di sistema. Se la propria non lo fa: dnsmasq con address=/.localhost/127.0.0.1. In produzione si imposta artifact_host_suffix (vedi Avvio → oltre il loopback).

Intorno all’iframe:

  • Barra di contesto — ancora, aggiungi-a-lista, copia link, condividi, modalità fullscreen / bare.
  • Rail dell’inspector — about / metadati “passport” (scheda identità), link (outlink + backlink), memorie correlate, cartella, commenti e versioni come pannelli dock.
  • Versioni e diff — git, snapshot dell’indice e working tree dietro un’unica facciata.
  • Progresso di lettura — scroll e permanenza per sezione; riprende alla riapertura; alimenta lo stato di lettura delle liste.
  • Confronto affiancato (desktop) — ?pane2= per due artefatti, un inspector condiviso sul riquadro in focus.
Regola di authoring per gli embed: niente <base href>, niente target="_top", niente scorciatoie verso window.parent. La SPA genitore è un’origin diversa di proposito.

Cronologia e reflection canvas

La cronologia è la timeline di attività: aperture (con scroll), ricerche, commenti. Il reflection canvas (?view=canvas) mostra quattro tracce giornaliere sincronizzate — creazione, lettura, sessioni, commenti — con una selezione a pennello (brush) che apre una galleria filtrata su ciò che si è selezionato.

Mobile

A larghezze ridotte il reader è un sheet a un solo pulsante: il controllo inspect apre un bottom sheet che ospita inspector, commenti e versioni senza pannelli separati a vicolo cieco. La cattura da telefono (share sheet / cattura SPA) è un drop di staging unidirezionale in una cartella capture/ — non è authoring mobile.
