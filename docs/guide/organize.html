Lists & notes

Reading lists order the work. Notes hold checklists and wikilinks. Both ride ordinary corpus machinery — no parallel databases for “soft” organization.

Reading lists

A list is a named, ordered sequence of whole artifacts or §sections of them. Read-state is derived (override → section dwell → scroll completion) — not a separately stored “read flag” that drifts from reality.

kb list create "Q3 design pass" --kb research
kb list add <list> <artifact>
kb list add <list> <artifact> --section overview
kb list show <list>
kb list update <list> <entry> --read     # entry = le_… id or 1-based index
kb list move <list> <entry> --to 1       # 1-based position (or --before/--after)
kb list prune <list>                    # dry-run: list tombstones, exit
kb list prune <list> --yes              # apply: drop them
kb list export <list> -o reading.md     # kb-list/1 Markdown or JSON
kb list import reading.md --into <list>

Tombstoned entries point at artifacts that were deleted or no longer resolve in the index. Prune removes those list rows; it does not delete source files.

Share or offline-export a whole list as a self-contained bundle (ordered entries + generated TOC) via kb share --list … --local out.zip — see Operate → share.

Notes and checklists

A note is a Markdown artifact with kb-category: note. It is searchable and commentable like anything else, but excluded from the gallery grid and atlas so personal scratch does not drown the library.

kb notes new --folder projects/kb --title "Open threads"
kb notes append <note> --item "Wire the guide into docs/README"
kb notes check <note> --item 0
kb notes list --kb research
kb notes show <note>

GFM task items are toggled by document order. Status helpers: done, archive, rm --yes.

Wikilinks and backlinks

In notes, [[target|alias]] is connective tissue, not a new table. Links resolve corpus-locally (id → source-rel path → exact title → unique basename) and ride the existing edge graph (kind=link), so they show up in backlink counts, atlas link-lines, and the reader’s Links panel.

kb notes links <note>      # outlinks + backlinks
kb backlinks <artifact>    # who points here

Ambiguous targets are dropped from the graph rather than guessed. Served HTML keeps [[…]] literal; the SPA renders resolved links from the server map.
