Search

Hybrid keyword-plus-vector retrieval is the default. One CLI verb, one API, the same modes in the web command palette.

On this page

  1. Three modes
  2. CLI and API
  3. Scope and filters
  4. Embeddings and models

Three modes

ModeWhat it doesNeeds model?
hybridBM25 + vector fused with Reciprocal Rank Fusion (k=60). Default.Yes
keywordPure BM25 lexical match — exact terms, paths, code tokens.No
semanticPure vector similarity — meaning over phrasing.Yes

If hybrid or semantic is requested without an embedding model, the daemon returns a problem+json 400. An optional reranker can refine hybrid results when configured on the daemon.

When in doubt, stay on hybrid. Keyword alone misses paraphrase; semantic alone misses exact identifiers. Hybrid is the day-to-day default for a reason.

CLI and API

kb search "borrow checker" --kb canon
kb search "borrow checker" --kb canon --mode keyword
kb search "borrow checker" --kb canon --mode semantic
kb search "borrow checker" --kb canon --json
kb search "borrow checker" --offline          # keyword-only, no daemon

# HTTP (loopback needs no token)
curl -s 'http://127.0.0.1:4000/api/search?q=borrow&kb=canon&mode=hybrid'

kb find <path-or-name> resolves to the 12-hex id and paths when you already know roughly which file. kb get / kb cat fetch metadata or HTML once you have an id; kb read opens the SPA permalink (or local file) in a browser rather than dumping content to stdout.

Scope and filters

  • Per-kb — pass --kb NAME on the CLI, or kb= on the API. The CLI has no --scope flag: omitting --kb only auto-picks when the daemon has exactly one corpus; otherwise the call fails.
  • Federated (API / SPA) — cross-kb search uses scope=all (the SPA’s unscoped search). Default scope is one kb. Multi-kb fan-out is on a single daemon, not a multi-daemon proxy.
  • Category — --category / ?category= gates on kb-category. Session transcripts are excluded from default search on purpose (the R0 rule); pass --category memory-session or use session tools instead.
  • Gallery filters — tags, folder, mtime window, read-state, explicit id sets — live on the docs list and deep-links from the reader; see Web reader.

Embeddings and models

Embeddings run in the out-of-process kb-embedder sidecar (ONNX Runtime, statically bundled). The daemon never links ORT itself.

Model resolution order at startup (highest wins):

  1. Per-kb embedding_model in kb.toml
  2. Daemon-wide [defaults].embedding_model
  3. Registry default bge-small-en-v1.5
kb model list
kb model set bge-large-en-v1.5 --kb research
kb model set bge-small-en-v1.5 --kb research --in-place   # same-dim swap
Dim changes fail closed. Boot compares on-disk lance dim to the model. On a dim mismatch: stop the daemon, remove <state>/<kb>/lance/, restart so the indexer rebuilds. Same-dim swaps can use --in-place.

If the embedder subprocess dies, a liveness probe respawns it; if it cannot, semantic search degrades to keyword-only and surfaces a degraded signal in the SPA and kb metrics.

Measure quality

kb bench turns retrieval into numbers: scaffold queries, discover relevant ids, then report Recall@k, MRR, nDCG, and warm latency per mode. Use it when you change models, chunking, or rerankers — not as a leaderboard contest.

kb bench init
kb bench discover
kb bench run
