Install and first run

Two binaries, one folder of files, a loopback daemon — searchable in under a minute once the first build is done.

Install

Pick a channel. All of them install two binaries side by side: kb (CLI + daemon) and kb-embedder (embedding sidecar). Keep them in the same directory so the daemon can find its sibling.

# one-liner (Linux / WSL2)
curl -fsSL https://raw.githubusercontent.com/nicolasacchi/kb/main/scripts/install.sh | sh

# Docker (both binaries + SPA + baked model)
docker pull ghcr.io/nicolasacchi/kb
# minimal run — mount config, state, and a corpus the container can see:
docker run -d --name kb -p 4000:4000 \
  -v "$PWD/config:/var/lib/kb/config:ro" \
  -v "$PWD/state:/var/lib/kb/state" \
  -v "$PWD/corpus:/corpus:ro" \
  ghcr.io/nicolasacchi/kb
# Paths inside kb.toml must match container mounts; non-loopback clients need a token.

From source

Needs rustc (pinned by rust-toolchain.toml), protoc, and optionally node 22+ for the web bundle. Build the two packages in separate cargo invocations so ONNX Runtime stays isolated to the embedder:

git clone https://github.com/nicolasacchi/kb && cd kb
cargo build --release -p kb-cli        # → target/release/kb
cargo build --release -p kb-embedder   # → target/release/kb-embedder
install target/release/kb target/release/kb-embedder ~/.local/bin/

# web reader bundle (gitignored; daemon serves web/dist)
# just ci-spa   # or: cd web && npm ci && npm run build
Prebuilt glibc floor. The curl binaries need glibc ≥ 2.39 (Debian 13+, Ubuntu 24.04+, Fedora 40+). On older glibc or Alpine/musl, use the Docker image or build from source. install.sh detects an incompatible libc and tells you rather than failing silently.

60-second first run

kb daemon                         # binds 127.0.0.1:4000 — no token on loopback
kb add ~/notes --kb notes         # register a folder as a corpus
kb search "the thing I wrote" --kb notes
kb status                         # health
curl -s http://127.0.0.1:4000/healthz

Leave the daemon in the foreground (or run it under systemd / Docker later). Open a second terminal for CLI verbs. Edits under the registered folder reindex automatically after a short debounce.

Loopback needs no token. Local CLI, curl, and the browser all just work on 127.0.0.1. Auth only kicks in when the socket is reachable from outside.

Optional embeddings (recommended)

Without a model, keyword (BM25) search still works fully. Hybrid and semantic modes need an embedder. Add a model when you register the corpus (first run downloads ~130 MB once into the cache):

kb add ~/notes --kb notes --embedding-model bge-small-en-v1.5
# or later:
kb model set bge-small-en-v1.5 --kb notes

Default registry model is bge-small-en-v1.5 (384-dim). Larger models can lift recall on technical English; a dim mismatch at boot fails loudly rather than corrupting the index — see Search → models.

Open the web UI

Browse to http://127.0.0.1:4000/. You get the gallery, search, sandboxed reader, atlas, lists, sessions, and comments. If you built from source without just ci-spa, the API and CLI still work; only the SPA shell is missing.

Going beyond loopback

The default bind is safe. The moment you bind a reachable address (0.0.0.0 or a LAN IP), do all three:

  1. Generate a bearer token — the daemon refuses a token-less public bind (override only with KB_ALLOW_NO_AUTH=1 when an upstream proxy is the gate): 
    kb token generate     # ~/.config/kb/token, mode 0600
kb token path
    Restart the daemon after generate/rotate.
  2. Put TLS in front — Traefik, Caddy, or nginx terminate TLS and set X-Forwarded-For. Do not expose plain HTTP on the public internet.
  3. Set production [server] fields in ~/.config/kb/kb.toml: 
    [server]
addr                 = "127.0.0.1:4000"            # keep daemon on loopback
artifact_host_suffix = ".artifacts.example.com"
parent_origin        = "https://kb.example.com"
# trusted_proxies    = ["172.17.0.1"]              # only if proxy is off-loopback
Safe pattern: keep the daemon on 127.0.0.1 and let the reverse proxy own the public address. A public bind with no token is wide open — that is why the daemon refuses to start that way.

Optional per-kb outbound scrubbing ([kb.NAME.outbound] strip_kb_prompt = true plus redaction patterns) strips the private prompt template and applies regex redactions on non-loopback artifact requests (e.g. when a proxy sets X-Forwarded-For). Loopback dev is untouched. kb share always strips the prompt on export regardless of this setting — see Operate → share.

Wire Claude Code (optional)

# in Claude Code
/plugin marketplace add nicolasacchi/kb
# install kb-memory, then:
/kb-setup

Capture + recall hooks shell out to kb; nothing runs an LLM inside the daemon. Other harnesses (Codex, OpenCode, …) drive the same CLI via shell + instructions files — see the agent page for memory and sessions.
