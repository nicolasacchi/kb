# Invariant → test map (GC-C2)

Traceability table for the 35 numbered invariant slots indexed in
[`../CLAUDE.md`](../CLAUDE.md) and detailed in
[`architecture-invariants.md`](architecture-invariants.md) — 35 active, 0
retired: slot #2 was open after kb-tui's retirement (v0.24) but was refilled by
kb-users/1 (v0.34). Every pinning test carries a `// invariant:N <hint>`
comment directly above the test fn (Rust) or test title (Playwright/vitest), so
`git grep 'invariant:N'` finds every test that would fail if invariant N were
violated.

Run `scripts/check-invariants.sh` for a live, always-current coverage count —
this file is the human-readable "why" behind each row (what each pin actually
exercises, and — for the gaps — what a pin would need to look like). The
script is non-blocking by design: an invariant with no runtime pin is often a
legitimate structural/compile-time constraint, not a test-coverage bug.

**Coverage at time of writing: 32/35 pinned, 3 UNPINNED, 0 slots retired** (see
the "Unpinned" section at the bottom for the detailed rationale on each of the
3). #23 and #31 were pinned in SC6 (web-only: a vitest SSE-invalidation-bridge
test + a Playwright scroll-restoration spec); the #32 `ErrorBoundary`
`resetKey`-not-`key` residual was closed in the same pass.

## Unpinned — summary

Three invariants have no runtime test pin, for two distinct reasons:

- **Compile-time / structural, not test-shaped** (#1 arrow pinning, #26 ONNX
  isolation): both are enforced by `Cargo.toml`/CI job structure rather than a
  test assertion. Writing a "test" for either would just re-implement what the
  build or CI topology already guarantees.
- **Environment-fragile** (#21 IPv6 loopback companion): the behavior is
  itself best-effort (falls back silently when IPv6 is unavailable), which
  makes a CI-safe pin awkward — the natural test would be flaky on
  IPv6-disabled runners.

#23 (SSE→TanStack invalidation bridge) and #31 (scroll restoration) were the
two genuine coverage gaps as of the previous pass; both were pinned in SC6 (see
their rows above) — #31's pin covers two of its three claims, with the third
(persist-on-navigate-away) now a documented, filed defect rather than a gap.

One further **residual gap** lives inside an otherwise-pinned row (so it
doesn't count toward the three):

- **#6 — `review_lock` multi-kb concurrency.** The
  `comments_concurrent_adds_no_lost_updates` e2e test hammers ONE kb, so it
  proxies "same-kb mutations serialize" but never exercises the per-kb scope of
  the lock. A pin would run concurrent comment mutations against two kbs in one
  daemon and assert both that each kb's review file stays lossless AND that the
  locks are independent (one kb's burst never serializes behind the other's).
  This is the gap note row 6's "see gap note below" points at.

(The former #32 `ErrorBoundary` `resetKey`-not-`key` residual was closed in
SC6 — see that row above.)

Re-run `scripts/check-invariants.sh` after adding a pin — it will move from
the UNPINNED list to the coverage table automatically (no map-file edit
required for the script itself, though this file's prose should still be
updated to describe the new pin).
