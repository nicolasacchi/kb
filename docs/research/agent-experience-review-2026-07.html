The agent-experience review — kb as infrastructure for coding agents (2026-07)

TL;DR

kb is already the most agent-native tool in its category — a runtime-derived CLI manifest (kb tools), fail-open memory hooks, deterministic LLM-free recall, RFC 7807 errors, a scriptable doctor, structured agent→human choice-comments, and golden-pinned grammars. The review found no architectural rot. What it found is last-mile debt in exactly the places agent pipelines break, three systemic gaps, and eleven concrete defects.

  • The headline gap: kb serves documents; agents need passages. Four of the five ideas that survived adversarial verification are the same theme — hybrid search already embeds, ranks, and then discards the winning chunk text (lance.rs:952 projects doc_id only); there is no plain-text fetch (only raw HTML or a 400-char excerpt); no single-call find-and-read; no budgeted context pack. Every retrieval an agent does today costs one extra round-trip and a whole HTML document.
  • The contract is 90% there, and the missing 10% is where scripts die. Only 2 of ~20 --json verbs emit a JSON error envelope; axum extractor rejections bypass problem+json; a typo'd /api/* path returns 200 with the SPA shell; the CLI exposes a fraction of /api/search's power and drops score from its Hit.
  • Real bugs shipped: kb pull flattens paths and silently mints new artifact ids (breaking invariant #27 and every cross-link); kb remember --scope project does not actually scope visibility (only --link does, and the two protocol docs contradict each other); kb add <file> fails on the recovery path its own skill prescribes; the memory protocol is not re-injected after compaction. Details in §Bugs.
  • The verify pass was ruthless and that is signal: of 24 canonical proposals, 6 were killed — MCP and the cross-harness capture envelope as already designed and deliberately deferred with data (Codex ≈1.5% of local sessions, OpenCode abandoned 2026-04), fleet soft-locks as violating a recorded refusal. kb's habit of recording refusals with rationale did exactly its job against a 43-agent fleet.

Method

The premise: the user of kb is an LLM coding agent — Claude Code, Codex CLI, OpenCode. The agent authors the artifacts, runs the searches, writes and recalls the memories, triages the comments, and often operates the daemon. Every surface was judged on: discoverability without reading source, token cost, machine-parseable output, error recoverability, statelessness across fresh sessions, and cross-harness portability.

Four phases, one workflow (wf_f48b5409-3ba): Explore — 12 Sonnet agents, one per subsystem (CLI, memory, sessions, HTTP API, indexing/authoring, search quality, plugins/skills, comments, docs, share/interop, ops, SPA-through-the-agent-lens), each returning evidence-cited frictions and proposals. Ideate — 5 Opus lenses (agent-protocol, memory-learning, multi-agent-fleet, authoring-loop, retrieval-context) plus one Fable wildcard, fed the explorers' digest. Merge — one Opus judge deduped 109 raw proposals into 34 canonical items across 10 themes (convergence across independent agents was scored as a quality signal). Verify — one adversarial agent per tier-1/2 item, default stance refute: hunt prior art in code/docs/plans, check the recorded non-goals, and be skeptical of ideas an agent would never actually invoke.

Everything below the strengths section carries its verification verdict: solid survived refutation, partial means the mechanism half-exists and only the named delta is new, killed is recorded in the ledger so it doesn't get re-proposed. §Beyond is the Fable synthesis layer — ideas from outside the fleet's output, clearly marked.

What already works — the agent-native foundation

Worth stating plainly, because the median tool in this space has none of it:

  • kb tools can never drift from the binary. It walks the live clap command tree at runtime (tools.rs) and emits a system-prompt-ready manifest of all 45 verbs — one command teaches a fresh session the whole surface.
  • Hooks fail open, deliberately. A down daemon, missing jq, or timeout never blocks a turn (kb-recall.sh, kb-wake.sh, kb-capture.sh all || exit 0) — the right default for unattended loops, though see §Sessions for the observability cost.
  • Recall is a pure function. rank × salience × decay, tombstone/supersede drop, 21 unit tests, reproducible from its inputs with zero model involvement (invariant #10) — a search result can be explained.
  • Handler errors are uniform RFC 7807 problem+json, and hybrid-search-without-embedder 400s include the exact fix command (search.rs:761).
  • SSE is script-grade: Last-Event-ID resume via header or query param, ?types= globs, synthetic lag/gap frames, and runtime-fetchable payload schemas (/api/events.schema.json).
  • kb daemon doctor is a real agent health check: six probes, OK/WARN/FAIL, --json, non-zero exit on Unhealthy, and a retry design that doesn't false-flag a cold model load.
  • The reverse channel exists: a Claude-authored comment can carry --choice-json one-tap buttons in the SPA — structured agent→human questions without a chat round-trip (review.rs:154).
  • Refusals are recorded with rationale (README Non-goals), which is why 6 of 24 verified proposals could be killed by citing prior rulings instead of re-litigating them.
  • kb find has a documented exit-code contract (0 = id, 1 = ambiguous + candidates, 2 = no match) built for composition; destructive verbs take --yes and fail safe on EOF.
  • Portable grammars are golden-pinned: kb-comments/1, kb-list/1, the session bundle, the wikilink ladder, the gallery URL grammar — the file formats an agent round-trips are tested contracts, not conventions.

Retrieval: passages, not documents 4× solid

The strongest convergence in the whole review. Independent explorers and ideators, from different starting points, all hit the same wall: every kb retrieval primitive returns either a doc-level stub or a whole HTML document — never the passage that matched. For a human with a browser that's fine; for an agent paying per token it's the dominant tax on every lookup.

The evidence is almost comic: the SQ5 chunk arm already embeds passages, already finds the best-matching chunk per document, and then chunk_vector_query (storage/lance.rs:952) projects Select::columns(&["doc_id"]) — the one column that could answer "why did this match" is computed and thrown away. Meanwhile Hit (routes/search.rs:426) carries score, tags, and summary, but no snippet; kb get --format md prints four metadata lines and no body; the only content path is raw HTML with its CSS and JS.

Five verified items compose into what should be v0.25's core track:

1 · Project the winning chunk as Hit.snippet solid

Add snippet: Option<String> + chunk_id to Hit, populated from the chunk arm's winner, gated behind ?snippet=1 / detail=full so the slim popover payload stays byte-identical. Cap ~300 chars around the match. Degrade to None (never error) when the kb has chunking off or BM25/doc-vector won the fusion. For unchunked kbs, a deterministic query-centered BM25-term window over Doc.body is the fallback.

2 · A plain-text content path solid

kb get --format text / ?text=1 exposing the already-parsed body_text() (parser.rs:938 — the exact extraction the indexer runs). Reading an artifact stops costing HTML+CSS+JS the agent must strip. The section-anchor selector variant is deferred: there is no stable heading-id→text mapping today, so it would be new indexing, not reuse.

3 · kb ask — single-call find-and-read solid

The single most common agent pattern is search → pick top hit → fetch → locate passage. Collapse it: one call returns the top fused hit's matching passage + citation + neighbor-section ids to widen. Pure deterministic composition over existing scoring — explicitly not the LLM-flavored /ask sketched in the Obsidian-competitive roadmap doc (consider naming it kb cite or kb snippet to avoid collision with that ruled-out idea).

4 · kb context "task" --budget N — the budgeted pack solid

One deterministic call assembling top section excerpts + related memories + related session digests, deduped on artifact id, greedy-filled to a token budget, each item carrying provenance and a token estimate. Replaces the 4–6 hand-chained calls (search + recall + why/recollect + sessions show) a session bootstrap costs today. Verifier's scoping: v1 is a thin dedup+fill layer over the existing recall/why/recollect scoring and invariant #28's buffered_join — not a new ranking engine. Once it exists, kb-wake.sh can call it and delete its hand-rolled jq formatting.

5 · CLI ↔ API search parity partial

The server already has scope/category/folder/tags/exclude-tags/since/sort params and a score + source_relative on Hit; the CLI sends only q/mode/kb/limit and its slim Hit drops score entirely (commands/search.rs:14-27). Pure wiring, high value. Separately (and gated on a re-run of the SQ4 A/B): unify the two incompatible filter grammars (kb_core::query's DSL vs /api/search's ad-hoc params — two different since vocabularies today), and feed the reranker the winning chunk's text instead of the one-line excerpt — the SQ4 bench doc itself names that as the root cause of its −0.20 R@1 regression.

Also in this theme, lower tier: graduated detail=id|slim|snippet|section|full tiers with documented token costs; an anchor field on Hit/RecallHit resolving to the existing /a/{kb}/{path}?sec= permalinks (the custom kb:// scheme was already considered and correctly rejected in 2026 — HTTP permalinks are clickable, custom schemes are not); kb facets --for-query for plan-before-fetch narrowing.

The protocol surface: finish the contract partial

kb's machine contract is genuinely good where it exists — the problem is coverage, and coverage is exactly what an agent script can't inspect ahead of time.

  • One error envelope, everywhere. Three verified holes: (a) hoist search.rs's {"error":…}+exit(1) wrapper into one json_err_exit() helper and apply to all ~20 --json verbs (today 18 of them leave stdout empty and dump anyhow chains to stderr — a jq pipeline written against kb search's contract breaks against every other verb); (b) the extractor-rejection problem+json wrapper; (c) the /api/* 404 fallback. Each independently shippable (§Bugs rows 6–7).
  • kb tools --json and kb tools --verb <name>. The clap walk already exists; a serde rendering gives agents pre-flight invocation validation, and a single-verb slice cuts the 961-line manifest to a ~40-line top-up mid-task. The verifier's caution stands: skip the HTTP /api/capabilities twin (the CLI is the protocol), and defer the per-verb output_contract field until a few verbs have stable serde-derived schemas to anchor it — otherwise it hand-drifts exactly like the thing it replaces.
  • Curate kb tools examples for the flagship verbs. remember/recall/why/recollect — the verbs an agent calls unprompted every session — have no curated example while atlas and token do (tools.rs:85-107). Small change, disproportionate onboarding value, and the right place to teach --link vs --scope correctly once the visibility bug is fixed.
  • GET /api/bootstrap / kb doctor --for-agent: identity + config + kbs + embedder health + inbox counts in one fail-soft call, replacing the 4–5 sequential calls a cold headless session chains today.
  • Consistency batch: --json on kb comments show (it already fetches the full JSON Value then hand-formats it); the single-kb auto-default extended from kb find to get/related; skipped: [{kb, reason}] on federated scope=all responses so a silently-dropped corpus (invariant #28's fold-and-drop) is distinguishable from a genuinely empty fleet.

Closing the authoring loop partial

Agents author every artifact, yet the 506-line contract is enforced socially: the parser silently truncates an oversized kb-prompt, silently falls back title→filename, silently drops unparseable kb-salience, and silently discards ambiguous wikilinks from the graph (parser.rs:404-419, indexer.rs:1301-1306, links.rs:186-200). Nothing reaches kb status, kb find, or the bus. The skill-side validator (validate-kb.sh) exists but is perl-regex over raw HTML — it can drift from what html5ever actually extracts, and it isn't in this repo's plugin copy at all.

  • kb debug-fields <file> --json → don't build a second validator. The verifier's refinement is the right call: a tiny daemon-free verb dumping parser::Fields + links::Resolution (title source, prompt bytes vs the 8 KB cap, tag slugification, salience/created parse results, ambiguous wikilinks). validate-kb.sh then shells out to it for parser-fidelity checks and keeps its cheap regex checks — one source of truth for "what will the indexer actually see", zero drift.
  • Ingest receipts as sugar, not a new pipeline. Everything needed exists: the single-path force nudge (quarantine.rs:203), the authoritative artifact.indexed completion event carrying id+fields (indexer.rs:1634), the 202+run SSE convention. kb ingest <file> = nudge + await that artifact's event with a bounded timeout, degrading to "queued — poll kb find". Collapses the racy write-then-poll loop into one authoritative "it is searchable, here is what was extracted, here are the warnings".
  • index.warning SSE class — the genuinely novel piece: the indexer has ~12 tracing::warn! sites for soft authoring defects that today only reach the log file. Emitting them on the bus enables a standing corpus-wide authoring-quality triage loop (the kb comments watch pattern, pointed at slop).
  • kb audit / GET /api/kb/{kb}/quality: the corpus-wide aggregation — title-fallback docs, truncated prompts, unresolved/ambiguous wikilinks — in one shot. Per-artifact fields on kb find --json misdiagnose which surface an agent polls for triage.
  • Embedded kb new presets: contract-passing skeletons (title, hierarchy, stable ids, kb-prompt, meta, visual-floor token roles) compiled into the binary, so a Codex/OpenCode agent with no skill tree gets the same authoring floor Claude Code gets. Provable by the lint verb above.

Memory as a learning system mixed

The memory subsystem's determinism is its moat — the verify pass defended it hard against the fleet's own enthusiasm, and the surviving shape is more interesting than the raw proposals.

  • kb why-memory <id> solid — the fact-centric provenance join. kb why is file→sessions→commits; nothing goes fact→origin-session→commits→files, even though RecallHit already carries session_id and the per-session routes exist. Ship it as a CLI-side aggregator over the three existing endpoints — no new server route. The verifier's honest caveat: a resolvable commit sha proves the commit exists, not that later commits didn't revert it — label it "commit still in history", not "still true", and no-op cleanly for memories without a session.
  • Write-time dedup partial — this is R6.1, so build it as R6.1. The evolving-the-memory research already specs write-time reconciliation against top-k neighbors. A synchronous --check-dup gate is the scoped-down slice, but it must fix the idempotency race first: memory filenames derive from slug-<unix_secs>, so two concurrent agents writing near-simultaneously can both pass the check and still collide on the same-second filename.
  • Negative memory partial: a kb-outcome: failure meta + kb remember --failed, with recall surfacing a warns flag so injection renders "X was tried and failed here" — never as a score term (the R3 invariant: outcomes are surfaced signals, not ranking inputs). The session half is mostly built: error_count and commits already exist; expose a derived outcome as a read-only recollect --outcome filter.
  • Salience health partial: ~40% of live memories sit at the 0.5 default — the "0.5 monoculture" the reflect skill fights by hand is invisible to any automated surface. A per-corpus salience histogram in /api/metrics turns "this corpus needs regrading" into a pollable trigger for /kb-reflect.
  • Usage-derived salience weak — the verifier was right to kill the ranking half. Writing on the recall path bends invariant #10 for a self-reported, gameable signal, and the negative case is already covered by forget/supersede. The surviving slice: a passive server-side times_recalled counter, exposed as a metrics diagnostic only, never folded into rank.

Also verified real: recall injection and --format md never surface memory body content — the 80-char title (hard-truncated mid-word) is all an agent sees, forcing a fetch round-trip on every recalled fact it wants to act on. Fixing fetch_metadata_md to include the body (or kb-summary) is small and compounds with kb context.

Sessions & cross-harness: respect the trigger, ship the cheap half killed partial

The fleet converged on a harness-neutral capture envelope (kb-capture/1 + adapters for Codex/OpenCode) — and the verifier killed it with the repo's own receipts: the identical idea is item #12 of the fresh-eyes review, scored, and deliberately deferred on measured data (OpenCode abandoned since 2026-04; Codex at ≈1.5% of local sessions, mostly automated noise), with the rule "build the adapter the week a second harness does real work". That ruling stands. What survives:

  • Ship the sanctioned quick win that fresh-eyes already adopted but nobody landed: the AGENTS.md memory-protocol block. AGENTS.md declares itself the harness-neutral entry point and covers comments + search — remember/recall/why/recollect appear nowhere in it, so the memory system is undiscoverable without Claude Code hooks even though the CLI itself is fully harness-agnostic. Generate it from one source so it can't drift from CLAUDE.memory.md.
  • Hook resilience batch partial: log every silent exit 0 branch of kb-capture.sh to a rotating .capture.log (a broken capture pipeline is invisible today until someone notices a recollect gap); inject a fixed [kb memory: daemon unreachable] marker on recall failure instead of pure silence (failure ≠ "no memories"); add compact to the SessionStart matcher (§Bugs).
  • Digest the final assistant text. A long exploration session with no decisions and no commits digests to title+prompt+file-basenames — nearly nothing for kb recollect to match. Deterministically appending the transcript's last assistant text block (the agent's own closing summary) narrows the deferred-R6 gap with zero LLM in the daemon.
  • Incremental capture weak: byte-offset delta parsing was killed — hook cost is linear string ops that stay sub-second, and reindex-burst latency is already the target of the tail-latency phase-3 plan. The surviving slice is a simple debounce (skip capture unless N turns / K KB elapsed).

Multi-agent coordination: what kb should and shouldn't be killed

The fleet lens produced the boldest proposals — advisory soft-locks (kb claim <path> --ttl), live presence (kb who), heartbeats — motivated by a real observation: the v0.24 plan literally encodes a hand-rolled READ-ONLY-DIRTY-FILES protocol because two sessions share one tree. The verifier killed the claims registry: kb-collaboration-model.html already refused file-locking/vault-style coordination ("regenerate-and-reindex, not last-writer-wins on hand-edited files"), and comments+.review are the recorded collaboration surface.

A minority report, for the record: the refusal reasons about artifact collaboration; the claims idea is about source-tree coordination between coding agents, which is arguably a different domain. But the verdict lands in the same place for a better reason — kb is a knowledge daemon, not a dev-workspace daemon, and turning it into the latter is scope creep with a thin constituency of one. What survives is the kb-shaped subset:

  • Blackboard scratch corpus — reuse memory + retention, add nothing. Subagents in a fan-out post findings as TTL-scoped memories (kb remember --ttl 4h --category blackboard routed to a scratch corpus governed by an R3 retention window — the primitive v0.24 is shipping right now); the orchestrator recalls-by-category instead of ingesting walls of returned text; entries self-prune. Same shape for kb post (write a scratch artifact, get back a citable id/permalink). No locks, no new store, comments stay the human channel.
  • kb events emit — the symmetric producer. T1 ships the consumer (kb events --follow); a namespaced agent.* producer over the same ring (kept out of the SPA's default subscription) turns the existing SSE bus into a deterministic subagent-completion channel with cursor/gap replay for free. Add --json (one object per line) to the T1 follower while it's being built — the plan currently only specs human blocks.
  • X-Agent-Id attribution, and only attribution: an optional header threading through history rows and the rate-limit bucket so co-tenant sessions on one shared token are distinguishable in the audit trail. Build it when a second concurrent harness is real (same bar as the MCP trigger) — no locks, no presence map, no claim stream.

Ops & docs hygiene partial

  • kb daemon log --tail N --level info — the crashed-daemon reader. v0.24's L1/L2 wires file logging; the deliberately-deferred piece was an HTTP log-tail. The verified delta is different: a disk-reading CLI verb (KbPaths-aware, globbing rotated kb.ndjson.* newest-first, JSON-lines passthrough for jq) that works precisely when the daemon is down — the case where an agent needs it most and where the HTTP endpoint by definition can't help. Skip --follow in v1.
  • Federated health: the skipped[] field on scope=all responses (also listed under §Protocol) — buffered_join's drop-on-error is good availability engineering that is currently invisible to callers.
  • Docs batch, all confirmed-real: fix invariant #11's heading; add DCO to Cadence; cross-link AGENTS.md ↔ CLAUDE.md ↔ CONTRIBUTING.md (AGENTS.md is currently an undiscoverable island with zero inbound links); put the invariant index on a diet — entries range 18 to 371 words (#30 alone is ~2,500 chars of always-loaded context), defeating the two-tier split's purpose. A ~40-word cap per index entry restores it; CLAUDE.md is ~24.5 KB (~6k tokens) loaded every session, and roughly a third of that is index entries that outgrew their job.
  • Self-index the contributor docs cheap, do it: a dev [kb.docs] stanza over README/AGENTS/CONTRIBUTING/invariants so kb search "DCO sign-off" answers in one call. kb's own contributor knowledge is currently the only knowledge near this repo not in kb.

Beyond the fleet: five Fable bets synthesis

Everything above is the fleet's output, verified. This section is mine — ideas that weren't in any agent's return, or that the merge dropped and I'm deliberately resurrecting. The common thread: kb's differentiation is that it is deterministic infrastructure for probabilistic authors. Every bet below extends that asymmetry instead of diluting it.

1 · Truth maintenance: kb stale and kb verify

A corpus written by LLMs rots in two specific, mechanically detectable ways, and this review found live instances of both in kb's own docs: claims whose cited code moved (invariant #11's heading survived its own body's correction), and documents whose source material changed after authoring.

  • kb-derived-from → kb stale. Artifacts already carry their prompt (kb-prompt); let them optionally carry their inputs — a meta listing the repo paths/globs the document was derived from. A deterministic kb stale [--kb X] then walks input mtimes/commits vs the artifact's own and reports "this doc predates 14 commits to the files it describes". The doc becomes a function of its sources, and staleness becomes a per-artifact, provenance-linked signal — categorically better than mtime recency. Surfaces in the About tab and as a search-result freshness field.
  • kb verify <id> — citation integrity. kb-authored research cites file:line pervasively (this document included). A deterministic check that parses those citations from an artifact's code/kbd spans and confirms each path still exists (and optionally that the line still contains the cited symbol) turns citation rot from invisible decay into a triage list. Zero LLM; pure parse + stat + grep.

Why this is the right kind of ambitious: it composes the existing edge graph (invariant #29) with a new edge kind (derivation), reuses the watcher/indexer, and gives agents the one thing no other knowledge tool gives them — a machine answer to "can I still trust this document?"

2 · kb-decision/1: artifacts as decision surfaces

The wildcard proposed this and the merge dropped it; I'm resurrecting it because it is the highest-leverage unbuilt idea in the whole exercise. v0.24 itself ran as an unattended overnight milestone; the binding constraint on autonomous runs is human decision latency, and today a blocking terminal AskUserQuestion is the only channel. But the primitive already exists: comments carry structured Choice buttons in both directions (review.rs:154), the SPA renders them, SSE announces them, and the wake hook injects context at session start.

Formalize it: a data-kb-decision block grammar in artifacts (options, default, expiry); verdicts persisted beside comments under the review_lock (invariant #6 — this rides the sanctioned collaboration surface, it doesn't compete with it); a decision.recorded SSE kind; kb decisions --pending --json; pending decisions injected at SessionStart. An overnight agent writes "I'm about to delete the TUI crate — approve / defer / modify" into its plan artifact, continues on other tracks, and picks up the verdict when the human taps a button over morning coffee — every ruling becoming a searchable, timestamped provenance record instead of a lost chat turn. This converts kb from a memory for agents into the async contract surface between agents and their humans.

3 · kb prime: generate the integration, don't port it

The cross-harness question keeps being framed as "port the hooks" (killed) or "build MCP" (deferred). There's a third shape nobody proposed: one command that emits the integration content. kb prime [--task "..."] [--format md|json] outputs the complete bootstrap block — the memory protocol, a kb tools slice, top recalled memories with bodies, open inbox items, pending decisions — sized to a budget. Claude Code's wake hook calls it (deleting the hand-rolled jq in kb-wake.sh and the drift between its heredoc and CLAUDE.memory.md — the visibility bug in §Bugs exists because there are two copies). A Codex or OpenCode user pipes it into AGENTS.md or a session preamble. One implementation, every harness, no adapters — and it subsumes kb context's session-bootstrap case while remaining honest about the recorded trigger: when a second harness does become real, the integration is a one-liner, not a port.

4 · Instrument the MCP trigger instead of arguing about it

The MCP ruling's revisit-trigger is "a second agent harness enters real use here, or credible inbound demand". The fleet's ideators argued industry trends; the verifier correctly replied that the ruling anticipated exactly that argument. Here's the kb-flavored resolution: make the trigger measurable. An optional KB_AGENT_HARNESS env stamp (set by each harness's integration, recorded on history rows / a counter table) plus kb fleet harnesses --since 30d turns "did the trigger fire" into a query instead of a debate. Meanwhile, build the plug rather than the socket: kb ask and kb context are the single-shot primitives an MCP tool would wrap — with them shipped, a future kb mcp (already designed, read-only, in the extensibility RFC §7b) is a weekend of glue behind a trigger that has provably fired.

5 · /kb-steer: the sessions corpus as a training set for the project's own steering docs

kb already captures every session; kb-reflect already dreams over memories. The unexploited asset is dreaming over sessions to improve the instructions. Recurring error signatures, repeated invariant violations, instructions that sessions demonstrably ignored, pitfalls hit twice (CLAUDE.md's own rule for when a pitfall gets documented!) — all of it sits in session_decisions/error_count/digests. A periodic agent-layer skill (deterministic evidence verbs in the daemon: e.g. kb sessions errors --group-by signature; LLM judgment strictly in the agent layer, matching the kb-reflect precedent) proposes human-gated edits to CLAUDE.md/skills: "4 sessions this month hit the concurrent-cargo phantom E0063 despite the pitfall entry — the warning may need to move into the justfile itself." The steering documents stop being write-only and start being empirically maintained. kb-artifact-evolve already proved this loop works for one skill; generalize it to the harness.
