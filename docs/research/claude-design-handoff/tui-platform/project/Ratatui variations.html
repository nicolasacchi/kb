kb tui — ratatui-buildable variations

Five layouts redrawn within ratatui's constraint envelope: pure cell grid, box-drawing borders, ANSI-16 colors, no anti-aliasing, no opacity. Every glyph here exists in standard fonts and every "color" is a foreground/background swap. The widget mapping is called out under each title.

ratatui constraints applied

  • Borders: Block with BorderType::Plain only (single-line box-drawing).
  • Color: solarized 16-color set, no alpha. "Dim" is a darker solarized swatch, not opacity.
  • Charts: Sparkline, BarChart, Gauge, LineGauge, Chart — characters from the block-element / braille families.
  • Layout: nested Layout::default().constraints([...]); no overlapping floats.
  • Highlight: List / Table with highlight_style(Style::default().bg(SELECTION)).
  • Modals: a Clear + centered Block on top of the frame.
variation · 01

Three-pane Block layout — the canon

Closest to what ratatui examples ship with: a vertical Layout with header + body + footer, and a horizontal split inside the body for sidebar / main. Sources is a Tree-rendered List; main is a Table; activity is a List tailing in place. Idiomatic, conservative, fastest to build.

variation · 02

Tabs across the top — one view at a time

Replace the sidebar with ratatui's Tabs widget. Each tab owns the full width: Status, Sources, Search, Errors, Stats, Help. Easier to read on narrow terminals (80 cols), and matches how btop / gh dash use horizontal real estate. Activity log slides into a collapsible bottom strip.

variation · 03
