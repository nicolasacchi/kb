kb tui — states

Frozen reference renders of the modes the live prototype passes through. Each frame is the same 1180×598 terminal viewport so they read as a strip. Open kb tui.html for the interactive version with all keybindings and the simulated SSE stream wired up.

state · 01

Empty — no kbs configured
First-launch state when the server is up but has no knowledge bases yet. Reduces the chrome to a single greeting card with the two ways to bootstrap.
~/work — kb tui
kb v0.1.0 │ active: — │ ● running :4000 │ uptime 3m 02s 0 kbs · 0 sources · 0 docs
welcome 
   ┌─────────────────────────────────────────────┐
   │   kb is connected · no knowledge bases yet  │
   └─────────────────────────────────────────────┘
a knowledge base groups one or more folders the server watches and indexes.
▌ create one now
:kb add work ~/work
creates a kb named "work" rooted at ~/work
▌ or import config
:server reload
picks up ~/.config/kb/config.toml changes
? for full keymap · q to quit
NORMAL · :command · ?help · qquit no kbs configured · :kb add <name> <root> to begin

state · 02

Onboarding — no server running
First launch from a clean machine. Server is unreachable; we offer the three obvious next moves rather than just blocking with a retry banner.
~ — kb tui
kb v0.1.0 │ active: — │ ✗ disconnected :4000 │ first run retry in 4s · [r] now
getting started 
   ╔═══════════════════════════════════════════════════╗
   ║  no kb-server reachable at localhost:4000         ║
   ║  this is normal on first launch                   ║
   ╚═══════════════════════════════════════════════════╝
▌ pick one
[1] kb tui --spawn — start a local server, then connect
[2] kb tui --server <url> — connect to a remote (over ssh/tailscale)
[3] kb serve — run the server in a separate shell
▌ where it looks
~/.config/kb/config.toml · default server, kbs, watcher rules
~/.cache/kb/tui.log · this client's log
retrying in 4s · backoff 1→2→4→8→16→32s · r retry now · q quit
OFFLINE · rretry · :server reload · ?help last attempt 0.6s ago · attempt 3
