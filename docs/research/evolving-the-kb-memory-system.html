Evolving the kb Memory System

The architecture is right and matches where the field landed. The data says we built the half that already works and starved the half that matters — so the highest-leverage move is not a smarter ranker, it is finally building the write side.

kb research 2026-06-29 method: 31-agent orchestrated workflow real data: live memory backend
Thesis kb's memory architecture is correct and SOTA-aligned. The binding constraint is not the deterministic ranker (it is over-built for 13 facts) but the empty, manual write side. The highest-leverage evolution is an offline, model-isolated session → fact distiller feeding a human-review queue — preceded by a handful of cheap correctness fixes — with the per-turn recall path (invariant #10) and the episodic pull-only contract (invariant #11) left intact.

1 · How memory works today

kb's memory is two LLM-free halves. Both are deliberate; both are documented as load-bearing invariants.

Curated agent memory — invariant #10

kb remember "<fact>" renders an HTML artifact into a memory corpus (memory = global, memory-kb = project-scoped). kb recall "<q>" is a hybrid search over those corpora followed by a pure, deterministic, model-free re-rank (crates/kb-core/src/memory.rs):

score = rel · salience · exp(−k · age_days)        rel = 1 / (60 + rank)
        salience ∈ [0,1] (default 0.5)   k = 0.01 (slow) | 0.1 (fast)

Superseded and forgotten memories drop at recall time; a DecayPolicy floor (strict 0.20 / balanced 0.15 / loose −∞) drops low-salience non-pinned memories. Recall fires every turn through a UserPromptSubmit hook injecting the top-5. The design slogan is exactly right: the live agent decides what to keep; kb only stores, ranks, and serves.

Episodic session memory — invariant #11

A Stop hook wraps the raw Claude Code JSONL transcript in HTML into the sessions corpus on every stop. The indexed surface is a deterministic digest, not the raw JSONL; transcripts are excluded from default search and recall, and pulled on demand via kb why <file> (provenance) and kb recollect "<task>" (semantic search over past work). Recollect's success and staleness are surfaced signals, never score terms. This half is healthy: lossless capture, one pure parser feeding both the sqlite rows and the served render, canonical id recovered from JSONL ground truth, multi-capture newest-superset handled uniformly.

3 · The external landscape

The field converged on one pattern, and kb already embodies it: an intelligent (LLM) write/consolidation path that runs in the background, feeding a cheap deterministic read path at inference. That is invariant #10's "smart write side, pure-math read side" split — externally validated as both lower-latency and higher-quality. kb built the read half well and never built the write half.

TechniqueSourceRelevance to kb
Hard read/write role split — a background "sleep-time" agent owns all writes; the live agent only readsLetta / MemGPT; Sleep-time ComputeThis is kb's #10 architecture, externally validated. It also names the missing half: kb has no background writer. ~5× test-time compute reduction is the case for an offline distiller.
Idle-time consolidation / defrag — merge duplicates, restructure, on a tunable cadence with a stronger non-latency-bound modelLetta MemFS defrag; LangMem ReflectionExecutor; Cognee Memifykb has explicitly no consolidation/dedup/conflict-detection. The proven template for turning 196 messy transcripts + 13 coarse facts into clean facts without touching the per-turn path.
Write-time reconciliation against top-k neighbors — ADD/UPDATE/DELETE/NOOP; soft-invalidate, never hard-deletemem0; Graphiti / Zep bitemporal KGExactly the dedup + auto-supersede kb lacks. Maps onto the deferred R6: retrieve nearest existing memories, emit kb-supersedes. mem0's 2026 reversal to ADD-only validates kb's append-only + drop-at-recall design — do not adopt destructive deletes.
importance × recency × relevance retrieval + periodic reflection writing cited insights back; decay from last retrievalGenerative Agents; RMMThe direct ancestor of kb's rerank. Transferable: provenance-cited reflection memories (a #11-safe batch writer). The access-reinforced recency idea is endogenous feedback that risks entrenchment — keep it off the deterministic hot path.
Score in pairs: accuracy × token-cost × latency; benchmarks under-measure write quality & forgettingLoCoMo / LongMemEval / BEAMTells kb how to judge whether memory helps. kb owns the latency/token story (~80–95 ms, top-5); it lacks a utility number — but harvesting an eval set needs a "used" signal kb cannot currently observe.
Memory as size-bounded blocks with a label/summary distinct from the value; files outside the window, pulled just-in-timeAnthropic memory tool + context editing; Letta memory blocksValidates kb's pull-only sessions and recall-then-expand posture. The label/summary split is a cheap upgrade that fixes kb's truncated-title problem and gives dedup a stable key — without abandoning memory = artifact.
The reassuring finding Nothing in the SOTA suggests kb's foundations are wrong. The deterministic, offline, append-only read path is exactly what Letta, mem0, LangMem and Cognee independently arrived at. kb is not behind on architecture — it is behind on one component: the background writer.

D2 · kb-reflect — the offline sleep-time distiller recommended

shipped 2026-07-06 — db7ce381 Built as the agent-layer skill /kb-distill (plugins/kb-memory/skills/kb-distill), not a daemon-cron worker — see the roadmap section below for the fidelity check against this design.

A standalone batch worker (kb reflect) reads session digests, proposes ADD / SUPERSEDE / MERGE / NOOP against the curated tier via an offline LLM, and writes accepted facts through the existing artifact write path into a human-review queue. It is the missing write side the data and the SOTA both point to.

  • Input is the deterministic session_digest (#11 R1), never the raw 2.48M-token JSONL — bounded token cost.
  • Reconcile retrieves the k-nearest existing memories and classifies each candidate; DELETE maps to SUPERSEDE/forget (matching kb's drop-at-recall philosophy and mem0's 2026 ADD-only retreat).
  • Write is 100% existing rails: render_artifact + POST, kb-supersedes on merges, kb-summary kills the truncated title, graded salience kills the 0.5 monoculture, lands in the memory corpus so #11 R0 stays clean.
  • Provenance rides the edge graph (#29): each reflection links to its source sessions and the facts it replaced, so kb why shows "distilled from sessions X, Y; replaces Z" for free, and a wrong synthesis is traceable and kb forget-able.
  • Recall is byte-identical — the model is confined to a subprocess recall never calls (#26 isolation precedent), no-op when unconfigured.

Why it wins: highest reviewer score, perfect invariant-alignment (5.0), and it is the only direction that attacks the actual 13-vs-196 constraint. The dry-run → queue → cron phasing de-risks it and is valuable before any auto-apply.

What the adversarial pass added Three fixes the original design missed: (1) an idempotency key — artifacts::create derives the filename from slug-<unix_secs>, so a batch emitting multiple ADDs in the same second, or a re-run over the same window, becomes a duplicate generator — the exact thing it exists to prevent. (2) MERGE needs multi-target tombstones; it does not ride the single-target supersede path as claimed. (3) Dedup must query raw list_docs, not the floor-filtered recall endpoint, which hides exactly the mis-scoped/dropped facts the corpus is messiest in. And a hard deliverable, not a footnote: a salience rubric + held-out distribution check, or the LLM rater collapses to all-0.8 and recreates the 0.5 monoculture in a confident-but-noisy form.

D1 · Calibrate, Reinforce, Distinguish — adopt, heavily pruned

Six small phases retuning existing signals with recall math preserved. Reviewers reached "adopt-with-changes" but gutted the flagship:

  • keep Title/summary split (kb-summary meta + nullable lance column), re-export DEFAULT_SALIENCE to kill the duplicated literal + add the missing route test, and fix the decay basis with a write-time kb-created meta (not filesystem btime, which is mutable and absent on network/overlay mounts — the proposed created_unix.or(mtime) fallback silently restores the bug).
  • drop P1 lowering RANK_K 60→12 is mathematically backwards. Verified: lowering K widens the rank-term spread, making search position more decisive and salience less able to reorder — the inverse of its stated goal. A salience-0.9 hit that wins at K=60 loses at K=12. The phase pitched as "the direct, measured fix" inverts its own arithmetic.
  • drop P3 usage-reinforcement is a real #10 violation, not a cosmetic one: the recall route would write recall_count every turn, so the same query returns different scores on successive turns — accrued mutable state on the hot path, the precise thing #10 exists to exclude. It also entrenches frequently-injected facts (memory poisoning) on a 13-fact corpus.

D4 · Typed memory tiers (working / episodic / semantic / procedural) — defer

The "rethink from scratch" option. Reviewers found it is mostly relabeling: episodic = sessions (exists), semantic = the memory corpus (exists), "working" = the hook's top-5 (not persisted — not a tier at all). The only genuinely new tier, procedural, is just the R6 distiller wearing a taxonomy. The two real wins it bundles (the decay-reset bug, the duplicated const) are ~30 lines each and need no tier abstraction. Vocabulary, not capability — at 13 facts, typing-for-typing's-sake.

D3 · Bitemporal entity-graph — reject; salvage one piece

Mint entity artifacts and typed/temporal edge kinds on the existing edges table; make recall a 1-hop graph expansion. Two fatal mechanism bugs:

  • Write-path collision: record_edges does delete-all-then-reinsert-per-src; its sole caller (EdgeRecordHook) owns the full link set, so any second writer adding supersedes/mentions edges is wiped on the next reindex. "Additive temporal edges for free" rests on a primitive that is single-set-per-src replace.
  • Read leakage: backlinks_of/edges_from do not filter by kind, so new edge kinds silently inflate backlink counts and pollute the graph route and atlas.

Salvage: supersede-as-edge (a queryable "what replaced this") — but only later, as a deliberate per-edge upsert with kind-filtered reads, not as a headline.

D5 · Closed-loop telemetry → auto-tune ("the memory thermostat") — reject the loop

Log every injection, mine a "used" signal from the next session, auto-tune salience/decay. Fatal: the used-signal cannot be observed. Recalled memories are injected as prompt text by the hook — the agent never Reads the memory's file and never searches its id, so it appears in neither session_files nor session_research (and classify_research never emits an artifact_open kind — it is a dead CHECK-constraint value). The reward signal the whole loop rests on is structurally near-empty. Keep the instinct (kb genuinely cannot answer "which of the 13 facts ever help") but earn it later via an explicit memory-id citation point and an offline eval harness — measurement, not a feedback loop.

5 · The recommended path

Recommendation Do not build a smarter ranker. The deterministic recall path is correct and over-built for 13 facts. Fix the write side instead.
  1. Near term — ship the four verified, model-free correctness fixes (title/summary split; DEFAULT_SALIENCE re-export + missing test; write-time kb-created decay basis; digest research-noise filter). Explicitly drop D1's backwards RANK_K retune and its usage-reinforcement term.
  2. Mid term — build the deferred R6 as kb reflect: offline, model-isolated, opt-in, starting with a no-LLM cleanup of the existing 13. Keep recall byte-identical and sessions pull-only; gate writes behind a human review queue.
  3. Far term — defer the bitemporal graph (D3) and the telemetry loop (D5); both have fatal mechanism bugs as designed and target a scale problem the corpus does not yet have. Earn their salvageable cores — correctly-implemented supersede-as-edge, a real citation-based usage signal, an eval harness — once the distiller has grown the curated tier enough that they matter.

6 · Phased roadmap

Near — verified correctness fixes this month · no new model · no schema rewrite

all 4 shipped — verified 2026-07-10 All four fixes below landed (tagged RA2/RA3/RA4 in the source): kb-summary meta + kb_summary lance column (parser.rs, lance.rs), DEFAULT_SALIENCE re-exported into routes/memory.rs, decay basis moved to the write-time kb-created meta (memory.rs, indexer.rs), and classify_research filters self-referential kb verbs out of the digest.

  • Title/summary split: optional kb-summary meta on render_artifact + a nullable kb_summary lance column (the v0.14 kb_session pattern); stop using the 80-char truncation as the display handle; one-shot retitle over the existing 13.
  • Kill the duplicated literal: re-export DEFAULT_SALIENCE from kb_core::memory to the route; add the missing recall-path test for the route's inline floor + Loose-rerank double-drop split.
  • Fix the decay basis: decay on a write-time-stamped kb-created meta — not filesystem btime — so reindex/rewrite no longer resets a memory's age.
  • Clean the digest: pre-filter self-referential kb verbs (remember/recall/recollect/why) and routine MCP UI tools out of the digest's research line, so the funnel and any future distiller input are clean.

Small, reviewer-verified, low-risk, and they unblock later work — clean titles and a clean digest are distiller inputs.

Mid — build the write side: the offline distiller next quarter · the central move

R6.0-R6.2 shipped 2026-07-06 — db7ce381 Landed as the agent-layer skill /kb-distill (plugins/kb-memory/skills/kb-distill/SKILL.md) plus a Stop-hook nudge (kb-distill-nudge.sh): ADD/SUPERSEDE/NOOP write vocabulary (MERGE narrowed to human-report-only, addressing this doc's own multi-target-tombstone concern by deferring it rather than risking it), --dry-run, and a mandatory --session-id serving as the idempotency stamp this doc flagged as missing. R6.3 (trusted cron) was not built — the skill stays agent-invoked, never a daemon background task, per the no-in-daemon-LLM non-goal.

  • R6.0 — no-LLM cleanup of the 13 first: merge the duplicate deploy/rebuild facts, re-salient the 8 stuck at 0.5, default linked_kbs to project. Most of today's real pain, zero model.
  • R6.1 — kb reflect --dry-run: read digests, propose ADD/SUPERSEDE/MERGE/NOOP with rationale and the neighbors compared, print only. Validates whether 196 sessions yield useful facts before any writes.
  • R6.2 — kb reflect --queue (default): land candidates in a review queue surfaced in the SPA /memory view; operator approves; accepted facts write through render_artifact with graded salience, kb-supersedes, and provenance links.
  • Guardrails baked in: raw list_docs as the dedup oracle (not floor-filtered recall); multi-target tombstones for MERGE; an idempotency key per candidate; a salience rubric + held-out distribution check.
  • R6.3 — trusted cron (optional): a daemon background task mirroring spawn_metrics_ticker, no-op unless KB_REFLECT_MODEL is set, --apply gated to high-confidence ADD/NOOP with SUPERSEDE/MERGE kept behind the human gate.

The single highest-leverage move, kept on safe rails: offline, model-isolated, opt-in, lands in the memory corpus, append-only, human-gated by default.

Far — earn-when-the-store-grows when the curated tier is 10–50× larger

  • Supersede-as-edge (D3's one good idea), implemented correctly: a per-edge upsert that survives the per-src replace, with kind-filtered reads so memory edges don't pollute wikilink/atlas counts.
  • A real usage signal at a new instrumentation point (explicit memory-id citation by the agent), logged as a surfaced signal only — never folded into the deterministic recall score.
  • A per-install eval harness (accuracy × token-cost × latency) to finally answer "is the salience/decay ranker worth it versus plain hybrid" on a corpus large enough for the numbers to mean something.
  • Capture-suggestion ("you re-derived X across N sessions — remember it?") as a deterministic join, independent of telemetry.

8 · Open questions

  • Will the project host a generative model for the distiller, and which — local for offline-purity vs hosted for quality? The entire mid-term plan is gated on this decision.
  • Is the 13-vs-196 imbalance a curation-effort problem or a discovery problem? Would auto-draft-on-signal (a commit, a correction, an AskUserQuestion answer triggers a one-keystroke "remember this?") outperform a periodic batch distiller — and should both ship?
  • At what corpus size does the deterministic ranker's salience/decay actually start to matter? Without the eval harness this remains an opinion.
  • Should episodic sessions ever get a conditional, evidence-gated PUSH (a "has-this-been-done" prompt-shape) — and only if pull demonstrably fails — or is auto-injection permanently off the table given the context-rot / self-reinforcement argument?
  • Is the unbounded, growing episodic corpus a near-term compaction problem (serve-time re-parse of multi-MB transcripts, multi-capture row accretion), warranting an archival/tiering policy before retrieval degrades?
  • Can a real "used" signal be captured cheaply (explicit memory-id citation by the agent), or is recall utility fundamentally unobservable without changing how memories are injected?

9 · Method & references

This report is the synthesis of an orchestrated multi-agent workflow run on 2026-06-29: 6 internal code analysts (recall ranking, capture/write, episodic sessions, storage model, UX surface, design rationale) and 4 external SOTA researchers ran in parallel; 5 divergent design directions were then generated, each scored by 3 adversarial reviewers (feasibility/invariant-alignment, real-data fit/cost-benefit, failure-modes); a final synthesis pass weighed the verdicts. 31 agents total. Real installation data was gathered live from the running memory backend (docker daemon, 127.0.0.1:4000). All file:line claims and mechanism bugs were verified against the source at HEAD.
