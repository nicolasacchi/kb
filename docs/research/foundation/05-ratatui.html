Topic 05 · TUI specification · Design handoff integrated 2026-05-11

verdictSix-tab ratatui dashboard.
Solarized Light, cell-perfect, command-issuer.

The Claude Design handoff bundle 1XoWvtO0FExl3zEpJ3WqqA is the implementation contract. Six tabs (HOME · SOURCES · DETAIL · STATS · ERRORS · SEARCH) over persistent two-row chrome and a one-row status bar. Every glyph, color, border, and keybinding is final. This page reproduces the spec with research cross-links, raises eight concerns, and proposes seven enhancements the design didn't cover.

TL;DR — what the executor builds

ratatui ≥ 0.30 + crossterm 0.29 + tokio (multi-thread) + tui-input + unicode-width + custom src/ui/theme.rs. Six tabs 1–6, persistent header / tab strip / status bar. Solarized Light only. Braille spinner @ 110 ms. Single-line box drawing only (BorderType::Plain). Mode pill changes color per view. TUI is a command issuer (:reindex, r, p, y, x, e) — not a pure observer. Mouse out of scope for v1. Three tokio tasks → one mpsc<AppEvent> → 30 Hz dirty-gated render, 60 Hz frame budget when bursty. Phasing: v0.1 ships HOME + SOURCES + ERRORS; DETAIL + STATS + SEARCH follow in v0.2 / v0.3.

A. Design handoff anchor

The bundle is the spec. This page is the cross-linked read.

Claude Design (claude.ai/design) handoff bundle 1XoWvtO0FExl3zEpJ3WqqA contains kb tui.html (the interactive prototype, the actual spec), Ratatui variations.html (five static layouts with widget callouts — useful when wiring an individual screen), Approaches.html (earlier paradigm exploration, background only), and a thin README.md (generic coding-agent intro, ~23 lines — not a spec). Raw bundle archived at claude-design-handoff/tui-platform/ — open kb tui.html (the spec) and Ratatui variations.html directly to see what this page reproduces.

kb tui.html is the source of truth — color tokens, view layouts, keybindings, animations. This page reproduces every section with kb-research cross-links, plus the concerns and enhancements that emerged from reconciling it with the existing research (sections G, H below).

Stack

  • Language: Rust edition 2021, MSRV 1.86 (matches ratatui 0.30; some toolchains report 1.88).
  • TUI: ratatui ≥ 0.30 (compatible with the design's ≥ 0.29 floor), crossterm ≥ 0.29 with event-stream.
  • Async runtime: tokio (multi-thread).
  • Event stream: tokio::sync::broadcast from the daemon's SSE consumer (see topic 04).
  • Config: TOML via serde + toml.
  • Logging: tracing + tracing-appender — file only, never stdout while the TUI is up.
  • Helpers: tui-input (search / command palette buffer), unicode-width (column math), ratatui-image (optional, source thumbnails).

Library deltas from the original research (section F below has the full background): the design does not pull in ratatui-themes — one custom palette suffices, so a ~30 LOC src/ui/theme.rs covers it. The braille spinner is hand-rolled (10 frames, 110 ms cadence) instead of throbber-widgets-tui to match the design tokens exactly. Both decisions are recorded in concern #8 below.

C. Six views

One tab per task. Same chrome. Different widgets.

Each view has its own mode-pill color, its own widget composition, and its own view-specific keybindings. Mappings: HOME · inv-green, SOURCES · inv-blue, DETAIL · inv-violet, STATS · inv-cyan, ERRORS · inv-red, SEARCH · inv-orange.

V1 · HOME (1, default tab)

Three-pane Block layout. Mode pill: inv-green.

Horizontal split — sidebar 22 cols | main fill
  Sidebar (Vertical):
    [Sources tree]   List · BorderType::Plain · title "▌ sources"
    [Run progress]   Gauge + Paragraph
  Main (Vertical):
    [Overview]       Table · 5 cols (kb, source, duration, files, status)
    [Totals]         Paragraph (one line, fg-muted)
    [Activity log]   List · auto-tails new SSE events, max 4 visible
  • Sidebar is the focus root on tab open. j/k moves selection through sources.
  • Enter drills the highlighted source → tab 3 (DETAIL) with that source loaded.
  • Activity log is read-only here; new events push from the bottom, oldest scrolls off.
  • Run progress gauge mirrors whatever source is currently indexing — not the highlighted one.

V2 · SOURCES (2)

Single-table k9s discipline. Mode pill: inv-blue.

Vertical:
  [Filter strip]   Paragraph — "[1] sources [2] runs [3] errors [4] queries  filter: _  N/N rows"
  [Sources table]  Table · highlight_style bg=selection

  • Columns: KB, SOURCE, FILES, OK, ERR, EDGES, LAST, STATUS.
  • The four numeric tabs at top ([1]…[4]) switch the table's "kind" — same widget, different rows.
  • r re-runs indexer on highlighted row; p toggles pause; Enter → V3.

V4 · STATS (4)

Read-only ambient board. Mode pill: inv-cyan.

Vertical:
  [KPI row]            4 equal columns, each a Paragraph with a huge bold number + delta line
  [Queries sparkline]  Sparkline (60 cells, last 24h)

V5 · ERRORS (5)

Error triage. Mode pill: inv-red.

Vertical:
  [Summary]    Paragraph — "⚠ 3 errors · archive / … · most recent 14:30:44 · filter: _"
  [Error list] Table · cols: KIND, PATH, AT, MSG (truncated)
  [Detail]     Vertical of 3 Paragraphs:
    - Traceback (frames as "at fn · path:line")
    - Source context (5 lines around the offending location, with caret underline in red)
    - Suggested fix + actions

  • Suggested-fix provenance is concern #7 — daemon supplies it.

V6 · SEARCH (6)

Query + results + neighborhood graph. Mode pill: inv-orange.

Vertical:
  [Query]      tui_input::Input — "/<query>_  N hits in Xms · across K kbs"
  [Filters]    Two rows of Tabs-styled segmented controls (scope, kind)
  [Results]    List · each row = 2 Spans-rich lines (title + snippet with highlighted match)
  [Graph]      ASCII-drawn neighborhood Paragraph (precomputed; uses box-drawing chars)
  • Tab cycles scope; Shift+Tab cycles kind.
  • g toggles full-screen graph view; arrow keys move focus node.
  • Enter or o on a hit opens the artifact in the user's browser via xdg-open (matches the design chat: "yes we should be able to open the browser").

Modal overlays

Render with Clear + a centred Block, sized to content.

  • Help (?) — single-column reference of every keybinding, grouped by ▌ navigation, ▌ modes, ▌ actions. ~45 cols × 25 rows. ? or Esc dismisses.
  • Command palette (:) — vim-style colon prompt. tui_input for the buffer. Below the buffer, a fuzzy-matched list of completions (verb + target). Tab accepts the highlighted completion, Enter runs the command, Esc dismisses. Verbs by HTTP endpoint (topic 11 §B.3): reindex, pause, resume, export, atlas recompute (cluster-4 addition). TUI-local verbs (no endpoint): connect <daemon> (daemon-switch shortcut for the D overlay), add <path> / remove <id> deferred to v0.2 when source-management endpoints land.

Typography

Terminal font is the user's monospace; the design assumes JetBrains Mono / SF Mono / equivalent. Do not override the user's font — the design relies only on cell width being uniform.

Box drawing

Single-line only: ┌ ┐ └ ┘ ─ │ ├ ┤ ┬ ┴ ┼. BorderType::Plain everywhere. No double-line, no rounded.

Glyphs

  • Spinner: braille frames ⠋ ⠙ ⠹ ⠸ ⠼ ⠴ ⠦ ⠧ ⠇ ⠏ at ~110 ms cadence.
  • Status: ✓ ok (green) · ✗ fail (red) · ~ modified (yellow) · ⏸ paused (muted) · ⚠ warn (orange) · ▶ in-flight (blue) · ? query (cyan).
  • Section caption marker: ▌ (cyan).
  • Sparkline cells: ▁ ▂ ▃ ▄ ▅ ▆ ▇ █ (use Sparkline widget; it picks these for you).
  • Bar fill: █ filled · ░ empty (for custom Gauge-style bars in home/detail strips).
  • Tree branches: ▾ ▸ ├ │.

Spacing

  • 1 cell of horizontal padding inside every Block (ratatui's default — leave it).
  • 1 blank row between major sections inside a panel.
  • Section caption (▌ name) sits on its own line, not embedded in the border title (matches the mocks).

Drive the redraw loop with tokio::select! over (sse_event, terminal_input, refresh_tick). Don't redraw on every event — coalesce to a 60 Hz frame budget; the original research's 30 Hz dirty-gated recommendation still applies as the floor for idle.

loop {
    tokio::select! {
        Some(input) = crossterm_events.next() => app.on_input(input),
        Some(daemon_ev) = sse_rx.recv()       => app.on_daemon_event(daemon_ev),
        _ = render_interval.tick()            => {
            if app.dirty { terminal.draw(|f| app.render(f))?; app.dirty = false; }
        }
    }
    if app.should_quit { break; }
}
G. Event protocol

SSE NDJSON. Canonical taxonomy lives in topic 04.

Canonical event taxonomy moved to topic 04 §canonical-taxonomy. The original 6-event list in this section was a subset; the deep-review pass found three incompatible taxonomies across topics 04 / 05 / 10 / 11 and rationalized them into one 17-event canonical set keyed by namespace (index.*, artifact.*, watch.*, comment.*, query, error, plus synthetic connection/lag/gap).

SSE channel /api/events emits NDJSON lines. Sample (full enumeration in topic 04):

{"t":"index.start","run":"r-2c1","kb":"rust-learning","src":"home-me-rust","path":"/home/me/rust","total":67}
{"t":"index.file","run":"r-2c1","path":"futures.html","ms":188,"edges":5,"ok":true}
{"t":"index.complete","run":"r-2c1","ok_count":65,"err_count":2,"duration_ms":12400}
{"t":"artifact.indexed","artifact_id":"a-9f3","kb":"work","path":"draft.html","hash":"…","mtime":172…,"change_kind":"modified"}
{"t":"watch.modify","kb":"work","path":"draft.html"}
{"t":"query","kb":"work","q":"borrow checker","hits":5,"ms":14}
{"t":"error","id":"e-77","kind":"parse","kb":"archive","path":"old-blog/2014/broken.html","msg":"…","fix":{"kind":"remove-trailing-comma"}}
{"t":"comment.created","id":"c-12","kb":"work","artifact_id":"a-9f3","author":"you","ts":"2026-05-11T14:31:58Z"}
{"t":"connection","state":"degraded"}

The TUI consumes index.*, artifact.*, watch.*, query, error, connection, lag, gap. It drops comment.* events in v0.1 — the comments panel is a v0.2 SPA feature; reconsider when the TUI grows a comments view.

tracing consumes the same stream so logs and TUI agree on ground truth. src field in events is the URL-safe slug (matches the {src} path segment in topic 11 §B.3 commands).

I. Raised concerns

Eight push-backs the executor needs to hear.

  1. Scope creep. Six distinct views ≈ 6× the v0.1 surface area the original 3-pane recommendation budgeted. Phase explicitly: v0.1 ships HOME + SOURCES + ERRORS; DETAIL + STATS + SEARCH follow in v0.2 / v0.3. Search depends on embeddings, which the briefing roadmaps to v0.2; DETAIL needs the latency-chart wire from the indexer; STATS needs the KPI/sparkline poll endpoint. None of those need to ship together. Cards 4/5/6 can be empty-state stubs in v0.1.
  2. TUI → daemon command channel — missing from existing SSE research. Resolved 2026-05-11 — see topic 11 §B.3. The design's :reindex, r, p, y, x, e keybindings imply RPC, not just SSE consumption. Resolution: nested kb-scoped endpoints under /api/kb/{kb}/...: POST .../sources/{src}/reindex (202 + run id), .../sources/{src}/pause, .../sources/{src}/resume, .../errors/{err}/apply-fix (202 + run id), .../errors/{err}/dismiss, .../stats/export. Async commands return 202 Accepted + {run, events} for SSE-filtered progress (topic 11 §D). CSRF via Origin allowlist (topic 11 §C) — the TUI has no Origin header so it passes. Same TCP:localhost:4000 the design assumes; Unix socket for self-host hardening deferred.
  3. SSE event taxonomy was flagged unpublished. The design supplies the names. Treat them as canonical (section G); emit events.schema.json v0.0.1 using these shapes verbatim. Topic 04 is the transport spec, this page is the consumer spec.
  4. Neighborhood graph view (V3 g modal, V6 ASCII graph). Resolved 2026-05-11 — see topic 11 §B.2. Endpoint is GET /api/kb/{kb}/graph/{id}?depth=1 returning {nodes, edges}. Atlas view in topic 10 §O″ uses UMAP-projected coordinates from the lance store as a fallback when edges are sparse. The anchor semantics from topic 09 apply to comments, not graph — edges are between artifact ids, not DOM anchors.
  5. Mode-pill colors per view are new design language. Document the mapping in theme.rs: HOME inv-green, SOURCES inv-blue, DETAIL inv-violet, STATS inv-cyan, ERRORS inv-red, SEARCH inv-orange. Don't infer per-view from the active tab — let the view declare its own pill style.
  6. State persistence across restarts (last tab, filters, sort order) is listed as open in the design. Recommendation: no for v0.1 — always start on HOME with default filters. Add to kb.toml in v0.2 if asked for.
  7. Error "suggested fix" provenance. The design is silent on who computes the fix. Decision: the daemon emits the suggestion alongside the error event — extend the schema to {t:"error", …, fix:{kind:"remove-trailing-comma", patch:"…"}}. TUI is dumb display; y POSTs to /errors/{id}/apply-fix and the daemon does the write. Never have the TUI derive fixes.
  8. Theme module vs ratatui-themes. Design assumes custom src/ui/theme.rs; the original research recommended ratatui-themes for multi-theme switching. Pick theme.rs for v0.1 (matches the design's single Solarized Light palette, ~30 LOC, no transitive dependency). Revisit ratatui-themes only if multi-theme switching becomes a requirement (the design's prototype HTML supports five palettes via tweaks panel — that's prototype-only, not in the README handoff).
J. Enhancements — missing from the design

Seven gaps to close before the executor starts.

  1. No-TTY fallback. When kb tui is piped (stdout is not a TTY) or the terminal doesn't support UTF-8, fall back to a line-oriented event firehose — the daemon's SSE stream as text. Detect with std::io::IsTerminal (Rust 1.70+, stable) on stdout. Bonus: makes kb tui | tee log.txt a useful debugging move.
    Spike update · 2026-05-11 · spike-ratatui confirmed: without the IsTerminal guard, crossterm's enable_raw_mode() followed by EnterAlternateScreen fails with bare os error 6 ("No such device or address") on non-TTY stdout — an unfriendly UX that surfaces in CI logs, script wrappers without -q, and any pipe. Production must check IsTerminal first and print: "kb-tui must be run from an interactive terminal (try `kb tui` from your shell)" before the fallback to line-firehose mode. Also confirmed: wrapping the binary with script -q -c './target/release/kb-tui' /tmp/kb-tui.log allocates a pseudo-tty so the binary launches and emits alt-screen + cursor-hide ANSI sequences — useful as a no-real-terminal-needed CI smoke test. Full context: docs/spike-findings.md.
  2. Terminal capability detection & ASCII fallback. Braille spinner needs UTF-8 + reasonable font coverage. Probe at startup; provide ASCII fallback frames / - \ | for terminals without braille. Bar fills similarly: █/░ fall back to #/..
  3. Colorblind safety note. The design uses red/green for OK/fail; glyphs (✓ ✗) carry the same information independently. Document this constraint explicitly in theme.rs so future palette additions don't break it.
  4. Multi-kb namespacing scaling story. Design mocks show four kbs hard-coded; v0.0.1 research says "one kb only". The TUI handles N kbs trivially in the sidebar tree; the sources table already has a KB column filter (V2); the activity log labels each event with kb=. No layout change at N=10. Re-flag at N→100 (sidebar tree wants virtualisation; sources table wants a search filter strip).
  5. Connection-state freeze on disconnect. Design proposes desaturating the body and freezing panels (rather than blanking) while the retry counter ticks. Cross-reference topic 04's Last-Event-ID replay: on reconnect with replay → fill the gap silently; without replay → show "snapshot resync" banner and clear the in-memory log to avoid stale state.
  6. Open-in-browser vs open-in-editor. Design chat says o opens artifact in browser; design README says o opens in $EDITOR. Disambiguate: o on a code/error row opens $EDITOR; Enter or o on a search-hit or HTML artifact row opens via xdg-open (browser for .html). Add to the keybinding table (already reflected in section D).
  7. Accessibility escape hatch. ratatui is not screen-reader friendly. Document that the kb daemon's HTTP API (GET /search?q=, GET /docs/{id}, GET /stats, GET /events) is the non-visual access path. The TUI is one client among many; the daemon is the source of truth.
K. Background · ratatui ecosystem in 2026

Why the design's choices match the patterns.

The handoff doesn't justify every library or pattern choice — this section documents the upstream context so the executor knows why ratatui 0.30 + the component pattern + tokio::select! are the right defaults, and what the alternatives look like if any of them turn out to be wrong.

Ratatui current state

Latest ratatui = 0.30.0, released 2025-12-26 after a year-long alpha/beta cycle. 0.31 planned but unreleased. MSRV 1.86. 0.30 is the biggest break since the tui-rs fork: workspace split (ratatui-core, ratatui-widgets, backends), no_std support, ratatui::run() entry point, crossterm version flags, Alignment → HorizontalAlignment (alias kept), FrameExt import needed for render_widget_ref.

Has state management crystallised? No.

Ratatui itself is strictly immediate-mode. Three serious add-ons reached usable maturity in 2025 — tui-realm (React/Elm hybrid, prescriptive), ratatui-elm (Iced-inspired, lazy redraw), tears (pure TEA). No canonical winner. The design picks the component pattern from the async-template / gitui — sufficient, no framework lock-in, easy to migrate to elm-style later.

Common pattern across all: dedicated collector task → channel → main loop drains channel → redraw. Nobody redraws directly from an HTTP/SSE callback. The design's async-edge prescription matches.

Async edges into a synchronous render

A tokio task per async source converts that source into AppEvents and pushes them onto one mpsc::UnboundedSender<AppEvent>. The render loop drains the receiver in select!. SSE, fs notifications, HTTP responses — all become AppEvent variants. This is the async-template's prescription and what bottom, gitui, and the elm-style frameworks all do under the hood.

SSE client

reqwest-eventsource is the lighter pick (auto-retry, GET-friendly). eventsource-client (LaunchDarkly) has more features. For kb (GET-style on localhost), reqwest-eventsource. Spawn one task; forward parsed events through tokio::sync::mpsc::unbounded_channel.

Reconnection UX

  1. Connected — quiet green dot in the header.
  2. Reconnecting / degraded — yellow dot + paused spinner + countdown.
  3. Disconnected — red dot, last-seen timestamp, body desaturated (see enhancement #5).

Decisions · 2026-05-11 (cluster 4: UX gaps — TUI side)

Open-points cluster 4 landed. Every TUI-side open question is now resolved.

  • Daemon transport. Resolved cluster 1. TCP localhost:4000 for v0.1; Unix socket considered for self-host hardening only.
  • Search-as-you-type plumbing. Resolved cluster 4. Debounced GET /api/search at 150 ms after the last keystroke (topic 11 §B.1). No streaming query channel for v0.1; revisit if v0.3+ shows it's needed.
  • Run history retention. Resolved cluster 4. Two distinct rings: the TUI's in-memory display ring is 200 events (renders the last 4); the daemon's replay ring (topic 04) is 1024 events for Last-Event-ID gap-fill. Plus daily-rotated ndjson at ~/.local/state/kb/runs/YYYY-MM-DD.ndjson for cross-session history. Scrollback-into-history is a v0.3+ TUI affordance.
  • Multi-daemon. Single per host or several? Resolved cluster 4 — multi-daemon from v0.1. The TUI keeps a daemon list in ~/.config/kb/daemons.toml (one section per daemon: [daemon.work-laptop] endpoint = "http://localhost:4000"). The header chrome shows kb <daemon> · <kb> (e.g. kb work-laptop · rust-learning) instead of just active: work. D opens a daemon-switcher overlay (modal · same pattern as ? help). Daemons identify themselves via GET /api/identity (topic 11). Discovery is config-only for v0.1; mDNS / .local auto-discovery defers to v0.4+ team-mode. SSE: TUI subscribes to one daemon at a time (the "active" one); switching daemon flushes and reconnects.

Resolved by the design handoff: write path (TUI is a command issuer), mouse policy (out of scope for v1), SSE event schema (the design names are canonical), state-management approach (component pattern, no framework). Resolved by clusters 1–4: transport, search plumbing, run history, multi-daemon, command channel, sandbox recipe.
