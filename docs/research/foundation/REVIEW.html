Foundation — review

Audit of the six foundation docs (storage, embeddings, watcher, SSE, TUI, bake-off) against the kb codebase at HEAD (post-v0.9, agent-memory cluster landed). The big calls — lance+sqlite split, RRF k=60, fastembed via load-dynamic ORT, notify+debouncer-full @ 400 ms, single firehose SSE — all shipped. Two surprises: the TUI shipped a fundamentally different 5-tab fleet-monitor (Eclipse Deep dark palette), not the spec'd 6-tab Solarized Light dashboard; and the bake-off recommended bge-large but production still defaults to bge-small.

01 · Storage (lancedb + sqlite)

shipped

The full cluster-3 decision is in code. The on-disk split is exactly as written: lance holds docs/vectors with a 5-field BM25 FTS (title, body, headings, code, prompt) and sqlite holds the relational tables (sources, errors, runs, edges, migrations). Hybrid search routes through lance's native RRF with the k=60 default. The doc's spec'd BEGIN IMMEDIATE + wal_checkpoint(TRUNCATE) + manifest-tar backup plan was replaced by a simpler VACUUM INTO in B1 — pragmatic simplification, not a regression. The configurable hybrid_k knob in kb.toml didn't ship as a per-kb setting (the doc spec'd it; current config.rs has no field for it), but the k=60 default it controls is hard-coded.

  • crates/kb-core/src/storage/lance.rs:26 — FTS_COLUMNS = &["title","body","headings","code","prompt"].
  • crates/kb-core/src/storage/lance.rs:397 — comment "fused via lance's RRF (k=60 default per topic 01 §Decisions)".
  • crates/kb-core/src/storage/backup.rs:32 — backup is VACUUM INTO, not the spec'd tar+manifest dance.

02 · Embeddings (fastembed via ORT)

partial

The model registry, the kb model {list,download,set,rm} CLI surface, the XDG cache, and the ort-load-dynamic feature flag all shipped on plan. However, the doc's mental model of "construct fastembed::TextEmbedding once per kb and call embed() in-process" was superseded by the I1 milestone: embedding now runs in a separate kb-embedder subprocess (one per kb) over a stdin/stdout JSON IPC, so ONNX runs at low CPU priority and a crashing model can be respawned without killing the daemon. The doc's per-kb embedding_model config field is honoured; the multi-model story is real (bge-small default, bge-base, bge-large, jina-v2-base-code all in the static registry).

  • crates/kb-core/src/embed.rs:67-99 — SUPPORTED_MODELS registry with the four planned models, default_model() returns bge-small-en-v1.5.
  • Cargo.toml:50-53 — fastembed = "5" with ort-load-dynamic + hf-hub-native-tls features, as spec'd.
  • crates/kb-core/src/embed_ipc.rs + crates/kb-embedder/ — I1 subprocess transport; the doc's in-process Embedder stays in embed.rs but is no longer the production path.

04 · SSE on axum

shipped

Exactly the pattern the doc prescribed. One broadcast::Sender<Envelope> in the bus, a VecDeque ring keyed by monotonic u64 for replay, single firehose at GET /api/events with ?types= glob filtering — no per-domain endpoints, no dual-direction split. The doc's {v, id, type, ts, payload} envelope shape and the Last-Event-ID resume contract are in events.rs, and the synthetic event: gap frame the doc called out as a hardening detail is present too. Sse::new(...) + keep_alive(...) in routes/events.rs.

  • crates/kb-core/src/events.rs:1-51 — module doc "Lifted from spike-sse (the broadcast + VecDeque ring + Last-Event-ID dedup pattern)"; broadcast::channel(live_capacity) + ring: Mutex<VecDeque<Envelope>>.
  • crates/kb-server/src/routes/events.rs:1-3,53,87 — single /api/events route with ?types= filtering, monotonic global id space, Sse::new(...).keep_alive(...).

05 · TUI

superseded

The library set (ratatui 0.30 + crossterm 0.29 + tui-input + unicode-width) shipped as spec'd, but the design the doc reproduced — six tabs (HOME · SOURCES · DETAIL · STATS · ERRORS · SEARCH) over a single Solarized-Light palette, mode pills per view — was replaced wholesale in the v0.6 "fleet-monitor" redesign. The shipped TUI is a five-tab dashboard (OVERVIEW · PIPELINE · TRAFFIC · ERRORS · EVENTS) on the "Eclipse Deep" dark palette (Tokyo-Night-inspired), with persistent fleet-aware chrome (multiple daemons, not one). The 3 → 5 tab evolution + the palette swap are load-bearing enough that the doc's screen-by-screen spec no longer maps cleanly to the code. The doc remains a useful artifact for "what the v0.1 design called for"; CLAUDE.md's "Where to find things" table is now the authoritative TUI map.

  • crates/kb-tui/src/app.rs:17-31 — pub enum Tab { Overview, Pipeline, Traffic, Errors, Events } — not the spec'd six.
  • crates/kb-tui/src/ui/theme.rs:1,17 — //! "Eclipse Deep" — Tokyo-Night-inspired dark palette; the doc's Solarized Light was rejected.
  • CLAUDE.md "TUI dirty snapshot" invariant #4 and the v0.6 fleet-monitor entries in the "Where to find things" table document the redesign.

14 · Embedding bake-off (2026-05-19)

partial

The infrastructure the bake-off depended on (three parallel kbs on one daemon, per-kb model selection, RRF hybrid mode) all works, and the per-kb-section embedding_model config field referenced in CLAUDE.md is honoured. The bake-off's recommendation, however — "skip directly to bge-large or stay on bge-small; bge-base is not the answer" — was not adopted as a default change: default_model() still returns bge-small-en-v1.5, and the "follow-up sweep on larger corpora" the doc proposed as the natural next step hasn't landed in code as a tracked benchmark. The doc remains valid as operator guidance ("if you have the disk, switch this kb to bge-large"), and bge-large is in the registry ready to be selected per-kb. The decision to keep bge-small as the global default is consistent with the bake-off's own "if bandwidth- or memory-constrained, stay on bge-small" caveat.

  • crates/kb-core/src/embed.rs:107-109 — default_model() returns bge-small-en-v1.5; embed.rs:84-91 shows bge-large in the registry but not promoted.
  • CLAUDE.md "Architecture invariant 12" — "Embedding dim is per-kb, captured at Storage::open time" — the bake-off's three-way-on-one-daemon setup is now a load-bearing invariant in the code.

Meta · audit notes

Hit rate is high — five of six docs are either shipped clean or only modulated by a later, intentional decision. The two divergences worth noting:

  • TUI redesign (doc 05). The v0.6 fleet-monitor was a deliberate scope shift; the original doc isn't "wrong", it's been superseded. Reading the doc today, the diff matters: phasing (v0.1 ships HOME+SOURCES+ERRORS) and Solarized Light were both abandoned.
  • Bake-off (doc 14) recommendation didn't land as a default change. The infra to act on it (per-kb model selection) shipped; the policy choice (promote bge-large) didn't. Worth re-running on larger corpora before any default change.
  • Minor: hybrid_k not user-tunable. Doc 01 promised it as a per-kb kb.toml field; current config.rs has no such field, k=60 is hard-coded. Cheap follow-up if anyone actually wants to tune it.
