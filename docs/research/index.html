kb — html artifact galleryResearch before the daemon.
Fewer assumptions later.

kb is a single Rust binary that indexes, searches, and serves a personal collection of LLM-generated HTML artifacts. Its design thesis comes from Thariq Shihipar's Unreasonable Effectiveness of HTML: when an LLM produces an artifact, HTML is a richer medium than markdown — spatial layout, inline SVG, <details>, <canvas>, real interactivity. This research sits between the briefing and any production code: eight parallel investigations + one feature design (commenting) + two design handoffs integrated (TUI · Web Gallery), seven challenges, eleven discussion topics, six spike-tests. Five canonical artifacts ship in sample-artifacts/ as the iframe sandbox and indexing-pipeline contract.

Headline pushbacks (challenges page)

  1. Iframe sandbox is storage-broken without subdomain serving. The proposed flag string fails every localStorage call. Adopt topic 06 recipe (subdomain + tighter flags + iframe-recreate).
  2. SSE event taxonomy needs a published JSON Schema before any client subscribes. Author events.schema.json in v0.0.1.
  3. Plugin / extension alternatives to the daemon — considered and rejected. Obsidian, Karakeep-fork, TiddlyWiki each fail on at least one of: observability, agent-ingest HTTP API, headless self-host, HTML-as-primary-unit. Daemon path confirmed.
  4. Event-log architecture (one source of truth, derived views) — defer; cluster 3 committed lance + sqlite split, so the practical "one-store collapse" question is the v0.3+ regression-test trigger now.
  5. Rust vs Go honest evaluation: Rust wins given embedding requirement; Go would win if vector search dropped.
  6. Single binary + workspace are not mutually exclusive — do both.
  7. MCP-wrapper is a thin shim, defer to v0.2 not forever.

The seam between research and implementation

High-leverage open questions
  • SSE event taxonomy unpublished. Resolved by both handoffs. Names index.start, index.file, watch.modify, query, error, connection, comments.updated are canonical (see 05 · §G + 10 · §J). Author events.schema.json v0.0.1 using those shapes.
  • TUI → daemon command channel. Design's :reindex / r / p / y / x / e imply RPC. Add POST endpoints to the v0.0.1 HTTP API. Resolved 2026-05-11 — see topic 11. All commands under /api/kb/{kb}/...; async returns 202 + {run, events}; Origin allowlist for CSRF.
  • SPA → daemon comments path. The kb-comments/1 exports need to reach kb/{kb}/.review/{id}.json for Claude Code to read and reply. Resolved 2026-05-11 — POST /api/kb/{kb}/review/{id} with GET sibling for Claude-reply sync, file-watcher emits comments.updated SSE on disk change. See topic 11 §B.
  • SPA iframe sandbox — Web Gallery prototype uses storage-broken flags. Adopt topic 06's subdomain recipe; rework the annotator bridge as a serve-time injected script. Resolved 2026-05-11 — see topic 06 Decisions callout and 10 · §O′ Decisions. Permissive baseline flags (topic 06 §G) minus allow-same-origin; serve-time injection of /_kb/annotate.js for the annotator; explicit targetOrigin on postMessage.
  • Neighborhood graph endpoint. TUI V3 / V6 + SPA Atlas view need graph data. GET /graph/{doc_id}?depth=1 returning {nodes:[…], edges:[…]}. See 05 · §I-4. Atlas cluster centers additionally need an offline UMAP / t-SNE build step over embeddings (10 · §M-6).
  • Wildcard subdomain DNS. Required by both topic 06 and the topic 10 sandbox resolution. Resolved 2026-05-11 — <id>.artifacts.localhost via RFC 6761 (Chrome (M67+, Dec 2017) and Firefox (84+, Dec 2020) auto-resolve; dnsmasq fallback for Firefox if the spike fails). Caddy + DNS-01 + wildcard cert remains the self-host path. Outstanding spike: verify Firefox (ESR + stable) resolves foo.artifacts.localhost to 127.0.0.1 without dnsmasq.
  • Storage spike outcome. sqlite-vec + FTS5 within 5% nDCG of lance? Decides one-store vs split. Resolved 2026-05-11 — commit to lancedb + sqlite split. sqlite-vec spike downgraded to a regression test if a kb crosses ~50k docs. See topic 01 Decisions.
  • Embedding model finalisation. bge-small for the prose-heavy default; explicit decision needed if the corpus skews to code (jina-v2-base-code). Resolved 2026-05-11 — multi-model from v0.1. bge-small default, jina-v2-base-code documented switch candidate. kb model {download,set,list,rm} shipped day one; per-kb selection via kb.toml; XDG cache at ~/.cache/kb/models/. See topic 02 Decisions.
  • Privacy scrub policy. Default opt-in (scrub system prompt, redact patterns) vs opt-out (preserve everything). Privacy default favours opt-in for shared artifacts; reproducibility favours opt-out for personal. Resolved 2026-05-11 — path-specific four-path decomposition: embedding excludes kb-prompt, BM25 indexes it as filterable field, bytes never modified, outbound scrubbing deferred to v0.2+. See topic 07 Decisions.
  • kb-tui write path. Pure observer or command issuer (POST add-source, trigger reindex)? Drives ratatui complexity. Resolved by design handoff: command issuer.
  • Mouse policy in TUI. Capture for scroll-wheel only, ignore clicks (recommended) or full click-routing (needs ratatui-interact). Resolved by design handoff: keyboard-only, mouse out of scope for v1.
Roadmap · what ships at each stage

From the v0.0.1 vertical slice to v0.4 self-host

Consolidates every commitment across the 11 topic pages and 4 cluster decisions. Each stage is independently shippable; the listed items must all land before the stage is considered done. Outstanding spikes are called out per stage.

v0.0.1 · vertical slice (~1 week)

Smallest end-to-end implementation that proves the architecture. Single user, single kb, BM25 only, no rendering, no TUI, no SPA. Validates the storage layout + event firehose + iframe sandbox recipe.

Workspace + build

  • kb-core (lib) + kb-server (binary) + kb-cli (binary) + top-level kb dispatcher. Rust edition 2021, MSRV 1.86.
  • Dependencies: axum 0.8 + tokio + lancedb + rusqlite + scraper + notify + notify-debouncer-full ≥ 0.7.0 + tracing + tracing-appender + serde + tower-http (gzip middleware).

Storage (topic 01)

  • On-disk layout: ~/.local/state/kb/<daemon-name>/<kb-name>/lance/ + …/<kb-name>/index.db.
  • lance: vectors (empty in v0.0.1) + columnar artifact rows + native FTS for BM25.
  • sqlite tables: sources, errors, index_runs, edges, schema_migrations.
  • Single writer per kb via tokio actor; readers never block.
  • kb backup <kb> with the atomic recipe (BEGIN IMMEDIATE → wal_checkpoint(TRUNCATE) → manifest read → tar fragments → COMMIT, indexer paused <500 ms).

Indexer + extractor (topic 07)

  • Walk a single configured folder per kb. Parse HTML with scraper.
  • Extract: title, h1, first paragraph, headings (h1–h6 + details/summary), code blocks, body text (DOM walk excluding <script>/<style>/<template>).
  • Facets: has_svg, svg_count, has_details, details_count, has_form, has_drag, has_animation, has_canvas, has_math, has_prompt, prompt_size_bytes, js_loc, css_loc, kb_category, size_kb.
  • kb-prompt template (<template id="kb-prompt">) preserved on disk verbatim; cap at 8k tokens in the BM25 prompt-field index.

File watcher (topic 03)

  • notify + notify-debouncer-full ≥ 0.7.0 with 400 ms window.
  • ENOSPC fallback → PollWatcher.
  • Initial walk on startup + re-walk on arm.

Search

  • BM25 only. Field-aware: title, body, headings, code, prompt. Hybrid + semantic deferred to v0.1.
  • CLI: kb search "query" returns ranked rows. kb search field:prompt "claude-code" filters by field.

CLI verbs (v0.0.1 minimum)

  • kb add <path> — register a source folder.
  • kb search <query> — BM25.
  • kb read <id> — xdg-open the artifact file.
  • kb cat <id> — dump artifact to stdout.
  • kb daemon — start the HTTP+SSE server.
  • kb backup <kb> — atomic snapshot.

HTTP API surface (subset of topic 11; see §B for full)

  • GET /api/kbs
  • GET /api/search?q=&mode=keyword&kb= (only keyword/BM25 in v0.0.1)
  • GET /api/kb/{kb}/docs/{id}
  • GET /api/kb/{kb}/sources
  • GET /api/events (SSE firehose, Last-Event-ID replay; 1024-event ring buffer)
  • GET /api/events.schema.json + per-type schemas at /api/events/schema/{type}/v1.json
  • POST /api/kb/{kb}/sources/{src}/reindex (proves the async 202 + {run, events} pattern)
  • GET /api/identity (daemon self-description — needed for v0.1 multi-daemon clients)

SSE event taxonomy (subset of canonical 19)

  • index.start / index.file / index.complete
  • watch.create / watch.modify / watch.delete
  • artifact.indexed / artifact.removed
  • query / error / connection
  • Synthetic: lag / gap
  • Deferred to v0.1: comment.*, comments.updated, atlas.recompute.*

Iframe sandbox infrastructure (topic 06)

  • Per-artifact subdomain serving: <id>.artifacts.localhost:4000 (axum virtual-host routing on Host: header).
  • Sandbox: allow-scripts allow-same-origin allow-popups allow-popups-to-escape-sandbox allow-forms allow-modals allow-downloads.
  • CSRF: Origin allowlist on writes (localhost:4000 + *.artifacts.localhost:4000).
  • RFC 7807 problem+json errors with URN type.
  • gzip via tower-http on responses > 1 KB; disabled for SSE.

Tracing + state

  • tracing structured logs → stderr + rotating file at ~/.local/state/kb/log.
  • Run history: in-memory 1024-event replay ring + daily-rotated ndjson at ~/.local/state/kb/runs/YYYY-MM-DD.ndjson.

v0.0.1 outstanding

  • Safari *.localhost spike — confirm whether dnsmasq is needed on macOS Safari (the only outstanding pre-SPA blocker).

v0.1 · TUI + SPA + multi-daemon (cluster-4 "maximalist")

SPA (topic 10) — maximalist v0.1

  • Fonts: Geist sans + Geist Mono + Lora serif. Self-host the WOFF2 files.
  • Top bar: daemon + kb selector + path label + Cmd-K search pill + view toggle (Grid/List/Atlas) + settings.

  • Multi-file artifacts: pages array + left Pages panel + pm:page handshake + load-event fallback for non-cooperating artifacts.
  • Cross-artifact backlinks: postMessage({type:'open-artifact', id}).
  • Cmd+K: three modes (cycle via Tab), prefix filters, score bars, right-side result preview pane (loads matched section).
  • Status pill (bottom-right): phases idle/indexing/degraded/disconnected, drop-up with recent events + "view errors" / "open in tui" footer.
  • Multi-daemon SSE aggregation: one EventSource per configured daemon, per-daemon lastEventId in localStorage, exponential backoff, aggregation = max(severity) / sum(in-flight). Stress-test with 3 daemons pre-ship.
  • URL routing: /?view=&tag=&kb= for gallery, /a/{kb}/{id}?page=N&comments=open for detail. Refresh-safe; shareable.
  • Keyboard nav: j/k row, Enter open, Esc clear filters, / focus Cmd+K, gg / G jump.
  • Empty / loading / error states: artifact 404, iframe load fail (retry button), daemon disconnected (banner row + last-known-state freeze).
  • Accessibility: landmark roles (banner / complementary / main / status), skip-link, :focus-visible visible on dark theme, aria-label on every icon-only button, aria-live="polite" on status pill.
  • Print stylesheet: hides chrome; prints empty-comments state (full comments inline in v0.2).
  • Onboarding (empty-kb): "drop HTML into kb/<name>/ or run kb add <path>" + "Show me an example" button invokes kb add --demo (daemon bundles kitchen-sink.html).
  • Permalink: /a/{kb}/{id} with "copy permalink" button.

  • Browser bar: Chrome 111+, Firefox 121+, Safari 15.4+.

v0.2 · comments + annotator + Claude round-trip

The comments milestone. Brings the SPA's annotator UI online, the daemon's review-write endpoint, the postMessage protocol additions, and the Claude-Code reply loop.

Comments (topics 09 + 10 §I)

  • kb-comments/1 JSON schema; persisted at kb/{kb}/.review/{id}.json.
  • Annotate mode: pen icon toolbar; click any block (heading / paragraph / list item / table row / code / callout) to attach. Select-first scopes to exact words.
  • data-cm-id anchors on every eligible block.
  • Threaded replies with author: "you" | "claude"; reply-composer you ↔ claude toggle.
  • Icon-only actions: jump · reply · edit · resolve/reopen · delete.
  • Filters: open / resolved / all with counts.
  • Three exports: Claude prompt (instructions + JSON file path) · kb JSON (schema file) · Markdown (human-readable). Copy + download per export.
  • Cross-page jump on multi-file: switch page → load → postMessage({type:'cm:flash', ref}).

Daemon endpoints + serve-time injection (topic 11)

  • GET /api/kb/{kb}/review/{id} + POST /api/kb/{kb}/review/{id} (atomic tmpfile+rename, per-id tokio::Mutex).
  • /_kb/annotate.js (~3 KB) — annotator script served from artifact subdomain. Daemon serves at http://<id>.artifacts.localhost:4000/_kb/annotate.js.
  • Response-rewriter middleware — when ?cm=on, inject <script src="/_kb/annotate.js" defer></script> + inline window.__KB_COMMENTS JSON before </body>. Use lol-html streaming rewriter; EOF append fallback for malformed HTML. Cache key includes ?cm=on.
  • postMessage protocol: cm:add, cm:flash, cm:refresh, cm:mode. Direction-aware targetOrigin; parent validates event.origin.
  • HTTP surfacing of model selection: SPA Settings page can read + switch via PATCH /api/settings.

SSE additions

  • comment.created, comment.exported, comment.resolved, comment.anchor_stale events emitted by indexer/file-watcher.
  • Aggregate comments.updated event (debounced 500 ms) → status pill comment badge.
  • SPA's status pill grows comment badge; click jumps to comments panel with unread filter.

SPA additions

  • Comments panel (right, 360 px) — group by file, current-file labeled "here".
  • Print stylesheet's "comments inline with anchors" path activates.
  • v2-deprecated: kb comments export CLI (replaced by SPA modal).

v0.4+ · self-host + team mode

When the daemon binds a public IP and multiple users participate. New threat model; new auth story.

  • Caddy + DNS-01 wildcard cert for *.artifacts.<domain>.
  • HTTPS: mkcert / self-signed for local; ACME for public.
  • Bearer-token auth: ~/.config/kb/token; per-kb ACLs.
  • Rate limiting: tower::limit on hot endpoints.
  • Multi-user cache key on serve-time-injected responses (?cm=on) to prevent comment cross-user leakage.
  • mDNS daemon auto-discovery: .local service advertisement for federation.
  • MCP wrapper (deferred from v2): Claude Desktop / external tooling integration.
  • Real-time push to Claude Code (deferred from v3): WebSocket or SSE outbound rather than file-watcher round-trip.

Colophon

How this was made

This research site was produced in a single Claude Code session by spawning eight parallel research agents, each given a tight brief covering one topic bundle. Each agent returned a markdown research document with sources; this site re-presents them in a uniform editorial format with cross-links, a shared CSS theme, and consolidated cross-cuts (challenges / discussion / spikes).

The prompt that produced this lives in the conversation that originated the research — not embedded in the artifacts themselves. (Topic 07 proposes a <template id="kb-prompt"> convention for the kb project itself; this research site predates kb's existence, so it doesn't yet follow its own advice.)

Every quantitative claim in the topic pages traces back to a 2025 or 2026 source linked in the page's footer. Where the missing kb-tui-spec.md and kb-spa-spec.md would have informed deeper conclusions, the research explicitly flags [needs spec].
