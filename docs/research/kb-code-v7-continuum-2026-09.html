The claim

kb-code v6.0 is a good instrument with a fragmented interface: twenty-seven routes, three chord machines, a rail of six tabs that do not scale, nothing resizable, a usages engine no screen uses, a canvas nobody can author, a review pipeline whose agent half has never run once. The operator's bar is precise: the human should always know and feel at home in the code, travelling continuously without hard stops that change the interface; better than GitHub; everything usable by the LLM too via CLI.

v7 answers with five unifications and a rule. One shell (the Desk): five resizable regions whose landmarks never move while the center swaps between reader, diff, dossier, board, dashboard and results. One grammar (kbc-scope/1): the same scope and query language in search, tree filter, usages, recipes, boards, review filters and every --scope. One ladder: the review-comment carry-forward resolver becomes the only way any anchored thing finds its line again, and an uncertain match is an honest orphan everywhere. One registry (cmd/1): keys, palette, which-key, context menu, help sheet and CLI twin generated from one declaration. One trail: navigation is a typed, walkable record, so a usage opened in another tab knows where it came from. The rule: every fact carries its class, every claim carries its author, every empty result explains itself.

Seven tagged milestones deliver it, kb-code-v7.0 through v7.6, priced at roughly 300 builder-days with two or three Sonnet builders in parallel and Fable orchestrating, gating and committing (the standing model policy). v7.0 is not a feature milestone: it is ground truth (repair, harden, measure), the Desk, and the one slice that makes the operator's named workflow, the LLM-authored PR review, execute end to end for the first time.

What the recon changed

These facts reshaped the design; each is load-bearing for a decision below.

  • The LLM-review path has never executed. 0 of 564 PR artifacts carry the machine block; five blockers: no loopback daemon registers the repo, the report JSON shape (nested verdict) does not match what the Room renders, the PR body is never fetched, findings/import is loopback-only by an explicit v6.0 ruling, and the artifact hint is written from neither side. → v7.0 gets a review-unblock slice; v7.3 is a protocol milestone.
  • usages/1 has zero SPA consumers. gr, the lens chip and the peek u all call the grep-tier /api/xrefs; three usage counts disagree; Ruby and Go cannot reach exact. Rails reverse edges are gated by a source-path predicate, and rails_edges rows are never deleted for stale blobs (phantom usages forever). → the repoint waits for those fixes.
  • Nothing is resizable; the tree shows HEAD, not the working tree; no git status decoration, no bottom panel, no scroll restoration, no trail, jumplist pane-1 only, cockpit tab and patchset not in the URL, sixteen keyboard-inert routes, three chord machines, and the review map is torn out of flow by an inherited .kbc-ego { position: fixed }.
  • Languages: twelve grammars, no HAML (57% of the target app's views), no SCSS/CSS/Markdown, Gemfile/Rakefile/.rake/.ru/.jbuilder in the unknown tier, fifteen highlight classes sharing one salt with symbols, ERB returns empty spans, and highlights are only written inside the symbols cache-miss branch (a highlight-only salt bump would silently un-highlight everything).
  • Rails lens: the locale index is rebuilt from disk per dispatched file (~519 MB of YAML re-read per reconcile), no inventory, no verb/path on routes, no namespace aggregation although constant nesting is the codebase's only organising principle (Reseller spans three path prefixes plus db/, spec/, and holds two different OrdersControllers).
  • Canvas: one node kind, opaque payload, no CLI by the recorded v3 D7 ruling, no authored edges, no export; kb's own boards.rs already speaks JSON Canvas 1.0.
  • Recipes: a closed enum of six, scope only a boot-time named entry, a 10 s client timeout that makes the blame recipes unusable, three honesty bugs; v3 D6 pre-authorised TOML recipes "if the operator asks twice" and this is the second ask.
  • CLI: ~125 forms, no manifest, no bearer token, no cwd→repo inference, pack annotations hardcoded empty, the installed binary predates the v6.0 verbs.
  • Worktrees: the git layer is worktree-correct with zero product presence; Claude Code's .git/worktrees/<n>/locked carries the owning session and pid and CLAUDE_BASE the base commit, a free ownership oracle nobody reads.
  • Security, from the critique (private): loopback is peer-IP only with no Origin/Host/CSRF check anywhere in kb-code; read_repo_file joins paths lexically and follows symlinks; merge-tree writes objects into the browsed repo's ODB; the prod container injects one shared bearer for every admin and kb-code has one identity by recorded ruling.

The spine: nine primitives

Build these once; every track rides them. Each carries its amended form after the critique.

P1 · The Desk

Five regions: left dock, main (one or two panes), right rail, bottom drawer, two icon stripes. Every separator drags; keyboard resize submode Ctrl-w r; double-click resets; sizes persist per repo in a versioned DeskState reducer (react-resizable-panels is the mechanism only, never the truth). Regions collapse to a badged stripe and never vanish. Presets Read / Review / Explore / Present plus named desks; a human drag marks the desk dirty and a preset never overrides it silently; a dirty desk is resolved by Save-as, Reset, or Keep. Two goldens replace the draft's "byte-identical chrome": a landmark golden (region identity, order and keyboard addressing identical across center modes; a mode may collapse a region, never move or rename one) and a viewport golden (at 1280×720 with the default desk the code region is ≥80 columns × 28 lines at the default font; the drawer opens as an overlay when it would violate that). Center modes: reader · diff · dossier · board · dashboard · results.

The right rail keeps kb #30's grammar: tab one is All (everything stacked), then Understand (outline, symbol passport, facts), History (blame, why, story, timeline), Review (threads, findings), Notes (annotations, bookmarks, the question stack); the always-visible self-suppressing passport cards stay. The rail follows the caret (debounced ~250 ms) with an explicit pin: pinned, the header reads "📌 Order#total — caret is in Order#refund · Space p to follow"; the subject is always named in a segmented chip (symbol | line | file) and a fallback is captioned, never blank.

The bottom drawer is a tab bar of named, stable-id result sets (usages ⁴² | search | recipe | diagnostics | findings): Space 1…9 direct, ]d/[d step, Space d toggle; a hard cap with visible eviction (an evicted tab greys with "closed — Space u to reopen"); pinned sets never evict; eviction is a view operation, never a data operation. Sets render as stitched excerpts ordered exact ▷ likely ▷ candidate ▷ observed, and above the cap degrade into a filterable search with the true total stated. A placement rule table (content kind → home) is user-editable and printable. Mobile: one column, the rail as the single bottom sheet with its stripe intact; the drawer is a tab inside that sheet, never a second sheet.

P2 · cmd/1, the command registry

One declaration home: crates/kb-code-server/commands/registry.json (JSON so the SPA can import it natively), embedded by the server via include_str! and served at GET /api/commands; the SPA consumes a generated, checked-in web-code/src/commands/registry.gen.ts. kb-code commands doctor is a CI gate: every shipped entry names a CLI twin or none:<reason> (the gate cross-joins registry ids with the clap tree, so a twin cannot be a stale string); reserved browser chords fail the build; a key declared global may not be redeclared narrower (internal shadowing lint); Esc rows are a first-class key class with a dismiss order (innermost first) and Esc never navigates; the conflicts report is generated and v7.0 exits with zero unratified rows. Execution stays layered as kb's keymap.ts proved (global scope dispatched centrally, other scopes owned by the surface that renders them); the CM6 keymap is generated from the registry. Surfaces derived from the registry: palette (⌘K / :, prefix modes > commands, @ symbols, # files, / text, ~ rooms, ?nl semantic, $ structural; scope chip; key column; "show unavailable and why"; mutating rows route through the one ConfirmProvider), which-key overlay after ~400 ms (passive observer, never dispatches), scoped ? sheet, the rehearsal overlay (hold the leader, hints render on the affordances), transient parameter popups that show the live kb-code … line, learn mode (local-first, never feeds ranking), printable cheatsheet and manifest. Deep links ?cmd= auto-execute only entries declared read-only and side-effect-free; anything else pre-fills the palette. Presets: vim (default) / plain (no bare letters) / helix-ish, as a column, never inheritance. A day-one script is an exit criterion (below).

P3 · kbc-scope/1 and kbcq/1, one grammar

The existing search/grammar.rs (lanes @ # / ~ ~~ ?nl, filters lang: path: repo: case:) grows, never gets replaced: quoting, negation, key:a|b, and/or/parens, kind: ext: ns: sym: ent: role: pack: owner: set: review: pr: session: since: changed: by: trust: has: annot: todo: diag: finding: read: wt: frame:, structural ast:'…' (ast-grep-style holes compiled to tree-sitter queries), $name saved-scope references, without: only beside a bounding clause. One Rust parser, one generated golden-pinned TS mirror; unknown filters are warnings; the rewritten query is returned so explain and CLI show what ran. path: and every scope become pre-filters resolved to a path/blob set before lanes run. A persistent scope chip in the TopBar on every surface (s edit, S clear, pinned across navigation). Scopes have two sources with stated precedence: config [scopes] entries are read-only seeds tagged source:config, saved scopes live in sqlite tagged source:saved, a name collision is a boot error. Importers derive scopes for free from Packwerk package.yml, CODEOWNERS (GitHub's exact last-match semantics), Rails engines and linguist-generated. An agent may propose a scope (pending chip, never auto-applied). Every new filter names its lane and its latency budget against ADR-5's frozen lane budgets, or names the lanes that refuse it.

P4 · The Ladder, one carry-forward

The anchor type stays kb_core::review::Anchor (kb #6, #25: one anchor grammar). kb-code's resolver, today's review_comments::resolve_for_ps_with_content ladder (exact → fuzzy → snippet-guard → honest orphan), becomes the only resolver, lifted into working-tree annotations (which today lack the snippet guard), board cards, tour/trail steps, search-set entries, lane facts, comment-index entries and review refs. One new rung above line anchoring: symbol_id, so a comment inside a moved or renamed symbol re-lands as symbol/exact (same path) or symbol/likely (matched through a rename). Orphans are a designed, attractive state: original snippet visible, one-key re-pin, never a guessed line.

P5 · Trust vocabulary

Classes: exact / likely / candidate (with precision tiers incl. lsp-live) plus one new class, observed, for runtime-derived evidence (AppMap traces, rails-runner snapshots, Coverband hits): sha-bound, refused (not degraded) when the producing sha is unknown or not an ancestor, re-anchored through the Ladder, sorted in its own section below candidate, never a definition answer, with its own oracle test set. Resolution states are a separate axis (pinned / exact / shifted / fuzzy / orphan) and doc freshness (fresh / drifted / orphaned) is a caption on the doc card, not a badge. Display rule, two axes: class in line style (solid / dashed / dotted; observed dotted plus a glyph because it is a different kind of evidence), anchoring in one leading glyph (● pinned, ◐ shifted, ○ orphan). Convention lanes (rails-lens) stay structurally capped at likely; an ExactClaim type is constructible only by the daemon-side pre/post blob re-hash, so no manifest can declare exact.

P6 · kbc-seq/1, one sequence substrate (as a layer)

Reading sets, workspaces, tours, trails, boards and the question stack are six projections of one shape: an ordered list of anchored references (span | symbol | entity | finding | query | session | note) with a per-projection sidecar (workspace: the Desk snapshot — panes, files, lines, scroll, rail tab, drawer tabs — plus the ref it was saved at and a Markdown description; tour: step notes; trail: tree parent, typed via, dwell; board: geometry pins, groups, edges, steps; inquiry: question text, parent question, collected results). Notes and comments attach to any projection through the annotations store with a set_id, so a workspace carries both free-form ideas and code-anchored comments that ride the Ladder. In v7.1 kbc-seq/1 lands as a projection layer: one wire schema with a required projection discriminator, one mutation family kb-code seq apply -f - --projection board with the familiar names (set, workspace, tour, trail, canvas) kept as documented aliases, and a resolver over the three existing tables (reading_sets, bookmarks, canvas_sets). The physical merge is deferred to its own unit with the migration treatment (backup, epoch, rehearsal). Every result surface converts into a projection with one key; exports are Markdown, JSON Canvas with namespaced kbc_* fields, kb HTML artifact, budgeted context pack.

P7 · The Trail and the Location Contract

One total serialisable Location (repo, frame, path/sym/ent, anchor, center mode, panes, rail tab, drawer tab) with one encoder/decoder and one pure transition(from, to) → push | replace | none table, golden-pinned. The router stays react-router with the Location Contract as an interface over two adapters: the Navigation API where available (per-entry scroll and caret keyed on entry.key) and a History-API fallback; kb #31's URL-keyed scroll layer (with the ephemeral-params carve-out) is the base; the browser support matrix is stated per milestone and a Firefox Playwright project lands with the adapter. In-app Back is the browser's back; there is no second stack; Back is always plain Back. On Back, the origin step's unfollowed edges appear as non-modal chips ("from here you also had: 6 usages, 2 callers, spec/…") in the trail rail. One jumplist (Ctrl-o/Ctrl-i) whose entries carry the typed via as a label; Recent Locations renders entries as code, filterable by via kind ("definition hops only" replaces the draft's second stack).

The Ramp (one commitment gradient on every result row, list and chip): hover = scent card (≥400 ms intent delay, cancelled on movement, suppressed while the list is keyboard-driven, never on touch; keyboard users get the same card inline on the focused row); K = peek (the shipped key, nests three deep with a breadcrumb, Esc restores the exact scroll); Enter = open in the focused pane; Shift-Enter = other pane; Ctrl-Enter / o = new browser tab, trail-linked; O = new browser window (pop-out of any pane, drawer or diff file, registered in the cross-tab registry). A trail-linked tab renders "↩ from order.rb:88 (usage_of Order#total, exact)"; u pushes the origin as a Back-able entry in this tab (the destination stays one Back away) and never tries to focus another tab. Provisional panes are off by default (peek → pane promotion only, auto-pinned on the second interaction); a pane carries at most two modifiers (frame · follow · trail) in one chip row. Linked panes (follow:usages|blame|tests|previous-revision, in the URL) refresh only on subject change, never on caret drift, are suppressed while focused or scrolled in the last 2 s, and show a "stale — Enter to refresh" chip. The Trail is a server object (kbc-trail/1: typed hops search/definition_of/usage_of/caller_of/blame/why/story/review/framework/manual/agent_suggested; dwell per step, never finer) that is recorded (browser-local in v7.0, server-side from v7.4 with pause, purge and GC) or authored by an agent. Cross-tab awareness uses BroadcastChannel + Web Locks; the per-tab EventSource stays (kb-code's recorded divergence from kb #24 keeps its trigger). frame= binds a tab or pane to a commit, patchset, session or worktree with a coloured band, the only chromatic pane state.

P8 · aug-lane/1, augmentation lanes

One provider protocol generalising kb-lip and rails-lens: a lane manifest lives in the daemon's own config (never in the repo), declares id, kinds, applies-to, source kind (git | file-watch | http | claim-ingest), trust ceiling and freshness. The daemon never spawns a non-git process (the scip run precedent made a rule): exec-shaped lanes run from the CLI, kb-code lane run <lane> spawns on the operator's box and POSTs a claim payload to a loopback ingest route. Facts persist as claims (payload, tool_version, config_hash, blob_sha, produced_at, producer) with no class column; class = min(lane ceiling, anchor state, freshness) computed per request in one function, so a stale fact can never be read as fresh. Six normalised kinds (line_mark, range, symbol_fact, file_fact, edge, diagnostic); a hard cap of four visible gutter slots with one composable Facts gutter; a Facts rail section; hover facts; kb-code facts, pack --with-facts under its own sub-budget, a fact query (fact:coverage.line_pct<40 AND fact:churn.commits_90d>10) that becomes a reading set. http lanes are loopback or allowlisted; an off-box endpoint is capped at candidate and must declare it sends source off-box. kb-lip (ceiling exact, blob guard), rails-lens (ceiling likely) and DCB doclens (lane zero) are retrofitted as lanes. Lanes never gate CI and have no place for a summariser. A retention policy (facts for HEAD, the last N indexed commits and any commit pinned by a review or session) exists from day one.

P9 · The Entity

A server-side entity index keyed (repo, fqn, kind) with entity_definitions (every reopening: blob, path, range, opener form, Rails role) and entity_edges (superclass / include / prepend / extend / subclass), built by the tiered extraction and reading the app's Zeitwerk configuration (autoload roots, collapse, inflections; that read is itself a trust-classed claim and degrades to a by-directory grouping with a caption). ?ent=<fqn> resolves through the existing resolve-symbol ladder; ent= composes with @ref. Merging is only ever on root-anchored fqn plus origin (app vs engine vs gem), never on a bare name. The entity/edge/viewpoint/orphan/coupling machinery is framework-generic with Rails as the first lens; kinds are discovered from app/* subdirectories plus suffix conventions and surfaced as a proposal the operator refines.

Ideas beyond the ask

The operator asked for the orchestrator's own thinking. These are the ideas that originated in the pre-evidence notes or in the synthesis, with where they landed; the research agents' wild ideas are credited in the tracks and the evidence bundle.

  • The hunk↔turn join. kb already joins session↔commit. Go finer: match every diff hunk to the exact Edit/Write tool call in the captured transcript by its old/new strings, so "why this hunk" is the tool call plus the assistant's surrounding reasoning, deterministically, no LLM in the daemon. Two-tier per sensitivity (D9, D18). Nothing in the survey has it.
  • The arena. This operator runs codex, grok, kimi and omp builders each in a worktree on the same task. The same file across N agent worktrees in N panes with a divergence gutter, each worktree's readiness, tests and coverage facts beside it, becomes the pick-the-winner surface (Track M SHOULD).
  • One claim record. Explain cards, rejected alternatives, decisions, branch stories, trail notes and entity answers were six formats in the draft; the LLM-side critique showed they are one thing. kbc-claim/1 with a kind field and a claim register is the unification (D18).
  • Everything is a sequence. Reading set, tour, trail, board and the question stack are projections of ordered anchored references (P6). The question stack itself, the inquiry trail the human-factors research called the most-cited comprehension gap, is the fifth projection: Space ? pushes a question, answering pops to its parent, the resume card leads with the open question.
  • Inline expansion and collapse-to-outline. Click a call and its definition expands under the line, nested, collapsible: a call chain in one column. Or fold a 2,000-line model to signatures and comments and expand on demand. Both ride outline/1 (Track E MUST).
  • Hover everything, Rails edition. Column type/null/default/index from schema.rb, association targets, scope and enum values, route → controller#action, i18n key → every locale, partial → file, CSS class → its SCSS, ENV var → read and set sites, constant → value; each atom capped at likely per the rails-lens ruling (D7).

  • The refusal log and the ignorance map. Every time the instrument declines (unresolved symbol, orphaned comment, stale scip, lip refused "indexing") is recorded with its reason; aggregated per file it is a map of where the instrument's own confidence is thin, and the agent's work queue (D18, an afternoon each).
  • Weather report / brief. "17 commits from 6 sessions; new RefundPolicy (4 call sites); deleted LegacyPricer; coupling shifted; two of your questions answered; one decision contradicted" — a deterministic diff of the map, the human's landing after a gap and the agent's kb-code brief --json at session start (D18, D23).

Refusals, of principle and of scope

Of principle (recorded, binding)

  • No in-daemon LLM: every "smart" surface is deterministic or agent-authored-and-stored as a claim.
  • No editing: member tables, search sets, multi-select and boards never mutate source; a lint autocorrect arrives as a suggestion through the existing apply path.
  • The daemon spawns nothing but git; no probes (per-line, user-pinned argv with click-to-rerun) without a separate operator ruling.
  • No LLM-authored HTML as a review body (D9-a); no HTML scraping in the daemon.
  • No per-identity server state (kb-code has one identity by the v0.34 ruling); no read-tracking off the operator's box.
  • No push-based GitHub; kb-code never writes GitHub; the gh round stays agent-layer.
  • kb-code never spawns agents and never provisions worktrees; it reads what agents create.
  • No freehand drawing on boards; no theme builder UI; no tracker semantics (assignees, due dates, boards) for comment claims; no recipe user-defined functions; exec lanes never gate CI; no smartlog library; no second scroll stack; no second anchoring scheme; no second query language.

A rail tab (All, Understand, History, Review, Notes) or a drawer tab (a named result set).

Only a moldable per-entity view (Track N) and the two legacy wire names rails-lens/1 and codelens/1.

Risks

  1. Shell refactor breaks the reader. Visual baselines first, legacy route behind ?shell=legacy for one milestone, one center mode at a time, a third of the refactor budgeted for test migration.
  2. Registry drift. commands doctor is a CI gate from the first commit.
  3. Two grammars. The TS mirror is generated and golden-pinned; the tree filter and search share one parser.
  4. A wrong exact. Every new lane ships its own oracle set; convention and runtime never mint exact; ExactClaim is a type; union search waits for per-worktree verification.
  5. Visual bankruptcy. Four gutter slots, the Lane Budget, three tree slots, theme lint, a notification policy of pull by default.
  6. Claim laundering. One claim register, always beside the fact, always with a drift caption; write-time burden bounded by required cores and --tier.
  7. Surveillance shape. Attention and trails local in v7.0, later opt-in with indicator, purge and retention, aggregate-only to the agent.
  8. Loopback is not authorization. The v7.0 hardening unit lands before any new mutation surface.
  9. Feature count. MUST/SHOULD/KILL per track; a cut review at every milestone close.
  10. Every milestone is a one-way door for the volume. Backup, migration inventory, epoch bump, redeploy dry run and rollback-by-restore are a standing exit item; only tagged milestones deploy.
  11. Re-extract cost. The salt split and Ruby locals re-derive acme-app's 6.5K files through a single-worker sink; measured and recorded before deploy.
  12. Browser floor. The Navigation API adapter is capability-gated with a History fallback; a Firefox e2e project lands with it or the Chromium floor is recorded.
