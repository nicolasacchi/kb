The connective-tissue program: memory × sessions × code × artifacts

kb writes lineage eagerly and reads it almost nowhere — the program is read-backs, chain assembly, and a correction arc, not new subsystems. The weakest pair is memory↔code.

2026-08-20 · status:open · project:kb · 14 agent outputs · red-team verified · 2 map overclaims corrected

How this was made

A 13-agent workflow (2026-08-20, ~40 min, ~1.94M worker tokens, 373 tool calls) in three phases: 5 Sonnet explorers mapped the memory, sessions, code, and artifact subsystems plus a dedicated six-pair cross-join inventory; 5 Fable lenses ideated over the merged map (provenance, graph/navigation, agent leverage, human operator, contrarian/subtraction); 3 Kimi workers added outside layers — cross-pollination from other ecosystems (job 01M0FMMEAK07FRM42WDKQG3GFK), an adversarial red-team of the full idea list (job 01M0FMGR5X1T7MEK5KX95BR0CA, verify --strict = verified, 46 findings all ok), and weakest-pair wildcards (job 01M0FMFZ08H6YMRQCPBCY59MSG). Kimi reports no token usage — absent, not zero. ~75 raw ideas were reduced to the waves below.

Corrections the chain caught Two exploration claims died under verification, which is why every Wave-A item cites its file: (1) the memory explorer claimed "memory↔code has no structural join anywhere" — false: CodeRefHook's only gate excludes memory-session transcripts (crates/kb-core/src/enrich.rs:136-140); ordinary memory artifacts are scanned into code_refs today. (2) the wildcard worker claimed LineEvidence::RevRemap is "never emitted" dead code — false: doclens/resolve.rs:584 emits it as DCB-W2.A's arm 1 for docs declaring a usable kb-code-rev. Both downstream ideas were reduced accordingly.

Three theses

1 · The write–read asymmetry

Every lens independently converged on the same pathology: joins get recorded at write time and die before any read path. The catalogue, all verified: U3 provenance metas (written by SelectionActions.tsx, parsed by nothing), WhySession.kb and memory_ids (fetched by kb-code, dropped at deserialize), memory_recalls.turn_id (recorded, never projected), via_subagent + subagent_* stats (on the wire, unrendered in the SPA), session_commits.trailers (stored, only Kb-Session consulted), session_research.kind='artifact_open' (CHECK-constrained, funnel-counted, icon-mapped, zero producers), and kb-session auto-stamping (full schema+route+flag support, no writer outside kb remember). The cheapest wins in the entire space are read-back completions of writes that already happen.

2 · Unlabeled join tiers, not missing joins

The complaints that read as "missing joins" are mostly fuzzy joins rendered with exact-join authority: the atlas session polylines (substring-scan /touches cache) and the reader's Sessions tab (exact session_files) silently disagree about the same artifact; Related-Memories similarity search reads as provenance; raised-during comment joins are temporal coincidence. kb-code already has the culture fix — trust classes and the oracle-bar rule ("a wrong exact is a release blocker") — but it stops at the daemon boundary. Export the labels, not a new engine: the red-team killed the L-sized "retrofit everything" version and kept the S-sized tier chips.

3 · The loop has no correction arc and no ritual

Memory's loop is write → inject. There is no in-session way to say "this injected fact is wrong" (the missing verb), no measurement of whether an injection was used, no code-drift feedback for the weakest pair, and — on the human side — no habitual surface, so every connective feature is pull-on-suspicion. Meanwhile the recall hook updates the fleet's working beliefs every turn while operator review is fully manual: the beliefs update faster than their owner.

Wave D — the one new surface: kb context

L The recorded deferral of kb context (fresh-eyes #10 (private), "the single most cross-entity-synthesizing idea on record") named exactly one blocker: no caller. The caller exists — kb-recall.sh receives the real task text and cwd on the first UserPromptSubmit. Design: a deterministic, budgeted, provenance-annotated pack (top recall hits with score decomposition, recollect digest pointers, open comments on matching artifacts, code_refs summary), injected as scent on turn 1 ("3 prior sessions, 2 open comments — run kb context") with the agent pulling substance — which keeps R0/R3 intact without a re-ruling. The contrarian's funding condition is the acceptance criterion: kb-recall.sh, /kb-distill, and /kb-weekly must rewire onto it (deleting their hand-chained 4–6-call assemblies) or the feature reverts — one home for context assembly, not a fifth. kb sessions resume-pack folds in as a continuation preset keyed to one session id. Red-team rank #8 — ranked low only because the rewiring is unproven, which the acceptance criterion converts from risk to gate.

The frontier: novel mechanisms worth their strangeness

F1 · Kb-Memory: commit trailers M memory↔code

The strongest genuinely new mechanism found for the weakest pair. The trailer dispatcher (plugins/kb-memory/hooks/git-dispatch/trailer-logic.sh, verified: stamps Kb-Session: today) also stamps one Kb-Memory: ⟨hex12⟩ per memory minted this session; capture already persists the full unfolded trailer block into session_commits.trailers and never parses it back — add one parse arm writing a memory_commits table (own table, per the code_refs precedent). Sounds wrong for ten seconds, then inevitable: prose citations become the same exact-id trust tier the session↔commit join enjoys, entirely kb-local, surviving kb-code being unreachable. The one frontier item that earns a new table. Needs an operator ruling: memory ids (opaque hex12) land in git history — fine for private repos; make it config-gated.

F2 · era-resolved citations M artifacts↔code — endorsed reduced

Judge a doc's citations against the commit it was written at, not only HEAD. The wildcard's premise was half wrong — RevRemap is already live (arm 1 for docs declaring kb-code-rev) — so the remaining real work is: derive the era from kb_session→session_commits for the majority of docs that never declare a rev, and split the single Confirmed verdict into "correct when written" vs "still correct now". That distinction is the one every drift surface currently conflates.

F3 · unlinked mentions M artifacts↔artifacts

Obsidian's lesson: the graph you wrote is half the graph you meant. A read-time suggestion queue (the dupes/triage shape — human applies, never a hook) finding docs whose bodies contain another artifact's exact title/basename with no edges row; applying authors a real wikilink. Memories may appear as targets with an honest "cannot link from HTML memory body" note — the twice-declined ruling untouched.

Record these refusals

The contrarian lens produced six recordable non-goals; the red-team endorsed all six as-is. Each names its re-open trigger, in the project's deferred-with-trigger style.

  • No unified transcript tailers. kb's R1 digest and kb-code's loopback raw-FTS lane index different projections for different masters; a shared cursor buys a cross-daemon contract and a new wedge mode to save disk reads. Display-level linkage only. Re-open: transcript volume 10×.
  • No stored memory-of edge table. Two tiers suffice: U3 exact provenance (A1) + the similarity panel labeled as similarity. A third store rots under relocate/supersede/forget and needs all three lifecycle registries.
  • Wikilinks inside memories → permanent non-goal. Third strike: comrak sees no inline markdown inside <p>-wrapped HTML; a fix needs a third parser agreeing with two golden-pinned ones. The recurring cost is re-litigation, not the feature. Auto-expires if memories become Markdown-bodied.
  • No memory-vs-artifact dupes widening. A memory duplicating a research doc is the system working — the distilled, injectable pointer. Flagging it trains deletion of exactly the curated layer.
  • No push events for citation drift. A drift event is a persisted trust class (violates DCB verbatim) addressed to nobody. Pull surfaces + the /kb-verify sweep cover the need.
  • No daemon-side memory↔code synthesis, either direction. Code-aware triage would need kb to consult kb-code (direction violation) or persist verdicts (DCB violation); auto review→memory export puts a deterministic daemon in a judgment seat. The agent layer composes verbs that exist or cost S.
