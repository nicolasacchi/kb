Making kb’s graph earn its keep — a bench-measured degree boost, the graph report verb, and connective tissue (2026-07)

The edge graph kb already maintains turns out to be worth +0.10 Recall@1 on hybrid search at the right (small) weight, a fleet-wide audit verb that found 244 rotten edges and 478 orphans, and one unbuilt-but-fully-specified inspector line — all deterministic, all from data the daemon already computes.

Method and provenance

Four parallel code surveys (graph substrate; search pipeline + bench harness; atlas + inspector wiring; session/memory/read schemas) grounded every design decision with file:line evidence at commit 02f7eff4. A read-only prototype then measured the real fleet (22 prod corpora over the loopback API), the boost was implemented and A/B-benched on the SQ6 harness (bench/kb.local.toml daemon on :4100, warm SQ6 lance state, hand-curated gold sets bench/queries/kb-docs.jsonl — 20 English technical queries — and corpus-f.jsonl — 24 Italian queries), and the report verb was built once the fleet numbers justified it. Bench lab (all baseline/delta JSONs, daemon configs, prototype script + fleet report) preserved at /tmp/kb-graph-lab/.

Caveats declared up front: the working tree carried unrelated in-flight cascade-delete work (uncommitted cascade.rs, +600 lines in sqlite.rs) — one pre-existing test fails from that work (list_detail_marks_tombstone_when_artifact_deleted: the list entry vanishes instead of tombstoning; deletion semantics, untouched by this change). The kb-docs corpus grew 133→134 docs mid-sweep (another session shipped artifacts); the confirming runs used the settled corpus. The box ran co-tenant builds (load average 26 at peak), which polluted wall-clock latency — see latency.

The graph kb already has

Everything below rides existing machinery — the point of the exercise was that no new substrate was needed:

  • Edges: one per-kb sqlite table (src_artifact, dst_artifact, kind) (V0001__initial.sql:38-45); only kind="link" is ever written. The single writer is EdgeRecordHook (enrich.rs:391-538) — three passes per indexed artifact: artifact-id hrefs, relative-path hrefs, and Markdown wikilinks gated on a literal [[. Corpus-local by construction (invariant #29): no kb column, one db per kb, wikilinks never resolve cross-kb.
  • Full-graph reads already exist: link_pairs() (every edge, sqlite.rs:356) and edge_counts() (per-artifact (out,in) degree in one GROUP-BY, sqlite.rs:403-428 — the same map behind the gallery’s backlinks/outlinks chips, “microsecond territory” per its own doc comment). Both return unordered results; every consumer here sorts.
  • Session touches are per-kb session_files rows (V0017) with a resolved target_kb/target_artifact_id when a touched file lands in a mounted corpus. Any aggregation must collapse to the newest capture per session (invariant #11) or it double-counts — and per invariant #19, touched is not read, which is why the orphan definition below excludes touches.
  • Memory links mean three things: memory_links rows (memory→kb recall scope, V0010), the kb_session lance column (memory→origin-session), and ordinary edges from a memory artifact’s own links. Only the third participates in the edge graph — and in practice doesn’t: see F2.
  • “Ever read” comes from the history table’s kind='open' visits via reading_rollup() (sqlite.rs:812-901) — with the subtlety that a list read_override can introduce rollup entries for never-opened artifacts (last_opened_unix: None), which a strict “never opened” must filter out.

Workstream 1 — the degree boost, designed then measured

Design

The signal is in-degree only: being linked to is the corpus’s own curation judgment, while out-degree would let an index page rank itself up by fan-out. The boost is additive and scaled to the RRF regime the fused scores live in (rrf_fuse emits Σ1/(60+rank), so a top-rank arm contributes 1/60 ≈ 0.0167):

score += weight × (1/RRF_K) × √in_degree / √in_degree_max        (fusion.rs::apply_graph_boost)
  • √ not ln, deliberately: IEEE-754 sqrt is correctly-rounded — bit-identical across glibc/musl/macOS, the same op-set discipline as atlas determinism (kb-core invariant #3) — where ln is libm-implementation-defined and can flip equal-score ties across platforms.
  • Normalisation is corpus-wide (max in-degree from the full edge_counts map), so a hit’s boost doesn’t depend on which other candidates the query surfaced.
  • Placement mirrors the title boost exactly: applied to the full over-fetched pool after apply_title_boost, before filter/truncation, at both hybrid sites — single-kb (search.rs hybrid arm) and per-corpus inside the federated fan-out (before the cross-kb RRF), each corpus boosting against its own degree map. Stable re-sort preserves the deterministic fused tie order. Keyword/semantic modes are untouched — they serve as controls.
  • Reranker interaction (SQ4): the cross-encoder overwrites scores downstream, so with a reranker enabled the boost only shapes which 50 candidates enter the rerank window — composing them further is a named non-goal of this pass.
  • Flag: [kb.canon] graph_boost = 0.25 — an Option<f32> beside the SQ4/SQ5 opt-ins in KbSection, threaded through KbContext, default None = off, query-time only (flipping needs no reindex), validation warns outside (0, 4]. Ship rule as commissioned: no regression on kb bench, or it stays off — and it ships off.

Results — quality

Protocol: kb bench run (Recall@{1,5,10}, MRR, nDCG@10, 20 queries) against the bench daemon, baseline captured flag-off, deltas via --baseline. kb-docs = kb’s own docs/research corpus (134 docs, 578 edges, top hub the research index at 33 in-links) indexed three times under bge-small/base/large.

The dose-response curve is the strongest evidence the effect is real: monotone gains at 0.25 (absolute R@1 reaching 0.80 on bge-large, from 0.70), mixed at 0.5, inverted at 1.0 — exactly the signature of a genuine-but-small signal that over-boosting drowns (hub mass displacing true matches). And the w=0.25 row reproduced identically across three separate daemon boots (initial run, a confirming run after the corpus settled at 134 docs, and the final clean pair: large-model deltas +0.100/+0.050/+0.041 every time). Semantic mode deltas were exactly 0.000 throughout — a clean control proving the index and embeddings never moved.

Results — corpus-f, and why it doesn’t clear the bar

corpus-f (245 Italian docs, sparse hub-dominated graph: 177 edges, 65% never linked, the concept-map index holding 24 of the in-links) was the stress case — most gold answers are unlinked chapters, so a hub-favouring boost could plausibly hurt. Measured across two independent baseline/boost pairs at w=0.25:

  • Pair 1: hybrid R@1 +0.042, R@5 +0.042, MRR +0.032 — all positive.
  • Pair 2 (different boots): R@1 +0.000, R@5 −0.125, MRR −0.036.

Those two pairs disagree by more than either delta — because the corpus’s flag-independent noise floor is larger than both (F1: same-boot keyword flips of ±0.167; hybrid baselines varying 0.833–0.958 R@5 across boots with the flag off). Honest verdict: on corpus-f the boost is inside the noise — not a proven regression, but not a cleared win either. Under the ship rule it stays off there, which the per-kb flag makes the natural state. The general principle this pins: enable graph_boost per-kb only where a corpus-local bench shows a clean win — dense, deliberately-linked technical corpora (kb-docs) qualify; sparse index-hub corpora didn’t demonstrate benefit.

Results — latency (honest version)

Architecturally the boost costs one edge_counts() call per hybrid query — a single grouped scan the code documents as “microsecond territory” at personal-kb scale and which the gallery already runs per page load — plus O(pool ≤ 400) hash lookups and a stable sort the title boost already pays. The wall-clock measurements, however, were dominated by environment noise in both directions: flag-on measured 33 ms faster than baseline in one quiet run (srv p50 28 ms vs 61 ms) and 168 ms slower in a run taken at load average 26 with co-tenant rustc + Chromium and post-restart embed churn. No latency effect is attributable at these corpus sizes; a dedicated idle-box micro-bench is the named follow-up if sub-millisecond accounting is ever required.

Workstream 2 — kb graph, the report verb

The fleet numbers (5.8% rot, 26% orphans, four corpora with fully-stale edge sets) justified promoting the prototype to a shipped verb. Three pieces, all new files or additive edits:

  • kb_core::graph_report — a pure function build(docs, edges, degrees, opened, top) → GraphReport. Every output list explicitly sorted (nothing inherits HashMap order), no clock reads: byte-reproducible for identical inputs, the atlas discipline applied to reporting. 5 unit tests pin the semantics, including a determinism test that permutes input order and asserts identical serialized output.
  • GET /api/kb/{kb}/graph/report?top=N — gathers list_docs + link_pairs + edge_counts + reading_rollup (filtered to last_opened_unix.is_some() — asserted-read overrides don’t count as opened), reads Markdown sources from disk for the wikilink pass, and calls the pure builder. Registered above /graph/{id} (matchit static-segment priority; ids are 12-hex so report can’t collide). Pure read — never bumps the index generation (invariant #15).
  • kb graph <kb> [--top N] [--json] — human summary + full JSON, following the kb related command shape.

Workstream 3 — connective tissue in the inspector (spec)

Not built this session; fully specified from evidence, using only data the atlas already computes.

  • Definition: an artifact is connective tissue when its link edges connect it to artifacts in ≥2 distinct atlas_cluster values — “this artifact bridges clusters X and Y.” Both inputs exist and are deterministic: the edges endpoint (GET /api/kb/{kb}/edges, note-inclusive) and the per-doc atlas_cluster i16 written to lance by every recompute (seeded k-means ≤12 on the high-dim embeddings, fixed DEFAULT_SEED, xorshift RNG, no transcendentals — bit-identical across machines).
  • The one data gap: the single-doc GET omits atlas fields (they ride only projection=atlas on the list endpoint), so the Detail route’s doc has no cluster. Recommended fix: no backend change — a useQuery(["docs", kb, "atlas"]) hook over the same projection=atlas call AtlasView already makes, per invariant #23 (staleTime Infinity, SSE bridge invalidation; map atlas.recompute.complete/atlas.recluster.complete onto that key if not already covered).
  • Placement: the inspector’s Links tab (PreviewInspector.tsx), one line above Outlinks — it already owns the graph UI and already fetches the full edge set. Incidental hygiene: that tab is the SPA’s last raw-useEffect fetcher; the new hook should replace it, closing the invariant-#23 carve-out it currently squats in.
  • Labels: derived client-side as the cluster’s most-frequent tag — the exact convention AtlasView uses (AtlasView.tsx:320-331). Never persist cluster ids or labels: k-means label integers churn when the corpus changes or k moves; they are stable only for an identical corpus. Deriving live keeps the line truthful under churn.
  • Notes nuance: atlas compute includes notes (it reads all embeddings); only atlas display filters them. So a note’s cluster and its edges are available to the bridge computation for free, even though the atlas canvas never shows them.

Findings beyond the ask

F1 — the BM25 arm’s tie ordering is unstable

Observed while controlling the A/B: corpus-f keyword Recall@1 flipped 0.875↔0.708 (±0.167, 4 of 24 queries) between two runs in the same daemon boot with zero code, config, or corpus change — then flipped back. kb-docs-small keyword drifted +0.05 across a restart the same way. Meanwhile semantic deltas were exactly 0.000 in every run: embeddings and vector search are bit-stable. The signature points at equal-BM25-score ties being ordered by index-internal state (segment layout shifting under background reorganisation), which hybrid RRF inherits in damped form. Two consequences: (a) every future ranking experiment needs its noise floor measured flag-off-vs-flag-off before trusting deltas of this size — this is now demonstrated protocol, not hypothesis; (b) a deterministic tiebreak inside the BM25 arm (or at ingestion into rrf_fuse) would harden invariant-grade reproducibility a corpus at rest should have. Filed as the highest-value follow-up.

F2 — memory corpora contribute zero edges

memory-kb holds 50 memories and 0 edges. Cause: production memories are HTML artifacts, and wikilink parsing is Markdown-gated (enrich.rs:469) — so the [[cross-references]] memory prose carries never become edges, and memory connectivity exists only as recall-scope rows (memory_links) and the session column. If memory-to-memory linking should feed the graph (and the Related-memories rail), either memories become Markdown or the wikilink pass learns a scoped HTML-text mode. Left as an open question — it touches the memory-format contract, not the graph.

F3 — a quarter of the fleet is orphaned, and the orphans are recent

26% of fleet docs are never-linked-never-opened, and on kb’s own docs corpus the orphan list includes the newest deep-work artifacts (security review, code-craft review). The connective habit — linking new artifacts from an index or their neighbours — decays exactly when output velocity rises. The report verb makes the decay visible; the resurface/reading-queue work is its natural consumer.

Constraints, honoured

  • No new dependencies — zero additions to any Cargo.toml; sqrt over ln was chosen partly to avoid even libm variance.
  • Corpus-local (invariant #29) — the boost normalises within one kb (federated search boosts per-corpus before the cross-kb RRF); the report is strictly per-kb; wikilink re-resolution uses the same corpus-local ladder, golden-pinned in links.rs.
  • Reproducible — boost: pure, stable-sorted, IEEE-exact ops; report: sorted outputs, no clock, permutation-tested; bench: seeded RNG, warm-cache protocol, signed-Δ baselines all preserved.
  • Invariant budget untouched — nothing here needs a new entry; the work lives inside #15 (no generation bump on reads), #19 (touched≠read), #23 (hook pattern), #29 (corpus-locality), and kb-core #3 (determinism discipline).

Open questions

  • BM25 tie-ordering hardening (F1) — where exactly does the instability enter (tantivy segment order? background compaction?), and is a doc-id tiebreak at the arm boundary enough?
  • Should kb graph exempt by-design orphan categories (memory-session) and grow a --fleet fan-out per invariant #28?
  • Memory corpora in the graph (F2): Markdown memories, or a scoped HTML wikilink pass?
  • Cross-kb link-rot: permalink/subdomain hrefs pointing at other corpora are parseable (the share engine’s classify_cross_link grammar) but recorded nowhere; a fleet-level rot report needs a route-layer fan-out resolving against every mounted kb — deliberately out of this corpus-local pass.
  • Composing the boost with the SQ4 reranker (fold degree into rerank_hits?) — only worth benching on a reranker-enabled kb.
