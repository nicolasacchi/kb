Memory as an instrument — the big-picture upgrade map for kb memory handling and visualization

kb's memory architecture is what the field's 2026 papers say memory should be — but the pipeline feeding it leaks at five verified joints, the scoring model never learns, nothing records what the agent was actually shown, and no surface lets the operator see memory as a living population. This map fixes all four, in dependency order.

2026-08-05 · status:open · project:kb · 5-agent research synthesis

Method

Five Sonnet research agents ran in parallel (2026-08-05, workflow wf_0f4e6de2, 717k tokens, 252 tool calls): a memory-engine code map, a visualization-surface map, a whole-ecosystem audit (kb daemon memory vs Claude Code file memory vs episodic sessions vs hooks, across all harnesses), an agent-memory state-of-the-art survey (19 systems/papers, 2024–2026), and a memory-visualization state-of-the-art survey. Fable synthesized. Every load-bearing claim below was spot-verified against the repo or the live corpus before inclusion; findings carry their evidence inline.

Diagnosis — four layers of the same problem

The population is real: 245 memory artifacts in .kb-memory (224 written in the last 5 weeks), 626 captured sessions (912 MB), recall running on every prompt of every session on the machine. The system is load-bearing. The research converges on four stacked findings:

  1. The pipeline leaks — write-path and routing defects mean the engine is fed damaged input (§A).
  2. The engine computes what it needs and throws it away, at both ends — the write path destroys its own payload (titles hard-cut mid-word to satisfy a rule that is false for current code), and the read path discards its own signal (the true BM25/vector relevance score is fetched and never used; the per-hit decay curve is computed and dropped before the wire) (§B).
  3. Nothing learns and nothing is recorded — salience is write-once, decay is static, no event anywhere records that a memory was injected into a session, so efficacy is structurally unanswerable (§B).
  4. Memory is invisible — the one memory-native surface is a top-50 ranked slice presented as if it were the corpus; supersede chains, provenance, decay trajectories, injection history, and cross-kb overlap all exist in the data and appear nowhere (§D).

Why this matters for the big pictureAny grand redesign inherits these leaks. The repairs are not "quick fixes" beneath this document's ambition — they are the difference between upgrading a memory system and upgrading a memory system that is being fed truncated, misrouted, unrecorded input.

What the field knows (and where kb stands)

The survey covered Letta/MemGPT (memory tiers, sleep-time compute), mem0 (extract→consolidate pipeline, graph variant), Zep/Graphiti (bi-temporal knowledge graph), LangMem (hot-path vs background writes), A-MEM (Zettelkasten evolution — and its no-audit-trail anti-pattern), HippoRAG (PageRank retrieval), Stanford's generative agents (recency×importance×relevance — the direct ancestor of kb's rank×salience×decay), ChatGPT/Claude memory products, FSRS-6 spaced-repetition science, CoALA's memory taxonomy, memory-poisoning research (MINJA: >95% injection success), and the benchmark wave (LoCoMo, LongMemEval, MemBench, STALE).

Where kb is ahead — and should double down

A 2026 paper ("Don't Ask the LLM to Track Freshness", arXiv:2606.01435) empirically re-derives kb's exact architecture: LLM writes candidates, deterministic code aggregates and scores — +10.8pp over LLM-judged conflict resolution at 64K context, widening to +21pp at 262K. kb shipped that pattern in 2025. Every memory is a human-readable HTML file (vs ChatGPT's opaque notepad); recall is a pure, unit-tested function; supersede semantics are explicit; per-kb scoping sidesteps ACLs entirely. Do not chase LLM-mediated memory. kb's determinism is the moat — every upgrade below preserves it.

The visualization vacuum — genuinely open ground

The sharpest external finding: nobody — not mem0, not Letta, not Zep, none of the funded memory-infrastructure category — has shipped a compelling visualization of memory as a first-class object: its health over time, its provenance, its lineage, or what the agent actually saw. The closest analogs are borrowed (Anki's forgetting curves + review queue, git blame lenses, RAG-provenance debuggers). kb, which already ships an embedding atlas with Procrustes time-lapse, a brush-synchronized reflection canvas, and full session capture, is closer to this than anyone. This is a place kb can be first, not a place to copy.

Equally important negative result: the hairball literature quantifies why a whole-corpus memory graph must not be built — node-link layouts degrade past ~link-density 3 and reliably hairball past ~50 nodes/200 edges. Everything that works at scale (Neo4j Bloom, Kumu, Excalibrain) scopes to one entity or one query and expands outward. The one legitimately graph-shaped memory view is a supersede chain: 2–6 nodes.

The upgrade map — five programs in dependency order

Program A — Repair the pipeline (the feeding layer)

  • Stop the title massacre. Delete the false "recall truncates at 80" rule from kb-distill; let titles be whole sentences; teach the skill that the summary (RA4) is the injection payload.
  • Inject content, not an index. kb-recall.sh renders kb-summary (already on the wire) under each hit within a fixed byte budget; kb-wake.sh likewise. This single hook edit changes what every future session on the machine actually knows.
  • Project-aware corpus resolution. resolve_memory_kb resolves from cwd/git-root (the hooks already compute a repo key), auto-falling back to global; a one-time migration re-homes the 77 misfiled memories using the provenance already stamped on each row. This unblocks per-project /memory panels for every other project on the fleet.
  • Nudge parity + failure-aware suppression. Port the distill nudge to codex/grok capture paths; verify the prior kb remember actually succeeded before suppressing. Add SubagentStop capture (or fold sidecar digests into the parent's distill input) to stop the 79–94% subagent loss.
  • Reconcile the file memory. The false-stale epidemic is likely a platform bug (report it), but the deeper fix is one write path: mirror auto-memory writes into kb remember with provenance, and let the kb-backed wake injection be the session-start surface — one memory, not three unsynced ones.

Program B — Close the loop (the keystone program)

B1. The recall-injection ledger. The single highest-leverage build in this document. kb's session renderer already parses every per-turn memory injection as Item::MemoryInjection (sessions/view.rs:476) — it is rendered as a chip in one session's transcript and then forgotten. Walking that same parse at session ingest and emitting one row per (memory_id, session_id, turn, timestamp) — a sqlite table in invariant #11's pattern, or edges rows (kind="recalled_in") riding invariant #29 — creates, with zero new capture, the dataset that unlocks everything downstream:

  • per-memory usage history ("recalled 40× this month" / "never recalled despite salience 0.9");
  • the agent's-eye ledger ("what was injected last week, into which sessions");
  • the efficacy join — sessions already carry the V0029 substance triage (trivial|routine|substantive), so "memories injected into substantive sessions" becomes a deterministic, LLM-free memory-efficacy metric no system in the survey has;
  • the input signal for usage-reinforced decay (B2).

B2. Scoring v2 — deterministic, explainable, and it learns. Three changes, all pure arithmetic, all unit-testable like today's rerank: (1) restore the discarded true relevance score (normalized per corpus) so what actually matches the query matters again; (2) FSRS-inspired stability: each recorded injection bumps a memory's stability by a closed-form factor — larger when the memory was near its floor (Bjork's desirable difficulty, formalized) — so used memories persist and unused ones fade honestly; (3) keep the full decomposition surfaced (--explain grows two factors). This amends invariant #10's formula text — an explicit operator ruling, not a drive-by.

B3. Soft forget — one change that completes three unfinished designs. rerank already filters status == "forgotten" — a filter with zero producers, dead code from an abandoned soft-delete (memory.rs:189). Flip kb forget from hard unlink to writing kb-status: forgotten (+ forgotten-at timestamp; a --purge flag keeps true deletion available). This simultaneously: lights up the existing scorer path; makes forget traceable; re-opens the door the 2026-07 temporal-query design had to close (recall --as-of was rejected only because forget is traceless); and aligns kb with Zep's invalidate-don't-delete without importing a graph database. Pair with the already-endorsed, never-built kb memory log <id> (walk one supersede chain with timestamps) and kb diff --between (scoped verdict=ship in July, ~100 lines, unbuilt).

B4. Census route. GET /api/memory/census: a plain, uncapped, paginated scan per memory corpus (salience, decay bucket, age, pinned, links, supersedes, last-recalled). Today no endpoint lists the whole population — /memory's "N memories" header describes a biased top-50 sample (server MAX_LIMIT=50 vs the SPA's requested 100) presented as the corpus.

Program C — Lifecycle intelligence at the agent layer (auditable, never automatic)

  • Conflict-candidate detection, deterministically. An EnrichmentHook (the existing ordered registry) that on memory index flags pairs of active, non-superseded memories with high embedding similarity + shared tags as a system-generated review comment ("possible contradiction with …") through the existing kb-comments surface. Code detects candidates; a human or agent resolves via the normal reply/resolve + --supersedes workflow. This attacks the field's hardest open problem (STALE: most frameworks <10%) in the one way that fits kb: candidates surfaced, never auto-resolved.
  • Scheduled sleep-time reflection. Letta's sleep-time compute + ChatGPT's dreaming, adapted: a nightly agent pass (cron, agent layer — never the daemon) reads recent memories + session digests and proposes merges/supersedes/salience adjustments as a reviewable diff through the existing proposals lane (/inbox already renders ProposalRow, which even carries a never-rendered supersedes field). This is the anti-A-MEM: consolidation with an audit trail and a reject button.
  • Types + entities on existing rails. A kb-memory-type: episodic|semantic|procedural meta (CoALA's minimal taxonomy — kb serves both a coding agent and a general assistant from one recall surface and currently can't tell a preference from a procedure), and entity [[wikilinks]] written at distill time riding invariant #29's edge graph — memory-to-memory and memory-to-artifact connective tissue with zero new infrastructure.
  • Origin/trust tagging. Extend U3 provenance so kb remember records kb-source: fetched-web|user-dictated|agent-inference. Surfaced-never-scored, like all provenance — but visible in every recall view, and untrusted-origin writes should warn on (or require opting into) global visibility. This closes kb's one concrete exposure to the MINJA-class persistence attack while respecting the one-trust-tier non-goal.

Design rules carried from the research: reference lines on every trend (a decay curve without the floor line hides the one thing that matters); one muted trust/staleness color ramp reused across all surfaces (uncertainty viz erodes trust when it looks alarming); correlation insights in a separate feed, never bolted onto every chart (the Exist.io lesson); and no whole-corpus graph view, ever.

Program E — Prove it (rigor nobody else can claim)

  • A kb-native memory bench in CI. Extend kb bench with hand-curated deterministic fixtures modeled on LongMemEval's five abilities and STALE's conflict taxonomy: "after A supersedes B supersedes C, recall(topic) returns only A"; "recall(never-mentioned) returns nothing" (abstention); "a propagated conflict is flagged by the conflict hook". Every LLM-mediated competitor needs an expensive non-reproducible judge run to test memory correctness; kb can make it a fast Rust test suite. That is a category-level differentiator.
  • Transcript-at-rest trust review. Windows Recall's unencrypted capture DB produced a same-day credential-dumping PoC and a product recall. kb captures full session transcripts (912 MB, secrets plausibly included) as first-class searchable data, and the live-follow lane already had to go loopback-only-hard for exactly this reason. Before shipping any scrub-back timeline or wider session surface, run an explicit at-rest/redaction review of the sessions corpus.

Ranked: what is genuinely game-changing

  1. The injection ledger + agent's-eye view (B1, D2). Novel — no surveyed system shows a human what their agent's memory actually did. Unlocks three other programs. Derivable today with no new capture.
  2. Deterministic usage-reinforced scoring (B2). Takes kb from 2023-vintage static decay to the field-leading model while staying fully explainable — the upgrade every competitor can't do without giving up auditability.
  3. Content-bearing recall + pipeline repairs (A). The cheapest items on this list change what every future session knows. Everything else compounds on top of a fixed pipeline.
  4. Soft forget + lineage + as-of (B3). One meta flip completes three designs kb already wrote, and gives memory a truthful past.
  5. The health dashboard + hygiene queue (D1, D6). Anki-for-your-agent's-memory: the operator finally sees and tends the population instead of trusting it blindly.
  6. Conflict candidates + reviewable reflection (C). Attacks the field's hardest open problem in kb's uniquely auditable way.
  7. One memory across harnesses and stores (A5). Ends the three-unsynced-systems era; kb becomes the memory, not one of several.
  8. The memory bench (E1). Small build, category-level rigor claim.

What not to build (refusals, reaffirmed by evidence)

  • No in-daemon LLM — the 2026 freshness paper is direct empirical validation of kb's stance; every program above keeps LLM steps at the agent layer behind review surfaces.
  • No whole-corpus memory graph view — quantified hairball thresholds sit far below kb's scale; scoped-and-expand or matrix views only.
  • No A-MEM-style self-rewriting consolidation — no memory mutation without an audit trail and a reject button.
  • No naive time-travel while forget is traceless — kb's own July ruling stands until B3 lands; a temporal query that lies is worse than none.
  • No memory-benchmark arms race — E1 is a regression suite for kb's own semantics, not a leaderboard entry (existing non-goal, unchanged).

Decisions for the operator

Correction 2026-08-07 — this document was wrong about decayTwo claims above (in §Diagnosis and the Health-timeline row of §D) described the decay-policy floor as something a memory crosses over time — "decaying toward invisibility", "drops in 9d". That is false. Verified in code during W4: the floor is compared against raw, undecayed salience at both enforcement sites (routes/memory.rs:511, kb-core/memory.rs:472); exp(-k·age) is applied only to the ranking score. So a memory whose author-set salience is above the floor is never dropped by ageing — it only ranks lower until it stops making the top-N. The sole true evictions are an author-set salience already at or below the floor (true from day one), an explicit kb forget tombstone, and a supersede. The error originated in a research agent's summary and was propagated here unverified; the W4 surfaces were corrected to state the honest semantics before shipping. Decay is a ranking force, never an eviction.
Ratified 2026-08-05All six rulings were answered by the operator the same day: (1) full invariant-#10 amendment (relevance + stability); (2) tombstone-default forget with --purge; (3) global corpus + opt-in project corpora, misfiled rows migrated; (4) untrusted-origin writes lose the global default (tag stays surfaced-never-scored); (5) ledger = per-kb sqlite table in the sessions pattern, edges derivable later; (6) one "memory-instrument" milestone in waves W0–W5 — plan file ~/.claude/plans/time-to-start-the-dapper-seahorse.md. The questions below are preserved as the decision record.
  1. Amend invariant #10's formula? B2 changes ratified invariant text (relevance term + stability term). The budget is capped at 35 with slot #2 open; the amendment should be explicit, with the old formula retired in the same commit.
  2. Soft forget as the new default? B3 changes kb forget's contract (tombstone by default, --purge for true deletion). Traceable forgetting is also less private than destruction — a genuine trade-off to rule on.
  3. Per-project memory corpora, or global-with-links? A3's migration needs a target topology: auto-provisioned memory-<project> corpora vs one global corpus with --link scoping. (The current state — everything in kb's project bucket — is the one clearly wrong answer.)
  4. Flip global-by-default for untrusted-origin writes? C4's trust tagging can stay advisory or gate the global default. The poisoning literature argues for gating; the one-operator posture argues advisory is enough.
  5. Where does the ledger live? Sessions-pattern sqlite tables (#11) vs edges rows (#29). Edges are cheaper and light up atlas/backlinks for free; a table is cleaner for time-series queries. Decide before B1.
