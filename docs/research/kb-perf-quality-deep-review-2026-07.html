How this review ran

Ten parallel research lenses (grokclaude fanout, Grok Build headless workers) each read the repo cold with a self-contained brief: four performance lenses (sessions routes · view engine · sqlite/actor · SPA), four quality lenses (fix-now audit vs the 2026-07-06 craft review · silent failures · duplication drift · test gaps), plus build-times and tech ideas. They produced 131 structured findings; 90 passed grokclaude verify --strict (evidence re-derived from the tree). Every finding acted on was additionally hand-confirmed in source by the orchestrating session — including both P0s, whose machine verification had failed on selector grounds while the defects were real.

Fixes were implemented by four grok builders in isolated worktrees against packet briefs, test-run to green per packet, then host-reviewed hunk-by-hunk and integrated as five commits. A measured endpoint-latency baseline was captured before any change (fresh lab, 191 docs / 5 kbs / 11 real session captures; /tmp/kb-perf-lab/results/baseline-889ec81.json).

Headline defects (all fixed in this wave)

P0 · UTF-8 cap-slice panic reachable from artifact serve

QERR-1 — parse_workflow_meta (sessions/view.rs) sliced a Workflow tool script at a raw 64 KiB byte index: any transcript carrying a >64 KiB script with a multi-byte character straddling byte 65,536 panicked the view engine — inline on the axum worker for artifact serve, and as an opaque 500 for /view and /live. The same defect class was fixed in parser.rs months ago and recurred in new code. Fixed with the crate's floor_char_boundary idiom + a straddling-boundary regression test (d7fa04e).

P0 · Rules-of-Hooks violation on the live-follow path

PSPA-1 — ArtifactPane called useIsMobile() + useLiveTailPortal() inside a conditional IIFE gated on follow-mode + presence: toggling follow (or a presence change) changed the component's hook count — React's "rendered fewer/more hooks" crash, in the reader. Hooks hoisted; render gate untouched (636b5c3).

Invariant #11 violations · multi-capture over-counting

PSTOR-1/6 — three sqlite reads skipped the newest-capture predicate that every per-session read must apply (a session captured at every Stop accrues many rows): session_files_in_folder (inflates the funnel's "commented" stage) and the reverse lookups session_files_for_artifact/_basename (duplicate "sessions touched this file" edges, one per Stop). All three now apply the predicate, with a multi-capture regression test (b6a5006).

The recurrence signal worth keeping: the byte-slice-at-a-cap panic class has now appeared twice (2026-07 parser lane, then new W-wave view code), and the 2026-07-06 review's fix-now list survived three milestones nearly untouched — 8 of 10 still open at this HEAD. Verified defect lists don't fix themselves; they need a scheduled repair wave like this one.

Quality findings → what changed

  • Drift already shipping (QDUP, all strict-verified): CLI accepted --turn 5 while the server silently ignored ?turns=5 — one grammar now lives in kb_core::sessions::view::parse_turn_window, both callers delegate, grammar unit-pinned. Three SPA relativeAge implementations disagreed (10 days rendered "10d", "1w", or "10d ago" depending on surface) — one export remains. Duration chips unified on humanizeDuration.
  • Silent loss made visible (QERR-3/4): unreadable sidecars and unparseable JSONL lines were skipped bare — both now warn and count (CaptureSummary.sidecars_skipped, SessionActivity.skipped_lines).
  • Error truthfulness (QERR-2/5/6): live-lane IO failures no longer masquerade as 404 "session not found"; ensure_*_index failures return the first actionable error instead of a vaguer downstream 500; view/live join errors emit problem+json.
  • Counter casts (QERR-9): session counters read with saturating conversions instead of as u32 wraps.
  • Tests that lied or were missing (QTEST): the presence e2e asserted enabled:false with a comment claiming the live dir is never configured — global-setup had configured it since F3; the spec now asserts the true contract and seeds a live transcript. New handler-level pins: presence/live 403 for non-loopback peers (no-store, no slug/transcript leak), live truncate-fallthrough reboots the carry, presence scan edge cases, turn-id stability across a growing re-capture.

Verification of this wave

  • The builder-pipe lesson, honestly: the four builders' worktree test runs piped cargo test through tail, swallowing exit codes (the repo's recorded pipefail gotcha, re-learned) — three RW1 test assertions were in fact wrong and only surfaced at the integrated just ci gate: two entity-order pins asserted double-decoding (&amp;gt; → >) against the one-pass inverse-of-sed-chain contract both implementations actually share, and the workflow-cap test's phases fixture didn't match scan_phase_entries' phase: 'x' grammar. All three corrected in 16898b9; the P0 panic-regression pin itself passed unmodified.
  • Gate result: fmt + clippy (-D warnings) green; 41/44 workspace test binaries green in a full single run; SPA gate green (tsc, vite build, vitest 807 + new pairs tests). The 3 remaining binaries are pre-existing load-sensitive flakes in subsystems RW1 never touched, each green when run solo (kb-core lib 1499/1499 incl. all 42 atlas tests; end_to_end 318/318; notes 3/3): 6 atlas tests die under full-suite memory churn with lance's external-sort pool starved to ~400 KB ("Resources exhausted" from merge_insert — kb-core configures no datafusion memory pool at all), plus two daemon-boot polling tests (fixture-index wait, wikilink-resolution wait) that time out under the same load. Filed as a CI-infra finding in the companion backlog.
  • Endpoint latency re-measured on the same lab corpus (results/baseline-889ec81.json vs results/after-rw1.json, commit 16898b9): zero regressions, every endpoint faster — but the improvement is uniform (−47…−74% p50 including endpoints RW1 never touched), which is the signature of a quieter box, not a code-attributable win. Honest read: no regression, consistent with expectations; the N+1/batching wins target multi-capture corpora far larger than the lab's 11 single-capture sessions. A ledger payload-size delta between runs was chased to the rolling day-window crossing midnight — the batch fold is field-for-field identical to the old per-session code.
  • Playwright e2e (release build): 200/204 on the first full run; the 3 failures were bisected against a baseline-commit worktree and all three reproduced identically pre-RW1 — inherited red specs from the post-v0.31 follow-ups lane, which never ran full e2e. Repaired in 62d3a39: a stale replay expectation (predating W2's closure change), a REAL SPA bug (?turn=end cold deep-links lost the scroll message before the iframe listener existed — now delivered via the kb-probe handshake like ?sec=), a live-tail spec asserting an open turn's text under the TurnClosed-only wire (confirmed by hand-polling /live), plus a fourth latent flake (the new 1s presence snapshot could serve the panel a stale-empty set). 25/25 across the affected spec files after repair; vitest 807/807.
  • Wire-behavior deltas shipped knowingly: ?turns=5 now filters (was no-op); live IO errors return 500 problem+json (were 404); SPA age/duration labels unified (drift table in the B4 commit); presence responses may be up to ~1s stale (TTL snapshot).
