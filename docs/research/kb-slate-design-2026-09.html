kb slate — the per-project blackboard for agents: design of record (September 2026)

A slate is where a project's working state lives while it is in play: who is on what, what is blocked, what was tried and failed, what nobody has answered. Every harness session on the box reads it as one small digest and writes to it with one verb family. It is deliberately not memory, not a lock, not a chat, and not a document anyone edits. Amended 2026-09-04: the board is erasable, its visible surface is finite, and every visual device is a rendering.

1. The claim

Two different things hide under the word "blackboard". One is a coordination board: who is on what, contested claims, handoffs between concurrent agents. The other is a thinking surface: a place to park hypotheses, partial results, open questions and dead ends that are too raw for memory and too valuable to die with the session. This design builds both as one log with one vocabulary, because on this box they are the same artifact: the kb-code v7 plan's Status section on 2026-09-03 already contained a take ("IN FLIGHT: A2 hardening (opus, v70-a2, resumed twice)"), a done ("LANDED on main: A0 cfc47c1a"), a dead end plus a warning ("its e2e was killed by the harness under load and NOT relaunched"), a decision ("RATIFIED by the operator") and an unacknowledged handoff ("Queued behind contention: A3 server half + A8"), all hand-written by one session with no per-entry author or time, invisible to every other harness.

The slate is the daemon-owned, append-only, provenance-stamped version of that section, keyed on the project rather than the milestone, readable and writable by all six installed harnesses through the shell. Its boundary with memory is promotion: memory holds what is true, the slate holds what is in play, and a post leaves the slate by being promoted to a memory, a note or the plan, or by being dropped.

NameThree independent design sketches converged on slate, because board (JSON Canvas sidecar), desk (kb handoff and kb-code v7 P1), room (kb-code Review/PR Room), inbox (twice), blackboard (grokclaude's job root), corkboard, canvas and workspace are all occupied in this repo or its siblings. A slate is what you chalk working state onto and wipe when the job is done; "clean slate" puts expiry in the name.

3. Operator rulings (2026-09-03 and 2026-09-04)

  • Build both halves (thinking surface and coordination kinds) as one log. Parallel sessions on one project are real here.
  • No zero-code experiment. Build directly.
  • Daemon-owned storage. If the daemon is down there is no slate. Not in-repo files.
  • Take rule: refuse a second live take on the same subject; --anyway overrides and marks both contested. Never a lock on the tree.
  • Milestone 1 scope: everything, including the SPA page (SL0–SL5; SL6 added 2026-09-04).
  • Topic default: untopic posts are allowed and land in a general lane; the digest header always shows every topic's now line.
  • The slate replaces the plan file's Status section. The plan keeps Context through Decisions.
  • Name: slate.

Rulings of 2026-09-04: the board

The operator's second ask: treat the slate as a blackboard, so agents can remove and change old things, and consider what a blackboard affords beyond text: drawings, emoticons, bigger and smaller text, location, grouping. Then: whether the same devices compress the memory system's injected knowledge without spending more tokens. The evidence pass (two researchers, one code reader, one skeptic; the skeptic refuted all eight elements of the first draft and each was replaced by the fix that survived its own attack, see Lineage) produced the shape below. The operator ruled to fold everything in and to have an implementing agent build the whole of it from this document.

  • Remove and change are real, and both are attributed posts: drop #n removes, edit #n supersedes. No post is ever rewritten in place (D17).
  • The visible surface is finite; the ledger is not. A post never fails for space. The response names what it pushed off the digest (D18).
  • Every visual device is a rendering of fields the post already carries. The SPA board gets emoji, colour, size, position and drawings; the injected digest gets plain words and order (D19–D21).
  • Nobody sizes their own writing. Emphasis is derived: the always-whole set, the operator's pin, other sessions' marks (D20).
  • Crossing out is a tried post, never a ghost with a lifetime (D22).
  • The memory recall line gets the same treatment as a separate track inside this milestone: cut scaffolding, depth by rank, order measured before it moves (D23–D24).
  • Build contract: an implementing agent builds SL1–SL6 from this document and the plan file; nothing recorded here is re-litigated (Build contract).

4. The spine

Entities

A slate is one project: identity <slug> = basename of the git main-checkout root resolved through git rev-parse --git-common-dir, the exact derivation kb recall --scope auto already uses for memory-<slug> (crates/kb-cli/src/commands/memory.rs:1570-1672) and the one grokclaude uses to root .grokclaude/ so linked worktrees share one blackboard. A Claude session in ~/project/kb, codex exec -C the same repo, and an omp worker in ~/tmp-tests/v70-a2 all resolve to slate kb. Outside a git checkout --slate <name> is required; there is no fleet-wide default slate, because a global board is the contamination result. The slug is validated daemon-side with the KbName grammar ([a-z0-9_-]{1,64}, crates/kb-core/src/types.rs:14-32) before it touches a path.

A post is immutable and sequence-numbered per slate; the board it renders is mutable through later posts (surface mutation). Every kind carries the same attributes (Hearsay-II's rule that hypotheses at every level share one record shape):

{ "seq": 55, "id": "e_3fa19c2b7d04", "at": 1756930920,
  "kind": "take", "line": "crates/kb-server/src/review_gate.rs — A2 bearer graduation",
  "body": null, "topic": "v7", "subject": "crates/kb-server/src/review_gate.rs",
  "refs": ["path:crates/kb-server/src/review_gate.rs:88", "session:8f2a…"],
  "re": null, "supersedes": null, "pin": null,

            "cwd": "~/tmp-tests/v70-a2", "origin": "agent",
            "user": "alex", "job_id": null } }

line is the only thing the digest shows (≤200 chars). body (≤2,000 chars of Markdown) is unfolded by kb slate show. refs (≤8) are typed pointers: path:<p>[:line], kb:<kb>/<id>, mem:<id>, session:<sid>, job:<ulid>, commit:<sha>, post:#<n>, plan:<file>#<anchor>. Bodies are references, not transcripts. Status is never a column: it is derived at read time from later posts (a done #55 closes take #55, a drop #12 tombstones warn #12, a post with supersedes: 60 replaces found #60 on the digest, a mark #60 raises its mark count, a human mark --pin #60 pins it, a newer now supersedes the old) and from silence. The projection therefore carries per post the derived fields marks, pinned, superseded_by, dropped_by, tier and contested; none of them is ever written.

Provenance is the beat tuple every hook already carries (BeatBody, crates/kb-server/src/routes/sessions.rs:6096-6116): harness validated against kb_core::sessions::HARNESSES (already six members including omp, constants.rs:29), session_id (the transcript's own id, the canonical join key of invariant #11, so kb why and kb recollect can answer who posted this and what they were doing), model when the harness supplies one, cwd, origin ∈ agent|human|import|unattributed (client-declared, never verified; see the rules matrix), and user from the Identity that auth_bearer already inserts. A post with no resolvable session id is accepted and stamped origin: unattributed; it is never refused (one trust tier).

There is no in-place rewrite, no move (position is derived, below) and no link op (a reference is a --ref post:#n or the words "see #n" in the line, which the evidence rates more reliable than a bare id field). A drop or edit that touches another live session's coordination post is friction, not an ACL: the record says who did it and the affected session is told. The blackboard's "erase wars" have a witness.

The finite surface. A blackboard is finite; the ledger is not. The visible digest keeps the ratified character budgets (6,000 / 2,000 / 1,500) and fixed section shares, and a post never fails for lack of room. Instead the append response carries displaced: [{seq, kind, line, age_secs}] (the first five, section-then-oldest, with displaced_total), the posts that the new one pushed out of the default digest (oldest-first inside its section, never a NOW, WARN, pinned post or unacknowledged HAND). The CLI prints them as pushed off the board: #41 idea "…" · #38 found "…" — kb slate drop/edit to tidy, or open --all. A session with more than eight undropped found/idea posts on the slate gets the same list on every post it makes (a nudge, never a refusal). Tokens are never counted: the daemon links no tokenizer and Claude's is proprietary, so every budget is characters.

Topics

Every post may carry a topic (a milestone slug such as v7, perf, slate). now is per topic. A session declares its topic once with kb slate open --topic v7, which writes ~/.cache/kb/slate-topic-<sid>; later posts by that session inherit it unless --topic is given. Posts without a topic land in the general lane. The digest header lists every topic's now line, which is the cross-milestone view nobody has today and the reason three milestones can share one repo safely.

Take liveness, derived and never written

For each open take the daemon computes, at read time, kb_core::sessions::live::derive_state(Holder::Agent, last_activity, now, source, &LivePolicy::default()) (crates/kb-core/src/sessions/live.rs:215-248) where last_activity is the latest of the take's own timestamp, the taking session's last beat in the live registry (LiveRegistry::snapshot, kb-server, source Hook), and that session's last post on the slate. Working → live; Stalled (silent ≥ STALL_AFTER_SECS = 45 min) → stale?; PresumedEnded (silent ≥ ABANDON_AFTER_SECS = 8 h) → expired, no longer blocks a new take; a done or hand on the subject → Finished. The constants are imported from crates/kb-core/src/sessions/constants.rs:82/108, never redeclared. A take whose session the registry does not know (Codex, Kimi and OpenCode until their beats are wired; every session after a daemon restart) is labelled with Confidence::Presumed and derives from posts alone. Nothing is ever auto-closed: silence cannot tell nobody-cares from everyone-waiting.

Contested takes

Under the per-slate lock, a take whose subject matches a live, non-finished take (exact normalized string, or a path-prefix relation such as crates/kb-server/ versus crates/kb-server/src/review_gate.rs) is refused with 409 (the existing Error::Conflict, problem type urn:kb:errors:conflict, title slate-taken; no new error variant) carrying the holder's line, harness, age and liveness. A refusal is the one moment a model reliably reads the other session's line. --anyway appends anyway and the projection flags both contested for the agents to sort out. Semantic matching is deliberately not attempted: Corkill's ad hoc integration problem stays in the agent layer.

5. The digest

kb slate open is the one digest verb. Everything else (hook lanes, the SPA, the context-pack count) is a presenter over the same pure projection, mirroring the session-view/1 engine-plus-presenters rule of invariant #11. Ordering is fixed and status-driven, never scored, and reads as "what would change your next action": (0) header and the untrusted-data sentence; (1) NOW per topic; (2) WARN; (3) HAND unacknowledged; (4) ASK open, your own asks with new answers first, then others' oldest first; (5) TAKE live and stale with owner, age, liveness; (6) FOUND and IDEA newest N; (7) TRIED count and newest three; (8) per-section "…N more, not shown" in exactly kb context's truncation wording; (9) the echo line: every NOW line repeated verbatim, without author or age, as the last line(s) of the block. Answers, done'd items, dropped and superseded posts are not in the digest; kb slate show #n unfolds a thread with bodies (DeLM's three-tier unfolding).

Rendering rules (the pure projection owns them; every presenter obeys them): a line is whole (own line, kind word in capitals, wrapped at the budget's width) when it is a NOW, a WARN, an unacknowledged HAND, a pinned post, a post with two or more marks, or a contested TAKE; every other line is folded (#n [who age] text, run in with · separators, section header carrying (shown of total · dropped)). Inside a section the order is pinned first, then marks descending, then newest first; the header's untrusted-data sentence ends with the one legend the digest has, [pin] and +n. The last line(s) of every non-empty digest are the NOW lines repeated verbatim without author or age (the echo line), so the single most action-changing fact sits at both edges of the block; the echo is included in the budget and is the last thing truncation removes after NOW itself. A superseding post carries (was #n); a dropped or superseded post never renders outside --all and history. Marks render as +n after the author tag. No emoji, no bold, no capitals beyond the kind word: every one of those is a rendering the SPA board applies from the same fields (The board).

Budgets follow the smallest hook caps on the box (Codex about 2,500 tokens per hook message; Grok 10,000 characters per PreToolUse; Codex and Kimi 32 KiB instruction chains): open defaults to 6,000 characters, the session-start hybrid injection to 2,000, the per-prompt delta to 1,500 and only when non-empty. Sections are budgeted fixed-share (NOW and WARN always whole; HAND 20%, ASK 20%, TAKE 20%, FOUND/IDEA 25%, TRIED 15%; unused share flows down) and truncation drops the oldest in a section, never a NOW, WARN or unacknowledged HAND. --json carries <section>_total, <section>_truncated and budget_exceeded, the CT-D1 contract. Budgets are characters, never tokens: the daemon links no tokenizer, Claude's is proprietary, and the same bytes tokenize differently on Kimi and GPT, so a token budget would be a character budget in costume. Room is never a reason to refuse a post (D18); what a post pushes out of the default digest is returned to the poster as displaced, and the pinned set plus NOW, WARN and unacknowledged HAND are never displaced.

The append response is the poster's only feedback loop with the finite surface, so it carries more than the post:

{ "post":      { "seq": 66, "id": "e_9c2f4a17b3d0", "kind": "found", "line": "…", "topic": "v7", "prov": { … } },
  "displaced": [ { "seq": 41, "kind": "idea", "line": "cache tokens client-side", "age_secs": 86100 } ],

Neither field ever blocks the write.

6. Decisions

Numbered so the plan file and the milestone commits can cite them. Reversals of recorded rulings are named as reversals.

D1 · One log, both halves
The thinking surface and the coordination board are one append-only ledger with one vocabulary. The coordination-only cost to the daemon is one conflict check and one liveness derivation.
D2 · Daemon-wide storage, one slate per project
Truth is <state>/slates/<slug>/ledger.jsonl plus meta.json, keyed on the project slug, not on a corpus. Not per-kb (a project maps to several corpora and not every project has one); not sqlite (schema-epoch and refuse-boot coupling for no coordination gain); not an in-corpus artifact (a hot write target for the watcher and last-writer-wins on whole-file rewrites).
D3 · Unindexed by construction
No lance row, no BM25, no atlas point, no reading progress. Slate text never enters kb search or kb recall. The only path from a slate into memory is an agent-layer promotion.
D4 · A second live take is refused, with an override
409 naming the holder; --anyway posts contested; --over reclaims stale. The killed file-claims registry stays killed: a take never consults or gates the filesystem.
D5 · Liveness is derived at read time from beats or posts
The desk's recorded refusal ("the daemon has no clock acting on content") is preserved: nothing expires on disk, no sweeper, no TTL column. The ratified 45-minute and 8-hour thresholds are reused, not redeclared.
D6 · Twelve verbs, five families, no decision, no reply and no in-place edit kind (amended 2026-09-04)
Decisions promote to memory; replies attach under asks; chatter stays in transcripts; mark joins housekeeping beside drop; a change is a superseding post (D17).
D7 · Hybrid injection, pull for substance
At session start and after compaction: now lines, warnings, unacknowledged hands and answers to the session's own asks in full, counts for the rest. Per prompt: a delta only when the session's cursor is behind. The context pack's scent line gains a count; there is no fifth lane, because one home per action.
D8 · The operator posts directly (reversal of the 2026-07 "comments remain the human channel" stance)
Posts stamped origin: human render as [you]. The war-room incident-commander model: now, warn, ask, drop, occasionally take; and the two devices only a human post carries, pin and the friction-free drop. Human posts are still data to an agent, never consent.
D9 · Topics are optional, now is per topic
Untopic posts go to a general lane; the header always shows every topic's now line.
D10 · The slate replaces the plan file's Status section
The plan keeps Context, Scope, Architecture, Phasing, Decisions, Risks, Verification, Critical files. Status is "see kb slate open --topic <milestone>"; the orchestrator posts now/done/warn; the distill skill writes a dated summary back at tag time.
D11 · Session id: explicit first, shared marker last
--session-id > KB_SESSION_ID > ~/.cache/kb/current-session. The marker is one file overwritten by whichever session's hook ran last; on 2026-09-03 it held the PERF worktree session's id while this session was writing. Hooks always pass the id they have from stdin.
D12 · Amend invariant #6, no slot 36
#6 becomes the daemon-owned sidecar-ledger family (.review/, .attachments/, .proposals/, slates/), each under its own lock, mutated only through routes and CLI, never hand-edited, never indexed as truth. The LSC precedent (amend #11 rather than add) is followed.
D13 · Tidy and distill are skills, never daemon logic
The daemon flags only what it can detect structurally (contested takes, hands unacknowledged over an hour, asks with answers but no done, caps). Dedupe, merge and promotion judgement are /kb-slate-tidy and /kb-slate-distill.
D14 · Push is deferred
Delivery is pull at the next prompt boundary everywhere. True push exists only for omp (extension subscribed to SSE, pi.sendUserMessage) and OpenCode (session.prompt with noReply) and is a later opt-in adapter.
D15 · Beats for Codex, Kimi and OpenCode ship in this milestone
The installers and README recipes exist but are not live; wiring them makes take liveness honest on five harnesses of six. Grok stays "unknown" and labelled.
D16 · The dispatcher, not the worker, speaks slate for headless jobs
grokclaude/ompclaude/kimiclaude/codexclaude prepend the digest to the brief, post a take on spawn, and on reap import report.json findings, questions and decisions as posts with origin: import and job:<ulid>. Kimi and omp workers may additionally post live (their bwrap sandbox keeps loopback); Codex and Grok workers cannot.
D17 · Erasure is an attributed post, never an in-place edit (amends the "no edit verb" sentence, 2026-09-04)
Remove = drop #n, change = edit #n (a same-kind post with supersedes: n), circle = mark #n, pin = the operator's mark. Each is a new sequence number, so every cursor replays it; the ledger stays append-only and the single-daemon sequencer is the only merge rule (no CRDT). Dropping or editing a live other session's now/warn/take/hand needs --anyway and is reported to that session in its next delta. No rewrite, no move, no link op.
D18 · The visible surface is finite in characters; the ledger is not; a post never fails for space
The ratified character budgets and fixed section shares stand. The append response names what the new post pushed off the default digest (displaced) and nudges a session past eight undropped found/idea posts; tidy stays a skill (D13) and nothing expires (D5). No token-denominated budget: the daemon has no tokenizer.
D19 · Visual devices are renderings; the injected digest is plain words and order
Emoji, colour, size, position, drawings and strikethrough exist on the SPA board, derived from the post's fields (kind, status, pinned, marks, age, liveness). The digest every harness reads uses kind words, one ASCII marker ([pin]) restated in its header, a mark count (+n) and the echo line. No glyph legend anywhere in injected text.
D20 · Emphasis is derived, never self-rated; no weight field, no region field
Whole-line rendering is earned by kind and status (NOW, WARN, unacknowledged HAND, contested TAKE), by the operator's pin, or by two or more marks from other sessions. Sections derive from kind plus status; topic is the only authored grouping. An author cannot make their own writing bigger.
D21 · Drawings: arrow chains in the line, a mermaid fence in the body, sandboxed on the board; no sketch kind
Any post's body may carry one ```mermaid fence; the board renders it inside a sandboxed frame and the injected text never inlines it. Bodies and lines containing box-drawing characters (U+2500–U+257F) or a %%{ directive are refused 400 no-ascii-art. Linear arrows (a -> b -> c) belong in the line.
D22 · Crossing out is a tried post; no ghost with a lifetime
A dead end is tried "…" --failed "…" naming (was #n) when it retires an idea or found. Dropped posts leave the digest at once and live in --all/history; nothing is kept "for N days", which would be the TTL D5 refuses.
D23 · The memory recall line is cut, deepened by rank, and its order is measured before it moves
The per-hit (id …, read N% — stopped at …) parenthetical goes (the machine marker already carries the id once); the freed characters fund a longer summary on the top hits while the bottom two keep only their title. The cut and depth by rank ship as the v2 default; the order (v2-last) and any typography ride the KB_RECALL_LAYOUT switch and become default only on a harness win; the marker gains pos=N so the recall ledger can see position from the first day.
D24 · The order-probe harness gates position and typography on both surfaces; kb bench cannot
kb bench measures retrieval over ids (Recall@k, MRR, nDCG), never model behaviour. Injection order and emphasis are judged by an agent-layer probe that puts a real pack where a hook puts it and asks a question only one hit answers, across two models. Its written result is the gate for any later change to the section order, the echo line or the recall layout.
D25 · The board is a second presenter over the same projection, plus bodies; the operator posts from it
/slates/:slug renders the materialized state (sections, topics, marks, pins, liveness, drawings) from GET /api/slates/{slug}?view=board, subscribes to slate.updated, and carries the composer and the drop/edit/mark/pin actions with the same friction rules as the CLI. It adds no fact the CLI cannot show; it adds every visual device the CLI refuses.

7. Storage

The proposals queue is the template (crates/kb-server/src/routes/proposals.rs: own dir, own per-kb AsyncMutex via KbHandles::proposal_lock_for at state.rs:983, own schema string, fleet fan-out, two SSE kinds, zero sqlite) with two deliberate deviations: the store is daemon-wide (one dir per slug under <state>/slates/, accessors slate_dir, slate_ledger_file, slate_meta_file added beside tombstone_era_file in crates/kb-core/src/paths.rs:244), and the ledger is JSONL rather than one JSON per entry because ordering is the semantics (cursors, deltas, supersede chains).

  • Lock. KbHandles::slate_locks: Mutex<BTreeMap<String, Arc<AsyncMutex<()>>>> and slate_lock_for(slug), the review_lock_for shape (state.rs:969-990). Every mutation: lock → read meta.head_seq → mint seq+1 → append one line with OpenOptions::append and fsync → write meta via fsx::write_atomic → emit slate.updated. The std guard never crosses an await (#15). Implementation choice for SL2: a slate_registry::SlateRegistry on KbHandles (the LiveRegistry precedent, state.rs:781) that holds the per-slug async lock and the cached head_seq, so the lock and seq minting live in one place; the std mutex on the map is for get-or-insert only.
  • Ids. e_<12 hex> minted in kb-core with review::short_random_hex() (the c_/r_/a_/l_ primitive, review.rs:1281); pinned as lowercase hex so it can never be confused with ErrorId's e- base32 form.
  • Meta. { "schema": "kb-slate/1", "slug", "created_unix", "closed_unix": null, "head_seq", "generation": 1, "rotated_from": null }. A schema mismatch refuses like review::load. The revision token is head_seq, not an mtime-dependent sha.
  • Reads scan the file and never lock; a 2,000-post slate is about 1 MB and projects in under a millisecond.
  • Caps are daemon-enforced 413s with a reason, never silent truncation: line ≤200, body ≤2,000, refs ≤8, live takes per session ≤3, open warns ≤5, open asks ≤20, open hands ≤10, posts per session per minute ≤6, ledger ≤2,000 posts or 2 MB, past which appends are refused 413 slate-full until rotate (archive the ledger as ledger.<gen>.jsonl and bump meta.generation; one directory per slug, see the rules matrix). A slate that outgrows a working-state budget has become a document and should be distilled, not grown. Marks: one per (session, target), a repeat returns the existing post. The found/idea nudge threshold is eight per session and the displaced list is capped at five, both constants in slate.rs.
  • Tombstones, supersedes and marks. drop, edit and mark all append; the projection builds three maps first (dropped set, supersedes map newest-wins, marks per target with the pin flag from the newest human mark) and filters, exactly as memory.rs:693-694 filters forgotten memories. A post that supersedes a dropped post is itself hidden; a mark on a hidden post counts nowhere. Only DELETE …?purge=true (loopback-only) removes a directory.
  • Registration. There is no central sidecar registry today: kb backup copies only the index, lance and .review/ (crates/kb-cli/src/commands/backup.rs:134-139; .attachments/ and .proposals/ are already unbacked), kb reset --all removes .review/ only (reset.rs:44-61), and DELETE /api/kb/{kb} drops storage only. The slate adds an explicit daemon-wide slates/ clause to kb backup and kb restore; kb reset never touches slates, since they are not per-kb; purge is the sole deletion path. No generation bump: the slate never touches the storage actor, so #15 and the three artifact-id registries of #2 are untouched.

The pure engine lives in kb-core: slate::project(lines: &str, now_unix: i64, policy: &LivePolicy, presence: &[Presence]) -> SlateDigest plus project_append/project_finish for the delta, with no clock, no I/O and no registry access; the route passes a presence slice extracted from LiveRegistry::snapshot. Goldens are crates/kb-core/tests/slate_fixtures/*.jsonl (invented strings only, the sessions-fixture rule) with an equivalence test across chunk sizes and insta snapshots of the rendered digest, the sessions/view.rs conventions.

Because a later post can hide an earlier one, the incremental delta is not purely additive: project_append emits, beside new lines, hide entries ({"hide": 60, "by": 65, "reason": "superseded"|"dropped", "who": "claude/4b7e", "why": "…"}) for every post the appended batch removed from the shown set, and project_finish folds them, so a delta consumer and a full projection agree (the chunk-equivalence golden covers drop and edit chains, marks, pins and the echo line). Validation is pure too: slate::validate_post refuses a line or body containing any character in U+2500–U+257F or the substring %%{ (400 no-ascii-art), an ask without a trailing ?, a found without a ref, a mark on the caller's own post, and a pin from a non-human origin. The displaced list is slate::displaced(before: &SlateDigest, after: &SlateDigest) -> Vec<Displaced>, a set difference over shown seqs, computed by the route inside the lock.

8. Security posture

  • Routes ride auth_bearer, mounted beside /sessions/beat and /sessions/live-status (router.rs:448-449, layer at :909), deliberately not loopback-only, so the SPA at kb.example.com behind Authelia works. A non-loopback caller gets the same posts through the forced-scrub floor redact_for_non_loopback uses (routes/sessions.rs:6431-6445): cwd collapsed to its basename and nothing else: lines and bodies keep their own 200/2,000 caps, since re-capping at OUTCOME_WIRE_MAX_CHARS (240) would truncate every body and every sketch at kb.example.com. Cache-Control: no-store.
  • Purge is loopback-only, checked inside the handler like presence (router.rs:434-437).
  • One trust tier. Any identity may done, take-over or close any post, and drop or edit any post whose author is not a live other session; the record says who. The two frictions (--anyway for a live other session's coordination post, and pin reserved to origin: human) are the human-versus-agent role split kb already has (author: you|claude), not an ACL: no owner-only edit, no per-agent permission, and an agent that wants a pin asks the operator on the slate.
  • Posts are untrusted data when read. The digest header says so in a fixed sentence; every line carries author and harness; human posts are marked [you] and are still data, never approval. This is a prompt-layer defence and the design does not pretend the store can authenticate content.
  • Session ids are attribution, never validated against the registry (D11). A missing id is stamped unattributed, not refused.

13. Lifecycle

  • Aging is displayed, never acted on. Every digest line carries an age bucket; takes carry live/stale?/expired plus the owner's registry state when known; hands render "unacknowledged 3h"; asks render "asker ended" when the asker's session is presumed ended so anyone may done them. No sweeper, no retention tick.
  • Promotion, lessons live once. kb slate promote #n --to memory|note|plan is a CLI composition: it runs kb remember … --link <slug> --session-id <sid> (or kb notes append, or appends a line to the plan file named by --plan <path>, default $KB_PLAN_FILE) and posts done #n "promoted → mem <id>" so the slate keeps a pointer. The daemon never authors the memory text.
  • Tidy and distill are skills. /kb-slate-tidy reads open --all --json, proposes drops for noise, --supersedes merges for near-duplicate founds, done for asks whose asker ended, and reports as ordinary posts. /kb-slate-distill <slate> reads a closed or rotated slate and writes one to five memories (decisions, and the tried dead ends with reasons), a narrative note, and dated plan-file status lines. kb slate doctor lists what the daemon can flag structurally.
  • Closing. close "<final now>" freezes the ledger (posts refused with the close time); a closed slate leaves ls after 30 days of display; purge is the only hard delete. Project slates live for weeks and rotate at the cap; topic slates are not separate stores, so a milestone "closes" by its distill.
  • Metrics without a benchmark. kb slate stats counts hands acknowledged vs expired, takes done vs expired vs contested, asks answered, tried-echo hits on take (duplicate work avoided), posts per harness and per session. Fewer abandonments, not speed, is what to watch.
  • Erasing has a witness. A drop or edit of your post shows up in your next delta with the actor and the why; a drop or edit of a live other session's coordination post needs --anyway; history lists every removal. The board stays wipeable without the erase wars a blackboard cannot audit.
  • The surface tidies itself through feedback, never through deletion. Every append returns what it displaced; a session past eight undropped found/idea posts is nudged on every post; /kb-slate-tidy reads history and the displaced lists as its worklist. Nothing is removed by the daemon (D5, D13, D18).

17. Refusals

Of principle (recorded, binding)

  • No lock on the tree. No kb claim <path>, no kb who, no heartbeat store of its own, no enforcement outside the slate. The 2026-07 rejection stands.
  • No in-daemon LLM. The projection is a sort; tidy, distill, dedupe and summaries are skills.
  • No CRDT, no multiplayer editing. One sequencer, one append-only log, no merge, no in-place edit (change is a superseding post).
  • No daemon clock acting on content. No sweeper, no TTL, no auto-close, no auto-release.
  • No indexing. Never in search, recall, atlas or reading progress.
  • No new invariant slot. #6 is amended.
  • No per-agent ACL, no private lane. One trust tier; the operator's private thinking stays in the plan file.
  • No MCP server. The shell is the protocol; the three-condition trigger is not met.

Of the board amendment (2026-09-04, recorded, binding)

  • No in-place rewrite, no move, no link op. Change is a superseding post; position is derived; a reference is a ref or prose.
  • No token-denominated budget. The daemon links no tokenizer; Claude's is proprietary; budgets are characters.
  • No refusal because the board is full. The ledger cap is a lifecycle 413 slate-full whose remedy is rotate, not a board-full refusal. The refused post would be the warn from the session with nothing of its own to erase. Feedback (displaced, nudge) instead.
  • No region field, no PARKING. Sections derive from kind and status; a second post-time axis is the thing six prompt styles get wrong.
  • No weight field. Self-rated importance inflates; emphasis on frontier models is noise; emphasis is earned by kind, pin and others' marks.
  • No emoji or glyph legend in injected text. Two to three tokens against one for the word, more on Claude's tokenizer, and the legend is not live on four of six harnesses. Emoji live on the board.
  • No sketch kind. A fence inside any body, sandboxed on the board, never inlined.
  • No ghost lines with a lifetime. A lifetime is a TTL (D5). Crossing out is a tried post.
  • No ASCII art. Box-drawing characters and mermaid directives are refused at validation.
  • On the recall line: no typographic salience, no grouping by type, no superseded ghost line, and no order flip without the harness verdict; kb bench is not the instrument.

Of scope (this milestone)

  • Push delivery into a running session (omp and OpenCode adapters later).
  • Semantic take matching and admission verification of findings (kb-code's doclens could later caption code-citing founds grounded or ungrounded, computed at render and never persisted).
  • Read acknowledgement beyond the served cursor.
  • Multi-machine slates (one box, one sequencer).
  • Anchored comments on posts (the post is the conversation; threads are answers and --re).

18. Risks

  • Adoption. If the instruction paragraph does not make agents take, tried and hand reliably, the slate is an empty room and the plan file stays the truth. Mitigation: D10 removes the double-write; the refusal on take is the one forcing function; stats make silence visible.
  • Fail-open hooks under load. On this IO-bound host hooks time out during builds and exit 0 with nothing; a session can believe it read the board when it did not. Mitigation: the cursor is client-side and the CLI rewrites it only after a successful read; the paragraph's "run kb slate open first" is the floor; the delta call inside kb-recall.sh must stay under about 2 s so it never costs omp's 24 s budget.
  • Stale liveness on beat-less harnesses until D15 lands; Grok stays a flag. Mitigation: honest labels, and "any post renews".
  • Misattribution from the shared session marker (observed). Mitigation: D11; hooks pass the id explicitly.
  • Worktree slug fragmentation if a hook re-implements the slug in bash. Mitigation: the CLI derives it from the common dir; a hook test pins a worktree case.
  • Coordination curse. Vague or ill-timed posts hurt more than silence. Mitigation: the posting rule, caps per minute, the tidy skill; measure abandonment and duplicates, not volume.
  • Cross-milestone contamination when three milestones share one repo. Mitigation: topics, per-topic now, section filters by topic in open.
  • Hygiene budget. A second fast-decaying surface beside MEMORY.md. Mitigation: caps as staleness control, done means gone, promote leaves a pointer, distill at tag time.
  • Dispatcher exit paths. Reaped, closed and round-failed jobs bypass the post-run hook today; a bridge that hangs only on the two trigger sites leaves live-looking takes. Mitigation: SL5 posts on all five exits and a test pins each.
  • Secret scan on the prepended digest. A slate post carrying a token-shaped string aborts every offload from that project until dropped. Mitigation: the harvest never copies bodies, only lines and refs; kb slate doctor lints lines with the same scanner grammar.
  • Erase wars. Two tidy passes dropping each other's posts. Mitigation: the live-author friction, the witness line in the next delta, history, and the tidy skill's rule to drop only what it or a presumed-ended session authored.
  • Displaced noise. Every append printing a displaced list trains agents to ignore it. Mitigation: only posts that actually left the default digest are listed, the list is capped at five, and the nudge fires only past the threshold.
  • The sketch frame. mermaid is the SPA's first third-party renderer of untrusted text. Mitigation: a sandboxed frame with an opaque origin, strict mode, no HTML labels, the daemon's %%{ and box-drawing lint, a 2,000-char body cap, and an e2e assertion on the sandbox attribute; the SPA document keeps its no-raw-HTML posture.
  • Recall goldens churn. Five hook tests change byte shapes at once. Mitigation: one commit, the v1 layout kept behind the switch with its own byte-identity test, the marker grammar tested for both forms.
  • Migration number collision with the v7 milestone. Mitigation: take the next free number at build time, never renumber a merged one; deploy binary-then-restart.
  • Harness cost and flake. 540 model calls on a loaded box. Mitigation: the probe is resumable per pack (a results line per call, skipped when present), runs under the throttle, and its verdict is recorded once as an artifact.
  • Emoji legibility on the board for screen readers and for the operator's taste. Mitigation: every glyph has the kind word beside it; the map is one file.

21. Glossary

  • slate — one project's working-state ledger and its digest.
  • post — one immutable, sequence-numbered typed entry.
  • take — an advisory lease on a subject string; never a lock.
  • hand — an explicit handoff that stays unacknowledged until taken.
  • topic — an optional milestone slug on a post; now is per topic.
  • digest — the pure projection of the ledger, ordered by what would change your next action.
  • delta — the posts since a session's served cursor.
  • promote — move a post's substance to memory, a note or the plan, leaving a pointer.
  • scribe — by convention, the session driving a milestone; the only one that rewrites now.
  • drop / edit / mark / pin — remove, change, circle, corner: the four surface mutations, each an appended post (D17).
  • displaced — the posts a new append pushed out of the default digest; returned to the poster, never deleted.
  • whole / folded — the two rendering tiers of a digest line, earned by kind, status, pin or marks.
  • echo line — the NOW lines repeated as the last line(s) of the digest.
  • board — the SPA presenter with glyphs, colour, size, position and drawings.
  • history — dropped and superseded posts with who and why; the board's drawer and kb slate history.
  • sketch — a mermaid fence in a post body, rendered in a sandboxed frame; not a kind.
  • layout v2 — the recall line after MR1: no parenthetical, depth by rank, pos= in the marker.
