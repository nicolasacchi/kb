Top three ideas

1 · Generation-keyed search result memo verified effort M

Gallery already memoizes its row-set + edge counts per (kb, index_generation) (invariant #15; routes/docs.rs:615–648). Search has no equivalent — only the query-embedding LRU (embed_cache.rs). Every identical (q, filters, mode) re-runs BM25 + chunk-vector + RRF (+ rerank) against an unchanged index. A per-kb SearchResultCache keyed on (generation, mode, q, filter-hash, sort, page, rerank-flag) reuses the proven seam. Success signal: second identical hybrid query with stable generation shows zero bm25/vector stage time in /api/metrics; kb bench unchanged.

2 · Passage-aware SQ4 rerank verified effort M

SQ5 chunking already embeds passages and max-pools chunk scores to documents (chunk.rs, lance.rs:~1193). But SQ4's cross-encoder still scores title + summary (search.rs:1828–1852) — the reranker literally cannot see the passage that made the hit. Feed title + best_chunk_text for chunk-sourced hits, falling back to summary. Open question that gates effort: whether artifact_chunks stores text or only vectors. Same data unlocks chunk-sourced snippets (smaller, ship first).

3 · One transcript parse per capture (architecture) effort L

The costliest structural fact from the view-engine lens: two independent full parsers walk every transcript — parse_session_activity (facts/digest) and session_view (IR), and a capture+index with open comments pays 4 full Value-walks of the main JSONL (lens PVIEW's confirmed call-graph table). The 2026-07-30 wave removed the worst per-view re-parse, but the dual-engine shape remains: any classification rule must land twice (the harness ladder is already comment-marked "two engines, one rule" in both files). Target: one streaming typed-event IR both project from; alternatively persist a compact activity sidecar at capture so index skips its second walk. This is the single highest-leverage refactor in kb-core; do it before the next sessions milestone grows either engine further.

Test-infra backlog (from lens QTEST + RW1 gate evidence)

  • Tame the lance memory-pool CI flake (new, found by RW1's gate runs 2026-07-31) — under a full just ci workspace run on this host, 6 kb-core atlas tests repeatedly die in lance's merge_insert external sort with "Resources exhausted" and a total pool starved to ~400 KB, while the same tests pass 42/42 solo and at --test-threads=2; two daemon-boot polling tests (end_to_end scrub fixture-wait, notes wikilink-wait) flake under the same load. kb-core configures no datafusion memory pool (rg memory_pool crates/kb-core → empty), so lance's default sizing reacts to transient machine state. Fix directions, cheapest first: pin RUST_TEST_THREADS for the lance-heavy suite in the recipe; configure an explicit pool/budget on the lance connection in tests; investigate the host's permanently-full swap. Until fixed, a red full-gate needs the solo-rerun triage this wave documented.

Capture-adapter unification

The four harness adapters have already drifted (lens QDUP, all findings verified): claude + grok prefer the Rust kb sessions capture writer; codex + opencode hand-roll HTML; tool-output caps differ 8× (opencode 2,000-char head-truncate vs grok 16,384 head-60/tail-40); wrap_envelope never emits kb-harness. Fix shape: keep per-harness translation in shell/jq, but pipe all four through the one Rust writer, and centralize the cap policy next to SESSION_CODE_FIELD_CAP_BYTES. M effort; touches the plugin hooks, so test with a real capture from each harness.

What was deliberately not proposed

Checked against the recorded non-goals: no in-daemon LLM (ranking/digest stays deterministic), no CRDT/multiplayer, no second identity/ACLs, no TUI rebuild, no mobile authoring, no MCP server (CLI is the protocol), no memory-benchmark arms race. One tempting duplicate was caught pre-proposal: a "session view parse cache" — already shipped as view_cache/replay_cache/live_tail_cache in W7.

When to revisit

  • After the next milestone touches either transcript engine → re-score the single-parse refactor (idea 3) before, not after.
  • If sessions_list/funnel latency degrades on prod → the newest-capture materialization item graduates from backlog to fix.
  • If a second HTTP-only agent workflow appears → the CLI/server binary split pays for itself.
  • kb bench after any rerank/snippet change — the SQ-series ship gate ("no regression or it stays off") applies to ideas 2 and the graph-boost wiring.
