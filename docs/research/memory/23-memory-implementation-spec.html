Build brief: make kb
Claude Code's memory.

This is the document Claude Code executes from. Topics 19–22 are the why; this is the how — the locked architecture and an eight-phase, green-CI build plan with exact file-level changes and per-phase acceptance tests. The design is settled: kb stays LLM-free, daemon-only, no MCP; the live agent calls kb remember; recall is a server-side ranked fan-out across memory corpora; and a dedicated SPA /memory view lets a human see and correct everything. Build it phase by phase, each phase green before the next.

How to use this spec

Implement M1 → M8 in order; each is an independent green-CI commit (feat(crate): … (M<n>) per the repo cadence). A phase is done when its acceptance tests pass and just ci is green. Don't start a phase until the prior one is committed. Read topics 19–22 for rationale before touching code; treat the invariants section as hard constraints. Every file:line below was mapped from the live tree but re-verify as you go — line numbers drift.

01 — Architecture (locked)

The shape, and the four decisions behind it

Every choice here was settled in 19–22 + operator review. Do not re-litigate; build to it.

  1. kb stays LLM-free. No Anthropic SDK, no claude-CLI shelling, no background extraction/consolidation. The live agent is the only intelligence — it decides what to keep and calls kb remember. Hooks are deterministic: recall is a search, episodic capture is a verbatim write.
  2. Daemon-only, no MCP. The only running process is the kb daemon. The agent talks to it through kb verbs over the Bash tool it already has.
  3. Server-side recall + full ranking. GET /api/memory/recall fans out across the memory corpora, merges, and re-ranks by RRF × salience × recency-decay, dropping superseded/forgotten memories.
  4. Full SPA Memory view. A dedicated /memory route — timeline + atlas mind-map + inline edit/merge/forget + reused comment-curation — split from normal artifacts.
Data flow (the loop). remember: agent → kb remember → ingest route → memory corpus (HTML artifact) → indexed. recall: UserPromptSubmit hook → kb recall → /api/memory/recall (fan-out + rank) → top hits injected into the turn. curate: human comments / edits in the SPA /memory view → agent reacts via kb comments watch → supersede/forget. Episodic: the Stop hook → verbatim transcript → [kb.sessions].
02 — Data model & schema

Memories are artifacts with three new metas

Reuse the artifact pipeline; add salience, decay, supersedes. Lazy column migration backfills existing datasets.

A memory is an ordinary kb HTML artifact in a memory corpus, with the four-type taxonomy as kb-category (memory-user|feedback|project|reference) plus three new metas:

<meta name="kb-salience"   content="0.8">        <!-- f32 0..1; importance -->
<meta name="kb-decay"      content="slow">       <!-- slow | fast; recency fade rate -->
<meta name="kb-supersedes" content="7f3a1c…">    <!-- artifact id this memory replaces -->

Parse in crates/kb-core/src/parser.rs — add three fields to Fields (near the existing kb_status/kb_severity), three selectors to ParserSet, and extraction in extract() mirroring the kb-status path; salience parses to Option<f32> (clamp 0..1; ignore unparseable). Add tests beside extracts_kb_status_from_meta.

Store in crates/kb-core/src/storage/schema.rs — add kb_salience: Option<f32>, kb_decay: Option<String>, kb_supersedes: Option<String> to Doc; three nullable Arrow fields (Float32, Utf8, Utf8) in the schema builder; pack them in docs_to_batches. Migrate existing datasets with a new ensure_v*_columns step (same lazy add_columns pattern as the kb-meta columns) — nullable, backfilled on the next index pass.

Surface in crates/kb-core/src/storage/lance.rs — add the three fields to DocSummary (returned by every query) so the recall re-rank can read them. DocSummary already carries mtime_unix + indexed_at_unix for recency.

Invariant. The lance embedding column stays nullable on the outer (per-row writes); per-kb embedding dim is captured at Storage::open — don't touch either. New columns are scalar + nullable, so they don't interact with the embedding width.
03 — Recall & ranking

/api/memory/recall: fan out, merge, re-rank

One server-side endpoint owns scope resolution + the ranking formula. The CLI and the hook are thin wrappers.

GET /api/memory/recall?q=<query>&scope=all|global|project&project=<name>&limit=5
  → 200 { "hits": [ { id, kb, title, score, salience, ... } ], "ms": N }

Scope resolution. A corpus is a memory corpus when its kb.toml section sets memory_scope = "global"|"project" (§02 config). scope=global → corpora with memory_scope="global"; scope=project → the project corpus (matched by the project param, or the single memory_scope="project" corpus on this daemon); scope=all → both. The handler lives in crates/kb-server/src/routes/memory.rs (new), registered in router.rs beside the search routes; it reads state.kbs to find the in-scope corpora. memory_scope is a new #[serde(default)] Option<String> on KbSection, threaded onto KbContext at boot (the handler sees KbContext, not the raw section). New corpora are discovered at daemon (re)start, not hot-added — the kb.toml watcher only re-arms existing sources.

Fan-out + merge. For each in-scope corpus, embed the query with that corpus's own embedder (memory corpora may differ in model/dim — re-embed per distinct model; if a corpus has no embedder, fall back to keyword/BM25 for it rather than failing the whole request), run the existing hybrid query (the path /api/search uses), over-fetch limit per corpus (so a high-salience hit ranked low in a busy corpus survives the merge), tag each hit with its source kb, concatenate, then re-rank globally. Rank-position relevance (above) sidesteps the cross-model score-scale mismatch. Add an acceptance test with two memory corpora on different embedding models.

The ranking formula (deterministic)

The relevance signal is rank-position, not a raw score — lance computes an RRF/relevance score internally but the query layer projects it away (DocSummary carries no score field), so derive relevance from each hit's position in its corpus result list: rel = 1/(60 + rank). Then final = rel × salience × exp(−k · age_days), where salience defaults to 0.5 when absent, age_days comes from mtime_unix (NOT indexed_at_unix — that resets on every reindex), and k from kb-decay (slow → 0.01/day, fast → 0.1/day; absent → slow). Then drop any hit whose id appears in another in-scope memory's kb-supersedes (unknown ids are no-ops), and any with kb-status="forgotten". Truncate to limit. Keep the math in a pure, unit-tested function in kb-core (memory::rerank(hits, now) -> Vec<Scored>). Optional enhancement: recover lance's real _score by widening the recall query's projection — but spike it against the pinned lancedb 0.27.2 first (it may require Select::All); ship rank-position for the MVP.

Why server-side. The CLI kb recall, the SPA, and the UserPromptSubmit hook all call this one endpoint, so the merge + ranking live in exactly one place. (Search itself stays single-corpus; this endpoint is the only thing that spans corpora.)
04 — Ingest

kb remember writes and indexes in one step

A synchronous ingest route backs the verb. The one hazard is the live watcher double-indexing the file.

POST /api/kb/{kb}/artifacts
  { "title", "body" | "body_html", "category": "memory-user",
    "tags": [...], "salience": 0.8, "decay": "slow", "supersedes": "<id>" }
  → 201 { "id": "<12-hex>", "path": "<slug>.html" }

Handler in crates/kb-server/src/routes/artifacts.rs (new; model on routes/reindex.rs for the shape, routes/search.rs for state access). It renders the memory HTML via a new kb_core::memory::render_artifact(title, body, category, tags, salience, decay, supersedes) -> String — a small shared builder that emits the full <!DOCTYPE html> + <meta kb-*> skeleton, callable by both this route and the CLI. (Do NOT try to reuse the kb new engine: it's a private fn in the kb-cli binary, the server can't call it, and it only substitutes placeholders into a template file that must already exist — it can't synthesize a document.) Then it writes the file into the corpus dir and indexes it through the storage actor.

The double-index hazard (must handle). The corpus dir is under the live watcher; writing the file fires a real watch.create ~400 ms later, and Created events bypass the indexer's content-hash dedup gate (only Modified is gated; the indexed_hashes cache is private to the indexer task, not reachable from a route). A naïve handler embeds the doc twice (~170 ms/doc). Two realistic mechanisms — pick one and let the M4 test enforce it: (a) MVP — write-only: the route writes the file and lets the watcher index it; "searchable immediately" becomes "within one debounce (~400 ms)", zero double-embed, no new plumbing. (b) Immediate: add a public actor message (e.g. MarkIndexedHash{id,hash}) the route calls before writing, AND make the gate honor it for Created too (a deliberate change to the Created-bypass at indexer.rs). Either way, enqueue writes through the single-writer actor — no parallel writer (CHANNEL_CAPACITY invariant). M4 acceptance: exactly one embed per ingest.
05 — CLI verbs

remember · recall · forget

Thin daemon wrappers in kb-cli; the agent-facing primitives.

kb remember "<text>" --scope project|global --category memory-user \
   --tags a,b --salience 0.8 --decay slow [--supersedes <id>]   # → POST …/artifacts
kb recall  "<query>" --scope all|project|global [--limit 5] [--json]  # → GET /api/memory/recall
kb forget  <id> [--kb <memory-kb>]                                    # delete file or set kb-status=forgotten

Add a Memory/verb arm to the clap Cmd enum in crates/kb-cli/src/main.rs and handlers in crates/kb-cli/src/commands/memory.rs (model on commands/search.rs + comments.rs): resolve the daemon via http::detect_daemon, send bearer auth, fall back to an offline lance read where sensible. kb remember renders the memory artifact via the shared kb_core::memory::render_artifact (§04) and POSTs it; --scope selects the target corpus from config. Provide --json on recall for the hook to parse.

06 — Invalidation & events

Stale, superseded, forgotten — live

Reuse the anchor-stale plumbing; add memory-specific SSE so the SPA updates without refresh.

Add memory.* string-const events in crates/kb-core/src/events.rs, emitted via the existing bus.emit(...) (the comment.anchor_stale call is the model): memory.ingested, memory.stale (superseded / decayed past a threshold), memory.resolved, memory.forgotten. The trigger is NOT the per-file indexer anchor hook — supersede is a relationship between two memories, not a function of one file's bytes. Emit memory.stale for id X from the ingest path when a memory carrying kb-supersedes=X lands; do the supersede/forget drop at recall time inside the pure rerank() (no sidecar needed). kb forget = delete the file (watcher → watch.delete → row removed) for the MVP; a soft kb-status="forgotten" would need a daemon-owned HTML rewrite that doesn't exist today — defer it.

07 — SPA Memory view

/memory: timeline, mind-map, curate

A dedicated route that reuses the gallery/atlas/comment machinery, scoped to the memory corpora.

  • Route — add /memory in web/src/app.tsx (React Router v6) + web/src/routes/memory.tsx; add a nav affordance (the gallery view-toggle is gallery-only) and its own scope control (all / global / project, mirroring the recall scope param — the single-select TopBar kb picker can't express "global + project at once").
  • Timeline — feed it from the /api/memory/recall endpoint (§03) with a loose/empty query: it already spans corpora, ranks, and drops superseded/forgotten, so the SPA makes ONE call instead of building client-side multi-corpus aggregation (no existing view spans kbs). For a single corpus, useDocs(kb, {sort:"recent"}) already gives authorship-recency — a new useMemories hook is warranted ONLY for cross-corpus merge, which recall already does. (Don't reuse HistoryTimeline — it's user-activity, not authorship.)
  • Mind-map — reuse AtlasView.tsx, but note atlas coords (atlas_x/y/cluster) exist only AFTER a recompute (the indexer never computes them; a fresh corpus shows a hash-scatter fallback). Specify the trigger: a debounced recompute on memory.ingested (mind the atlas rate-limit) OR surface the existing recompute button. Needs the corpus to have an embedder; treat the map as a best-effort layer, not an M7 hard gate.
  • Curate (two parts) — (a) comment curation: reuse CommentsPanel.tsx + useReview.ts on a memory artifact's detail view (CommentsPanel is iframe-coupled — half its props drive in-iframe behaviour). (b) edit / merge (set kb-supersedes) / forget: a new memory-actions component wired to the ingest/forget routes (M4–M6) — net-new mutations, NOT part of CommentsPanel.
  • Live — subscribe to the new memory.* SSE via the generic subscribeEvent in web/src/api/sse.ts (no SSE-layer change); refresh on change, mirroring useReview's comments.updated.
  • Split / scope — add a memory_scope field to KbSummary / GET /api/kbs (it carries none today) so the SPA can tell which corpora are memory and render the view distinct from kb-docs/research. This is a backend dependency for M7 (land it in M2).
08 — Hooks plugin + protocol

Deterministic Claude Code hooks (no LLM)

Greenfield — no hook scaffolding exists in the repo. Every hook just runs a kb verb.

// .claude/settings.json
{ "hooks": {
  "UserPromptSubmit": [ { "hooks": [ { "type": "command", "command": "~/.claude/hooks/kb-recall.sh" } ] } ],
  "SessionStart":     [ { "hooks": [ { "type": "command", "command": "~/.claude/hooks/kb-wake.sh" } ] } ],
  "Stop":             [ { "hooks": [ { "type": "command", "command": "~/.claude/hooks/kb-capture.sh" } ] } ]
} }
  • kb-recall.sh (UserPromptSubmit) — read the prompt from stdin (jq -r .prompt), kb recall "$prompt" --scope all --limit 5 --json, print a compact titles+ids block to stdout (injected as turn context). Silent on no hits. No LLM.
  • kb-wake.sh (SessionStart) — print the memory protocol + a compact index (a couple of kb reads). No LLM.
  • kb-capture.sh (Stop — not "SessionEnd", which is not a real hook) — receives transcript_path (a JSONL file) on stdin; read + wrap it verbatim as an HTML artifact into [kb.sessions]. No LLM, no extraction.

Capture of curated memory is NOT a hook — the live agent calls kb remember per the CLAUDE.md memory protocol. This is the load-bearing artifact AND the main risk: if the agent never invokes the verb, nothing curated is captured (only the verbatim Stop transcript dump). Mitigate by shipping a strong protocol, having kb-wake.sh re-inject it every session, and making the demo (§11) prescribe the exact eliciting prompt so M8 is reproducible rather than model-whim. Verify ALL THREE hook contracts against current Claude Code docs before shipping: the teardown hook is Stop (not SessionEnd) and delivers transcript_path; UserPromptSubmit stdin is .prompt and its stdout injects into the turn (prefer the explicit hookSpecificOutput.additionalContext JSON form for robustness).

11 — Live demo runbook

Feel the loop end to end

After M8, run this to see how it behaves — the point of building it all.

  1. Configure [kb.memory] (memory_scope="global") + [kb.memory-kb] (memory_scope="project") + [kb.sessions]; start kb daemon.
  2. Install the hooks + the CLAUDE.md memory protocol in a scratch project.
  3. Session A: state durable facts → confirm kb remember wrote artifacts (CLI list + the /memory view).
  4. Session B (fresh): ask about those facts → the UserPromptSubmit hook injects them (recall works across sessions); check the ranking (salience + recency).
  5. Supersede one fact (kb remember … --supersedes <id>) → the old one drops from recall and the SPA shows memory.stale.
  6. Correct one via a kb comment → the kb comments watch loop updates it; kb forget <id> removes one. Watch it all live in /memory.
12 — Invariants & risks

Hard constraints — breaking these fails subtly

Respect these (from the kb architecture invariants)
  • Single-writer storage actor — ingest enqueues through the existing actor; never add a parallel writer (CHANNEL_CAPACITY).
  • lance embedding column nullable on the outer; per-kb dim captured at Storage::open — new columns are scalar + nullable, don't touch the embedding width.
  • Arrow/lance version pinning — don't pull deps that fork the arrow version.
  • Atlas determinism — if the Memory view triggers a recompute, keep the layout seed-deterministic.
  • Watcher Created bypasses the dedup gate — so ingest either writes-only and lets the watcher index (MVP), or adds a public pre-seed actor message + makes the gate honor it for Created (the M4 test guards exactly-one-embed).
  • clippy — new pub fns go before any #[cfg(test)] mod tests; run cargo fmt before each commit.
Top risks (deep-review-surfaced): lance does not expose the per-hit RRF score → recall ranks on rank-position, not raw score (M3); the memory HTML renderer is net-new in kb-core (the kb new engine can't be reused — private, kb-cli-only); ingest double-index → MVP writes-only and lets the watcher index, M4 proves single-embed; new corpora need a daemon (re)start (no hot-add); memory_scope is additive but sweeps ~17 struct-literal sites + must surface on /api/kbs; Stop (not SessionEnd) is the teardown hook and delivers transcript_path; the atlas mind-map needs a recompute + an embedder; agent-explicit capture depends on the agent actually calling kb remember (lean on the protocol + wake hook); cross-model corpora must embed per-corpus with a BM25 fallback.
