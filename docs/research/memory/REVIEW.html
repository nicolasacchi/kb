Audit of 19-23 against the live tree at v0.9 + two post-tag fix commits. Read with the docs in the same folder.

Milestone outcome

The agent-memory track shipped as v0.9, tagged at the end of an eight-phase push (M1-M8) each landing as a single green-CI commit on main. Track M followed the build brief in doc 23 end-to-end and implemented the native subsystem path argued in doc 22, not the phased A → B → C path doc 19 recommended.

Post-tag bug. vector_query on an empty corpus panics inside batches_to_summaries at crates/kb-core/src/storage/lance.rs:777: the function does batch.column_by_name("id").unwrap(), but lance's autoprojection on an empty result can omit the column, so the unwrap kills the storage actor task for that kb. Recall fan-out (M3) is the path that hits it — a freshly-configured memory corpus with zero artifacts in it panics on the first kb recall. Found while smoke-testing the docker daemon; not covered by the M3 acceptance tests because those seed each corpus before querying. Fix is either projecting id explicitly or replacing the unwraps with a soft return of an empty hit list.
Doc 19

partial 19-kb-as-claude-code-memory.html — hub & recommendation

The framing shipped — kb did become Claude Code's memory cockpit, with the curation, atlas-map and comment-loop arguments holding up — but the doc's phased recommendation didn't: it told us to start with Approach A (zero-build corpus + protocol), promote to B (CLI verbs) when shell-call friction bit, and build C (native subsystem) only if agent memory became a kb pillar (19-…html:204-207, the #recommendation ordered list). In practice the project jumped straight to C, executing doc 23's M1-M8 brief on a fresh branch. Approach A's deliverables (the [kb.memory] corpus shape, the protocol prose) were absorbed into C as setup, not run as their own milestone. Reading 19 as a problem-statement + landscape survey: SHIPPED. Reading it as a build sequence: NOT followed.

  • Native subsystem code present at crates/kb-core/src/memory.rs, crates/kb-server/src/routes/memory.rs, crates/kb-cli/src/commands/memory.rs — i.e. doc 22's path, not the doc-19 phased one.
  • The "memory cockpit" thesis (SPA view + atlas + comment curation) materialised at web/src/routes/memory.tsx and the live memory.* SSE wiring in crates/kb-server/src/routes/artifacts.rs:120-178.
Doc 20

superseded 20-memory-corpus-and-protocol.html — Approach A (zero-build)

Officially SUPERSEDED by the v0.9 decision to build the native subsystem, but a lot of its DNA was kept. The four-type memory-{user,feedback,project,reference} taxonomy as kb-category values stayed as the canonical authoring shape (see hooks/CLAUDE.memory.md). What didn't ship from this doc: the "Claude writes the file directly with the right meta tags and the watcher picks it up" zero-build flow — v0.9 instead exposes POST /api/kb/{kb}/artifacts and kb remember CLI as the canonical ingest paths (crates/kb-server/src/routes/artifacts.rs + crates/kb-cli/src/commands/memory.rs:Cmd::Remember). The double-index hazard doc 20 hand-waves was finally pinned down in doc 23 and resolved by the "write-only" MVP route — same outcome (watcher does the embed), with a real test guarding exactly-one-embed.

  • Taxonomy lives on in hooks/CLAUDE.memory.md and the meta-walker in crates/kb-core/src/memory.rs (salience/decay/supersedes triplet).
  • Doc 20's "session transcript dump" recipe became the kb-capture.sh Stop hook into [kb.sessions] — see hooks/kb-capture.sh + hooks/README.md:8-10.
Doc 21

superseded 21-memory-mcp-and-memory-tool.html — Approach B (CLI verbs, no MCP)

SUPERSEDED as a milestone of its own, but its core argument — build CLI verbs, don't run an MCP server — became a load-bearing decision in v0.9. The kb remember / kb recall / kb forget verb trio doc 21 sketched is exactly what shipped, just folded into the C build rather than staged separately. The "build-vs-buy" analysis (Mem0 / Anthropic memory tool / MemPalace) directly motivates the LLM-free invariant called out in CLAUDE.md's "Agent-memory subsystem (v0.9, track M)" section: kb stays deterministic; the live agent does the writing.

  • Verb subjects: crates/kb-cli/src/main.rs:1034 (Remember), :1064 (Recall), :1084 (Forget) — matching the doc-21 surface 1:1.
  • No MCP server in the tree; the only agent-side glue is three shell hooks under hooks/ (kb-recall.sh / kb-wake.sh / kb-capture.sh) declared in .claude-plugin/plugin.json.
Doc 22

shipped 22-memory-native-subsystem.html — Approach C (native)

SHIPPED. v0.9's M-track is doc 22's blueprint. The three-meta authoring shape (kb-salience, kb-decay, kb-supersedes) became the canonical schema, parsed in M1 and rendered by memory::render_artifact. The "lifecycle-hooks plugin so memory is automatic" beat lands as the M8 hooks + .claude-plugin/plugin.json. Invalidation via supersede chains is live: list_supersede_targets in the storage actor feeds the corpus-wide tombstone scan inside recall (see "Architecture invariants" rule for memory in CLAUDE.md). The atlas "mind-map of the agent's knowledge" beat is live via the existing AtlasView reused from /memory — with the doc-23-flagged caveat that it needs an embedder + a recompute, not a hard gate.

  • Pure rerank on rank-position × salience × decay: crates/kb-core/src/memory.rs:73-98. The doc-22 supersede-as-tombstone idea is implemented at crates/kb-core/src/storage/lance.rs:737 (list_supersede_targets) and consumed at crates/kb-server/src/routes/memory.rs:178.
  • Lifecycle plugin: .claude-plugin/plugin.json + hooks/{kb-recall,kb-wake,kb-capture}.sh + hooks/CLAUDE.memory.md.
Doc 23

shipped 23-memory-implementation-spec.html — implementation spec (M1-M8)

SHIPPED end-to-end. All eight phases landed as the green-CI commits listed in the milestone outcome above. The four big architectural calls doc 23 locked in are all honoured in the tree: (1) recall ranks on rank-position (1/(60+rank)) not raw score, because lance projects no per-hit score — see memory.rs:66-91; (2) the supersede/forget drop happens inside the pure rerank from a corpus-wide tombstone scan, so an old memory drops even when its superseder isn't in the retrieved window — see routes/memory.rs:178; (3) ingest is the write-only MVP, watcher indexes (the Created bypass of the dedup gate stays as-is, no parallel writer) — guarded by an M4 e2e test; (4) memory corpora are discovered at daemon (re)start, no hot-add. The "Stop (not SessionEnd)" hook contract call-out also held up — see hooks/README.md:10.

  • Test coverage matches the doc-23 testing matrix: pure rerank unit tests + a recall e2e + an M4 ingest e2e (exactly one embed within ~400ms) + Playwright tests/e2e/spa-memory.spec.ts for M7.
  • Post-tag gaps doc 23 didn't predict: (a) the lance.rs:777 panic on empty corpora; (b) KB_DAEMON_URL wasn't honoured by the hooks, fixed in b282311 — the spec assumed the default daemon URL, which broke for docker-daemon and multi-daemon users.

Roll-up

  • shipped 22, 23 — the chosen path + its build brief, both reflected in the tree at v0.9.
  • superseded 20, 21 — Approaches A and B; their best ideas (taxonomy, verb shape, LLM-free posture) were folded into C.
  • partial 19 — framing and thesis SHIPPED; phased A→B→C recommendation NOT followed.

Two known follow-ups remain: the empty-corpus panic at lance.rs:777 and any further docker-daemon-vs-local-daemon hook ergonomics the 68b3b86 docs commit didn't already cover.
