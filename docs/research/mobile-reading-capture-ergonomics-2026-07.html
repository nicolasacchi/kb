Mobile Reading and Capture Ergonomics for kb

Idea brief through one lens: the phone as reader + triage + capture device — not an editor. Ideas are built from kb’s own prior research (mobile redesign, web-UI board, e-ink path, quick-capture/share-target, reading lists), not generic “make it like Notion” freelancing.

1. Lens summary

kb’s phone job is asymmetric: agents author long HTML artifacts on the desktop; the human mostly reads queues, triages comments, and captures scraps with one thumb on a train or couch. The SPA already has the right skeleton — immersive reader, bottom tab bar with Capture, reading lists + QueueBar, v0.25/v0.26 capture (paste-text + share_target POST /capture) — but several high-value mobile paths are still keyboard-only or half-wired, and the cross-origin artifact iframe (invariant #7) forbids the usual “restyle the document” reader tricks.

Prior research already fixed the frame: lists are the mobile primary; edge-swipe is fragile against the sandboxed iframe; PWA offline shell stays trigger-gated on an Android + Authelia retry story (share-target itself has shipped); bare browser TTS was rejected as competitor-parity without a demonstrated need. This brief mines that ground for concrete next moves — three finishes you can ship without reopening non-goals, plus four wild bets that stay legal by routing around the iframe, the prompt-scrub export rule, and the memory agent-ingest boundary.

Non-goals this brief respects

No mobile editor. No restyling sandboxed HTML artifacts from the parent. No PWA offline app-shell until the Authelia-retry trigger fires (ideas that need installability name the gate). No “highlight → auto memory” that pretends human provenance is agent ingest (invariant #10). TTS only reappears as pre-rendered, scrubbed, list-bound audio packs — not Web Speech of the live SPA.

2. What kb already decided (load-bearing)

  • Mobile chrome path: Phase-2 phone = FAB + bottom sheet; comments as modal sheet; iframe full-bleed; no native app (surfaces/12-mobile-redesign).
  • Reader breakage: TocSpy overlay on ≤390px is the one real phone-reader break — collapse-by-default under ~860px (web-UI audit D1).
  • Queue nav: ContextBar onPrev/onNext/position/total exist but are largely inert; list trail + QueueBar exist; sibling [/] and list n/p are keyboard-only on touch.
  • Capture: POST /api/kb/{kb}/capture + share-target POST /capture + SPA CaptureSheet (files/drag/paste-text) shipped v0.25–v0.26. Auth cookie expiry mid-share is the documented sharp edge.
  • E-ink sister path: server-rendered e-ink mode → EPUB/OPDS → KOReader; SPA is a poor e-ink client (kb-on-e-ink-readers).
  • Recorded kills: skeleton loaders; bare TTS; offline PWA shell (trigger-gated); share-engine-as-backup (lossy under invariant #9).

3. Ideas

01 · NEAR

Thumb-zone queue chevrons (wire what’s already there)

wildness 1 effort S reader · lists
Pitch

On mobile detail (and immersive), float two large, safe-area-aware prev/next hit targets in the lower thumb arc — same slot language as the immersive toggle. When ?list=&entry= is present, drive them from the list trail; otherwise from folder siblings. Wire ContextBar’s dormant onPrev/onNext/position/total and show a slim “3 of 11 · Up next →” footer. No edge-swipe in v1.

Inspiration

Kindle/KOReader page chrome; Instapaper queue; web-UI audit’s kept “on-screen prev/next” (critic: chevrons first, swipe later).

kb_fit

Reader detail + QueueBar / list trail + ContextBar props already declared.

invariant_risk

none — pure chrome wiring outside the iframe. Defer edge-swipe (fights invariant #7 pan/scroll).

02 · NEAR

Phone-readable reader: TOC collapse + Continue shelf

wildness 1 effort S reader · recent
Pitch

Ship audit D1: Topics default collapsed under the mobile breakpoint and never steal the column. On the Recent tab, add a one-row “Continue” shelf: last in-progress artifact (resume % + stop heading) plus the active list’s next unread with est_minutes (“12 min left in Evening pack”). Tap opens immersive with list context preserved.

Inspiration

Pocket/Instapaper home “continue”; Apple Books reading now; kb web-UI audit mobile “Continue reading” shelf.

kb_fit

TocSpy + history reading progress + lists est_minutes/remaining_minutes + BottomTabBar Recent.

invariant_risk

none. Resume toast must not fight silent scroll-to-stop already in detail.

03 · NEAR

Share-target capture that survives Authelia

wildness 2 effort M capture · pwa-gate
Pitch

Share-target already POSTs to /capture and 303s to /?captured=…. The real mobile failure mode (documented in self-host) is cookie expiry → login redirect eats the multipart body. Fix the gate, not the fantasy offline shell: stage the share payload in a tiny same-origin holding page (or SW form-cache) before auth, replay POST after Authelia returns, then land the existing toast. Optional: after successful install on Android, surface a one-time “Share to kb works when…” checklist in Settings.

Inspiration

Android Share Target + credentialed PWA patterns; Wallabag/Omnivore “save from share sheet”; kb’s own deferred trigger (“Android phone + Authelia retry story”).

kb_fit

manifest.webmanifest share_target, routes/capture::share_target, capturedParam toast, CaptureSheet.

invariant_risk

Stay on the existing auth_bearer route_layer for /capture (invariant #4). Do not weaken public bind. HTML from the wild stays sanitize-default-ON on this path. This is not full offline PWA — only retry across the login hop.

04 · STRETCH

One-hand comment triage deck

wildness 3 effort M comments · triage
Pitch

A full-screen “Inbox deck” of open you-authored comments across the active kb: one card = artifact title + anchored excerpt + comment body. Thumb gestures on the chrome card (not the iframe): swipe right = mark needs-reply later (pin to a “Tonight” list), swipe left = resolve (with undo toast), tap = open artifact at anchor in immersive with composer focused. Keyboard twin keeps audit’s j/k/r/d triage mode for desktop.

Inspiration

Mail triage (Superhuman/Outlook focused inbox); Tinder-style card decks done tastefully; GitHub mobile review queues; kb audit “keyboard triage mode for Inbox/Comments”.

kb_fit

Comments API + resolve/reply, Inbox/Anchors routes, lists add-entry, existing mobile inspector sheet patterns.

invariant_risk

Gestures only on SPA chrome cards — never over the sandboxed iframe. Resolve goes through normal comment mutations + SSE; destructive bulk still hits the one-confirm host (invariant #32).

05 · WILD

Agent-built “commute pack” lists

wildness 4 effort M lists · agents · sessions
Pitch

Agents already touch artifacts and can kb list add. Productize a convention: a pinned list named like pack/2026-07-18-commute with a target budget (e.g. 25 min from remaining_minutes). Overnight (or end of coding session) the agent fills it from “touched today + open comments + unread longreads,” ordered for continuous read. Phone opens Lists → pack → immersive chevrons through the queue. Human never builds the queue; they only swipe/advance and optionally eject (“not tonight” → back to backlog list).

Inspiration

Readwise daily review; Spotify Daily Mix; airline “gate pack”; kb sessions “recently touched by agents” discovery idea + list time estimates.

kb_fit

Reading lists CRUD + est_minutes, session_files / agent activity signals, CLI list verbs agents already use, mobile Lists tab.

invariant_risk

none if packs are ordinary lists (no new intelligence in-daemon). Ranking stays agent-side; daemon remains deterministic storage. Don’t auto-write human memories from pack completion.

06 · WILD

Scrubbed audio packs (TTS reopened with a new angle)

wildness 5 effort L lists · export · commute
Pitch

The audit killed in-SPA Web Speech of long-form artifacts (no demonstrated need; competitor parity). Reopen only as: for a commute pack, a button “Render audio” runs server-side (or laptop-side agent) over share-scrubbed plain text (invariant #9: prompts already stripped), produces chaptered M4A/OGG per list entry, and attaches them as downloadable artifacts or OPDS-adjacent files. Phone plays with lock-screen controls and auto-advances the list’s audio queue — eyes-free twin of chevron reading. No live SpeechSynthesis in the reader chrome.

Inspiration

Speechify / NaturalReader export; podcast queues; KOReader TTS; e-ink report’s EPUB offline path (same scrubbed substrate).

kb_fit

kb share scrub pipeline, lists, capture folder or attachments, optional OPDS/export sibling to e-ink roadmap.

invariant_risk

Must use scrubbed export text only (#9). Prefer offline files over streaming model APIs in the daemon (keeps local-only posture). Don’t put TTS inside the artifact iframe. Interactive/JS-heavy artifacts flag as “not narratable” rather than mangling.

07 · WILD

Server-paginated “tap pages” reading mode

wildness 4 effort L reader · e-ink · one-hand
Pitch

Borrow Phase-1 of the e-ink report for phones: a JS-light, server-rendered /read/{id}?page=N (or ?view=pages) that splits scrubbed-or-markdown-friendly bodies into word-budget pages. Left 30% tap / right 70% tap = prev/next page (classic e-reader hit zones), progress dots, no scroll fighting. SPA list chevrons hop artifacts; in-artifact taps hop pages. Works one-handed on a jostling bus; doubles as the Boox/Kobo browser client.

Inspiration

Kindle tap zones; KOReader; Instapaper pagination experiments; kb e-ink architecture B (server-rendered reading mode).

kb_fit

Daemon artifact serve + index-page/browse patterns; reading progress history; lists continuous read; e-ink CSS hooks from the e-ink report.

invariant_risk

Pagination runs on server-owned HTML/Markdown paths — not by injecting into author JS inside the subdomain iframe. Strip kb-prompt on non-loopback (#5/#9). Interactive widgets degrade to “open full artifact” rather than fake pages.

08 · WILD

Thumb-arc radial actions (one-hand command palette)

wildness 4 effort M chrome · capture · search
Pitch

Long-press the mobile Capture tab (or immersive FAB) to fan a semicircle of 4–5 actions in the thumb arc: Capture, Search (cmdk), Continue pack, New comment on current, Share sheet (navigator.share). Release on a wedge to fire. Short tap keeps today’s single action. Gives power-user density without a second row of tab bar icons or reaching the top of a large phone.

Inspiration

iOS AssistiveTouch arcs; Firefox Continuum experiments; game console radial menus; mobile redesign FAB open decisions (position/content).

kb_fit

BottomTabBar Capture event, Cmdk, CaptureSheet, Web Share idea (audit keep), immersive FAB slot.

invariant_risk

none if actions only dispatch existing SPA events. Provide a non-gesture path (long-press accessibility menu / explicit “More”) for AT. Honour prefers-reduced-motion with a static list sheet fallback.

09 · WILD

Pocket memo queue (capture when the daemon can’t hear you)

wildness 5 effort L capture · offline-edge
Pitch

A deliberately tiny standalone route /pocket: one textarea, optional tags, big Save. On failure (offline, 401, 5xx) append to a local IndexedDB outbox and show a badge on Capture. Next successful session drains the outbox through normal POST …/capture as markdown stubs (from:pocket). This is not a full offline reader and not a SW-cached corpus — it’s the commute parking lot for thoughts when Authelia or the tailnet is unhappy. Pairs with idea 03’s retry machinery.

Inspiration

Drafts app / Capture One-tap notes; Google Keep offline; fresh-eyes “phone-capture kernel” inbox.md idea; shared-outbox patterns in PWAs without claiming full offline.

kb_fit

Capture API + notes/markdown pipeline + Capture tab badge + existing toast grammar.

invariant_risk

Do not pretend the outbox is searchable memory. Drain only via capture (provenance-stamped files), never silent memory writes (#10). Scope stays text stubs — no caching of artifact bodies (avoids the rejected offline app-shell). Clear UX that items are local until acked.
