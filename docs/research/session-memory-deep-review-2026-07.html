Dogfooding review · episodic memory

Session memory under the microscope — 12 real sessions vs their digests, 36 confirmed defects, and the repair portfolio (2026-07)

2026-07-06 · ultracode workflow wf_1c23d6c7 (65 agents, 3.99M subagent tokens, 1,299 tool calls; 12 fidelity readers · 5 code reviewers · infra prober · prior-art reader · 38 adversarial verifiers · 5 ideation lenses · 3-judge panel) · companion: coverage-gap analysis

Verdict

The architecture is right and the implementation is dishonest. Invariant #11's core rulings — transcripts as pull-only episodic memory, a deterministic LLM-free digest as the indexed surface, canonical id from the JSONL — all survived adversarial review; the canonical-id recovery even worked around a live capture bug exactly as designed. But measured against raw-transcript ground truth, the digests of the 12 most recent kb sessions score a mean 2.6/5 for usefulness to a future agent, and the review confirmed 36 defects (10 high) across every layer:

  • The subagent iceberg. Every ultracode session hides 79–94% of its real work: the digest reads only the main-thread transcript, so a 140-agent, 12.8M-token workflow session digests to "12 tool calls, 0 files edited" (B3). The sessions where the most work happens are recorded worst.
  • Provenance is fabricated or destroyed. Commit subjects are stored as the literal strings commit or $(cat <<'EOF' for the two dominant Claude Code commit forms (B5); a read-only git tag -l becomes a fake "tag" record; 21 pr-link events across 4 PRs produced zero records.
  • Retrieval's front door fails on its own names. A session is not findable by its own exact title in 7 of 12 cases; kb recollect misses the kb project's directly-on-topic sessions while 37-day-old cross-project hits outrank them at opaque ~0.013 scores (B8), and kb sessions search is a single LIKE-substring that can't match "episodic memory" against "sessions-episodic-memory" (B9).
  • Prod linkage is structurally dead. In the containerized deployment, transcript host paths (~/…) never match container corpus mounts (/srv/…), so in_corpus=0 forever, the funnel's "commented" stage is permanently zero, and the R5 session↔comments join has never fired (B7).

Bottom line for the question asked: as a catalog, yes — as memory, not yet. kb sessions list/show and kb why genuinely accelerated this very review; kb recollect and kb sessions search failed at their one job and the analysis fell back to raw-JSONL archaeology. The fix portfolio below is ranked and mostly small: the top five programs are S/M-effort, deterministic, and invariant-#11-compatible.

The headline: the subagent iceberg

Multi-agent orchestration became the dominant working style in July (7 of the 12 sessions are ultracode), and it is precisely the style the digest cannot see. Task/Agent subagents and Workflow fleets write their transcripts to sibling files (<sid>/subagents/agent-*.jsonl); kb-capture.sh reads only the main transcript, and the usage totals that Claude Code hands back in task-notification blocks are discarded by the parser. What the digest gets right Where the main thread is the whole story, the mechanics are solid: canonical session-id recovery from the JSONL worked in all 12 (including around the live trailing-dash capture bug — invariant #11's guard proven in production); first prompts are verbatim; main-thread tool_calls and token_total are exact; commits=[] and decisions=[] are correct when nothing happened; the one deliverable that WAS main-thread-authored (the security review HTML) is properly recorded with write+edit rows. The defect census — 36 confirmed, 2 refuted

38 candidates (15 from live dogfooding, the rest from code review) were each handed to an independent adversarial verifier instructed to refute. 36 survived with file:line mechanisms or live reproductions. Grouped by layer:

Capture layer

highB2 started_at is the capture-hook's wall clock (the filename timestamp), not the transcript's first event — so every single-capture session stores ended_at < started_at and duration_ms=0. A ~50-hour session reads as 0ms; recollect's recency decay and R8's temporal windows all ride these corrupted numbers. Fix point: track MIN/MAX event timestamps in parse_session_activity (sessions.rs:534-538).

mediumB14 Sessions with no aiTitle get the opaque "session <8hex>" name even at 1,203 messages, and synthetic "[Request interrupted by user]" markers pass the wrapper filter into titles/prompts.

lowB13 / NEW-sid-trailing-dash The sid sanitiser (jq -r | tr -c 'a-zA-Z0-9' '-') converts jq's trailing newline to -: 86 of 138 live capture files end -.html and every plugin-era <meta name="kb-session"> carries a trailing dash. Low on its own — but it is the detonator for B8 below.

lowNEW-capture-hook-fails-silently All 6 failure paths in kb-capture.sh exit 0 with zero logging (jq/mv stderr explicitly suppressed) — a broken jq or full disk halts all capture with no trace (kb-capture.sh:12,16,18,41,43,55).

mediumlifecycle gap Capture fires only on Stop. A session that ends in a background-workflow completion, abort, or spend-limit death keeps its launch-time snapshot forever — e1b3277a's digest predates the entire 71-minute review it launched.

Digest / enrichment

highB3 Main-thread-only parsing: all subagent/Workflow activity invisible (the iceberg above). Sidechain JSONLs sit next to the transcript and are never read.

highB5 extract_commit_message cannot parse the two dominant commit forms: git commit -F - heredoc → subject "commit"; -m "$(cat <<'EOF'…)" → literal $(cat <<'EOF'. Every July session's commit provenance is garbage; the repo is local at capture time, so git show -s --format=%s <sha> would resolve truth for free.

mediumB4 The touches heuristic substring-scans the whole transcript (including hook-injected recall/MEMORY.md quotes) against every doc id and path across all kbs — hence "39 fuzzy touches" on a session that read 0 files, printed as bare unexplained hex.

lowB6 No (kind, sha) dedup in extract_commits plus a first-hex-token fallback that re-captures already-seen shas — kb why prints the same commit twice.

lowNEW-git-tag-readonly Read-only git tag/-l/--list invocations are classified as VCS "tag" write actions — fabricated provenance (31c9abc9, ae3afd3d).

lowNEW-error-count-semantics error_count is a main-thread tool-friction tally: subagent deaths, spend-limit kills, and user interruptions all invisible.

mediumPR blindness 21 structured pr-link events across 4 PRs in one session → zero records; PRs are the principal deliverable of multi-repo work and have no digest representation at all.

Prod deployment

highB7 / NEW-in-corpus The dockerized daemon's corpus mounts are container paths (/srv/*) while transcript file paths are host paths (~/*): resolve_corpus_path can never match, so session_files.in_corpus=0 for every row since the container deploy — permanently zeroing the funnel's "commented" stage, the R5 session→comments join, and the A4/A7 in-corpus file links. Fix: per-kb host_path aliases pushed as extra CorpusMounts + one reindex.

mediumNEW-kb-cat-split-brain kb cat resolves ids only against the host-local lance store with no daemon fallback — ids returned by the containerized daemon's own API error "not found" with no hint (this is the B12 mystery's root).

Retrieval

highB8 kb recollect misses the kb project's own directly-on-topic sessions. Sharpest cause: the trailing-dash bug gives every plugin-era capture a dash-suffixed kb-session meta that lance stores verbatim while sqlite holds the canonical id — the join silently drops them; compounding: the embedded digest text doesn't reliably contain the title or any outcome text. 7 of 12 sessions are unreachable via their own exact titles.

mediumB9 kb sessions search = one case-insensitive LIKE '%<whole query>%' over title/prompt/cwd. "episodic memory" can't match "sessions-episodic-memory"; zero matches misreport as "no sessions captured yet".

mediumNEW-recollect-legacy-hybrid recollect retrieves via the legacy blind top-60 RRF hybrid_query — none of the SQ2 fusion/title-boost, SQ4 reranker, or relevance-floor work applies to episodic search. The 2026-06 search-quality program never reached the sessions surface.

lowNEW-recollect-latency Full hybrid fan-out to every corpus with no session-digest pre-filter: ~4.5s observed cold.

lowNEW-digest-not-pullable The verbatim R1 digest (the exact text that gets embedded and ranked) is unretrievable through any CLI/HTTP path — recollect shows a 400-char excerpt truncated mid-word; kb cat dumps the multi-MB raw transcript instead.

lowNEW-no-category-escape-hatch The documented R0 opt-in (?category=memory-session) is HTTP-only: kb search has no --category, so kb search --kb sessions silently returns 0 hits (B12's other half — intended exclusion, missing escape hatch).

CLI ergonomics

mediumB1 list/threads human output omits the session id — the one key every follow-up verb requires. Chaining means re-running with --json + jq.

mediumNEW-limit-not-forwarded kb sessions list --limit is never forwarded to the API: DEFAULT_LIMIT=50 caps every response silently (80 sessions exist; the coverage-gap companion had to work around this).

lowscripting shape list --json wraps rows in {"sessions":[…]}, show --json in {"session":{…}}; epoch timestamps with no ISO twin and no sanity flags — every scripted consumer trips once.

Aggregate views

mediumB10 Threads = exact-cwd + fixed 2-day transitive gap (THREAD_GAP_SECS), nothing else — near-daily work on one project collapses into a 28-session/12-day mega-thread (a 43-session/19-day one exists elsewhere). The design's edited-set-overlap and prompt-similarity signals were never implemented.

lowB11 The "top research queries" rollup aggregates every session_research kind including skill invocations and plan_spans — output is dominated by kb-artifact ×11, deep-review ×10.

mediumNEW-folders-rollup-scope sessions_folders aggregates COUNT/SUM over all capture rows with no newest-capture scoping — an invariant-#11 violation, currently latent only because the prod DB happens to hold zero duplicate rows.

lowNEW-session-files-bare-join session_files_for_basename (kb why's file→sessions join) is a bare WHERE basename = ? with none of its siblings' newest-capture subquery — the exact pattern architecture-invariants.md:220 names as "the bug".

SPA surface

highNEW-focus-deeplink-miss Every /sessions?focus=<sid> deep link (PreviewInspector.tsx:1214, memory.tsx:308, AtlasInspector.tsx:170) resolves only against loaded cursor pages (PAGE_SIZE 50) with no by-id fallback — any target beyond page 1 silently renders the empty "select a session" rail.

mediumNEW-stale-detail-rail The ["session", sid] detail query has staleTime: Infinity but is covered by neither the SSE bridge nor per-hook wiring — after each Stop capture the header shows fresh counts while every body section stays stale (an unrecorded invariant-#23 exception).

mediumNEW-raised-comments-dead R8's "raised-during-session" comments are computed, serialized, and e2e-tested server-side — and rendered by no client: the SPA card early-returns on the structural-only total, the CLI drops the field from both outputs. A raised-only session shows no comments anywhere.

mediumNEW-touches-fetched-discarded Every session selection fires the expensive /touches endpoint (transcript scan + up-to-50k-doc index build on cache miss) whose result has been dead code since commit d6d2cf1a removed its render; the 300ms hover prefetch issues 3 raw fetch() calls that warm neither cache the click path reads.

mediumNEW-save-thread-errors SaveThreadButton swallows HTTP failure (null, no toast — invariant #32 violation) and leaves the button stuck at "saving…" on network rejection; save-thread also stamps every entry with one kb while threads legally span corpora.

lowNEW-why-hook-dead-code useWhy/fetchWhy/EMPTY_WHY survive as zero-consumer dead code from the AS2 panel replacement (useSessions.ts:316-338, api/sessions.ts:235-247).

Refuted / intended (the honest column)

refuted Stale duplicate capture artifacts poisoning recollect: no pre-fix duplicates remain on disk — all 138 session ids are unique.

intended "The digest has no outcomes" is true as described but is R1's intent-only design working as ruled; the fix is an additive outcome field (portfolio P3), not a bug fix. Likewise the tiny-digest search surface and R0's default exclusion were confirmed as intended (invariant #11), with the CLI escape hatch as the real gap.

Did episodic memory help this review? (the dogfooding answer)

This review is itself the best test case: a task squarely about past sessions, run with the tool under review.

  • Worked: kb sessions list --folder instantly framed the working set; show/resume gave real per-session substance (decisions, files, first prompts); kb why sessions.rs surfaced the four design decisions and commit trail that shaped the file — provenance no other tool has. Capture is firing reliably (7 captures that day, including this session's own).
  • Failed: kb recollect "session memory episodic improvements" returned five cross-project sessions at ~0.013–0.016 and none of the three directly-on-topic kb sessions; kb sessions search "episodic memory" returned a wrong "no sessions captured yet"; every digest of the July review sessions hid the actual work behind the subagent blindness, forcing raw-transcript archaeology (jq over multi-MB JSONLs) for ground truth.

So the honest current state: the catalog verbs are load-bearing; the memory verbs are not. An agent that already knows which session it wants is well served; an agent asking "has something like this been done?" — the R3 promise — is not.

The repair portfolio — 45 ideas, 3-judge ranked

Five ideation lenses (agent-UX, digest-fidelity, retrieval, product-workflow, first-principles) generated 45 ideas from the confirmed evidence; a 3-judge panel (agent-value · feasibility-in-this-codebase · strategic fit) scored each 0–10. Cross-lens convergence was strong — four lenses independently proposed the subagent rollup and the exact-title arm — so the now-tier collapses into five programs:

8.7 · S effort · P1 — Resurrect prod linkage: per-kb host-path aliases

Add optional host_path/path_aliases to [kb.*] config; install_corpus_mounts pushes each alias as an extra CorpusMount deriving the same ArtifactId (existing longest-prefix sort handles specificity). Set aliases in the daemon's kb.toml, kb reindex the sessions corpus. Un-deadens in_corpus, the funnel's commented stage, R5 joins, and file links in one small change. Highest score in the portfolio; pure fix-class.

8.3 · S/M effort · P2 — Truthful lifecycle: transcript timestamps + end_reason + terminal capture

Derive started_at/ended_at from MIN/MAX transcript event timestamps (the loop already exists at sessions.rs:534-538); flag rather than silently zero inversions; add active_duration beside wall span for multi-day marathons. Add a deterministic end_reason (clean-stop | interrupted | spend-limit | abort) from tail markers, and register capture on SessionEnd/task-notification turns so background-workflow sessions aren't frozen at their launch snapshot. Existing rows self-heal on reindex. Every recency-dependent feature (recollect decay, R8 windows, staleness labels) becomes truthful for free.

8.2 · M effort · P3 — Findability: outcome field + exact-title arm + --explain

Three deterministic pieces: (1) store the tail of the final substantive assistant message (~1–2 KB, verbatim) as an outcome digest field — indexed into the R1 surface, shown in show/resume; (2) add an exact/near-exact lexical arm over display_name + first_user_prompt to recollect's RRF (same 1/(60+rank) grammar, submission order per invariant #28) so a query that IS the title can never miss; (3) kb recollect --explain [--expect <sid>] printing per-arm ranks — turning every future retrieval miss from a mystery into a bug report. Also fold the B8 dash-suffix reconciliation in here: normalize the lance-stored kb-session meta to the canonical id at index time.

7.9 · L effort · transformative · P4 — The subagent rollup

Two deterministic layers: (1) parse task-notification <usage> blocks (agent_count, tool_uses, subagent_tokens, duration, failures, workflow name) into a subagents digest section — cheap, immediate, fixes the headline counters; (2) have kb-capture.sh append sibling subagents/agent-*.jsonl content so subagent Reads/Edits/commits flow into files/research/commits tagged via_subagent:true, kept out of main counters. The feasibility judge flagged the real risk — concatenating multi-MB sidechains into the capture <pre> could balloon lance — so layer 2 should extract tool_use lines only, not full transcripts. Do layer 1 immediately; sidechains are perishable.

7.5 · M effort · P5 — Commit truth + deliverable ledger

Rework extract_commits into a verify-against-git pass: emit rows only for mutating commands with success results, scan all [branch sha] output lines (catching &&-chained commits), resolve every subject via git -C <cwd> show -s --format=%s, dedupe on (kind, sha), stop classifying read-only git tag as writes, and record repo/branch so multi-repo sessions attribute correctly. Ingest pr-link events as first-class deliverable rows, and link in-session kb remember ids + kb-artifact skill outputs to the session so kb why <deliverable> finally resolves.

Next tier (7.3–6.3)

  • Resume block v2 (7.3) — goal + branch + outcome + verified commits + open loose ends; today's 3-line block would not save a resuming agent one minute.
  • Capture hygiene (7.3) — fix the sid trailing dash at the source, add stderr logging to the hook's failure paths, a captures-enumeration verb (invariant #11 makes multi-capture invisible even to debugging).
  • Agent scripting contract (7.0) — uniform --json envelopes, ISO timestamps beside epochs, sanity flags, ids in human output (B1), forward --limit/cursor (the 50-cap bug).
  • /kb-distill (7.0) — agent-layer LLM memo written back as a linked memory; the daemon stays deterministic, the episodic→semantic bridge gets built where LLMs are allowed. (Shipped 2026-07-06, commit db7ce381 — see the next-prompts playbook F1 entry.)
  • Recollect latency + affinity (6.7) — category-prefiltered session search; folder/cwd affinity tier in ordering.
  • R0-safe reachability (6.7) — --include-sessions opt-in on search + a redirect hint when an excluded row would have matched.
  • Error taxonomy (6.3) — typed error rows (kind + first-line excerpt + subagent failures) instead of a bare count.

Later / probation

  • Delete the funnel and research rollups; threads on probation (6.0) — the strategy judge rewarded this: both aggregates are broken in ways nobody noticed (commented=0 forever, skill-dominated "research"), which is usage evidence. Repair P1/P5 first; if the funnel still isn't consulted after its inputs become truthful, remove it.
  • One query surface / revisit pull-only (5.3) — giving kb recall an opt-in episodic arm, or one-line episodic hints in the recall hook. The panel ruled the R3 pull-only decision stays until the pull verbs actually work — retrieval quality, not the ruling, is the bottleneck today.
  • Week-in-review rollup (4.7), threads from shared work-product (4.3) — real ideas, wrong quarter; both depend on P2/P4/P5 data being truthful first.

Suggested phasing

The five now-programs are one coherent milestone track ("truthful sessions"): P1 and P2 are small and unblock everything recency- and linkage-dependent; P3 makes the memory verbs earn their names; P4 layer 1 is a parser change; P5 turns provenance from fiction to fact. Acceptance test: re-run this review's fidelity harness (12 newest sessions, digest vs transcript, same rubric) and require mean usefulness ≥4/5, zero fabricated provenance, and recollect hitting an exact-title query at rank 1 in 12/12. The harness prompt is in this artifact's kb-prompt template; the workflow scripts are resumable (wf_1c23d6c7).

Relation to prior rulings Nothing here reopens a recorded refusal: every program is deterministic and LLM-free in the daemon (the one LLM idea, /kb-distill, lives in the agent layer like /kb-reflect); the digest-not-JSONL and pull-only rulings are strengthened, not revised — the review's sharpest finding is that the rulings were right and the plumbing under them was never held to their standard.
