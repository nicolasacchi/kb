kb sessions & share — a visual tour of v0.20

Two tracks landed in v0.20: Sessions “follow the work” turns captured Claude Code transcripts into a navigable record of what each session did, and self-contained Share lets any artifact leave the instance as a portable bundle or single page. This walkthrough shows each capability in the running UI and CLI, and maps every one back to the seven original asks.

What shipped — the seven asks

The work started from seven concrete asks about the sessions feature. Every one is satisfied; the phases (P0–P8) below group them by where they surface. The self-contained share track (FS-A–FS-E) shipped alongside.

AskWhat it meansWhere to see it
A1Separate sessions by their working directory (folder)Sessions index — folder facet
A2Readable names, not session-<ts>-<sid>.htmlSessions index — row titles
A3Show the first user interaction on the indexSessions index — subtitle line
A4Link the files a session changed / read / usedInspector — Files touched
A5Keep raw JSON behind a button; parse it cleanly otherwiseTranscript — “view raw” + parsed Q&A
A6Summarise files read/edited, including outside kbInspector — Files touched
A7Make the session↔file link visible from both endsBidirectional links

Beyond the asks, the journal layer adds decisions (P3/P4), effort stats and a resume card (P4), git-commit linkage (P5), sessions search + per-project rollups (P6), narrative threads (P7), and save-thread-as-list (P8).

The sessions index — folders, names, first prompts

A1 · A2 · A3 · A4 · P1

The index reads like a worklog. Sessions are grouped by date, each row carries the readable title derived from the first prompt A2/A3 (never the timestamped filename), a folder badge A1, and at-a-glance counts — messages, files edited A4, duration. The folder facet in the header (“all folders / api (1) / widget (2)”) filters to one working directory, and the list / threads toggle switches view.

The session inspector — decisions, commits, files, resume

A4 · A6 · P3 · P4 · P5

Selecting a session opens a detail panel that is the heart of “follow the work”. In one view:

  • Effort stats P4 in the header — 7 messages · 2 edited · 4 tools · 9k tok · claude-opus-4-8.
  • Decisions P3 — every AskUserQuestion rendered as a clean question → answer pair, no JSON.
  • Commits P5 — git commits the session produced, parsed from the transcript (a1b2c3d4 · feat: dark-mode toggle).
  • Files touched A4/A6 — edited vs. read, including paths outside the kb corpus.
  • Resume context P4 — a copy-ready brief (goal, edited files, decisions, commits) to hand to the next session.

The rendered transcript — parsed, with a raw escape hatch

A5 · P3

Opening the transcript renders the JSONL into a readable conversation — a header with model, cwd, branch, turn counts, tool calls, duration and token totals, then each turn as a collapsible block. The AskUserQuestion turn shows “◆ you answered” with the parsed question and answer P3. The raw JSON is never gone: a “view raw” link and a per-message “raw” toggle keep it one click away A5.

Bidirectional session ↔ file links

A7 · P2

The link works from both ends A7. From a session, Files touched links out to what it changed. From an artifact, the reader’s inspector grows a “Sessions” section listing the sessions that touched it — here, the caching deep-dive shows the session that edited it, with the action (edit) and a link back into the sessions view.

Search & per-project rollups

P6

A search box filters sessions by their content P6. Select a folder and a per-project rollup header summarises the whole project at a glance — widget · 2 sessions · Jun 20 – Jun 20 · 4 files edited · 17k tok.

Narrative threads

P7

The threads view clusters sessions in the same folder that form a continued effort — a run with no gap larger than two days P7. Here the two widget sessions (the dark-mode toggle, then persisting the preference) collapse into one thread spanning Jun 20, while the API session stands alone. Each thread also carries a “save as list” action (next section).

Save a thread as a reading list

P8

Clicking “save as list” on a thread materialises it into an editable kb-list/1 reading list P8 and jumps to it. The list holds one entry per session, reorderable and annotatable like any list, with markdown / json export. Because a transcript has no “read” progress, each session entry shows a neutral ◆ marker instead of a read-state dot — read-state is suppressed for session entries by design.

Self-contained share

FS-A · FS-B · FS-C · FS-D · FS-E

The Share dialog now offers three ways out of the instance: Publish online (a gated or public live URL), Download bundle — an offline .zip with in-share cross-artifact links relativised so it works as a self-contained set FS-A–D, and Download page — the single open page in its native format FS-E.

Choosing Download page collapses the host/audience options — they don’t apply to a lone file — and explains exactly what you get: a self-contained .html (or the raw .md source) with the kb-prompt stripped and outbound redactions applied.

  2026-06-20 09:00Z  [sessions/widget]  Add a dark-mode toggle to the settings panel

kb sessions threads clusters the same way the SPA does:

$ kb sessions threads

How it was verified

Green across the board Every screenshot above came from a release daemon built at HEAD f3203573, serving a local corpus seeded with the synthetic sessions shown. The milestone shipped with kb-core 872 unit tests, kb-server + kb-cli 266 integration/e2e tests, 158 SPA vitest cases, and Playwright specs covering the full sessions surface (P0–P8) plus share — all passing — and is deployed live on kb.example.com.

The synthetic data is deliberate: the production instance holds real session transcripts of actual work, which are private, so this tour uses a throwaway demo corpus that exercises every code path without exposing anything. To regenerate the tour, re-seed the same transcripts and re-capture — never point the camera at prod.
