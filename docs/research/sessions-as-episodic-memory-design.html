Sessions as episodic memory for Claude Code

kb already captures and parses every Claude Code session. This design turns those captures into a pull-only episodic memory the agent queries to reconstruct why something was done and whether something similar was done before — kept strictly distinct from the curated semantic memory it sits beside.

1 · Problem, restated precisely

kb already captures every Claude Code session verbatim — the Stop hook plugins/kb-memory/hooks/kb-capture.sh wraps the raw JSONL transcript in HTML, stamps kb-category=memory-session, and drops it in the [kb.sessions] corpus, indexed write-only and never rewritten (invariant #27). It already parses each one deterministically — sessions.rs::parse_session_activity extracts the title, cwd, files touched, decisions (AskUserQuestion answers + plan approvals), effort, and git commits into per-kb sqlite (sessions / session_files / session_decisions / session_commits).

What is missing is retrieval. Today sessions are only browsable (GET /api/sessions, kb sessions list/folders/threads/show). The asks:

  1. Let the agent search old sessions to learn WHY something was done and find whether something SIMILAR was already done — with the tools to do it.
  2. Add a derived insights layer over the captures (how kb was used, what was researched) that also links to comments (the session↔artifact link already exists).
  3. Keep it conceptually distinct from the curated agent-memory (kb remember / recall).

Three code-verified facts reshape the design:

Live latent bug — fixed by R0

~/deploy/kb/kb.toml sets [kb.sessions] memory_scope = "global", and the recall fetch (routes/memory.rs:252-273) runs hybrid_query / bm25_query / list_docs with no category filter. The capture hook stamps no kb-salience, so a transcript defaults to 0.5 and clears the 0.15 Balanced floor. Net effect: multi-MB raw JSONL transcripts are injected into every-turn recall on the live kb.example.com deployment, and they dilute normal document search (the FTS/vector queries at lance.rs 626/744/776 carry no category predicate either).

  • The transcript is unsearchable as itself. A session <body> is one giant <pre> of raw JSONL; the embed source is fields.body (indexer.rs:1092). It retrieves badly for itself and pollutes everything else.
  • WHY already exists as joins. session_files_for_artifact (reverse link via target_artifact_id), session_decisions_for_session, session_commits_for_session, first_user_prompt, the lance kb_session column, and the federated reverse route artifact_sessions (sessions.rs:878). WHY is an assembler, not a new index.

2 · The conceptual model: recall vs recollect

The two-tier split the asks are groping toward is the canonical episodic vs semantic memory distinction (Tulving → CoALA). Prior art is unanimous that kb is structurally correct and must not merge the two.

recall — existsrecollect — new
Memory typeSemantic — "what tends to be true"Episodic — "what happened in this case"
SourceCurated by kb rememberAuto-captured verbatim transcript
MutabilitySupersede / forget at recall timeAppend-only, never rewritten (#27)
DeliveryPushed every turn (kb-recall.sh)Pulled on demand (agent calls a verb)
Ranking1/(60+rank) × salience × exp(-k·age)rel × recency-decay × success-boost (success a capped tie-breaker)
Answers"What do I know?""Why was X done? Has Y been tried?"
Asserted as truth?YesNo — evidence with provenance + staleness

The one-liner that must never blur: kb recall pushes curated semantic facts the agent asserts as currently-true (they decay, supersede, forget). kb recollect / kb why pull immutable episodic evidence the agent reasons over to reconstruct why/whether-before — with provenance and staleness, never asserted as current truth, never auto-injected.

They interoperate only through a deliberate one-way promotion (episode → fact), deferred to R6. Promoted facts land in the existing project/global memory corpus (not the sessions corpus), so R0 can sever sessions from recall cleanly while promotion keeps a scoped home. Never auto-promote (re-pollutes the semantic tier) and never auto-inject sessions — the documented #1 cause of context rot and the memory-self-reinforcement poisoning vector.

3 · Retrieval — WHY + SIMILAR

The two needs want different machinery and ship as two verbs.

WHY — kb why <path|artifact-id> (a structured join, not a search)

Reuse session_files_for_artifact (fanned out by artifact_sessions) to find the sessions that touched a path, ordered by edit-strength (edit > write > read) × recency, then inline the already-extracted first_user_prompt, decisions, and commits. The answer is fully deterministic: "this file is like this because you asked X, decided Y, it shipped as commit Z." Two caveats the assembler must handle:

  • Fuzzy-match false positives. Path→session matching is basename-fuzzy (TouchesConfidence::Fuzzy, sessions.rs:838): a same-named file in another folder can false-positive. Prefer target_artifact_id + canonical paths and label fuzzy hits rather than asserting them.
  • Second-order fan-out. artifact_sessions does a per-session lookup_session after its buffered_join (sessions.rs:914) = O(sessions × corpora). For a hot file, batch the session-metadata lookup (one fan-out keyed by the id set) — never a nested per-session fan-out loop (#28).

SIMILAR — kb recollect <q> over a clean digest surface

Genuine semantic retrieval, and it must not search the JSONL blob. The digest (§4) becomes the embedded/FTS unit; recollect runs federated hybrid search over digests, RRF-fused, then re-ranked with a deterministic, memory::rerank-shaped score: rel × recency_decay(started_at) × success_boost.

Success is a tie-breaker, not a multiplier

Commit SHAs are "detected, not ground truth" and a session may commit work unrelated to the matched digest, so success_boost is a low-default, tunable, capped tie-breaker — not a primary multiplier — and each hit surfaces success/error/recency as separate fields the agent weighs. A golden test pins the failure mode: a high-error, no-commit exploratory session with a stronger digest match must outrank a tangentially-committing session for a "why" query.

Staleness is queryable metadata, never deletion (the #1 documented failure mode is a confidently-wrong old session explaining a since-rewritten subsystem). Computed at query time from started_at age, whether touched files changed/were deleted since, and whether decisions were later superseded — returned on each hit, nothing mutated (#27). This is v1 scope: shipping recollect without staleness ships a hallucinated-rationale generator.

The interface is pull-first. recollect and why are CLI verbs the agent invokes deliberately, advertised by one SessionStart line and a skill. Nothing is injected per turn.

4 · The searchable surface — embed the digest, not the JSONL

The single highest-leverage change. For kb_category == "memory-session" rows the indexer substitutes a deterministic insight digest — title, first user prompt, decisions (Q→A), research queries, commit subjects, edited+read basenames, cwd/branch — assembled from fields the parse already produces. The raw transcript stays verbatim on disk and is served unchanged (#27). Net effect: vector + BM25 + the reranker see clean, dense, meaning-bearing text. This is the "index by description, not raw body" pattern (Voyager / Document-Summary-Index).

Three override points — all must be intercepted
  1. embed_body — indexer.rs:1092 (fields.body.clone()).
  2. chunk source fields.body — indexer.rs:1154 (conditional: sessions aren't chunked in the live config — no chunked in kb.toml — so wire it but drop the unconditional chunk-from-digest snapshot test from v1).
  3. body_text_excerpt — parser-derived (parser.rs:413, threaded at indexer.rs:1211): override a parser output, not a local let.

Shared parse. The digest needs SessionFacts (first prompt, started_at, message_count) and the JSONL activity, so it must share parse_session_html_full (sessions.rs:228, the wrapper the hook calls at enrich.rs:139) — not parse_session_activity (:263, the <pre> sub-parse, which lacks SessionFacts).

One writer. The embed/chunk run in index_file before the post-upsert SessionCaptureHook. So index_file runs the shared parse itself pre-upsert, builds the digest, embeds it, and writes session_insight.insight_text there — one writer, no drift; the hook is demoted to writing only the child rows. A sidecar .insight.html artifact is rejected: it doubles the artifact count, needs its own gallery/atlas exclusion, and writing it into a watched dir triggers a re-index feedback loop.

Secrets. The digest is assembled only from structured fields (titles, queries, basenames, commit subjects) — never arbitrary prose — so it cannot smuggle a secret into the vector/FTS index; any non-loopback serve inherits the existing scrub (#9). The digest is the data-minimization point so the agent's common path never re-reads the raw blob.

4a · The exclusion mechanism — spike before committing

R0 must stop transcripts polluting default search and recall. The mechanism is unproven and load-bearing: .only_if("kb_category != 'memory-session'") is used nowhere alongside full_text_search()/nearest_to() in lance.rs today (only plain scans at 994/1039/1098/1473/1513). Whether the pinned lance pushes a prefilter through a fused FTS+vector query — and whether it pre- vs post-filters (corrupting RRF / under-filling limit) — is unknown.

So R0 leads with a throwaway spike. If .only_if composes and pre-filters, use it. Else the proven fallback: post-query filter on the already-projected kb_category (SEARCH_PROJECTION, lance.rs:593) in MetaFilters::keep with a documented over-fetch multiplier. The recall path needs its own exclusion (it bypasses MetaFilters): exclude memory-session corpora in in_scope (memory.rs:117) or post-fetch-filter the recall row-set — and do not blindly drop memory_scope from kb.toml (audit consumers; SessionCaptureHook is category-driven and independent of it).

5 · Insights layer — research extraction + comments

"More of the same parse, more child tables." Today the parse mines tool_use blocks only for file actions and Bash-git; it walks past Task (subagents), WebSearch/ WebFetch, MCP tools, Skill/slash-commands, ExitPlanMode, and the kb CLI driven via Bash (kb search|recall|find|remember|comments). All extractable from the same content[] array, reusing the git_action_of Bash segmenter (sessions.rs:553) as the proven precedent.

Data (R4). One additive migration V0021 mirroring V0017–V0019: a session_research(artifact_id_session, session_id, seq, kind, query, target_kb, target_artifact_id) child table (kind ∈ kb_search|artifact_open|web|skill|subagent|plan_span) with indexes, plus the 1:1 session_insight (introduced in R1 as V0020; insight_text + scalar counts), keeping the multi-hundred-byte insight_text out of the wide sessions row scanned by sessions_list. Backfill is free: one reindex re-runs the parse and replaces all child rows with no source rewrite (#27).

Honesty framing. Parsing kb-CLI intent out of free-form Bash (quoting, pipes, env X= prefixes, aliases) and version-varying Task/MCP block shapes is heuristic — extract via version-tolerant .get().and_then() chains, frame as "detected, not ground truth" like git SHAs (#10), and pin each tool-block shape with golden tests so extraction can't silently drift across Claude Code versions.

Comments linkage — a computed-on-read join, no new edge table

Comments mutate independently (resolve/reply/reanchor long after a session ends), so a persisted edge goes stale instantly. The chain already exists: session_files.target_artifact_id → that artifact's review file via the canonical GET /api/reviews?artifact_id= (never reading .review/*.json directly — #6). GET /api/sessions/{sid}/comments collapses the session's touched in-corpus artifacts and fans out reviews via buffered_join (#28).

A temporal variant ("comments raised during this session") is nearly free: history_record_comment (sqlite.rs:515) timestamps every comment creation, so a window query over [started_at, ended_at] (the mechanism /readings already uses) gives it — but history is per-kb and a session's comments span corpora, so the window must federate across per-kb history via buffered_join, and ended_at can be null on crashed sessions (fall back to a bounded window from started_at). There is no resolved_at in kb-comments/1, so "resolved during" is out of scope without touching #6; ship "raised during" + "comments on touched artifacts" only.

Aggregation (capstone). Build on /api/sessions/folders and /threads: per-folder/per-thread research rollups (top kb queries, top web queries, hot artifacts, most-used skills/subagents) and the deterministic funnel — searched → opened → edited → committed → commented — all GROUP BY over the new tables, summed cross-corpus exactly like folders(). The literal "what has this project been researching" view.

6 · Agent & human surfaces

Agent (pull-first):

  • kb why <file> — recall-formatted WHY answer (fuzzy hits labelled; batched lookup).
  • kb recollect <q> [--folder] [--since] [--similar-to <sid>] — federated digest search, recall-shaped output (N sessions in M ms, then <sid8> <title> [<kb>/<folder>] score= + why/decision snippet + separate success/error/recency fields + a staleness flag), capped ~8 hits so it never floods context.
  • New federated GET /api/why and GET /api/sessions/recollect on routes::buffered_join (FANOUT_CAP=8, submission order, drop-on-error — #28; no std::sync::Mutex across the fan-out await — #15).
  • One SessionStart discovery line in kb-wake.sh; a kb-research-style SKILL.md documenting the verbs. No per-turn injection.

Human (SPA): extend the existing A7 SessionsTouchedPanel (PreviewInspector.tsx) into a "why is this like this" answer (each touching session's decision/why-snippet, deep-link to /sessions?focus=<sid>); a research-insight card on sessions.tsx; the research funnel on the folder/thread card. Reuse the SSE SharedWorker bridge (#24) for live refresh.

7 · Where (if anywhere) an LLM belongs

Everything above is deterministic (#10). The only justified LLM use is an optional, offline, opt-in kb sessions distill (deferred to R6) that reads the deterministic digest, calls a local model, and writes a one-line "what & why" as a kb remember-style curated fact stamped kb-session, flowing into the existing recall system in the project/global memory corpus — never a new store, strictly off the retrieval/index hot path. The deterministic digest is always the source of truth and the fallback.

Honest dependency caveat

bge-small and the cross-encoder reranker are not generative — a local generative model is a net-new process the project does not host today. "Reuses the kb-embedder IPC isolation (#26)" is pattern reuse, not an available model. R6 is deferred so the deterministic core ships and proves the search win first; distill is a no-op when no model is configured.

10 · Risks & mitigations

  • Lance composability (foundation of R0/R1). .only_if runs nowhere alongside FTS/vector today. → R0 leads with a spike; proven post-query kb_category filter + over-fetch is the fallback; recall needs its own exclusion.
  • Shared-parse + write ordering. Digest needs parse_session_html_full (not :263); three override points (one outside index_file); single writer for insight_text pre-upsert.
  • Success-signal false positives. Capped tie-breaker + separate fields + a golden test pinning exploratory-beats-tangential-commit.
  • Fuzzy path attribution. Prefer target_artifact_id + canonical; label fuzzy hits.
  • WHY fan-out amplification. Batch the per-session lookup; never nested fan-out (#28).
  • Heuristic extraction drift. Version-tolerant accessors; golden test per tool-block shape; "detected, not ground truth".
  • Secrets in transcripts. Digest from structured fields only; non-loopback inherits the scrub (#9); the digest is the data-minimization point.
  • Staleness is mandatory in v1 — query-time trust signal, never deletion/rewrite (#27).
  • Comments-join federation + null ended_at. Federate the per-kb history window; bound from started_at on crashed sessions; bound per-artifact review lookups.
  • Table sprawl + cascade discipline. V0020/V0021 follow wholesale-replace + sessions_delete cascade (#11), keep insight_text out of the wide row.
  • Test-count guard. R0 flips existing transcript-in-results/recall tests; enumerate them so the per-crate count change is expected (CLAUDE.md guard), not a surprise.
  • Poisoning / self-reinforcement. Sessions stay pull-only and descriptive; promotion (R6) is deliberate and never automatic.

11 · Prior-art lineage

  • Tulving — episodic vs semantic memory; CoALA (arXiv:2309.02427) — episodic/semantic/procedural memory + internal vs external actions → the "pull" framing.
  • Letta / MemGPT — passively-recorded recall memory vs agent-queried archival memory → the push/pull split.
  • cass — Rust, SQLite-as-truth + Tantivy BM25 + FastEmbed + RRF (near-identical to kb's stack); raw, pull-only session search; trust_tier / stale_reason; refuses write-time summarization.
  • "Encode rich, consolidate later" (arXiv:2502.06975) — validates verbatim capture, warns against write-time distillation.
  • Voyager / Document-Summary-Index — index by NL description, not raw body → the digest-embed fix.
  • ReasoningBank {title, description, content} — the optional distillate shape (R6).
  • AgentLeak — logs leak >60% of secrets → digest-from-structured-fields-only.
  • Memory self-reinforcement — sessions-injected-as-guidance poisoning vector → never auto-inject/auto-promote.

12 · Deferred

  • R6 — optional offline LLM distill (kb sessions distill) + explicit episode→fact promotion (kb sessions promote); needs a net-new local generative model surface.
  • Decision-level / passage-level retrieval (finer than whole-session) if whole-session proves too coarse.
  • Session chunking on the digest — moot today (sessions aren't chunked); wired conditionally.
  • "Resolved during this session" — needs resolved_at on kb-comments/1 (#6 cost).
  • Cross-session "were the edits later reverted / re-touched" as a real success signal beyond commits.
  • A procedural-memory layer (Voyager-style retrievable recurring workflows) — the untapped CoALA third axis.
  • An MCP tool surface for the verbs — a skill is the recommended ergonomic; MCP is a net-new always-on process.
  • Conditional "why/has-this-been-done" prompt-shape push — pull ships first; push only if pull proves insufficient.
  • Timeline view (already deferred) + any aggressive archival/compaction policy for the unbounded episodic corpus.
