kb sessions — follow-the-work design

The sessions corpus already parses almost everything the user wants — folder, title, first prompt, file edits, decisions — and then throws it away on every serve. The plan turns one shared extractor and one widened table into a navigable work journal: readable rows grouped by project, bidirectional file links everywhere, and a follow-the-work layer of decisions, commits, timelines and resume cards.

Thesis & the seven asks

A kb session is a captured Claude Code transcript: the Stop hook plugins/kb-memory/hooks/kb-capture.sh HTML-escapes the raw JSONL, wraps it in one <pre>, and drops session-<ts>-<sid>.html into the [kb.sessions] corpus. Today the corpus is a flat, day-bucketed stream of cryptically-named blobs. The opportunity: the renderer already extracts the working directory, the AI title, the first prompt, every file edit and every steering decision on each serve — and discards all of it. The plan persists that extraction once at index time and builds a work journal on top.

The user framed seven concrete asks (labelled A1–A7) plus a meta-goal — "a tool that helps the end user follow the work." Each ask maps to one or more numbered features (S1–S10):

AskWhat the user wantsFeatures
A1Separate sessions by their per-session folder (kb has no folders, but each session has a cwd).S3, S4, S5
A2A readable name instead of session-20260618T071023Z-8fb51651-…html.S3, S4, S5
A3The index shows the first user interaction so each row is self-describing.S1, S4, S5
A4Link the files a session changed / read / used (to the kb artifact where one exists).S2, S3, S6, S7
A5Parse everything nicely by default; raw JSON only behind a button; AskUserQuestion shown as clean Q&A.S8
A6A summary of files read & edited, including files outside any kb corpus.S2, S3, S6, S7
A7Bidirectional session↔file links visible everywhere — and the reverse, an artifact showing the sessions that touched it.S6, S7
metaFollow the work over time.S9, S10

How sessions work today (and where they leak)

The pipeline is three stages, confirmed against the source. There is no contradiction between the "dumb" capture hook and the 1,743-line renderer — they are different stages.

The three stages

  • Capture (kb-capture.sh) — escapes the JSONL into one <pre>, stamps kb-category=memory-session, kb-session=<sid>, a hardcoded <title>Session transcript <ts></title>. Zero extraction. The on-disk file is the lossless store and is never rewritten.
  • Index-time enrich — enrich.rs's SessionCaptureHook (the first ordered hook) calls sessions::parse_session_html and upserts one slim V0008 row into the per-kb sqlite sessions table, so /api/sessions never re-scrapes the multi-MB body.
  • Render-on-read — crates/kb-server/src/routes/artifact.rs (~L652) calls session_render::render_if_session on every serve, after the outbound scrub and before probe/runtime injection. It re-parses the <pre> JSONL into user/assistant cards, collapsible tool calls, decision cards, a jump rail and a header summary. A renderer change needs no reindex.

What already works

session_render.rs already deserializes and renders cwd, gitBranch, aiTitle, every Read/Edit/Write/Bash tool call, AskUserQuestion answers, plan approvals, token usage and duration. A2 is half-done: aiTitle drives the in-page <h1> (derive_summary, L576–580) but not the artifact <title>, the kb list title, or the filename. A5 is mostly done: AskUserQuestion is already parsed into a decision card (render_user_decision, L1045; parse_qa_pairs, L1103), and raw JSON is not the default — only malformed lines fall back to a <details>.

Where it leaks

Confirmed gaps
  • The data is extracted and discarded. V0008 persists exactly 7 columns (artifact_id PK, session_id, started_at, ended_at, message_count, first_user_prompt, source_relative). cwd, git_branch, file edits and decisions live only inside the HTML.
  • A3 first-prompt extraction is bugged. The render-path extractor (first_text_of) picks the <local-command-caveat> wrapper on modern transcripts, not the typed prompt. The clean signal is promptSource == "typed" with a wrapper-stripping fallback for old (v2.1.148) transcripts.
  • Two divergent first_user_prompt implementations already exist (sessions.rs 200-char vs session_render 280-char) — adding more extraction without factoring one parser guarantees a third.
  • A5's AskUserQuestion card is silently broken on recent sessions. It matches only the prose prefix "User has answered your questions: ", but the dominant form is now "Your questions have been answered: " (~70 vs ~31 in-corpus), so the Q&A card falls through to raw text on most recent sessions.
  • No session→file table. /touches is a per-request whole-transcript substring scan, corpus-only, with no read/edit split and structurally blind to out-of-corpus files (A6). There is no reverse artifact→sessions endpoint.
  • A1 folder grouping is absent end to end. cwd is parsed but persisted nowhere; the list is a flat cross-kb day stream. cwd is not a session constant — ~60% of sessions span 2–5 directories.
  • The open-artifact link mis-resolves. The runtime posts open-artifact with a raw absolute file_path, but detail.tsx treats it as source-relative.
  • ended_at is wrong. It is the capture mtime, not the last-event timestamp, so /readings windows and durations are imprecise.

Foundation: one extractor, one migration (S1, S2)

Everything downstream rests on two pieces of groundwork that change no user-visible behaviour (beyond the A3 fix). This is phase P0.

S1 — the one shared pure extractor

Add a single pure parse_session_activity(transcript) -> SessionActivity in crates/kb-core/src/sessions.rs, and refactor session_render to call it so the rendered view and the persisted row can never drift. The struct carries everything the asks need:

SessionActivity {
  ai_title,            // LAST aiTitle line (current code wrongly takes the first)
  cwd, all_cwds,       // modal key + the full set
  git_branch,
  first_user_prompt,   // fast path: first user line with promptSource=="typed";
                       // fallback: first non-meta/non-sidechain user line NOT
                       // starting with 
  ended_at,            // max event timestamp
  files: [FileTouch{ abs_path, action: read|edit|write }],
  edited_set,          // authoritative: LAST file-history-snapshot.trackedFileBackups
  questions: [QA{ question, chosen, options }],
  errors, token_total, tool_calls, model,
}

Golden-test it against three fixtures: a modern transcript with promptSource (e.g. f7ab49ec), an old transcript without it, and an AskUserQuestion turn. This single change fixes the bugged A3 extraction and removes the duplicate first_user_prompt logic with no schema change.

S2 — V0017: widen the row, add the edge table

One combined migration (next free slot is V0017; V0016 is the latest on disk) because cwd, title and git_branch are wanted by three different clusters — uncoordinated ALTER TABLEs on sessions would collide.

  • Widen sessions: add title, cwd, git_branch, files_read_count, files_edited_count; add idx_sessions_cwd; correct ended_at to the last-event ts. All additive/nullable so old rows backfill on reindex.
  • Add session_files: (artifact_id_session, session_id, abs_path, basename, action CHECK(read|edit|write), in_corpus, target_kb, target_artifact_id, occurrences, first_seen, last_seen), PK (artifact_id_session, abs_path, action); indexes on session_id and target_artifact_id. Populated once at index time; deleted in the indexer unlink pass beside sessions_delete (model on V0014's cascade child).
Lockstep hazardSessionRow, the V0008/V0017 column list, sessions_upsert, sessions_list COLS and map_row must all move together — a single missed column shifts every positional r.get(N) and silently corrupts the mapping (sqlite.rs ~L1921–1990). This is the most error-prone change in the whole plan; add a row-count assertion test.

Identity & index — A1, A2, A3 (S3, S4, S5)

S3 — persist identity & file edges from the enrich hook

The central architectural move. Extend SessionCaptureHook::enrich to call parse_session_activity on ctx.html and persist: title = ai_title (fallback first prompt), the modal cwd, git_branch, the corrected ended_at, and the counts. For each file touch, canonicalise the path via paths::canonical_abs first (invariant #27 — symlinked roots like macOS /var or WSL mounts otherwise fail silently), prefix-test it against the mount table, and resolve an in-corpus path to its artifact id purely via ArtifactId::from_path(doc_rel_path(abs, root)) with no doc lookup. Out-of-corpus paths persist with in_corpus=0 and a plain path (A6). Write through session_files_replace (one transaction) via a new StorageHandle verb.

The fork, resolvedEnrichCtx today knows only the current kb, but a session in [kb.sessions] routinely edits files under [kb.kb]. Resolution: widen EnrichCtx with &[(KbName, source_root)] from state.kbs and resolve at index time. The mount list is small and static-ish; this makes both the file manifest and the reverse lookup pure indexed seeks — exactly what A7 needs.

S4 — server: display_name, folder, the folders route

SessionOut gains a server-computed display_name (title → first_user_prompt → sid[:8], never null — no client label drift) and a folder (basename of cwd, full cwd in the tooltip). Once title is a column, drop the per-row get_by_id().title lance read. Add GET /api/sessions/folders → {folder, count, latest}[] via buffered_join (invariant #28), and a ?folder= param applied per-kb before the cross-kb merge so keyset pagination stays correct.

S5 — SPA: two-line rows, first interaction, folder filter

Centralise sessionDisplayName(row) in web/src/lib/, reused by SessionListRow, SessionInspector and SessionPicker. Render the agreed two-line row and the folder-filter-then-day-buckets layout:

┌ Sessions ──────── [Folder: kb ▾] ────────┐
│ ── Today ──────────────────────────────  │
│  ● Evolve sessions into a journal          │  ← bold aiTitle (display_name)
│    "review the sessions, make them more…"  │  ← dimmed first_user_prompt
│    kb · 2h · 14 files · 3 decisions        │  ← meta strip
│  ● Fix SSE reconnect race                  │
│ ── Mon Jun 23 ─────────────────────────   │
│  ● Relativize share permalinks             │
└───────────────────────────────────────────┘

The folder dropdown is fed by /api/sessions/folders and defaults to all; selecting one threads ?folder= through the keyset query, and the day buckets render within it.

File activity & bidirectional links — A4, A6, A7 (S6, S7)

S6 — files endpoint + reverse artifact→sessions endpoint

With session_files persisted, both link directions become cheap indexed reads instead of multi-MB scans:

  • GET /api/sessions/{sid}/files → rows grouped read|edit|write; out-of-corpus rows carry plain paths (A6).
  • GET /api/artifacts/{kb}/{id}/sessions → the sessions that touched this artifact, newest-first, backed by an index on target_artifact_id, collapsing actions per (session, artifact) to max severity (edit > write > read).

Both fan out across kbs (a session in one corpus touches files in another) via buffered_join(FANOUT_CAP=8) in BTreeMap order, folding partials and dropping-on-error — never a serial loop or a ?-propagate (#28, #15). /touches becomes a thin shim deriving ids from session_files WHERE in_corpus=1; the per-request touches_cache retires.

S7 — SPA: the manifest, the reader panel, the link fix

  • Session side: replace the bare <code>{id}</code> "artifacts touched" block with a grouped read / edited / created manifest — in-corpus files as <Link to=/a/{kb}/{source_relative}>, out-of-corpus as muted <code> with copy + "show N more" folding away target/, node_modules and lockfiles.
  • Artifact side (A7): add a "Sessions that touched this file" panel to PreviewInspector in detail.tsx, fed by the reverse endpoint, mirroring the existing memory "from session" line with a session-colour swatch; lazy-fetch, invalidate on the session.captured SSE event (invariant #23).
  • The fix: normalise the open-artifact message — the runtime posts a raw absolute file_path but detail.tsx treats it source-relative. Stamp a source-relative data-path at render time (reuse S3's resolution) or extend the message to carry kb + target_artifact_id.

Presentation — A5 (S8)

A5 is mostly satisfied at render time; the work is to fix the silent breakage and add the raw escape hatch. This phase depends only on S1, so it can ship right after P0.

  • Fix the decision card: add a "Your questions have been answered: " arm to render_user_decision reusing parse_qa_pairs, and — more durably — read the structured toolUseResult.answers map keyed against questions[] so a future wording change can't break it; keep the prose match only as fallback. Handle multiSelect (array → <ul>).
  • Per-block raw: add a <details class="ses-rawblock"> with pretty JSON on the lossy cards (tool_result, decision, attachment). Update the runtime's expand/collapse selector from :not(.ses-debug) to :not(.ses-debug):not(.ses-rawblock) in lockstep, or "expand all" becomes a wall of JSON.
  • Whole-session raw: add wants_raw(&uri) (mirroring wants_annotator) gating the render call at artifact.rs ~L650. A ?raw=1 request skips only session_render — never the kb-prompt outbound scrub (#5/#9). build_document emits a "view raw transcript" download link.
Render costRender-on-read means every presentation change re-runs on each serve over a 2–6 MB body. The richer cards plus the structured-answer pairing compound that cost; pair S8 with a render cache (keyed on artifact id + mtime) so the heavier renderer does not regress serve latency.

The follow-the-work layer — beyond the asks (S9, S10)

Once the shared extractor and the enrich hook run, the journal features are nearly free — each is a cheap indexed read over data already parsed. All are deterministic and LLM-free, matching the agent-memory ethos (invariant #10): they surface detected signals, never claimed ground truth.

S9 — persist decisions, commits, errors, effort

  • Decisions (session_decisions): question→chosen-answer from the structured toolUseResult.answers (S8), plus ExitPlanMode approvals and tool rejections — the steering moments of a session.
  • Commits (session_commits): best-effort SHAs parsed from git commit/push/tag Bash calls and their results, validated against the git root via the #14 resolver — answers "what shipped from this work" and bridges to the existing Versions/Diff surface.
  • Errors & effort: an error count + sampled blob; token_total, tool_calls, model on the row — so the index can flag the heavy sessions.

S10 — the navigable work journal

  • Per-project timeline: a folder-scoped chronological lane (display name + first prompt + duration + files-changed + decision count), seeded by the existing day-bucketing.
  • Decisions log: a cross-session feed and a per-session inspector section of every steering moment as jump anchors — the spine of "follow the work".
  • Deterministic resume card: last typed prompt + edited-but-uncommitted files (session_files minus session_commits) + open decisions + branch + recent actions, with a copy button and a kb sessions resume CLI verb. No LLM.
  • Sessions-scoped search: the transcripts are already in the lance hybrid index — filter kb-category=memory-session, group by folder, facet on model/duration/first-prompt. Mostly UI/routing, no new indexing.
  • Narrative threads: cluster sessions by shared cwd + contiguous time + edited-set overlap + first-prompt similarity, materialised as kb-list/1 lists (V0015, invariant #25 — suppress list read-state derivation for session entries). Auto-clustering is a suggestion the user can edit.
  • Per-file history in the reader: with session_files, each artifact shows its lineage — created in session X, revised in Y, referenced in Z — a mini work-journal per artifact.

Smaller wins that ride the same data: inline red/green diff rendering for Edit (the input carries old_string/new_string); auto-collapse routine tool output but auto-expand errors and decisions; a hot-files heatmap across all sessions; and an out-of-corpus promotion hint ("this folder is edited often — bind-mount it as a kb").

Invariants this plan must respect

  • #27 — ids are source-relative, Doc.path canonical. The readable name and links are display only; never rename session-<ts>-<sid>.html or re-key the artifact. Canonicalise every edited path before any prefix test.
  • #11 — kb-session meta is canonical; new columns/tables are additive. session_id is non-unique (artifact_id is PK; re-captures create a second row), so every per-session table keys on artifact_id (+ session_id) and handles multi-capture.
  • #8 / #19 — history is append-only; the session↔reading link stays a derived join, never a history-row mutation. /readings precision rides the corrected ended_at.
  • #28 / #15 — the new /files, /folders and reverse endpoints fan out via buffered_join(FANOUT_CAP=8) in BTreeMap order, fold partials, drop-on-error; no Mutex guard crosses a fan-out await.
  • #5 / #9 — ?raw=1 and per-block raw dumps skip only session_render, never the outbound kb-prompt scrub; wire raw strictly after scrub.
  • kb-core #2 / #5 — all sqlite/lance writes go through StorageHandle from the best-effort enrich hook, never inline in index_file.
  • #14 — commit linkage uses the existing git-root resolver; never assume cwd is the git root.
  • #23 / #24 / #25 — new panels refresh only via session.captured/deleted through the SharedWorker SSE bridge; narrative threads reuse kb-list/1 grammar with session read-state suppressed.

Remaining open questions

The six surfaced forks are resolved; a few smaller calls are deferred to implementation time:

  • Render cache: land alongside S8 or as its own commit? Recommendation — alongside, since the richer renderer is what creates the pressure.
  • Thread auto-clustering thresholds (time gap, Jaccard overlap, prompt-similarity cutoff): tune empirically on the existing back-catalogue before exposing; ship suggestions as user-editable, never silent.
  • Folder label collisions: when two corpora share a basename, fall back to the full cwd or the kb name; decide once /api/sessions/folders is live against real data.
  • Error sampling budget: how many error snippets to persist per session before it is noise — start small (≤5) and revisit.
