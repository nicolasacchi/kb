Topic 10 · Web Gallery / SPA specification · Design handoff integrated 2026-05-11

verdictThree views. Iframed detail. Claude in the comments.
Multi-file is a first-class artifact.

The Claude Design Web Gallery handoff bundle E4XcIWFBUnJJqWOWAaNBeA is the implementation contract for kb's user-facing SPA. Grid · List · Atlas views over the artifact catalog, iframed detail with floating chrome, Cmd+K hybrid search, in-iframe annotation with kb-comments/1 exports, and a status pill that consumes the same SSE stream the TUI does. This page reproduces the spec with cross-links across topics 01/02/04/05/06/07/09, raises ten concerns, and proposes nine enhancements. The five canonical sample artifacts ship in sample-artifacts/.

TL;DR — what the executor builds

React + Vite + CSS variables. No Babel-in-browser. Geist sans + Geist Mono + Lora serif. Single accent variable (--accent defaults to #7c8cff) drives every interactive surface. Three gallery views: Grid (5 card styles, hybrid default), List (icon + title + summary + tags + age columns), Atlas (pan/zoom spatial canvas clustered by accent tag). Detail view = iframed artifact + four floating-chrome variants (capsule default). Multi-file artifacts are first class via a pages: [{label, src, file}] array. Cmd+K cycles hybrid / keyword / semantic with prefix filters. Comments live in localStorage, export to kb/{kb}/.review/{id}.json for Claude Code to read and reply to. Status pill consumes the canonical SSE event taxonomy from topic 05 §G.

Layout · HIGH (design-locked) Iframe sandbox · MED (conflicts topic 06) Scope · MED (5 card styles × 4 chromes × 3 views)

B. Stack

React + Vite. CSS variables. No runtime Babel.

  • Build: Vite + React 18 + TypeScript. The prototype's https://unpkg.com/@babel/standalone tag is concern #9 — production must bundle.
  • State: useState + URL routing (enhancement #2). No external state manager required at v0.1 scale.
  • Fonts: Geist (sans, weights 300–700), Geist Mono (400, 500), Lora (serif, 400, 500, 600). Self-host in production; the prototype hits Google Fonts.
  • Theme: data-theme="dark" | "light" on <html>. Both palettes defined as CSS variables (section §K).
  • Accent: single --accent custom property, default #7c8cff (kb-violet). Five swatches available: #7c8cff, #e89a4a, #5db59a, #d56b8a, #9b6bd5. --accent-soft derives via color-mix(in oklch, var(--accent) 18%, transparent).
  • Browser bar: Chrome 111+, Firefox 121+, Safari 15.4+. Drivers: color-mix(in oklch, …) needs Chrome 111+ / Firefox 113+ / Safari 16.2+ (later than the prior "Chrome 105+" claim, which only covered :has()). On Safari, the artifact-subdomain DNS resolution needs dnsmasq — see topic 06 Decisions.
  • SSE: native EventSource. Cross-link to topic 04.

Atlas view

Pan/zoom spatial canvas. v0.1 production: each artifact's 2-D coordinates come from a UMAP projection over the kb's embeddings, computed at index time and cached in the lance store. Cluster labels are derived from k-means over the projected coords keyed by accent tag (see §O″ cluster-4 decision). Edges connect any two artifacts sharing ≥ 2 tags. Prototype fallback (used only when UMAP cache is cold): the prototype hard-codes 9 cluster centers (rust, memory, async, errors, systems, types, perf, pin, default) and a deterministic hash placement — see prototype source for the hash recipe. Concern #6 resolved by cluster 4 (UMAP commit).

  • Hash function: hashOf(id) = sum of char codes × 31. Angle = (h % 360)·π/180, radius = 60 + (h % 110). Within a cluster, identical id → identical position.
  • Zoom range 0.5–2.0; pan unbounded.
  • Click any node opens detail (same handler as Grid/List).
  • Cluster labels render at the cluster center, dimmed.

Crumb (top-center)

Iframe rendering

The prototype's <iframe sandbox="allow-scripts allow-popups allow-forms allow-same-origin"> uses the right flag set but the wrong serving origin (same as the parent → footgun per topic 06 §A). Production uses topic 06's amended recipe: keep allow-same-origin (storage works, CodePen pattern), serve from a different origin (<id>.artifacts.localhost:4000, RFC 6761 auto-resolution on Chrome+Firefox, dnsmasq fallback on Safari). Drop only allow-top-navigation*. Recreate the iframe per render (key={artifactId + ':' + pageIdx}). postMessage RPC with direction-aware targetOrigin (parent → iframe uses subdomain; iframe → parent uses http://localhost:4000; parent must validate event.origin). Full detail: topic 06 Decisions.

F. Multi-file artifacts

A new first-class artifact dimension.

The design promotes multi-file artifacts to a first-class concept. An artifact may carry a pages array; if absent, the artifact is single-file as before.

{
  id: 's05',
  title: 'INC-0315 · Checkout Outage Postmortem',
  realSrc: 'artifacts/pm/00-summary.html',
  pages: [
    { label: 'Summary',      src: 'artifacts/pm/00-summary.html',  file: '00-summary.html'  },
    { label: 'Timeline',     src: 'artifacts/pm/01-timeline.html', file: '01-timeline.html' },
    { label: 'Root Cause',   src: 'artifacts/pm/02-cause.html',    file: '02-cause.html'    },
    { label: 'Action Items', src: 'artifacts/pm/03-actions.html',  file: '03-actions.html'  },
  ],
}

UX

  • Gallery card — "N files" badge in the preview's top-left.
  • List row — inline pill in the title row.
  • Detail view — slim left-edge Pages panel (240 px) with numbered files, current-file highlight, current-page dot, and prev/next stepper buttons.

Two-way sync (postMessage handshake)

  • Host → iframe: swap src when the user clicks a page in the Pages panel.
  • Iframe → host: when an internal <a href="01-timeline.html"> link is followed, the iframe posts {type:'pm:page', page:N} so the Pages-panel highlight stays in sync.

Concern #7 — the handshake leaks contract into the artifact author. Resolution: optional. Without the handshake, the host falls back to watching the iframe's load event and matching location.pathname against the pages[].src entries.

The reference multi-file artifact is sample-artifacts/pm/00-summary.html + 3 siblings.

G. Cross-artifact backlinks

Iframes can navigate the host.

Artifacts can embed inline cards or links that open other artifacts in the host gallery. Mechanism: iframe posts {type:'open-artifact', id:'s02'}; the host validates id against ARTIFACTS and switches the open artifact.

Reference: cost-of-abstraction.html page 3 has a backlink card pointing at s02 (the Rust Errors field guide). Stand-alone (file://) it renders as a visible card; iframed by the gallery it opens the linked artifact via postMessage.

Cross-link to anchor stability discussion in topic 09 — same DOM anchor model (data- attributes) underlies both the comment system and backlinks.

H. Cmd+K search overlay

Three modes. Prefix filters. Score bars.

Opens on ⌘K / Ctrl-K / / (when no input is focused). Backdrop click or Esc closes.

Modes

Cycle via Tab (badge text on the right of the input):

ModeBadgeWhat it does
hybrid (default)k+vBM25 + vector cosine, combined score. Implies both stores are present at query time — confirms topic 01's split-store hypothesis.
keywordkBM25 / FTS5 only. Fast, exact.
semanticvVector cosine only. Embedding-based. Cross-link to topic 02 for the model choice (bge-small).

Prefix filters in the query string

  • tag:rust — filter to artifacts with the tag.
  • kb:work — filter to the named kb.
  • since:7d — time window.
  • mode:semantic — switch mode inline (alternative to Tab).

Filters compose AND-wise with the free-text terms.

Result row

  • Icon · title · highlighted snippet (matched substring wrapped in <mark>) · tag chips · kb label.
  • Right edge: score bar (0…1) + numeric score (2 decimals).
  • Arrow keys move selection; Enter opens; hover also selects.

Empty states

  • No query: "type to search across N artifacts in K kbs."
  • Query, no results: "no matches. try fewer terms, or mode:semantic."
I. Comments & annotation

Annotate the iframe. Threaded. Claude replies. Three exports.

Supersedes topic 09's v1 export-only model. The anchor stability analysis in topic 09 stays load-bearing; the schema and threading model below are the new contract.

Annotate mode

Toggled by the pen icon in the floating chrome. When on, a bridge script is injected into the iframe's contentDocument (concern #10 about sandbox compatibility flagged). The bridge:

  • Adds data-cm-target to every eligible block: headings, paragraphs, list items, table rows, code blocks, callouts.
  • Adds dashed-accent hover outlines.
  • On click: opens a popover above the element with a textarea. Selecting text first scopes the comment to the exact words (kind: selection); clicking without selection scopes to the whole block (kind: block or heading).
  • On save: posts {type:'cm:add', artifactId, file, fileLabel, kind, tag, ref, snippet, body} to the host. The host appends to localStorage and opens the Comments panel.
  • Existing comments get a 3 px accent left-rail on their anchored element; resolved ones go grey.

Comments panel (right, 360 px)

  • Filter strip: open / resolved / all with counts.
  • Mode toggle: "turn on annotate mode" / "annotating · click any block".
  • Comments grouped by file. Current file labeled "here".
  • Each comment row: relative time + author, body, threaded replies, icon-only actions (jump · reply · edit · resolve/reopen · delete).
  • Replies are themselves authored as you or claude. Claude-authored replies get an accent left-rail and a sparkle mark.
  • The reply composer has a you ↔ claude segmented toggle so the user can paste Claude's response back in inline (when working without the export flow).
  • Jump action: host posts postMessage({type:'cm:flash', ref}) to the iframe; the annotator script (loaded via ?cm=on, see topic 06) handles the scroll-into-view + flash. Cross-page jump on multi-file: host first sets pageIdx (which swaps the iframe src), waits for load, then posts cm:flash. Note: the prototype's host-side iframe.__cmFlash() direct call (in comments.jsx) does not work in production — the iframe is cross-origin from the parent (subdomain serving), so iframe.contentDocument access is blocked by Same-Origin Policy regardless of the allow-same-origin sandbox flag. allow-same-origin only governs whether the iframe gets an isolated opaque origin; it does not make the iframe same-origin with the parent. postMessage is the only path.

Schema (kb-comments/1)

{

    "tags": ["systems", "workflow"],

  "generatedAt": "ISO",

      "kind": "block" | "heading" | "selection",
      "tag": "p",
      "ref": "el-12",       // data-cm-id on the element
      "snippet": "the visible text — used to confirm the element"
    },
    "author": "you",
    "body": "the comment text",
    "createdAt": "ISO",
    "editedAt": "ISO|null",
    "replies": [{
      "id": "r_x",
      "author": "you" | "claude",
      "body": "...",
      "createdAt": "ISO",
      "editedAt": "ISO|null"
    }]
  }]
}

Three exports

  1. Claude prompt — a self-contained instruction pointing Claude at kb/{kb}/.review/{id}.json, telling it how to address open comments, append replies with author: "claude", and flip status to resolved.
  2. kb JSON — the structured file (schema above).
  3. Markdown — readable summary for issue trackers / humans.

Each export has copy + download. Concern #4 — the JSON must reach kb/{kb}/.review/{id}.json; recommend a daemon endpoint (POST /kb/{kb}/review/{id}) for v0.2 when comments ship.

Persistence

  • Browser: localStorage key artifact-comments-v2; v1 schema auto-migrates on load.
  • Disk (v0.2): kb/{kb}/.review/{id}.json via daemon API.

Cross-link: anchor stability across regenerate is topic 09 §C (auto-fuzzy-match + needs-review for low-confidence anchors). Snippet + ref is the fallback when data-cm-id attributes drift.

M. Raised concerns

Ten push-backs the executor needs to hear.

  1. Iframe sandbox is storage-broken — same conflict topic 06 flagged. Resolved 2026-05-11 (amended post deep-review) — see topic 06 Decisions callout. Prototype uses sandbox="allow-scripts allow-popups allow-forms allow-same-origin". When the iframe is served from the parent's origin, allow-scripts + allow-same-origin is equivalent to no sandbox at all (the embedded script can remove the sandbox attribute). Resolution: keep the prototype's flag set (it's correct), change the serving origin to <id>.artifacts.localhost:4000. Per-artifact subdomain via RFC 6761 (Chrome M67+, Firefox 84+ auto-resolve; Safari needs dnsmasq). With allow-same-origin + different serving origin, the iframe gets a real, isolated origin (storage works) and the parent's DOM is cross-origin (safe). The original cluster-1 decision to drop allow-same-origin was wrong — it conflicted with §B's own opaque-origin analysis. iframe-recreate via React key, direction-aware targetOrigin (parent → subdomain; iframe → localhost:4000).
  2. :has() CSS dependency. The auto-slide of .float-pill--capsule when right-side panels open relies on .detail:has(.detail-stage.with-comments). Ships in Chrome 105+, Safari 15.4+, Firefox 121+ (late 2023). Resolution: set the minimum-browser bar; for older browsers, fall back to a JS class toggle in the same component.
  3. Comment system supersedes topic 09 v1. Topic 09 proposed export-only, no threading, no Claude-replier. Design has gone further: threaded replies, author: you|claude, three export formats, kb-comments/1 schema, in-iframe annotator with data-cm-id anchors. Resolution: keep topic 09's anchor-stability analysis as the load-bearing technical work; the schema and threading model are now §I above. The "auto-resolve on regen with fuzzy anchor re-match" stays — wire to anchor.snippet.
  4. Comment write path needs daemon endpoint. Resolved 2026-05-11 — see topic 11 §B.3. Comments persist in localStorage in the browser and need to reach kb/{kb}/.review/{id}.json for Claude Code to read and reply. Resolution: POST /api/kb/{kb}/review/{id} writes the body atomically to disk; GET /api/kb/{kb}/review/{id} reads it back for Claude-reply sync. File watcher (topic 03) picks up the change and emits comments.updated via SSE; status pill grows a badge. v0.2 deliverable alongside the comments milestone. The export modal's "download" path stays as the v0.1 fallback when the daemon isn't running.
  5. Status-pill event names diverge from the canonical TUI taxonomy. Design prototype uses index.progress + watcher.event; the TUI integration (topic 05 §G) canonized index.file, watch.modify, etc. Resolution: the TUI names win (they're already in the integrated spec); SPA renames as documented in §J above.
  6. Atlas cluster centers don't generalize. Hard-coded 9 centers in app/atlas.jsx assume a fixed tag vocabulary. Resolution: derive cluster centers from embeddings (topic 02) via UMAP / t-SNE in a build step; cache per kb. Tag names label clusters but don't drive their positions. v0.3+ work.
  7. Multi-file pm:page handshake leaks contract into artifact authors. Asks the artifact to emit JS to coordinate with the host. Resolution: make optional. Without the handshake, the host watches iframe load events and matches location.pathname against pages[].src to infer the current page. Document both paths.
  8. Combinatorial UI scope. 6 card styles × 4 chrome variants × 3 views × 3 densities × dark/light = 432 surfaces. Tweaks panel is design-review only. Resolution: v0.1 ships one default per axis (see §L); Settings exposes theme + accent + density only. Card style + chrome variant + view default to hybrid/capsule/grid; Atlas + List + alt card styles ship in v0.3 as opt-ins.
  9. Babel-in-browser is prototype-only. The bundle's <script src="https://unpkg.com/@babel/standalone…"> tag is for the design surface, not production. Resolution: Vite + React + TypeScript bundle. The unpkg URLs do not ship.
  10. Annotator bridge with cross-origin iframe. Resolved 2026-05-11 (amended). The prototype writes a <style> and event listeners into the iframe's contentDocument from the parent. With the amended cluster-1 decision (keep allow-same-origin, but iframe is on a different origin), this direct DOM access fails — the iframe is cross-origin from the parent. Resolution: serve-time injection. When the SPA toggles annotate mode, it requests the artifact with ?cm=on; the kb daemon rewrites the response to insert <script src="/_kb/annotate.js" defer></script> before </body> (with EOF fallback when </body> is missing, using a streaming HTML rewriter to avoid matches inside <script> literals). The script runs in the artifact's own origin, has full DOM access (allow-same-origin is in!), and communicates with the host via postMessage with explicit targetOrigin. The injection also writes an inline JSON payload (<script>window.__KB_COMMENTS = […]</script>) so left-rail data-cm-has-comment marks paint on first frame — no postMessage round-trip flash. Cache key includes ?cm=on so the plain artifact stays cacheable. Annotator protocol additions: cm:flash {ref}, cm:refresh {comments}, cm:mode {on}.
N. Enhancements — missing from the design

Nine gaps to close before the executor starts.

  1. Keyboard navigation across views. Design supports Cmd+K + in-modal arrows; no j/k on Grid/List, no / outside the modal. Add: j/k moves card selection, Enter opens, Esc clears filters. Match the TUI's vim-mode for consistency.
  2. URL routing. Detail state lives in React state — refresh blows it away, no shareable links. Add a URL parameter shape: ?view=grid&tag=rust&artifact=s05&page=2&comments=open. Sync on mount and on state change. Equivalent to the TUI's "always start on HOME" question, but for the SPA the answer is "deep-link everything."
  3. Empty / loading / error states. Design has "no matches" (gallery) and "no comments yet" (panel). Missing: artifact 404 (id in URL not in catalog), iframe failed to load (timeout / network / sandbox violation), daemon disconnected (status pill red, banner row). Spec all three.
  4. Accessibility. Design uses <button> everywhere (good) but: no landmark roles on top bar / left rail / main; no skip-link; no visible focus on dark-theme floating chrome; no aria-label on icon-only buttons. Cross-link to topic 05 enhancement #7 — daemon HTTP API is the non-visual escape.
  5. Print / export the artifact + comments. Useful for archival; missing. window.print() against the iframe with a print stylesheet that inlines comments next to their anchors.
  6. Search result preview pane. Cmd+K shows score + snippet but no preview. For semantic mode, a right preview pane loading the artifact at the matched section would close the loop. v0.3 nice-to-have.
  7. Onboarding / empty kb. Design assumes 25 artifacts loaded. First-run (empty kb) is undefined. Add: "no artifacts yet — drop an HTML file into kb/{kb}/ or run kb add <path>."
  8. Comment notification path. Once Claude has replied via the .review JSON loop, the SPA needs to know. Daemon emits comments.updated SSE event (added to the §J taxonomy table); status pill grows a comment badge; on click, jump to the Comments panel with the unread filter active.
  9. Permalink / share. The "copy permalink" button in Details panel has an undefined destination. v0.1: copy http://localhost:4000/a/{kb}/{id} (HTTP form, works in any browser). Custom-protocol kb://artifact/{kb}/{id} is internal-only; defer to v0.3.

O″. Decisions · 2026-05-11 (UX gaps · cluster 4 of 4)

Final cluster landed. Maximalist v0.1.

Open-points cluster 4 of 4 — every UX gap enumerated in §M (concerns) and §N (enhancements) is now decided. The chosen shape is bigger than the minimum v0.1 surface; the user explicitly chose the more ambitious path on three of four sub-questions.

Atlas clustering algorithm (resolves §M-6)

UMAP via the umap crate (Brett Hodges, 0.5.x), computed at index time, cached per kb. Seeded for determinism across runs. Recompute on +10 % artifact delta or on explicit kb atlas recompute. Output: 2-D coordinates per artifact, persisted in the lance store alongside embeddings. Topic 02 documents the embedding pipeline; topic 11 §B.2 gains an implicit dependency (the graph endpoint will use these coordinates as a fallback when the requested artifact lacks explicit edges).

Tag-based cluster labels still apply on top of the UMAP positions — cluster centroids are derived from the placed artifacts (k-means with k = number of distinct accent tags ≤ 12), labels read off the dominant accent tag in each cluster. This preserves the design prototype's readable labels while the geometry comes from the embeddings.

Settings persistence (resolves §enh table)

Hybrid: daemon canonical, localStorage cache. User prefs (theme, accent, density) and per-kb prefs (last view, last filter set if URL routing didn't capture it) live in ~/.config/kb/kb.toml under [ui] and [kb.<name>.ui]. The SPA reads localStorage first on load for 0-RTT paint, then reconciles against the daemon's GET /api/settings (added in topic 11). On change, the SPA writes both: localStorage immediately, daemon via PATCH /api/settings debounced 500 ms. Conflict policy: last-write-wins, no merge — settings are small enough that this is fine.

Multi-daemon shape (resolves topic 05 open question)

Multi-daemon from v0.1. Both the TUI and the SPA grow a daemon selector. Each daemon identifies itself via GET /api/identity (added in topic 11). Clients keep a list of known daemons in their own config:

  • TUI: ~/.config/kb/daemons.toml — one section per daemon ([daemon.work-laptop] endpoint = "http://localhost:4000"). The header chrome shows kb <daemon> · <kb> (e.g. kb work-laptop · rust-learning). D opens a daemon-switcher overlay.
  • SPA: stored under [ui.daemons] in kb.toml. Top bar's kb selector becomes a daemon + kb selector (the existing dropdown grows a daemon header).
  • Discovery for v0.1: config-file only. mDNS / .local auto-discovery is v0.4+ team-mode territory.
  • SSE aggregation: the SPA's status pill aggregates across all configured daemons (sums of in-flight indexing, max-severity connection state). Per-daemon detail in the drop-up. The TUI subscribes to one daemon at a time (the "active" one).
