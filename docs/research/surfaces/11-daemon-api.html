Topic 11 · Daemon HTTP API contract · Open-points cluster 2 of 4 · 2026-05-11

verdictFlat for cross-kb, nested for scoped.
Origin allowlist. 202 + run id. No version segment.

Every prior integration (topics 04 / 05 / 10) pointed at concrete endpoints; none enumerated the whole shape or resolved the design forks. This page is that contract. 28 endpoints across five groups: cross-kb reads, kb-scoped reads, kb-scoped writes, and per-artifact subdomain serving. CSRF via Origin allowlist. Async commands return 202 Accepted + run id + filter hint. JSON in / out, RFC 7807 problem+json for errors. Same axum process serves the API, the SPA shell, and the artifact subdomains.

TL;DR — what the daemon exposes

Same axum process binds 127.0.0.1:4000 and routes by Host: header: localhost for API + SPA, <id>.artifacts.localhost for artifact bytes. All paths nest under /api/...; kb-scoped operations use /api/kb/{kb}/..., cross-kb use flat /api/.... No version segment for v0.1 — break/add when needed via /api/v2 alongside, Sunset header for v1. Origin header allowlist on POSTs (reject browser cross-site CSRF); non-browser callers (TUI, CLI, Claude Code) have no Origin header and pass. Async commands (reindex, apply-fix, stats/export) return 202 Accepted + {run, events}; progress flows over the SSE firehose with run-id filter. Errors: application/problem+json (RFC 7807).

A. Anchor

Cluster 2 of the open-points discussion. One contract, three consumers.

Three client surfaces speak this API:

  • TUI (topic 05) — subscribes to /api/events; POSTs commands; reads stats, sources, errors.
  • SPA (topic 10) — fetches docs, runs Cmd+K search, posts review JSON, consumes the same SSE stream for the status pill.
  • Claude Code / CLI — reads kb/{kb}/.review/{id}.json from disk (written by the SPA POST), edits it, kb's file watcher picks up the change and emits comments.updated SSE.

The cross-cutting nature is why this page exists. Each consumer's research page (topics 04, 05, 10) describes its piece; topic 11 is the whole picture.

C. Auth + CSRF model

Origin allowlist. No tokens for v0.1.

Threat model

The daemon binds 127.0.0.1:4000 — already isolated from the network. The one remaining attack surface: any browser tab the user opens can fetch() against localhost. A malicious site could fire fetch('http://localhost:4000/api/kb/work/sources/X/reindex', {method:'POST'}) and trigger work on the user's behalf.

Rule

On every POST / PATCH / DELETE / PUT request, the daemon enforces:

  1. If Origin: header is present, it must equal http://localhost:4000 or http://<something>.artifacts.localhost:4000. Otherwise 403 Forbidden.
  2. If Origin: is absent (curl, TUI, CLI, Claude Code — none are browsers), the request passes. Loopback binding already restricts these to the trust zone.

Reads (GET) are not Origin-checked; they're either public-on-localhost or pulled into iframes by intent. The cost of a malicious page reading kb data is low (and they'd hit CORS preflights anyway for anything beyond simple requests).

Why not a token

  • Adds a setup step (~/.config/kb/token generation, distribution to clients) for negligible v0.1 security gain on a loopback service.
  • The Origin check accomplishes the same thing for the realistic threat (browser-mounted CSRF) with zero ceremony.
  • Self-host (when the daemon binds a public IP) is a different threat model. Tokens land then.

Identifier conventions in URL paths

  • {kb}: the kb's name from kb.toml — lowercase, [a-z0-9-] only. Daemon validates and rejects with 400 if invalid.
  • {src}: the slugified absolute source path. Slug rule: lowercase, leading / stripped, remaining / → -, non-[a-z0-9-] → _. The daemon maintains a slug ↔ absolute-path map; GET /api/kb/{kb}/sources returns both fields ({src, slug, path}) so clients can construct the URL without re-slugifying.
  • {id} for artifacts: opaque hash, content-addressed (sha256-prefix-12 of canonicalized HTML bytes), stable across regen-in-place. Format: a-<12-hex>. Surfaced in artifact.indexed events.
  • {err} for errors: daemon-assigned UUID, e-<6-base32>. Returned in error events (the event schema gained an id field post deep-review; see topic 04 canonical taxonomy). Stable for the lifetime of the daemon process; cleared on restart.
  • {run} for indexing runs: r-<6-base32>, daemon-assigned, returned in 202 responses + index.* events.
D. Async command shape

202 + run id + filter hint.

Indexing and fix-apply can take minutes. Synchronous POSTs would tie up an HTTP connection and starve other callers. The contract:

Request

POST /api/kb/work/sources/home-me-rust/reindex HTTP/1.1
Host: localhost:4000
Origin: http://localhost:4000
Content-Length: 0

Response

HTTP/1.1 202 Accepted
Content-Type: application/json

{
  "run": "r-2c1",
  "events": "/api/events?filter=run:r-2c1",
  "started_at": "2026-05-11T14:31:58Z"
}

Progress

The caller subscribes (or stays subscribed) to /api/events with the supplied filter. Events tagged with the same run id flow through:

event: index.start
data: {"t":"index.start","run":"r-2c1","kb":"work","src":"/home/me/rust","total":67}

event: index.file
data: {"t":"index.file","run":"r-2c1","path":"futures.html","ms":188,"edges":5,"ok":true}

event: index.complete
data: {"t":"index.complete","run":"r-2c1","ok_count":65,"err_count":2,"duration_ms":12400}

Callers without an open SSE connection can poll /api/events?filter=run:r-2c1&since=<Last-Event-ID> for the same effect (ring buffer up to topic 04's configured size).

Bare-202 (no body) rejected because it forces clients to pattern-match events to commands by source path / kb, which fails when two reindexes overlap. Synchronous rejected because indexing routinely runs >1 minute and would hold an HTTP connection.

E. Error shape

RFC 7807 problem+json.

All 4xx / 5xx responses set Content-Type: application/problem+json and a body of the form:

{
  "type":   "urn:kb:errors:source-not-found",
  "title":  "source not indexed",
  "status": 404,
  "detail": "no source matches id 'home-me-rust' in kb 'work'",
  "instance": "/api/kb/work/sources/home-me-rust/reindex"
}

The type is a URN (RFC 7807 §3.1 — absolute URI or URN; URN avoids the base-URL ambiguity on self-host). Catalog: urn:kb:errors:<kebab-name>. Clients match on type; title is the user-facing string (TUI error pill); detail is the diagnostic (SPA toast).

Standard HTTP status codes always: 200 sync OK, 202 async accepted, 400 bad request, 403 CSRF / Origin rejected, 404 not found, 409 conflict (e.g. concurrent review edit), 422 validation, 500 internal, 503 daemon shutting down.

The type URI is the canonical machine identifier; clients should match on it. The TUI surfaces title in the error pill; the SPA surfaces detail in the toast.

F. Miscellaneous defaults

Compression, content negotiation, body shapes.

  • Compression. tower-http gzip middleware on responses > 1 KB. Disabled for /api/events* — SSE buffering breaks streaming.
  • Content types. JSON in / out for the API. HTML for /, /a/..., and artifact subdomain pages. JS for /_kb/annotate.js. No XML, no form-urlencoded.
  • Permalink shape. /a/{kb}/{id} for single-file artifacts; /a/{kb}/{id}?page=N for multi-file. Path form (/a/{kb}/{id}/p/N) rejected — query is friendlier to React routing.
  • Cache headers. Long-cache the SPA's content-hashed bundles in /assets/*; no-cache for HTML shells (/, /a/...); subdomain artifact bytes get the file's mtime as Last-Modified + a short max-age (kb regenerates frequently).
  • HEAD requests. Supported on all GETs.
  • CORS. Same-origin only by default. The subdomain origins (<id>.artifacts.localhost:4000) and the parent (localhost:4000) are different origins; they communicate only via postMessage (concern topic 06 decisions). The daemon does not send any Access-Control-Allow-* headers, and the SPA does not need to call the API from any other origin.
G. Implementation pointers

One axum process. Virtual-host routing. Standard middleware.

  • Routing. One axum::Router. A small extractor branches on Host: — localhost goes to the API + SPA tree; anything matching *.artifacts.localhost goes to the artifact subtree. axum::extract::Host already exposes this without ceremony.
  • Origin allowlist. A tower::Layer on the write routes. Reject if Origin: is present and not in the allowlist; pass otherwise. ~15 LOC.
  • Async commands. tokio::spawn the work, mint a run_id, send the response, push index.* events into the broadcast channel as the work progresses. The ring buffer from topic 04 already handles replay; ?filter=run:<id> is a server-side filter applied before sending each event to the consumer.
  • Annotator injection. A response-rewriter layer on the artifact subdomain. Triggered only when ?cm=on; finds the last </body> in the stream, inserts the script + JSON payload before it. The injection is reversible (drop ?cm=on → cached vanilla bytes).
  • Comment write. POST /api/kb/{kb}/review/{id} validates the body against the kb-comments/1 schema, writes atomically (tmpfile + rename) to kb/{kb}/.review/{id}.json. The file watcher (topic 03) picks up the change and emits comments.updated.
  • Schema serving. /api/events.schema.json and per-type schemas are static files compiled into the binary via include_str!. Cache hint: ETag = build timestamp.
Recommendation Confidence · HIGH

v0.0.1 ship subset

Not all 28 endpoints land in v0.0.1. The vertical slice in index.html's "v0.0.1 vertical slice" covers:

  • GET /api/search · BM25 only at v0.0.1, hybrid by v0.2.
  • GET /api/kb/{kb}/docs/{id} · metadata.
  • GET /api/events + the schema serves · transport + taxonomy.
  • POST /api/kb/{kb}/sources/{src}/reindex · proves the async pattern.
  • Subdomain serving · proves the iframe sandbox recipe.

v0.1 (TUI + SPA ship together — cluster 4 ambition): the rest of the kb-scoped commands (pause, resume, dismiss, apply-fix, stats/export) + the full event taxonomy + the cluster-4 additions: GET /api/identity (multi-daemon), GET / PATCH /api/settings (hybrid persistence).

v0.2 (comments ship): review endpoints + comments.updated event + the annotator injection + the permalink routes.

v0.3 (Atlas + graph ship): GET /api/kb/{kb}/graph/{id} + POST /api/kb/{kb}/atlas/recompute. UMAP build step from topic 10 §O″ precomputes 2-D coordinates at index time.

Open follow-ups
  • JSON schemas per endpoint body. Each request/response shape needs a schema in the v0.0.1 deliverable. Out of scope for this discussion; tracked as a topic 04 sub-task.
  • Concurrent review edits. If the user POSTs review JSON while Claude Code is editing the on-disk file, the POST wins (overwrite). If-Match + ETag would do optimistic concurrency. Defer to v0.3 if it becomes a real problem.
  • Self-host auth. When the daemon binds a public IP, the Origin allowlist is insufficient. Token + per-kb ACLs land then. Not v0.1.
  • Rate limiting. Not needed on loopback. Add tower::limit if self-host happens.

Resolved by this discussion: auth model (Origin allowlist), async shape (202 + run id), path scoping (nested + flat hybrid), versioning (none for v0.1), permalink shape (/a/{kb}/{id}), annotator security (target-origin lockdown), error shape (RFC 7807), compression policy (gzip except SSE).
