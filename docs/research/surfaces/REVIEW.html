Surfaces — audit · Eight docs vs HEAD · 2026-05-24

Most of the surfaces design shipped.
The two newest docs (mobile, multi-daemon) are still spec.

This page reviews the eight docs in docs/research/surfaces/ against the current state of the kb codebase. For each doc: a one-paragraph verdict and one or two code citations. Docs 06–11 are the v0.1–v0.5 design cluster; they shipped or got cleanly superseded by later milestones. Docs 12 and 13 are 2026-05-19 design reviews proposing work that hasn’t happened yet.

TL;DR — per-doc verdicts

shipped 06, 07, 08, 09, 11 partial 10 not-shipped 12, 13

The cross-cutting surprises: (1) doc 11’s POST /api/kb/{kb}/review/{id} whole-document write — the original comments wire shape — was retired in v0.7 R8 in favour of fine-grained endpoints under review_lock. (2) doc 13’s multi-daemon SPA proposal landed only at the SSE-aggregation layer; the cross-origin REST switcher (CORS, per-daemon bearer, ?daemon= URL state, host-side /api/daemons) was never built.

06 · Iframe (sandboxing + injection + scroll)

shipped The doc’s amended post-deep-review recommendation — permissive sandbox flags plus per-artifact subdomain serving — is what the daemon does today. Probe + annotator are both serve-time injected. SPA + daemon agree on the flag string.

  • crates/kb-core/src/iframe.rs:28–30 — SANDBOX_FLAGS = "allow-scripts allow-same-origin allow-popups allow-popups-to-escape-sandbox allow-forms allow-modals allow-downloads", exactly the §G recommendation.
  • crates/kb-server/src/routes/artifact.rs:28–29 defines PROBE_PATH = "/_kb/probe.js" and ANNOTATE_PATH = "/_kb/annotate.js"; the ?cm=on rewriter at line 446+ injects the annotator. The runtime invariant «artifact_host_suffix is runtime, not a const» in CLAUDE.md captures the v0.6 lift of the suffix out of iframe.rs into [server] artifact_host_suffix.

07 · HTML effectiveness (BM25 field-aware indexing, kb-prompt template)

shipped Five-field BM25 (title / body / headings / code / prompt) lives in lance; <template id="kb-prompt"> with the 8 KB cap is parsed and stored; the «path-specific four-path decomposition» (embed body only, BM25 the prompt, never modify bytes on read, scrub only on outbound) is the daemon’s current policy. Hybrid search uses lance RRF (k=60), the doc’s recommended pattern.

  • crates/kb-core/src/storage/lance.rs:26 — FTS_COLUMNS = &["title", "body", "headings", "code", "prompt"], exactly the five fields the doc requested.
  • crates/kb-core/src/parser.rs:26 — PROMPT_MAX_BYTES: usize = 8 * 1024 with the truncate-on-overflow path at line 293+; the §G «<template id="kb-prompt">» recommendation is also load-bearing per CLAUDE.md invariant 8 (id is reserved).
  • Outbound scrub: crates/kb-core/src/scrub.rs:6–73 implements strip_kb_prompt via lol-html; the doc’s «deferred to v0.2+» line is satisfied (it landed in v0.3, per CLAUDE.md history).

08 · Prior art survey

shipped This doc is a positioning argument, not an engineering spec. Its conclusion — «one daemon + thin clients» with HTML-as-snapshot — is exactly what the kb workspace embodies: a Rust daemon (kb-server) plus three thin clients (kb-cli, kb-tui, the SPA in web/). No alternative architecture was reopened.

  • crates/ workspace layout: kb-core/ + kb-server/ (the daemon) + kb-cli/ + kb-tui/ + web/ — literally the four-client shape the doc argued for.
  • The CLAUDE.md project guide opens with «A Rust daemon that indexes, searches, and serves a personal collection of LLM-generated HTML artifacts. Ships a CLI, a 5-tab fleet-monitor TUI, and a single-page web UI» — the wedge is the product description.

09 · Comments / kb-comments/1 protocol

shipped The four anchor scopes (File / Chapter / Section / Selection) and the auto-fuzzy-match with stale/reanchored states are exactly what ships. The doc itself acknowledged supersedes for §D (wrapper-page shim → serve-time /_kb/annotate.js) and §E (HTTP API → topic 11). Both supersedes are reflected in code. The R8 / R9 endpoint reshape (fine-grained mutations, explicit reanchor) is a refinement on top, not a contradiction.

  • crates/kb-core/src/review.rs:150–232 — enum Anchor with File / Chapter / Section / Selection; fuzzy_resolve_anchor implements the Jaccard / Jaro-Winkler scoring the doc’s §C described. Resolution at L195+ encodes the stale-vs-reanchored states.
  • The SSE event comment.anchor_stale the doc names lives at crates/kb-core/src/indexer.rs:925; the v0.7 R9 explicit-reanchor flow (PATCH .../comments/{cid}/anchor) is wired at crates/kb-server/src/router.rs:196–199.

10 · SPA / Web Gallery spec

partial The visual contract, three views (Grid / List / Atlas), iframe detail, Cmd+K search, FloatingPill, annotator bridge, status pill — all shipped. Atlas with UMAP shipped in v0.3. What didn’t ship cleanly: the doc’s §O″ promised maximalist polish «all in v0.1» (j/k vim-nav, empty/loading/error panels, print stylesheet, Cmd+K result preview pane). Most landed by v0.5 polish but some (e.g. dedicated print stylesheet) only show up as a single @media print block.

  • SPA structure under web/src/components/ matches the doc 1:1: FloatingPill.tsx, CommentsPanel.tsx, AtlasView.tsx, Cmdk.tsx, StatusPill.tsx, LeftRail.tsx, TopBar.tsx.
  • iframe contract verified: web/src/routes/detail.tsx:32 uses the same SANDBOX string as kb_core::iframe (cited in the source comment at L24–28); per-artifact subdomain rendering is real in production.
  • Print stylesheet: a single block at web/src/styles/app.css:2433 — tiny vs the doc’s ambition. Mobile responsiveness is also thin (see doc 12 below).

11 · HTTP API surface

shipped (with one notable retirement) The 28-endpoint contract, the /api/kb/{kb}/... nesting, the Origin allowlist, the 202 + run id + filter async shape, RFC 7807 problem+json — all in the daemon today. v0.4 added bearer auth + rate-limiting (a layer above this doc); cluster-4 additions (/api/identity, /api/settings PATCH) shipped. The one retirement: POST /api/kb/{kb}/review/{id} (the whole-document write) is gone — v0.7 R8 split it into fine-grained routes::comments endpoints (add / reply / resolve / edit / anchor / delete + resolve-all) running under a single review_lock. GET stays.

  • crates/kb-server/src/router.rs:61–215 — the full router. Cross-kb flat routes (/identity, /kbs, /search, /stats, /events, /events.schema.json) and the kb-scoped tree under /kb/{kb}/... mirror §B.1–B.5.
  • Problem+JSON is everywhere: crates/kb-server/src/routes/review.rs:15,44,47,50,57 uses error_to_problem_json; the middleware exposes it workspace-wide. routes::errors::apply_fix is still a 202 stub (doc 11 §B.3 «POST .../apply-fix») at crates/kb-server/src/routes/errors.rs:99.

12 · Mobile redesign

not-shipped Dated 2026-05-19 as a «design review · open». None of P1 (tablet CSS-only) or P2 (FloatingPill bottom-sheet rebuild) landed. The CSS files have a handful of max-width media queries on gallery.css only, none on app.css or component-specific styles. No FloatingPillMobile.tsx, no CommentsPanel «variant» prop, no spa-mobile.spec.ts. The atlas placeholder for narrow widths isn’t there.

  • web/src/styles/ has exactly five @media blocks (per grep -rn '@media' web/src/styles/): four max-width rules in gallery.css (720, 1280, 900, 600 px) and one each in tokens.css (prefers-color-scheme) and app.css (prefers-reduced-motion + print). No 768-px tablet breakpoint, no 375-px phone breakpoint.
  • web/src/components/FloatingPill.tsx still exists as the single desktop-shaped component; no FloatingPillMobile.tsx sibling; CommentsPanel.tsx has no variant prop.

13 · Multi-daemon (fleet) architecture

partial Dated 2026-05-19. The fleet TUI shipped years ago and is the v0.6 redesign’s centrepiece. The SPA D7-prep groundwork landed (web/src/api/base.ts with the daemon-base getter/setter; sse.ts daemon-aware multi-EventSource). The user-facing surface that did ship is the SSE-aggregation pattern: a DaemonsManager in Settings lets the user enroll peer daemons, and the SPA opens one SSE per daemon. The cross-origin REST switcher proposed in §B2 — /api/daemons on the host, ?daemon= URL state, per-daemon bearer in api/bearer.ts, a DaemonPicker component, tower-http::cors, cross_daemon_origins in kb.toml — was not built. Today the SPA still data-fetches from one daemon (the one that served it).

  • web/src/api/base.ts ships the D7-prep primitive (the doc names this file), but the production code path keeps the base as "" — no boot path calls setDaemonBase. There is no web/src/api/bearer.ts, no web/src/api/daemons.ts, no web/src/components/DaemonPicker.tsx (grep across web/src/ finds zero hits for any of those).
  • Server-side: no crates/kb-server/src/routes/daemons.rs; router.rs has no tower-http::cors layer; config.rs has no cross_daemon_origins. The TUI’s DaemonPicker overlay (crates/kb-tui/src/app.rs:168) is the only daemon-switcher in the fleet.
  • What did land: web/src/components/DaemonsManager.tsx + web/src/api/sse.ts::saveDaemonUrls — a localStorage-backed list of peer SSE URLs the SPA subscribes to. This is the «pattern A» / fleet-aware-SSE shape, not the «B2 true multi-origin» the doc proposed.
Net findings audit · 2026-05-24

Surfaces 06–11 are basically done. The five oldest docs in this folder (iframe sandbox + serve-time injection, BM25 + kb-prompt template, daemon-as-product, kb-comments/1 anchor protocol, daemon HTTP contract) describe the kb daemon as it exists. Where they got rewritten — e.g. doc 11’s monolithic POST /review/{id} → the R8 fine-grained mutations — the change is in the direction of more discipline, not less.

Surfaces 12 + 13 are still open. The mobile redesign is unstarted; the multi-daemon SPA shipped only its fleet-SSE half (B2 baseline never landed). Both are recent (2026-05-19) and tagged kb-status=open, so they read as the current backlog more than as accepted-but-undone work. If multi-daemon SPA federation becomes a v0.10+ ambition, doc 13’s impl hit-list is the starting plan.
