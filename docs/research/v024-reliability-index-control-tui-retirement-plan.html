kb v0.24 — reliability, index control, TUI retirement, daemon logging

Thirteen green-CI commits across four tracks: supervise the storage actor and make deletes actually cascade, make indexable extensions configurable and single files excludable from SPA + CLI, retire the kb-tui crate after closing its two real parity gaps, and turn on the file logging that was built but never wired.

2026-07-03 · status:done · milestone:v0.24 · baseline: main @ 8fece1b7

Context

A five-agent, code-only assessment of the workspace (100,238 Rust LOC across five crates, 51,048 LOC in web/, ~1,700 tests) ran on 2026-07-03. It found a disciplined codebase with four residual clusters: unsupervised single points of failure on the storage hot path, a deletion/lifecycle story much weaker than the creation story, full-corpus in-memory work on gallery/atlas read paths, and several 80%-built user features. The operator then set four directives that define this milestone:

  • No new file-type parsers. Do not add PDF or other formats. Instead make the indexable-extension set configurable, mapping extensions onto the two existing parse pipelines (HTML, Markdown).
  • Per-file exclusion. A way to exclude a single file from the index, operable from both the SPA and the CLI.
  • Remove the TUI — after verifying everything it does is covered by SPA + CLI.
  • Better daemon logging if the code shows it is needed. It is: the rolling-file appender in crates/kb-core/src/tracing_init.rs is complete but dead code — no binary calls it. The daemon logs to stderr only, with zero file persistence and zero retention, while paths.rs:222 creates an empty log/ dir on every boot.

Scale walls (gallery full-corpus scans, atlas memory) and the feature bundle (highlights, unread shelf, bulk ops) are deliberately out of scope — see the backlog.

Track R — reliability architecture

Actor supervision (R1)

StorageActor::run() is spawned at storage/actor.rs:867 with no panic boundary; a panic in any handler silently kills the task and every later op resolves to a dropped-oneshot error while the daemon looks healthy. Panics are reachable today: arrow decode unwrap()s at storage/lance.rs:969, 1601-1606, 1824 and RecordBatch::try_new(..).expect(..) at storage/schema.rs:298, 475. Design: per-message catch_unwind (via futures::FutureExt, AssertUnwindSafe) that logs, replies with a storage error, and keeps consuming — the single-writer model makes each handler transactional, so surviving a panicked message is sound. The unwrap sites become typed Error::Storage; the 13 raw .lock().unwrap() sites adopt the poison-tolerant pattern already used at embed_cache.rs:146.

Systematic delete cascade + orphan sweep (R2)

indexer::process_delete (indexer.rs:1666) currently cleans the lance row, sessions, snapshots, and memory-links — but leaks edges (both directions), corkboard rows, pinned memories, reading history + sections, list entries, and the .review/<id>.json sidecar with its attachments. Design: a single cascade engine in kb-core with two modes — Full (true deletion) and KeepUserData (exclusion: keep sidecar + history) — so the cleanup set lives in one place instead of ad-hoc call sites. The reconcile pass gains an orphan sweep as a backstop (indexing has one; deletion currently has none), catching dependents left by any pre-v0.24 failed delete. Cascade mutations bump the storage index generation so the gallery memo invalidates (invariant #15).

Retention (R3)

sqlite.rs:975 states retention isn't implemented; history, reading_sections, and edges grow unbounded. Design: an optional [retention] config section (per-table day windows, default keep forever so nothing changes silently) plus a background prune task in kb-server bring-up, following the spawn_startup_compact pattern (lib.rs:923) and registered in the tasks vec so teardown_tasks joins it on shutdown/reload. History pruning must respect invariant #8 (append-only semantics; pruning old rows is a retention exception, never an edit path).

Security bundle (R4)

Two small hardening items from the audit: (a) kb-cli/src/commands/share.rs:263-287 extracts share zips with no decompression-bomb caps — add per-entry, aggregate (256 MiB, matching routes/download.rs), and entry-count (10k) limits; (b) lance filter strings are built by hand-rolled quote-escaping at ~14 format! sites — centralize into one escape_literal helper so a future site can't forget it.

Track X — index control architecture

Configurable extension map (X1)

The whole gate is two pure predicates: is_markdown (indexer.rs:207) and is_indexable (indexer.rs:216), consumed at four ingest sites — walk_core (indexer.rs:311), the watcher's initial_walk (watcher.rs:286) and emit_for_paths (watcher.rs:598,604) — with parse dispatch at indexer.rs:1083-1090. Design: an ExtensionMap (extension → Html | Markdown) resolved at bring-up with the existing three-layer precedence (per-kb KbSection.extensions → [indexer].extensions → built-in default of exactly today's set), validated in KbConfig::validate (config.rs:927) with a hard error for unknown pipeline names. Threading follows the established parameters: into run_with_ingest/index_file like chunked/versions_mode (lib.rs:1367-1398), into WatcherConfig via a builder (watcher.rs:75), and onto KbContext (state.rs) for the reindex route. A new config key is picked up automatically by the PUT /api/config in-process restart (invariant #13).

TrapShrinking the map must delete, not orphan. The reconcile delete pass (indexer.rs:491-517) only deletes a stored doc when the file is gone from disk (try_exists re-check at :509). A doc whose extension leaves the map still exists on disk, so it would never be cleaned. X1 therefore adds an explicit reconcile step: stored docs whose extension is no longer mapped are routed through the Full cascade. The identical trap shapes exclusion (below).

Secondary literal copies of the extension decision (share mod.rs:823/829, routes/mod.rs:65, cloudflare.rs:69, CLI import/synth) stay as-is in this milestone: they gate serving MIME and share packaging for already-indexed artifacts and are correct for any Html/Markdown-mapped extension; a follow-up note in the code points them at the map.

Per-file exclusion (X2–X4)

State: a new V0023__excluded_files.sql table (source-relative path PK, excluded_at, optional note), following the sources.paused schema shape rather than the quarantine pattern — quarantine piggybacks on the transient errors table and is failure-driven, wrong for user intent. (Originally planned as V0021, but V0021__session_files_basename_index.sql and V0022__history_source.sql landed since — V0023 is the next free slot.) Actor plumbing follows the standard triple (msg variant + handle method + match arm, templates at actor.rs:42/915/1668).

Enforcement (rewritten 2026-07-11, post-GC-B7): this plan originally named "process gates" / index_file, but GC-B7 (6c9baa38) split index_file into prepare_doc (read → parse → embed → build Doc, per file) and finish_indexed_doc, with flush_prepared_batch committing groups through one upsert_docs merge_insert — process_one no longer exists. The correct gate is therefore: walk_core + the watcher's emit paths (initial_walk/emit_for_paths) + a per-item exclusion check at the top of prepare_doc, returning its existing Ok(None) skip arm. The batch mechanics (drain-batching, merge_insert, bisect-style per-doc fallback) stay untouched, and the gate must not break the per-doc fallback-isolation contract pinned by GC-F2's test (indexer.rs::poisoned_doc_in_batch_falls_back_per_doc_and_only_it_fails, d5c66045). Per D6, sources.paused becomes enforced at that same seam. Excluding an artifact performs an immediate KeepUserData cascade and emits artifact.removed, because reconcile will never clean an excluded-but-present file (same trap as above). Re-including forces a reindex nudge through the ingest sink, mirroring quarantine restore (quarantine.rs:203); comments re-anchor from the preserved sidecar.

Surfaces: server routes GET/POST /api/kb/{kb}/exclusions + DELETE /api/kb/{kb}/exclusions/{path} with new artifact.excluded/artifact.included SSE kinds registered in routes/schema.rs; CLI verb kb exclude <target> (with --rm, --list, --json) resolving via http::resolve_artifact_target (http.rs:239); SPA — a card action button (pattern at Card.tsx:79-120), an exclude action in the reader's inspector About tab, and a Settings → Excluded pane mirroring Quarantine.tsx. Gallery invalidation is nearly free: artifact.removed already drives the docsGate (queryClient.ts:127); the two new kinds join that list plus a ["exclusions", kb] query key.

Track L — daemon logging architecture

Recon headline: kb_core::tracing_init::init (daily-rolling ndjson JSON layer + stderr layer, returning the WorkerGuard) has zero call sites — the module is exported at kb-core/src/lib.rs:44 and never used. The three live init_tracing implementations (kb-cli/src/main.rs:3617, kb-server/src/main.rs:51, embedder) are stderr-only with inconsistent default filters.

L1 wires the existing appender into both daemon entry points (the in-process kb daemon path and the standalone kb-server binary), holding the guard for process lifetime. The file layer defaults to info (not the module's current debug — unbounded debug ndjson is the wrong default), overridable via KB_LOG_FILE_LEVEL. Files land in the already-created <state>/log/ (paths.rs:82,222).

L2 adds the two follow-ons: a retention sweep ([server].log_retention_days, default 14, pruning at boot + daily, same background-task lifecycle as R3) and a runtime log level — a tracing_subscriber::reload handle stashed in a OnceCell (the install_corpus_mounts process-global precedent, lib.rs:1171), a PUT/GET /api/log-level route beside /config (router.rs:167; state-changing, so origin_allowlist already covers CSRF), and kb daemon log-level. A log-tail endpoint is deferred (D5): operators have the file path, and kb events --follow (T1) covers live watching.

Rollback

One commit per phase, all on main: git revert <sha> per phase, in reverse order if multiple. T2's revert restores the crate wholesale. The V0023 table is additive and inert under revert (refinery is forward-only; an orphaned excluded_files table breaks nothing). Retention and file logging are config/env-gated with keep-forever/off-by-default semantics, so reverting their consumers leaves no data loss. The only irreversible action in the milestone is retention pruning itself — which ships disabled by default.
