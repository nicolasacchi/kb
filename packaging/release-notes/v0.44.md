## kb v0.44 — security release

**Upgrade from v0.43.** v0.43 predates the fix for a DNS-rebinding bypass of the
loopback gate that needed no credential (a browser tab on an attacker-controlled
name could reach the loopback daemon's `/api` tree, including destructive
routes). Every earlier tag is affected. See `SECURITY.md` for the boundary table
and the known open edges.

### Before you upgrade

- Run `kb backup --all` first. `refuse_if_volume_ahead` makes a rollback refuse
  to boot: this release advances schema epochs (kb-core V0042; kb-code
  V0039-V0045, including the V0040 workspace rekey), and an older binary will not
  open the upgraded volumes.
- Notes sidecars are stamped `kb-comments/2`; a pre-v0.44 binary refuses them.
  Export or remove notes before any rollback.

### Channels

- Release tarballs now include the web reader (`share/kb/web/dist`, and
  `share/kb-code/web-code/dist` for kb-code) plus a sample corpus. The daemons
  find it relative to the executable; `scripts/install.sh` installs it.
- `install.sh` fails closed: a missing checksum sidecar or sha256 tool aborts
  unless `KB_INSECURE_SKIP_VERIFY=1`. When `gh` is signed in it also runs
  `gh attestation verify`, and that HARD-FAILS for every tag without
  build-provenance attestations: every tag before v0.44 (v0.43 included) and
  any `KB_BASE_URL` mirror. `KB_INSECURE_SKIP_VERIFY=1` is the escape hatch.
- Tarballs and both images carry build-provenance attestations
  (`gh attestation verify <file> -R nicolasacchi/kb`,
  `gh attestation verify oci://ghcr.io/nicolasacchi/kb:<ver> -R nicolasacchi/kb`).
- ghcr garbage collection no longer deletes any version carrying a semver or
  `latest` tag; a `channels exist` job probes the advertised channels anonymously.
- Attestation referrers can show up as untagged ghcr package versions; the GC job
  never deletes untagged versions (safe, unbounded). See `docs/packaging.md` for the
  manual cleanup.
- Platforms: Linux x86_64/aarch64 with glibc >= 2.39, and WSL2. Docker for older
  glibc. macOS and native Windows are unsupported.

### Behaviour changes to check

Server and proxies
- `[server] hostnames` entries that can never match are now hard validation errors.
- Artifact-iframe Hosts are refused on `/api`, `/capture` and `/metrics`.
- kb-code behind a same-host proxy that sets `X-Forwarded-For` now needs `hostnames`.
- `trusted_proxies` accepts DNS names (re-resolved every 30 s); names stop being
  trusted after about 5 minutes of failed resolution (fail closed).
- The dev-mode `frame-ancestors` is loopback-only.

Notes and comments
- CLI and agents get 409 on any mutation of a private note (the SPA sends
  `X-Kb-Visibility: all`).
- Note-only writes emit no events; attachment `Cache-Control` is `private,no-cache`;
  an unknown `?kb=` on `/api/review-notes` is 404.

Backups
- `doctor` backup-age now FAILs a state dir with `index.db` and no scheduled-name tarball.
- `remote_dest` for the schedule and `backup --all` is now `remote_dest/<tarball>`.
- New `[backup] remote_timeout_secs` and `keep_exports`; daemon-wide state is packed
  into the first kb's tarball.

Capture and CLI
- A bare `kb search` on a multi-kb daemon searches every kb but keeps the default
  exclusion of session transcripts (the stderr note says so; use `--kb <sessions kb>`
  or `--category memory-session`). Scripts that relied on the old 400 for an ambiguous
  bare search must pass `--scope one`.
- `kb remember` exits 0 with `queued` when the daemon is slow or down (outbox replay).
- Commit subjects are scrubbed at capture time; the `doctor` scrub audit samples the
  newest 500 (`KB_DOCTOR_SCRUB_LIMIT=0` for all). The CLI lowercases authors and warns
  outside the agent vocabulary.

kb-code
- CLI exit codes changed: 400 -> 2, an off-host loopback-only refusal -> 8, a drifted
  `suggest apply` or dirty checkout -> 3. `compose --slugify` twin slugs are now `-<6 hex>`.
- Forge credentials fail closed (no ambient fallback); `retrack` refuses a guessed PR
  target (`base-undetermined`); PR fetches have a 1800 s deadline. New job kinds
  `start`/`snapshot`/`retrack`/`retrack-bulk` (a job's `pr_number` carries the review id
  for `snapshot`/`retrack`); the CLI sends `?async=1`; the CLI read timeout is 600 s with
  job poll budgets.
- Wire changes: `in_diff` is `bool|null`, batch frames carry `review_ids`, `touched_in`
  gains `rebased`, and `FailureClass` gains `dubious-ownership`.
- A cleanly closed kb-code database with no `-wal` is no longer re-snapshotted on every
  epoch-crossing boot; a loopback-only store `restore` verb exists (mirror refs are
  re-imported by sync).
- Merge-commit-merged PRs are reviewable (base pinned to the merge-time tip);
  fast-forward and rebase merges still 409 with `--base`.

### Dependencies

- `xxhash-rust` 0.8.19 (advisory: the safe xxh3 custom-secret API accepted a too-short
  secret in release builds).

### Known issues

Deliberately deferred and documented, not scheduled.

kb-code
- A PR merged by squash or rebase stays `409 pr-already-merged` (git alone cannot recover
  a merge-time base); pass `--base <sha>`.
- `explain-base` reports the resolution the review recorded; it never re-runs the chain
  (a read must not fetch).
- Review queue: lane 3 cannot match a line-less whole-file finding to an author hunk (it
  stays queued until resolved or superseded); lane 5 covers review-bound flag-for-agent
  threads only (working-tree flags stay on the unified inbox).
- `touched_in` does not follow a file renamed between patchsets across a base move; such
  pairs report `rebased`, never an author touch.
- Store restore does not restore the `refs/remotes/work-*` mirror refs (store sync
  re-imports them); fetch locks use a blocking flock with a documented bound.
- Wire types: 11 grandfathered kb-SPA shadow types remain; hand exports and `json!` sites
  are ratcheted, not eliminated.
- Prod review-store forge features stay local-only until the repo has an `https` remote
  and a pinned `token_file` (see `docs/configuration.md`).
- U13 acceptance gates (V0044->V0045 relocation gate 1 especially) have no retained per-gate
  evidence against a prod-shaped volume, and gate 1 never produced a verdict; run
  `kb-code rehearse-migration` on a restored production volume before upgrading.

Capture, memory and CLI
- codex/opencode/kimi/omp/grok adapter fallbacks scrub and fail closed (no spool); replaying
  a `kb remember` for a memory edited in place between write and replay answers 409
  (`.rejected` in doctor).
- The SLO `recall_coverage_pct` uses a fixed 7-day window; `kb-wake-kimi.sh` prints no
  chores line; the weekly-note chore is not evaluated at SessionStart (`kb chores` shows it).
- CLI authorship: rows saved as `you` before v0.44 are not backfilled.
- Capture file names (`sanitize_sid`) and `kb-capture-throttle.sh` still use the lossy session
  key, so distinct non-plain session ids can collide on a capture file name (cross-crate
  file-name contract, deferred). Old lossy-named hook markers are not migrated: non-plain
  session ids get one extra nudge/wake/heartbeat once, and old capture files stay as older captures.
- `kb remember` without a client key writes no `kb-client-ref` marker; idempotency for those
  still rests on the name shape.
- `kb slate stats --design-checks`: "orchestrator" is approximated as the busiest attributed
  session, and "take honoured by another session" is a proxy.
- Harvest: a refused supersede (live other author) skips that round; the record stays in
  `report.json`.

Posture and supply chain
- The restrictive-Default trait is implemented for `Visibility` only; other defaulted
  enums are inventoried (the inventory test fails on a new one without an impl).
- lance default features are unchanged (`deny.toml` documents the advisories with
  review-by dates); cargo-mutants is an advisory, label-triggered lane.
- The multi-distro first-run smoke job runs after v0.44 is published.
- Pre-v0.44 history keeps two comments naming an internal host.
