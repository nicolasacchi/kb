## kb v0.44 — security release

**Upgrade from v0.43.** v0.43 predates the fix for a DNS-rebinding bypass of the
loopback gate that needed no credential (a browser tab on an attacker-controlled
name could reach the loopback daemon's `/api` tree, including destructive
routes). Every earlier tag is affected. See `SECURITY.md` for the boundary table
and the known open edges.

### Before you upgrade

- Run `kb backup --all` first. `refuse_if_volume_ahead` makes a rollback refuse
  to boot: this release advances schema epochs (kb-core V0042; kb-code
  V0039-V0045, including the V0040 workspace rekey), and an older binary will not
  open the upgraded volumes.
- Notes sidecars are stamped `kb-comments/2`; a pre-v0.44 binary refuses them.
  Export or remove notes before any rollback.

### Channels

- Release tarballs now include the web reader (`share/kb/web/dist`, and
  `share/kb-code/web-code/dist` for kb-code) plus a sample corpus. The daemons
  find it relative to the executable; `scripts/install.sh` installs it.
- `install.sh` fails closed: a missing checksum sidecar or sha256 tool aborts
  unless `KB_INSECURE_SKIP_VERIFY=1`. When `gh` is signed in it also runs
  `gh attestation verify`.
- Tarballs and both images carry build-provenance attestations
  (`gh attestation verify <file> -R nicolasacchi/kb`,
  `gh attestation verify oci://ghcr.io/nicolasacchi/kb:<ver> -R nicolasacchi/kb`).
- ghcr garbage collection no longer deletes any version carrying a semver or
  `latest` tag; a `channels exist` job probes the advertised channels anonymously.
- Platforms: Linux x86_64/aarch64 with glibc >= 2.39, and WSL2. Docker for older
  glibc. macOS and native Windows are unsupported.

### Behaviour changes to check

Server and proxies
- `[server] hostnames` entries that can never match are now hard validation errors.
- Artifact-iframe Hosts are refused on `/api`, `/capture` and `/metrics`.
- kb-code behind a same-host proxy that sets `X-Forwarded-For` now needs `hostnames`.
- `trusted_proxies` accepts DNS names (re-resolved every 30 s); names stop being
  trusted after about 5 minutes of failed resolution (fail closed).
- The dev-mode `frame-ancestors` is loopback-only.

Notes and comments
- CLI and agents get 409 on any mutation of a private note (the SPA sends
  `X-Kb-Visibility: all`).
- Note-only writes emit no events; attachment `Cache-Control` is `private,no-cache`;
  an unknown `?kb=` on `/api/review-notes` is 404.

Backups
- `doctor` backup-age now FAILs a state dir with `index.db` and no scheduled-name tarball.
- `remote_dest` for the schedule and `backup --all` is now `remote_dest/<tarball>`.
- New `[backup] remote_timeout_secs` and `keep_exports`; daemon-wide state is packed
  into the first kb's tarball.

Capture and CLI
- `kb remember` exits 0 with `queued` when the daemon is slow or down (outbox replay).
- Commit subjects are scrubbed at capture time; the `doctor` scrub audit samples the
  newest 500 (`KB_DOCTOR_SCRUB_LIMIT=0` for all). The CLI lowercases authors and warns
  outside the agent vocabulary.

kb-code
- CLI exit codes changed: 400 -> 2, an off-host loopback-only refusal -> 8, a drifted
  `suggest apply` or dirty checkout -> 3. `compose --slugify` twin slugs are now `-<6 hex>`.
- Forge credentials fail closed (no ambient fallback); `retrack` refuses a guessed PR
  target (`base-undetermined`); PR fetches have a 1800 s deadline. New job kinds
  `start`/`snapshot`/`retrack`/`retrack-bulk` (a job's `pr_number` carries the review id
  for `snapshot`/`retrack`); the CLI sends `?async=1`; the CLI read timeout is 600 s with
  job poll budgets.
- Wire changes: `in_diff` is `bool|null`, batch frames carry `review_ids`, `touched_in`
  gains `rebased`, and `FailureClass` gains `dubious-ownership`.
- A cleanly closed kb-code database with no `-wal` is no longer re-snapshotted on every
  epoch-crossing boot; a loopback-only store `restore` verb exists (mirror refs are
  re-imported by sync).
- Merge-commit-merged PRs are reviewable (base pinned to the merge-time tip);
  fast-forward and rebase merges still 409 with `--base`.

### Dependencies

- `xxhash-rust` 0.8.19 (advisory: the safe xxh3 custom-secret API accepted a too-short
  secret in release builds).
