## kb v0.45

### N6

- kb-code: a review finding's `touched_in` now follows a file rename across a
  base move (git `-M`, 50% similarity, the same bound `resolve_path` uses). A
  rename-only patchset is no touch, a rename plus an author edit at the finding
  is `exact`, and `rebased` remains only when the rename cannot be resolved
  (below the bound, unreadable change set, ambiguous). `/since` is unchanged.
