## kb v0.45 — protocol registry, public mirror, capture spool

Hardening and tooling on top of v0.44: a versioned protocol registry with
`kb validate`, a public-mirror recipe with its own config check, a capture
spool for every harness adapter, a release smoke test, a smaller dependency
tree, and fixes found while stabilising v0.44. Each `### N<x>` section below is
one lane.

### Before you upgrade

- No schema migration: kb stays at schema 44 and kb-code at epoch 45, so a
  rollback to v0.44 is a binary swap.
- The kb-memory plugin hooks and the `kb` binary should be updated together.
  New hooks name captures with `kb sessions capture --stamp`; with an older `kb`
  they retry without it, so nothing is lost, but the unified session key (N4,
  N10) only takes full effect once both are current.
- `kb validate` embeds `schemas/`; source builds need that directory (the
  Dockerfile copies it).

### Fixes since v0.44

- Artifact permalinks (`/a/{kb}/…`) no longer hang while the kb's storage actor
  is busy: the OG-meta and moved-path lookups are one lookup under a 750 ms
  deadline, after which the plain shell is served (N12).
- Opening a moved artifact by its old path inside the app now lands on the new
  location and the address bar shows the live path; `GET
  /api/kb/{kb}/docs/by-path/…` follows the moves log like the id route (N13).
- `kb backup`: a failed `tar` can no longer leave a `.partial` file behind (tar's
  gzip child could re-create it after cleanup).
- kb-code web UI: a caret line-sync write that fired after a navigation (for
  example add-to-board opening the board) no longer sends you back to the file.
- `Cargo.lock` is back in cargo's canonical order, so a local cargo run no
  longer leaves a diff in the checkout.

### N7

- The cloud object-store stack is no longer compiled into `kb` and
  `kb-code-server`. kb only ever opens local filesystem paths, but the
  `lance` dependency was declared with its default features (aws, azure, gcp,
  oss, goosefs, geo, ...), which pulled in opendal, reqsign, the AWS SDK, `rsa`
  and an advisory-affected `quick-xml`. `lance` is now declared with
  `default-features = false`; the dependency count drops from 1002 to 827 packages (binary size was not measured).
  On-disk data is unchanged (no migration, no schema epoch change).
- A new CI step (`cloud-stack-absent`) fails if that stack returns to
  `Cargo.lock` or if arrow/lance stop resolving to a single version.

### N1

- New `kb validate <file>`: an offline check of a sidecar or wire file against the
  versioned protocol registry in `schemas/` (kb-comments/1 and /2, kb-list/1,
  kb-slate/1, kb-proposal/1, kb-recall/1, kbc-findings/1 and /2,
  kbc-review-context/1, kbc-github-export/1, kbc-cmd/1, kbc-theme/1). It never
  edits a file. See `docs/protocols.md`.

### N5

Resolved from v0.44 known issues:

- **Posture beyond `Visibility`.** `slate::Origin` now implements `Posture`
  (restrictive value `Agent`, pinned by `origin_default_is_restrictive`).
  `CredentialPin` stays a reviewed selector (`Auto` is a ladder, not a point on an
  access axis) but its inventory reason now cites a behavioural test,
  `credential_pin_default_never_inherits_without_opt_in`, and the inventory fails if a
  cited test does not exist. No `Default` or serialized form changed.
- **Configurable `recall_coverage_pct` window.** `[kb.<name>.slo]
  recall_coverage_window_days` (absent = 7, clamped to 1..=365 with a validate warning,
  never a boot failure). The window is not a target, and the indicator's detail text
  names the window it measured.
- **`kb-wake-kimi.sh` chores line.** The Kimi first-prompt wake payload now ends with
  the one-line `kb chores --line` (3 s cap, silent on any failure), like `kb-wake.sh`.
- **Store restore of work mirror refs.** `kb-code store restore` now restores
  `refs/remotes/work-<id>/<branch>` heads from a GC pre-apply bundle (create or
  fast-forward only, same rejection rule). Routine backup bundles still carry
  `refs/kbc/*` only; `store sync` re-imports mirrors for those.

### N6

- kb-code: a review finding's `touched_in` now follows a file rename across a
  base move (git `-M`, 50% similarity, the same bound `resolve_path` uses). A
  rename-only patchset is no touch, a rename plus an author edit at the finding
  is `exact`, and `rebased` remains only when the rename cannot be resolved
  (below the bound, unreadable change set, ambiguous). `/since` is unchanged.

### N4

- Fixed: the codex, opencode, kimi, omp and grok capture adapters now spool the session on capture failure instead of losing it (the v0.44 Known issue "adapters do not spool"); a spooled item is replayed, scrubbed, by the next successful capture.
- Fixed: non-UUID session ids no longer share a capture file (`a_b` and `a-b` used to collide); `kb sessions capture --stamp` names a new capture after the session's real start time. Existing lossy-named captures keep working and are never renamed.

### N2

- New `docs/public-mirror.md`: the public read-only mirror deployment recipe
  (dedicated daemon, edge allowlist, Traefik and Caddy rules derived from
  `docs/public-mirror/allowlist.txt`, threat table, curl checklist). Docs and
  a no-boot test only; the daemon is unchanged.

### N3

- CI: new `first-run` workflow installs the published release (tarball via the
  tag's `install.sh`, with checksum and provenance verification) on clean
  debian, ubuntu, fedora and arm64 containers, pulls the ghcr image anonymously,
  and checks the SPA, keyword search, the watcher and `kb daemon doctor`. It runs
  after each release and on manual dispatch, and reports without gating.

### N8

- The protocol registry now covers the contracts other programs read:
  kb-sibling/1, coderef/1, coderef-feed/1, unified-inbox/1, kbc-claim/1,
  kb-capture-grok/1 and kb-session-bundle/1, all checkable with `kb validate`.
  kb-code-server tests validate its real output against the `kbc-*` schemas, so
  Rust/schema drift fails CI, and the kb-recall/1 id rule has a single source.
  `docs/protocols.md` classifies every versioned contract string in the code.

### N9

- `kb doctor --public-mirror` lints a `kb.toml` against the public-mirror
  posture in `docs/public-mirror.md` (ten named rules, file-only, exit 1 on
  findings, `--json`). It cannot see tokens or `KB_ALLOW_NO_AUTH`, which come
  from the environment.

### N10

- The beat heartbeat, distill-nudge and kimi-wake markers use the unified
  collision-free session key; markers written before the upgrade still count,
  so nothing fires twice. omp subagent sidecars keep readable file names (a
  short hash is added only on a collision, independent of discovery order) and
  are spooled and replayed with the main transcript.

### N11

- kb-code: `touched_in`'s rename-aware read runs each distinct diff at most once
  per request instead of up to twice per renamed finding and patchset.

### Deferred to a later release

- lip/1 (kb-lip to kb-code) is not registered: an honest drift test needs a real
  round trip per endpoint against a test language server.
- The codex, kimi, omp and opencode capture formats are not registered yet
  (each needs its own template-versus-schema parity test); kbc-review/1 needs a
  front-matter document kind in `kb validate`; kb-code's daemon-to-own-CLI
  envelopes stay unregistered until something outside the product reads them.
- Public mirror: a manual run of the degraded web UI behind a real edge.
- Release smoke (`first-run`): its first live run against a published release,
  hybrid-search gating on the docker leg, musl and glibc older than 2.39, and
  `kb add` hot-reload.
- Capture spool: omp sidecars of session ids outside `[A-Za-z0-9_-]` are not
  spooled (the main transcript still is).
- Binary size after N7 is not measured; the package count (1002 to 827) is the
  recorded delta.

### Not planned

- A daemon `/api/schemas` endpoint, a fix/write mode for `kb validate`, schema
  generation from Rust, and an MCP server were outside N1's brief; MCP remains a
  recorded non-goal (README → Non-goals).
- `recall_coverage_window_days` stays a signed field on purpose: a negative
  value warns and clamps instead of failing the TOML parse.
