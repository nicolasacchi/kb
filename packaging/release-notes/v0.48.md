## kb v0.48 — sidecar-heavy omp sessions, bounded capture, wider secret scrub

### Before you upgrade

- No migration in this release (kb schema 45, kb-code epoch 46 unchanged).
- The secret scrubber covers more shapes (below). Captures already on disk are
  not rewritten automatically: after upgrading the `kb` CLI, run
  `kb sessions rescrub` (dry run, prints per-lane counts) and then
  `kb sessions rescrub --apply`.
- The omp capture changes are in the hook scripts (live from the checkout or
  plugin the extension loads); the scrub and capture changes are in the `kb`
  binary — update both.

### Fixes

- **Segmented omp capture catches up sidecar-heavy sessions.** Subagent
  sidecars were all placed in the newest part because their first line (omp's
  title slot) carries no timestamp; placement now reads the session header
  (then the first message, then the slot's update time, then the file mtime).
  Translated sidecars are cached per file and reused until the file changes, so
  a pass cut off by its deadline keeps its work. While older parts wait, the
  tail gets at most half a pass and a failed tail makes the next pass
  frozen-first; a landing reserve keeps time for writing; the per-part landing
  cap scales with the payload (20 s + 1 s per 8 MiB, at most 90 s). Measured
  live: a 545 MB omp session with 435 subagents, previously never captured,
  is now a complete 27-part chain and a turn costs seconds.
- **`kb sessions capture` no longer holds every subagent sidecar in memory.**
  Each sidecar is streamed once (digest and scrub in one pass) and only the
  head/tail windows the capture can keep are retained; output is byte-identical
  to the previous release. Scrub CPU still scales with the total sidecar bytes.
- **Secret scrub coverage:** labeled secrets, bearer tokens and shell
  continuations split by a JSON-escaped (or double-escaped) newline are now
  redacted when the value looks like a credential (it contains a digit, `+` or
  `=`); a private key written with real newlines is redacted (bounded body,
  never across transcript records). A purely alphabetic passphrase on the line
  after its label is still not redacted.
- **Atlas place mode:** a drop that lands before the screen redraws no longer
  loses the placement.

### Known issues

- The existing same-line labeled-secret rule also redacts a non-secret word of
  8+ characters that follows a label on the next real line (over-redaction,
  not a leak).
