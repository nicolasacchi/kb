## kb v0.49 — idempotent secret scrub

### Before you upgrade

- No migration (kb schema 45, kb-code epoch 46).
- After upgrading the `kb` CLI, run `kb sessions rescrub` (dry run) and then
  `kb sessions rescrub --apply` once: captures already re-scrubbed with v0.48
  should report only the secrets v0.48 could miss (below); a following dry run
  must report 0.

### Fixes

- **The scrubber is idempotent.** The environment-variable rule matched the
  scrubber's own `[masked]` marker, so `KEY=[masked]` was "redacted" again on
  every pass and `kb sessions rescrub` (and `kb doctor --hooks`) reported
  captures as affected forever; a second `--apply` rewrote identical bytes. A
  value that is exactly a scrub marker is now skipped, and rescrub counts a lane
  only when its bytes actually change. `scrub(scrub(x)) == scrub(x)` is pinned
  by a property test over every rule.
- **A vetoed match no longer hides a secret.** When a newline-tolerant labeled
  match was vetoed (its value did not look like a credential), the scrubber
  skipped past the whole span, so a real secret behind an inner label
  (`password:` then `"client_secret": "…"` on the following lines) survived the
  first pass. The scrubber now resumes right after a vetoed match.
- A labeled environment variable such as `MY_PASSWORD=…` now stays
  `[redacted:labeled-secret]` instead of becoming `[masked]` on a later pass.
