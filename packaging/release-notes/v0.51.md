## kb v0.51 and kb-code v9.1 — "Crossings"

kb and kb-code now cross into each other, and kb shows more of what is happening
around you. Cited code paths open kb-code at that file, kb-code shows which
documents cite a file and which files agents are editing, and kb answers "what
changed since I was last here" for a whole project, for one artifact, and for any
past date. Agent sessions waiting on you are a live state, sessions say whether
their code was checked after the last edit, and artifacts have a reading mode.

### Before you upgrade

- One kb schema migration: V0046 adds a nullable `evidence_json` column to
  `sessions` (kb schema 45 to 46). It backfills nothing and runs on boot; no
  `kb reindex` is required to start. Captures indexed before the upgrade show the
  session checks as "not extracted" until you run `kb reindex <kb>` on the
  sessions corpus; new captures are filled at capture time. kb-code has no new
  migration (epoch stays 46).
- A daemon built before V0046 refuses to boot on an upgraded `index.db`. Take a
  `kb backup` before upgrading if you may roll back; see "Rolling back across
  V0046" in docs/self-host.md.
- To get the new live states in daemon mode, update the kb-memory plugin hooks:
  the "blocked on you" state, the last-tool line and the file presence beat each
  need hook changes (Claude Code only). Without them nothing breaks; those
  features simply stay empty. `KB_BEAT_PATHS=0` and `KB_BEAT_TOOLS=0` opt out.
- The reader's time machine reads the artifact's git history. A deployment whose
  corpus has no `.git` (for example a container bind-mount without it) gets only
  index-snapshot and working-tree versions.
- All-corpora search now ranks by relevance across corpora. There is no measured
  before-and-after on a real bench yet; `kb bench run --federated` is the way to
  measure it on your own corpora.
- Four zstd advisories (RUSTSEC-2026-0391, -0398, -0403, -0410) are ignored in
  `deny.toml` with a recorded reachability review: arrow and lance still need
  zstd 0.13 and the patched line needs arrow 60. The exception is reviewed by
  2027-01-31, or sooner when a lance release supports arrow 60 or newer.
- The `[kb_daemon]`, `[doclens]` and `code_url` settings are unchanged. For the
  "verified" state of the Code chip, kb's origin must be in kb-code's
  `[doclens] origins`. To let kb-code attribute edits made in a differently named
  checkout directory (bind mounts), set `projects = ["<dir name>"]` on its
  `[[repos]]` entry.
- GitHub Actions version bumps (#160) are not part of this release.

### kb

- **Since you left.** The Front Page opens with a strip naming, per project, the
  sessions that ran, the commits they recorded and the slate posts made since your
  last visit. `kb changes --since 2h` answers the same question in a terminal.
  Nothing is marked read.
- **Since your last visit, per artifact.** Open an artifact that changed since
  you last visited and a one-line banner names the changed sections; click one to
  jump to it, or View changes for the diff from the version you last saw. The
  Library's Reading filter gains "changed since visit", and `kb diff <doc>
  --since-visit` gives agents the same answer. Agent reads (`kb cat`, `get`,
  `read`) never count as your visit, and a browser open right after `kb read` is
  now its own visit.
- **The reader's time machine.** Open any artifact as it stood at a date
  (`?at=`): older body, captioned, with a then | now split and an "Open as of..."
  control in the versions panel. Historical views are not counted as reads.
- **Reading mode.** Press `r` in the reader (or More > Reading mode) for kb's
  reading style: a serif, narrow column in light or dark. Tick a corpus under
  Settings > Preferences to open its artifacts that way by default. Pages that are
  mostly media, or that carry `<meta name="kb-reading" content="off">`, are left
  as authored. Memory artifacts and other unstyled pages now open in the same
  voice from the daemon, with the fonts served by kb.
- **Blocked on you.** An agent session waiting on a permission prompt or an MCP
  question is a live state: the Sessions page lists it first under "Needs you",
  the header chip reads "1 blocked", and `kb sessions status` marks the row. A
  `session.state` event fires when a session becomes blocked or unblocked, so a
  `[webhooks]` or `kb events` notifier can alert you. The flag clears when the
  approved tool finishes, at your next prompt or when the turn ends. codex, Kimi
  and Grok have no equivalent hook and never show as blocked.
- **A quiet session names its last tool.** `kb sessions status` and the Now band
  show e.g. `stalled? · last: Bash 38m`, so a long build reads as work and not as
  death. It is the tool name only, never arguments, and means started, not running.
- **Did the code get checked?** Sessions carry a one-sentence verdict such as
  "cargo test passed after the last edit" or "edited, no checks ran", read from a
  fixed list of test, lint and build commands in the main transcript. It never
  guesses: a result that cannot be attributed reads as outcome unknown. It shows
  on the Worklog row, in the inspector's Checks section and in `kb sessions
  list|show|resume`.
- **The citation is the door.** A cited code path in an artifact is a link that
  opens kb-code at that file and line. A dashed underline is kb's unverified
  guess; it turns solid once a checkout is chosen and kb-code has checked it.
- **A Code chip in the reader** names where the nearest cited code lives and
  opens it in kb-code, saying plainly when kb has only read the citation.
- **Cross-corpus search ranks by relevance.** All-corpora search no longer lists
  the alphabetically-first corpus's top hit first. `kb bench run --federated`
  adds a `scope=all` case; relevance labels may be `kb:id`.
- **Claude Code sessions report which files they edit** (in memory only, relative
  to the repo root) so kb-code can show them.
- **Phones.** Library cards and Index rows no longer carry action buttons on
  touch devices; open the artifact and use More for Download and Exclude.
- Fixed in passing: an idle Claude session no longer flips back to "in progress"
  a minute after it finishes.

### kb-code

- **Cited by** on a file now also reads kb's live code references, so documents
  that were never pinned are listed (marked "unpinned"), and the strip says when
  kb could not be asked. With one citing document the top-bar chip opens that
  document at the cited section.
- **Files glow as agents change them.** A solid rail in the session's colour means
  kb saw that session touch that exact file; a dotted rail means it is probably the
  one active session; a plain rail means something changed it and we cannot say who.
  Marks stay, dimmed, until you open the file (up to an hour). Home and the top bar
  show "1 session working - 4 files in 10 min". Toggle: "presence" in the tree
  header. Edits in linked worktrees are reported separately from the main checkout.
- **Home shows blocked sessions:** "1 session blocked on you . permission: Bash".

### Fixes

- **Stale ingest errors.** An ingest error for a file that no longer exists now
  closes itself: a file that vanishes during ingest counts as a delete, and the
  reconcile pass dismisses open errors whose path is gone.
- **Made-up style tokens.** The css-vars lint rejects an undeclared custom
  property even when it has a fallback; every existing hit now uses a real token,
  so a few spacing, radius and shadow values shift by a pixel or two.

### API

- `GET /api/changes` (kb): per-project sessions, commits and slate posts since a
  time; also `kb changes`.
- `GET /api/kb/{kb}/artifacts/{id}/since-visit` (kb): the changed sections since
  your last web visit; the docs list accepts `?read=changed`.
- `GET /api/kb/{kb}/docs/as-of?at=&ids=` (kb): which version each of up to 100
  artifacts stood at for an instant. `GET /?at=<unix>` on an artifact's own
  origin serves that version's body.
- `GET /_kb/reading.css` (kb): the reading-mode stylesheet served to artifacts.
- `GET /api/sessions/live-touches` (kb, kb-live-touches/1): recent file touches
  per live session, scrubbed to repo-relative paths.
- `POST /api/sessions/beat` accepts `detail.paths`, `root`, `project`, `tool` and a
  blocked/unblocked event; `GET /api/sessions/live-status` accepts `blocked=1`,
  and its rows carry `blocked`, `blocked_tool` and the last started tool.
- Sessions responses carry the checks verdict (`evidence`); `session.state`
  fires on a change of `(state, blocked)`.
- kb-code adds the read-only relays `GET /api/kb/presence` (kbc-presence/1) and
  `GET /api/kb/blocked`; `GET /api/doc-refs` claims carry `source`
  (`pinned` or `kb-live`) and the response carries `live_lookup`.
- kb adds `GET /api/kb/{kb}/code-refs?by_target=<path>` as the live lookup behind
  kb-code's Cited by.
- `kb changes`, `kb diff <doc> --since-visit` and `kb bench run --federated`
  are new CLI forms.

  minor and patch group of 20 updates (with a reviewed skip of the older

  output is unchanged. `@vitejs/plugin-react` 6 in kb's web app, with
  `@babel/parser` now an explicit dev dependency of the annotate-bundle guard.

  versions. Four zstd advisories remain with the audited exception above.
- Dependabot no longer opens `@types/node` major bumps; the runtime is Node 22.
