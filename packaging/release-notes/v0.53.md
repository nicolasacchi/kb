## kb v0.53 — session handoff, kimi removed

A minor release on v0.52.1. It adds a cross-harness session handoff between omp
and Claude Code (with one schema migration), removes kimi harness support, fixes
a watcher race that could keep a deleted file indexed, and makes the kb-term
binaries report their real version.

### Before you upgrade

- **Schema: V0048.** It adds two nullable columns and an index to `sessions`
  and backfills nothing. Like every migration it raises the volume's schema
  epoch, so a v0.52.x daemon **refuses to boot** on a migrated volume. If you
  might roll back, run `kb backup` first; see "Rolling back across V0048" in
  `docs/self-host.md`.
- **Breaking: kimi support is removed (#312).** See "Removed" below for what is
  refused, what stays readable and what to clean up on a host that had the
  kimi hooks installed.
- **kb-code stays at v9.2.** The only kb-code changes drop kimi from the
  worktree lock-owner list and keep old kimi-authored comments labelled as agent
  comments. There is no kb-code feature change and no need to roll out a new
  kb-code image.

### New: hand a session over between omp and Claude Code (#300)

- **`kb sessions handoff <id> [--to claude|omp]`** writes a brief: a
  deterministic, LLM-free first prompt for a new session of the other harness
  (the source's own summary, the user prompts, open todos, files touched, the
  recent turns and pointers to pull more), within a character budget.
- **`--transplant`** writes a native session file instead, which the target
  resumes with `claude -r` or `omp -r`. It never overwrites an existing file,
  and `--dry-run` writes nothing. `--launch` starts the target harness in the
  session's directory; `--print` writes only the brief to stdout. It works
  offline: it reads the harness's own session file first and falls back to the
  newest kb capture (lossy for omp).
- **Lineage.** Every brief and transplant opens with a
  `[kb-handoff from <harness> session <id>]` line. kb reads it back as
  `continued_from`, shown on the session detail and card next to
  `continued_in`. It is displayed, never used for ranking. Captures indexed
  before the upgrade show no lineage until `kb reindex` re-parses them.
- **Daemon:** `GET /api/sessions/{id}/handoff` returns the brief from the
  capture. For a non-loopback client the secrets scrub runs on the transcript
  before rendering and on the text after.
- **Web:** a "Continue in Claude Code / omp" panel on the session page and in
  the list inspector renders the brief on request and offers copy-only
  commands. With `[terminal] enabled = true`, "Open in terminal" launches the
  transplant in a kb-term pane.

### Removed: kimi harness support (#312)

- kb no longer captures, beats, wakes or launches kimi sessions. The kimi hook
  scripts (`install-kimi-hooks.sh`, `kb-capture-kimi.sh`, `kb-wake-kimi.sh`,
  `kb-distill-nudge-kimi.sh`), the kimi live adapter, the kb-term kimi profile
  and its doctor checks, and the SPA's kimi options are gone. The closed harness
  set is now claude, codex, grok, omp and opencode.
- **Old kimi sessions stay readable.** They are still listed, labelled "kimi",
  with no resume command. New kimi input (a beat, a filter, a slate post, a
  launch) is refused with a 400, like any unknown harness.
- **Clean up a host that had the kimi hooks:**
  1. Remove kb's entries from the `[[hooks]]` list in your kimi config by hand.
     The removed installer could only uninstall entries it had marked, and older
     installs carry no markers.
  2. Drop the kimi binary directory from the kb-termd `PATH` drop-in if you
     added it, then `systemctl --user restart kb-termd.service`.
  3. `KB_HOOK_FMT=kimi` is no longer recognised; an unknown value falls back to
     the default JSON envelope.

### Fixes

- **A deleted file could stay indexed (#310).** The file watcher drops a create
  followed by a delete inside its 400 ms debounce window. If a reconcile pass
  had just indexed such a file, it stayed searchable until the next pass (up to
  a minute). A reconcile pass now re-checks the files it just indexed after 3 s
  and removes any that are gone. A file that arrives with an old modification
  time (`mv`, `cp -p`, `rsync -t`) and is deleted that quickly still waits for
  the next pass.
- **kb-term reports its real version (#309).** `kb-term`, `kb-termd` and
  `kb-tap` print the release version (they printed `0.0.0`); a local build says
  `0.0.0-dev`. `kb-term doctor` shows the tap's version and warns when it
  differs from kb-term's own (a mixed install). Packaging refuses an archive
  whose three binaries disagree with its version.
- **Terminal tier (#311):**
  - The relay retries a re-open refused with "too many viewers" within its
    existing retry budget; the old stream's slot can still be held for a
    moment while its pane closes.
  - `kb-term kill` reaps a stale entry only when tmux answers that no server
    is running; any other error keeps the files.
  - `docs/http-api.md` now documents that a REST kill of a stale id returns
    200 with `stale_removed: true` (the behaviour since v0.52.1).
  - The installer warns about a `PATH` directory containing `:`.
  - A poisoned viewer-slot lock no longer reads as "no viewers".
- **Supply chain (#313).** RustSec published an "unmaintained" notice for
  `chrono` (RUSTSEC-2026-0543) with no successor release. kb accepts it with an
  audited exception in `deny.toml`. It is not a vulnerability: any future
  chrono vulnerability gets its own id and still fails CI. The exception is due
  for review by 2027-02-28; the lasting fix is moving kb's own date code off
  chrono.
- **Tests and CI (#308).** Terminal end-to-end documentation, a processing
  barrier for one negative check, pixel-delta evidence kept on green runs, and a
  self-test for the hook-test diagnostics. Invisible to an operator.

### Upgrading a terminal host

1. Re-run `scripts/install-kb-term.sh` from this release, then restart
   `kb-termd` only (`systemctl --user restart kb-termd.service`). Do not restart
   the `kb-term@*` holder units: that ends every live session.
2. `kb-term --version` should print `0.53`, and `kb-term doctor` shows the tap
   at the same version.
3. Update the kb daemon image to this release for the relay changes and V0048.

### Known limits still open

- **`--graphics` is not wired** in `kb-term attach`; the kitty graphics core
  has never run against a real Ghostty or kitty.
- **Real-device phone checks are still pending.** Read and Drive modes are
  covered by unit and end-to-end tests, not by a pass on physical phones.
- **A same-pid, same-terminal `start` beat from another session can steal a
  terminal's binding.** Recorded and pinned as a known limit, not fixed.
- **Within one epoch a full join does not tell the SPA the tap's current marker
  sequence,** so a later resume may resend markers already folded into the
  join. Unchanged since v0.52.
- **The viewer cap (8 per session) is shared by SPA and CLI viewers.** A ninth
  viewer is refused with the specific "too many viewers" error.
- Linux x86_64 only for the kb-term archive; the terminal tier is not exposed on
  a public mirror, and none may be added.
